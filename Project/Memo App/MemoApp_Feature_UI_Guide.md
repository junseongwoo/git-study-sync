# WPF Markdown Memo App 기본 기능 및 사용자 친화 UI 구성

## 1. 문서 목적

이 문서는 WPF로 Markdown 기반 메모 앱을 만들 때 추가하면 좋은 기본 기능과 사용자 친화적인 UI 구성을 정리한 문서다.

목표는 단순히 `.md` 파일을 열고 저장하는 수준이 아니라, 회사 업무, 프로젝트 작업, 수정 이력, 기억할 내용, 해야 할 일을 매일 편하게 기록하고 다시 찾을 수 있는 개인 업무 도구를 만드는 것이다.

## 2. 앱의 기본 방향

이 앱은 다음 사용 방식을 기준으로 설계한다.

- 모든 메모는 기본적으로 Markdown 파일로 저장한다.
- 사용자는 폴더와 파일을 직접 열어도 내용을 확인할 수 있어야 한다.
- 앱은 `.md` 파일을 더 편하게 찾고, 분류하고, 작성하게 도와주는 역할을 한다.
- 데이터베이스는 필수가 아니다. 검색 인덱스, 캐시, 설정 정도만 보조 파일로 둔다.
- 회사 업무, 프로젝트, 스케줄, 작업 기록을 한 앱에서 다룰 수 있어야 한다.

## 3. 추천 화면 구성

가장 추천하는 기본 화면은 3분할 구조다.

```text
-----------------------------------------------------------------------+
| 상단: 검색창 / 새 메모 / 저장 / 오늘 / 설정                          |
+----------------------+----------------------+-------------------------+
| 왼쪽                 | 가운데               | 오른쪽                  |
| 프로젝트/카테고리    | 메모 목록            | Markdown 편집기          |
| 태그                 | 정렬/필터            | 미리보기                 |
| 즐겨찾기             | 최근 메모            | 메타데이터/할 일         |
+----------------------+----------------------+-------------------------+
| 하단: 상태 표시줄 - 저장 상태, 파일 경로, 마지막 수정 시간            |
+-----------------------------------------------------------------------+
```

### 3.1 왼쪽 영역

왼쪽 영역은 메모를 찾기 위한 기준을 제공한다.

추천 구성:

- 전체 메모
- 오늘
- 즐겨찾기
- 미완료 TODO
- 프로젝트
- 카테고리
- 태그
- 휴지통 또는 보관함

예시:

```text
전체 메모
오늘
즐겨찾기
미완료 TODO

Projects
  SDC_uLED
  MemoApp
  개인공부

Categories
  회사업무
  회의
  이슈분석
  개발기록

Tags
  #WPF
  #MVVM
  #Recipe
  #LightControl
```

### 3.2 가운데 영역

가운데는 선택된 조건에 맞는 메모 목록을 보여준다.

목록에서 보여주면 좋은 정보:

- 제목
- 프로젝트명
- 태그
- 마지막 수정 시간
- TODO 개수
- 중요 표시
- 미리보기 한 줄

목록 정렬 기준:

- 최근 수정순
- 생성일순
- 제목순
- 프로젝트순
- TODO 남은 순
- 중요 메모 우선

### 3.3 오른쪽 영역

오른쪽은 실제 작성 영역이다.

추천 구성:

```text
-------------------------------------------------
| 제목                                            |
| 프로젝트 / 카테고리 / 태그 / 중요 여부          |
+------------------------------------------------+
| Markdown 편집기              | 미리보기         |
|                              |                  |
|                              |                  |
+------------------------------------------------+
| TODO / 첨부 / 링크 / 변경 이력                  |
-------------------------------------------------
```

처음부터 편집기와 미리보기를 복잡하게 만들 필요는 없다. 1차 버전에서는 탭으로 나눠도 된다.

```text
[편집] [미리보기]
```

나중에 익숙해지면 좌우 분할 편집으로 확장한다.

## 4. 기본 기능 목록

## 4.1 메모 생성

사용자가 새 메모 버튼을 누르면 새 Markdown 파일을 만든다.

기본 동작:

- 제목 입력
- 프로젝트 선택
- 카테고리 선택
- 태그 입력
- 템플릿 선택 가능
- 파일명 자동 생성

파일명 추천 규칙:

```text
yyyy-MM-dd_HHmm_제목.md
```

예시:

```text
2026-07-14_0930_LightRuntime_SetValue분석.md
```

파일명에 사용할 수 없는 문자는 제거하거나 `_`로 바꾼다.

## 4.2 메모 저장

저장은 두 가지를 모두 지원하는 것이 좋다.

- 수동 저장
- 자동 저장

추천 정책:

- 사용자가 입력을 멈춘 뒤 1~2초 후 자동 저장
- Ctrl+S 수동 저장
- 저장 실패 시 화면 하단 상태 표시
- 마지막 저장 시간 표시

상태 표시 예시:

```text
저장됨 - 2026-07-14 09:41:22
저장 중...
저장 실패 - 파일이 다른 프로그램에서 사용 중입니다.
```

## 4.3 Markdown 편집

기본 편집 기능:

- 제목
- 본문
- 굵게
- 기울임
- 코드 블록
- 체크박스
- 표
- 링크
- 이미지 경로

단축키:

```text
Ctrl+B: 굵게
Ctrl+I: 기울임
Ctrl+K: 링크
Ctrl+S: 저장
Ctrl+N: 새 메모
Ctrl+F: 검색
```

WPF 학습 목적이라면 처음부터 완성형 에디터를 만들기보다 TextBox 기반으로 시작해도 된다.

1차 구현:

- TextBox 또는 AvalonEdit 사용
- Markdown 원문 편집

2차 구현:

- Markdown 미리보기 추가
- 문법 하이라이트
- 줄 번호

3차 구현:

- WYSIWYG에 가까운 편집 보조 기능

## 4.4 검색

검색은 이 앱에서 매우 중요하다.

기본 검색 대상:

- 제목
- 본문
- 프로젝트
- 카테고리
- 태그
- 작성일
- 수정일
- TODO 내용

검색 UI:

```text
[검색어 입력                                  ] [전체] [제목] [본문] [태그]
```

검색 결과 표시:

- 검색어가 포함된 제목
- 검색어가 포함된 본문 일부
- 파일 위치
- 마지막 수정 시간

검색 방식 단계:

1. 단순 파일 전체 검색
2. 메모 로딩 시 메모리 인덱스 생성
3. `.memoapp/index.json` 캐시 생성
4. 필요하면 SQLite 또는 Lucene 계열 검색 도입

처음에는 단순 파일 검색으로 충분하다.

## 4.5 프로젝트 / 카테고리 / 태그

프로젝트는 업무 단위, 카테고리는 문서 성격, 태그는 검색 보조 기준으로 나눈다.

예시:

```yaml
project: SDC_uLED
category: 이슈분석
tags:
  - LightRuntime
  - RS232C
  - WPF
```

구분 기준:

| 구분 | 의미 | 예시 |
|---|---|---|
| Project | 일이나 제품 단위 | SDC_uLED, MemoApp |
| Category | 문서 성격 | 회의, 이슈분석, 개발기록 |
| Tag | 검색용 키워드 | MVVM, Recipe, Config |

## 4.6 즐겨찾기와 고정 메모

자주 보는 메모는 즐겨찾기 또는 고정 기능이 있으면 편하다.

추천 기능:

- 즐겨찾기
- 상단 고정
- 최근 열어본 메모
- 자주 수정한 메모

Markdown metadata 예시:

```yaml
favorite: true
pinned: false
```

## 4.7 TODO 관리

메모 안의 체크박스를 자동으로 수집하면 유용하다.

Markdown 예시:

```md
- [ ] LightConfig UI 정리
- [x] ApplyConfig 흐름 분석
- [ ] SetValue/GetValue 문서화
```

앱에서는 다음 화면을 제공한다.

- 전체 TODO
- 오늘 TODO
- 프로젝트별 TODO
- 완료 TODO 숨기기
- 미완료 TODO만 보기

## 4.8 변경 이력 기록

회사 업무나 프로젝트 수정 이력을 기록하려면 변경 이력 템플릿이 필요하다.

추천 템플릿:

```md
# 변경 이력 - 제목

## 변경 일시

## 변경 대상

## 변경 전

## 변경 후

## 변경 이유

## 확인 방법

## 남은 문제
```

메모 앱에서 이 템플릿을 새 메모 생성 시 선택할 수 있게 한다.

## 4.9 첨부 파일과 이미지

Markdown 문서에서 이미지를 참조할 수 있게 한다.

추천 구조:

```text
MemoVault
  Projects
    SDC_uLED
      2026-07-14_LightRuntime.md
      assets
        2026-07-14_LightRuntime_01.png
```

이미지 삽입 예:

```md
![LightRuntime 흐름](assets/2026-07-14_LightRuntime_01.png)
```

## 4.10 백업

메모 앱은 개인 업무 기록을 담기 때문에 백업이 중요하다.

추천 정책:

- 앱 시작 시 1회 백업
- 하루 1회 자동 백업
- 저장 전 이전 파일 백업
- 최근 30일 백업 유지

백업 구조:

```text
.memoapp
  backups
    2026-07-14
      Projects
      Daily
      Templates
```

## 5. 사용자 친화 UI 원칙

## 5.1 화면은 항상 현재 상태를 보여줘야 한다

사용자는 다음을 즉시 알아야 한다.

- 지금 어떤 파일을 보고 있는지
- 저장되었는지
- 어느 프로젝트의 메모인지
- 검색 결과가 몇 개인지
- TODO가 몇 개 남았는지

## 5.2 자주 쓰는 기능은 상단에 둔다

상단 추천 버튼:

```text
새 메모 | 저장 | 오늘 | 검색 | 즐겨찾기 | 설정
```

너무 많은 버튼을 처음부터 넣지 않는다. 자주 쓰는 기능만 먼저 둔다.

## 5.3 오른쪽 클릭 메뉴를 제공한다

메모 목록에서 오른쪽 클릭 메뉴:

- 열기
- 이름 변경
- 즐겨찾기
- 프로젝트 이동
- 태그 수정
- 파일 위치 열기
- 삭제

## 5.4 삭제는 바로 지우지 않는다

삭제 시 바로 파일을 지우지 말고 휴지통 폴더로 이동한다.

```text
.memoapp
  trash
```

실수로 중요한 메모를 지울 수 있기 때문이다.

## 5.5 검색은 빠르고 단순해야 한다

검색창은 항상 접근 가능한 곳에 둔다.

추천 위치:

- 상단 중앙
- Ctrl+F 포커스 이동

검색 결과는 입력 즉시 갱신되게 한다.

## 6. MVVM 기준 구성

추천 ViewModel:

| ViewModel | 역할 |
|---|---|
| MainViewModel | 전체 화면 상태 관리 |
| ProjectTreeViewModel | 왼쪽 프로젝트/태그 트리 |
| MemoListViewModel | 가운데 메모 목록 |
| MemoEditorViewModel | 오른쪽 편집 상태 |
| SearchViewModel | 검색어, 필터, 결과 |
| ScheduleViewModel | 오늘 일정, 할 일 |
| SettingsViewModel | 저장 경로, 앱 설정 |

추천 Service:

| Service | 역할 |
|---|---|
| MemoFileService | md 파일 읽기/쓰기 |
| MemoMetadataService | front matter 파싱 |
| MemoSearchService | 검색 |
| MarkdownRenderService | 미리보기 변환 |
| BackupService | 백업 |
| ScheduleService | 일정 파일 읽기/쓰기 |
| TemplateService | 템플릿 관리 |

  - LightRuntime

## 8. 구현 우선순위

처음부터 모든 기능을 만들면 복잡해진다. 아래 순서로 진행하는 것이 좋다.

### 1단계

- 기본 3분할 화면
- md 파일 목록 로드
- md 파일 열기
- md 파일 저장
- 새 메모 생성

### 2단계

- 프로젝트/카테고리/태그 metadata
- 검색
- TODO 체크박스 수집
- 오늘 메모 화면

### 3단계

- Markdown 미리보기
- 템플릿
- 즐겨찾기
- 휴지통
- 백업

### 4단계

- 일정 관리
- 작업 기록 자동 연결
- 검색 인덱스 캐시
- 설정 화면

## 9. 추천 첫 화면

처음 실행했을 때 바로 업무를 시작할 수 있어야 한다.

추천 첫 화면:

```text
왼쪽: 프로젝트/오늘/미완료 TODO
가운데: 오늘 수정한 메모와 최근 메모
오른쪽: 선택한 메모 편집
상단: 검색창과 새 메모 버튼
```

앱을 켰을 때 빈 대시보드보다 최근 작업과 오늘 할 일이 보이는 편이 실제 사용성이 좋다.

## 10. 결론

이 메모 앱의 핵심은 예쁜 메모장이 아니라, 매일 업무 내용을 잃어버리지 않게 해주는 개인 업무 기록 시스템이다.

따라서 1차 목표는 다음 세 가지다.

- 빠르게 적기
- 쉽게 찾기
- 안전하게 저장하기

이 세 가지가 안정되면 Markdown 미리보기, 일정 관리, 템플릿, 통계 같은 기능을 단계적으로 붙이는 것이 좋다.
