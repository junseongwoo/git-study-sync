# WPF Markdown Memo App 일일 스케줄 구성 가이드

## 1. 문서 목적

이 문서는 메모 앱 안에서 하루하루 진행해야 하는 업무와 스케줄을 관리하기 위한 구조를 정리한 문서다.

목표는 단순한 달력 앱이 아니라, 실제 업무 흐름에 맞게 오늘 해야 할 일, 진행 중인 일, 완료한 일, 내일로 넘길 일을 Markdown 파일로 남기는 것이다.

## 2. 스케줄 기능의 기본 방향

스케줄 기능은 다음 목적을 가진다.

- 오늘 해야 할 일을 아침에 정리한다.
- 진행 중인 일을 시간대별로 기록한다.
- 완료한 일과 미완료한 일을 구분한다.
- 미완료한 일은 다음 날로 이월할 수 있다.
- 프로젝트 메모와 하루 일정을 연결한다.
- 하루 작업 기록이 자연스럽게 업무 일지가 되게 한다.

## 3. 추천 화면 구성

스케줄 화면은 메모 화면과 별도 탭 또는 별도 View로 구성하는 것이 좋다.

```text
-------------------------------------------------------------------+
| 상단: 날짜 선택 | 오늘 | 이전날 | 다음날 | 새 일정 | 이월          |
+----------------------+----------------------+---------------------+
| 왼쪽                 | 가운데               | 오른쪽              |
| 월간/주간 캘린더     | 오늘의 일정          | 선택한 일정 상세     |
| 프로젝트 필터        | 시간대별 계획        | 관련 메모            |
| 미완료 할 일         | TODO                 | 작업 기록            |
+----------------------+----------------------+---------------------+
| 하단: 오늘 완료율 / 남은 작업 / 마지막 저장 시간                  |
+-------------------------------------------------------------------+
```

## 4. 하루 스케줄 파일 저장 구조

일정도 Markdown 파일로 저장한다.

추천 위치:

```text
D:\MemoVault
  Daily
    2026
      07
        2026-07-14.md
        2026-07-15.md
```

또는 현재 작업 폴더 기준으로는 다음과 같이 둘 수 있다.

```text
D:\_WJS\Memo
  Daily
    2026
      07
        2026-07-14.md
```

## 6. 스케줄 항목 데이터 구조

앱 내부에서는 일정 하나를 다음 모델처럼 생각하면 된다.

```text
ScheduleItem
  Id
  Date
  StartTime
  EndTime
  Title
  Project
  Category
  Status
  Priority
  LinkedMemoPath
  Note
```

상태값 예시:

| Status | 의미 |
|---|---|
| Planned | 예정 |
| InProgress | 진행 중 |
| Done | 완료 |
| Delayed | 지연 |
| Canceled | 취소 |
| CarryOver | 이월 |

우선순위 예시:

| Priority | 의미 |
|---|---|
| High | 오늘 반드시 해야 함 |
| Normal | 일반 작업 |
| Low | 여유 있을 때 |

## 7. 하루 업무 흐름

하루 스케줄 기능은 다음 흐름을 기준으로 설계한다.

```text
앱 실행
  -> 오늘 Daily 파일 로드
  -> 없으면 오늘 Daily 파일 생성
  -> 어제 미완료 항목 확인
  -> 오늘로 이월할지 선택
  -> 오늘 핵심 목표 작성
  -> 시간대별 일정 작성
  -> 업무 진행 중 상태 변경
  -> 완료/미완료 정리
  -> 퇴근 전 내일로 넘길 일 정리
```

## 8. 아침 계획 기능

아침에 앱을 열면 오늘 계획을 빠르게 잡을 수 있어야 한다.

추천 기능:

- 오늘 Daily 자동 생성
- 어제 미완료 TODO 표시
- 이월 버튼
- 오늘 핵심 목표 3개 입력
- 시간대별 작업 추가

아침 화면 예시:

```text
오늘 핵심 목표
[ ] SDC_uLED LightRuntime 문서 정리
[ ] MemoApp UI 구조 설계
[ ] WPF Binding 예제 작성

어제 미완료
[ ] PGRecipeControlWindow ComboBox 정리     [오늘로 이월]
[ ] ConfigWindow Align Light UI 확인        [오늘로 이월]
```

## 9. 진행 중 기록 기능

일정을 단순히 완료 체크만 하는 것이 아니라, 작업 중 생긴 내용을 바로 적을 수 있어야 한다.

추천 UI:

```text
일정 선택
  제목: LightConfig Set/Get 분석
  프로젝트: SDC_uLED
  상태: 진행 중
  관련 메모: LightRuntime_SetValue분석.md

작업 기록
  09:20 ApplyConfig 확인
  09:35 SetOffset/GetOffset 확인
  09:50 0-base/1-base 혼동 포인트 정리
```

Markdown 기록 예시:

```md
### 09:20 - LightConfig Set/Get 분석

- ApplyConfig는 PortName, BaudRate, DataBits를 적용한다.
- SetValue 성격의 메서드는 LightRuntime의 SetOffset, SetLevel 계열이다.
- GetValue 성격의 메서드는 GetOffset, GetLevel, GetChannelPowerStates다.
```

## 10. 미완료 이월 기능

업무에서는 계획한 일을 모두 끝내지 못하는 경우가 많다. 그래서 이월 기능이 중요하다.

이월 정책:

- 완료하지 못한 TODO를 다음 날 Daily에 복사한다.
- 원래 날짜에는 `CarryOver` 표시를 남긴다.
- 몇 번 이월됐는지 표시한다.

예시:

```md
- [ ] ConfigWindow Align Light UI 표시 확인
  - carryOverFrom: 2026-07-13
  - carryOverCount: 2
```

UI에서는 다음처럼 보여줄 수 있다.

```text
미완료 작업
-------------------------------------------------
[ ] ConfigWindow Align Light UI 표시 확인
    2026-07-13부터 이월됨 / 2회
    [오늘로 이월] [보류] [삭제]
```

## 11. 프로젝트 메모와 스케줄 연결

일정 항목은 관련 메모와 연결할 수 있어야 한다.

예시:

```yaml
linkedMemo: Projects/SDC_uLED/2026-07-14_LightRuntime_SetValue분석.md
```

사용 흐름:

```text
스케줄에서 작업 선택
  -> 관련 메모 열기
  -> 작업 내용 작성
  -> 일정 상태 완료로 변경
```

이렇게 하면 스케줄은 “무엇을 할지”, 메모는 “무엇을 했고 무엇을 알았는지”를 담당한다.

## 12. 반복 일정

반복적으로 해야 하는 업무가 있다면 반복 일정 기능을 둔다.

예시:

- 매일 아침 작업 계획 작성
- 매일 퇴근 전 작업 정리
- 매주 월요일 프로젝트 진행 상황 정리
- 매주 금요일 백업 확인

반복 일정 설정 예시:

```yaml
repeat:
  type: weekly
  days:
    - Monday
  time: "09:00"
```

처음 구현에서는 반복 일정 자동 생성까지 가지 않아도 된다. 템플릿에 기본 항목으로 넣는 방식부터 시작한다.

## 13. 알림 기능

PC에서 사용할 앱이라면 알림 기능도 유용하다.

추천 알림:

- 일정 시작 10분 전
- 오래 진행 중인 작업 알림
- 퇴근 전 미완료 정리 알림
- 자동 저장 실패 알림

단, 1차 버전에서는 알림보다 스케줄 기록과 저장 안정성을 우선한다.

## 15. 일일 화면에서 제공할 버튼

추천 버튼:

```text
[오늘] [이전날] [다음날] [새 일정] [오늘 파일 열기] [이월] [저장]
```

버튼 역할:

| 버튼 | 동작 |
|---|---|
| 오늘 | 선택 날짜를 오늘로 변경 |
| 이전날 | 하루 전 Daily 로드 |
| 다음날 | 하루 뒤 Daily 로드 |
| 새 일정 | 시간대별 일정 추가 |
| 오늘 파일 열기 | Daily md 파일 직접 열기 |
| 이월 | 미완료 항목을 선택 날짜로 복사 |
| 저장 | 현재 Daily 파일 저장 |

## 16. 구현 우선순위

### 1단계

- 오늘 Daily 파일 자동 생성
- 오늘 할 일 작성
- 완료 체크
- Daily md 저장

### 2단계

- 시간대별 일정 추가
- 이전날/다음날 이동
- 미완료 항목 표시
- 이월 기능

### 3단계

- 프로젝트 메모 연결
- 주간 보기
- 반복 일정 템플릿

### 4단계

- 알림
- 완료율 통계
- 월간 요약
- 프로젝트별 작업 시간 집계

## 17. 주간 요약

일일 스케줄이 쌓이면 주간 요약도 만들 수 있다.

주간 요약 예시:

```md
# Weekly Review - 2026-W29

## 이번 주 완료한 일

## 진행 중인 일

## 지연된 일

## 다음 주 우선순위

## 배운 내용
```

이 기능은 처음부터 구현하지 않아도 되지만, Daily 파일 구조를 잘 잡아두면 나중에 쉽게 만들 수 있다.

## 18. 결론

스케줄 기능은 캘린더처럼 예쁘게 보이는 것보다 매일 실제로 쓸 수 있어야 한다.

가장 중요한 기능은 다음 네 가지다.

- 오늘 해야 할 일을 빠르게 작성한다.
- 진행 중인 내용을 바로 기록한다.
- 완료와 미완료를 명확히 구분한다.
- 미완료 작업을 다음 날로 자연스럽게 넘긴다.

이 구조가 잡히면 메모 앱은 단순 기록 도구가 아니라 매일 업무를 정리하고 이어갈 수 있는 개인 작업 관리 도구가 된다.
