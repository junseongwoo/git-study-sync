# RecipeWindow - PG 매핑 탭 사용자 매뉴얼

## 1. 이 탭에서 하는 일

PG 매핑은 **cell의 Y Index별로 사용할 PG 장비 번호를 정하는 설정**이다. 공식 문서상 `YIndex`는 PG mapping의 기준이다.

예를 들어 Y Index 0의 cell들이 PG 1을 사용해야 한다면, `Y Index = 0` 행의 PG를 `1 — 주소`로 선택한다. 같은 Y Index를 가진 모든 cell에 이 설정이 적용된다. PG 매핑은 cell별 설정이 아니다.

화면에 표시되는 endpoint 주소와 실제 장비 배선/구성의 대응은 현장 설정을 기준으로 반드시 확인한다. 콤보박스와 실행 연결의 세부 동작은 현재 코드 기준의 **[추론]** 이다.

## 2. 컨트롤별 사용 방법

| 컨트롤 | 역할 | 사용 방법 |
|---|---|---|
| 상단 안내 문구 | 매핑 기준과 기본값을 설명 | Y Index와 PG 번호가 항상 같아야 한다는 뜻은 아니다. 새 Y Index의 초기값만 같게 만들어진다. **[추론]** |
| `Y Index 동기화` 버튼 | 현재 Cell 목록에 맞춰 매핑 행을 생성/정리 | Cell map을 만들거나 재생성한 뒤 먼저 누른다. 기존에 지정한 유효 PG 선택값은 유지되고, 새 Y Index에는 같은 번호의 PG가 초기값으로 배정된다. **[추론]** |
| `Y Index` 열 | 매핑의 기준 번호 | 읽기 전용이다. 번호를 바꾸려면 이 탭에서 수정하지 말고 Cell map/Cell 생성 조건을 확인한다. |
| `PG (번호 — 주소)` 열 | 해당 Y Index가 사용할 PG endpoint 선택 | 드롭다운에서 실제 연결 대상의 번호와 주소를 함께 확인한 후 선택한다. `(SIM)`은 simulation endpoint 표시다. **[추론]** |

## 3. 권장 설정 순서

1. 먼저 기본 설정/Cell map에서 cell 구성을 완료한다.
2. Cell을 새로 만들거나 재생성했다면 **Y Index 동기화**를 누른다.
3. 표의 모든 Y Index 행을 확인한다.
4. 각 행의 **PG (번호 — 주소)** 콤보박스에서 실제 해당 Y group이 사용할 PG를 선택한다.
5. PG 번호뿐 아니라 주소(host:port)와 `(SIM)` 표시를 함께 확인한다. **[추론]**
6. Recipe를 저장한다.
7. 실제 검사나 에이징을 시작하기 전에 선택 cell의 예상 PG가 맞는지 별도 PG 제어/시험 동작으로 확인한다. **[추론]**

## 4. 예시

cell들의 Y Index가 0, 1, 2이고 실제 설비 연결이 다음과 같다고 가정한다.

| Y Index | 선택할 PG | 의미 |
|---:|---|---|
| 0 | `0 — 192.168.0.10:포트` | YIndex 0 cell 그룹은 첫 번째 PG 사용 |
| 1 | `2 — 192.168.0.12:포트` | YIndex 1 cell 그룹은 PG 2 사용 |
| 2 | `1 — 192.168.0.11:포트` | YIndex 2 cell 그룹은 PG 1 사용 |

이처럼 Y Index 순서와 PG 번호 순서가 다를 수 있다. 화면의 기본값은 편의를 위한 초기값일 뿐 배선 관계를 보증하지 않는다. **[추론]**

## 5. `Y Index 동기화`를 언제 눌러야 하나요?

다음 경우에 누른다.

- Cell map을 처음 생성한 뒤
- Cell map을 재생성하여 Y Index 그룹이 바뀐 뒤
- 새 cell/Y Index 그룹을 추가한 뒤
- 행이 현재 cell 구조와 맞지 않는다고 판단될 때

동기화는 기존 PG 선택을 가능한 한 보존한다. 하지만 cell 구조가 바뀌면 새 행이 생기거나 더 이상 사용되지 않는 행이 사라질 수 있으므로, 동기화 후에는 반드시 모든 행의 PG 선택을 재확인한다. **[추론]**

## 6. 사용 시 주의사항

- `Y Index`는 0 이상이어야 하며 직접 편집할 수 없다.
- PG 선택은 0 이상이어야 한다.
- 같은 Y Index에 매핑을 여러 개 두면 recipe validation 오류가 발생한다. 일반 UI 동기화 후에는 한 행씩만 보여야 한다. **[추론]**
- PG 번호가 endpoint 수보다 크면 실제 PG 제어/검사/에이징 실행에서 오류가 날 수 있다. **[추론]**
- endpoint가 표시되지 않고 `(PG 미구성)`만 보이면 현재 PG 구성 정보를 먼저 확인한다. 이 표시는 mapping을 실제 장비 연결로 검증했다는 뜻이 아니다. **[추론]**
- Simulation Mode에서는 `(SIM)` endpoint가 표시될 수 있다. 실제 장비 시험과 simulation 시험 결과를 혼동하지 않는다. **[추론]**

## 7. 이 설정이 영향을 주는 기능

현재 코드상 PG 매핑은 에이징 테스트/에이징 Run, 검사 step의 pattern 제어와 PG 소등, PG recipe 제어에서 cell의 PG 대상을 결정하는 데 사용된다. 따라서 매핑 변경 후에는 그 Y Index 그룹이 의도한 PG를 사용하는지 확인해야 한다. **[추론]**
