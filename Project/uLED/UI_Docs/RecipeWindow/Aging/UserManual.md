# RecipeWindow - 에이징 탭 사용자 매뉴얼

## 1. 목적

에이징 탭에서는 PG pattern과 유지 시간을 step 단위로 구성하고, 선택한 cell에 매핑된 PG로 그 순서를 시험 실행한다.

공식 문서에 에이징 운전 절차가 별도로 정의되어 있지 않으므로, 아래 실행 세부는 현재 화면/코드에 근거한 **[추론]** 이다. 현장 표준이 있으면 그 절차를 우선한다.

## 2. 사전 확인

1. Recipe에서 검사할 cell을 하나 선택한다.
2. 선택 cell의 Y 위치에 PG mapping이 설정되어 있는지 확인한다.
3. 에이징 step을 1개 이상 작성한다.
4. PG 연결/장비 안전 상태를 확인한다. Simulation Mode 여부도 함께 확인한다. **[추론]**

`Test PG`에는 선택 cell에서 해석한 PG 번호가 표시된다. PG 번호를 찾을 수 없으면 테스트를 시작할 수 없다. **[추론]**

## 3. Step 작성

### Step 추가

1. **Step 추가**를 누른다.
2. 새 행의 `Use`, `Type`, `Name`, `Pattern`, `Duration (sec)`를 입력한다.
3. 필요한 순서대로 반복한다.

새 행은 기본적으로 사용 상태의 `PatternOn`, pattern 1, 300초로 추가된다. **[추론]**

### 입력 항목

| 항목 | 입력 방법 |
|---|---|
| Use | 실행할 step만 체크한다. 체크 해제한 행은 테스트 시 실행하지 않는다. **[추론]** |
| Step | 실행 순서 번호다. 번호가 중복되지 않도록 입력한다. |
| Type | `PatternOn` 또는 `OffWait`를 선택한다. |
| Name | 식별하기 쉬운 이름을 입력한다. 예: `R Aging`, `Cooling wait` |
| Pattern | `PatternOn`이면 사용할 PG pattern 번호(1~25)를 입력한다. **[추론]** |
| Duration (sec) | 상태 유지 시간(초)을 1 이상으로 입력한다. |

### 권장 예시

아래는 코드에 존재하는 기본 RGB 구성과 같은 순서의 예시다. 현재 UI에 ‘기본 RGB 추가’ 버튼은 없으므로 필요한 경우 행을 직접 추가한다. **[추론]**

| Step | Type | Name | Pattern | Duration |
|---:|---|---|---:|---:|
| 1 | PatternOn | R Aging | 1 | 300 |
| 2 | OffWait | Rest | 0 | 180 |
| 3 | PatternOn | G Aging | 2 | 300 |
| 4 | OffWait | Rest | 0 | 180 |
| 5 | PatternOn | B Aging | 3 | 300 |

`OffWait`는 소등 후 대기하는 유형이므로 pattern 값은 실행에 사용하지 않는다. **[추론]**

## 4. 테스트 실행

1. 실행할 step의 `Use`를 체크한다.
2. 순서 번호/시간/pattern을 확인한다.
3. 화면 상단의 `Test PG`가 의도한 PG인지 확인한다.
4. **테스트**를 누른다.
5. 열리는 **AgingProgressWindow**에서 진행 상태를 확인한다.

테스트 시작 전에는 사용 step 존재 여부, 선택 cell, 중복 step 번호, duration, `PatternOn` pattern 범위를 확인한다. 조건을 만족하지 않으면 오류 메시지를 확인하고 recipe를 수정한다. **[추론]**

## 5. 진행 창 사용

진행 창은 전체 진행률과 현재 PG/step 상태를 보여 준다.

- **PG Status**: 현재 실행 대상의 PG, cell, step, pattern, 시간, 상태를 확인한다.
- **Aging Plan**: 각 step의 실행 상태를 확인한다.
- **Stop**: 현재 테스트를 중단한다.

창의 X 버튼으로 창을 닫는 것만으로는 테스트가 중단되지 않을 수 있다. 중단이 필요하면 반드시 **Stop**을 누르고 종료 상태를 확인한다. **[추론]**

## 6. 중단/오류 후 처리

**[추론: 현재 코드 동작]**

- Stop 또는 오류 발생 시 PG 소등을 시도한다.
- 실행 상태는 checkpoint 파일에 저장될 수 있다.
- 같은 recipe 파일과 같은 PG로 다시 시작하면 완료된 step은 건너뛸 수 있다.
- 중단 시 진행 중이던 step은 부분 시간부터 이어서 실행하지 않고 해당 step 처음부터 재실행한다.

이 재시작 동작은 공식 운영 규정이 아니라 코드 동작이다. 재시험 전에 장비 상태와 PG의 실제 소등 상태를 확인한다.

## 7. 삭제

- 특정 행을 삭제하려면 행을 선택하고 **Step 삭제**를 누른다.
- 모든 행을 삭제하려면 **전체 Step 삭제**를 누른다.
- 두 동작 모두 확인 창이 표시된다. **[추론]**
