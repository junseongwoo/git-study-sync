# 표준맵 사용 검사 분석

> 대상 문서: **표준맵사용검사-technical-manual.md**  
> 분석 기준: 2026-07-28 현재 `uLedAoiConsole`, `uLedIp`, `uLedInspection.Algorithms`, `uLed.Contracts` 소스

## 1. 한눈에 보는 결론

이 기능은 Micro LED 셀 이미지에서 각 dot의 **최종 측정 좌표**를 확정하는 좌표계 시스템이다. 핵심은 검출된 blob의 중심을 곧바로 레벨 측정에 쓰지 않는다는 점이다.

- 표준맵이 없으면: 밝은 blob을 검출해 dense map을 만들고, 그 맵 좌표에서 레벨을 샘플링한다.
- 표준맵이 있으면: 양품 셀에서 만든 `std_map.csv`를 기준으로 소수 표본만 재검출하여 셀의 similarity 변환(이동·회전·배율)을 구하고, 변환된 표준맵에서 전 dot을 샘플링한다.
- 고정배치가 신뢰되지 않으면: 검출 기반 자동정합으로 offset 후보를 구한 뒤 RGB 채널로 재검증한다.
- 끝까지 정합하지 못해도: 좌표를 비워 두지 않고 prior 배치로 측정하되 `fixed-prior(unverified)` 상태를 결과에 남긴다.

WinForms 관점에서는 Form 코드가 검사 알고리즘과 장비 제어를 직접 묶는 구조가 아니라, **ViewModel → Console recipe/전송 계층 → IP runtime → 알고리즘**으로 책임이 분리된 구조다.

### 호출 관계

```text
RecipeEditorViewModel
  ├─ 표준맵 생성: CreateStandardMapForCellAsync
  │    └─ CurrentBuffer 검사 → StandardMapBuilder → std_map.csv 저장
  └─ recipe/IP 업로드
       └─ ULedIpConnection.AddStandardMapMetadata
            └─ console.standardDenseMapData 전송

IpNodeRuntimeService.TryApplyStandardDenseMap
  └─ PanelInspectionJobModel.UseStandardDenseMap 설정
       └─ PointGridInspectionAlgorithm.InspectDensePointSet
            ├─ 표준맵 없음: InspectDenseWithConfirmedMap
            └─ 표준맵 있음: InspectDensePattern → ApplyStandardMapPlacementLadder
                 ├─ InspectWithFixedPlacement
                 └─ 실패 시 InspectWithAutoMatching → RGB 재검증
```

**핵심 요약:** 표준맵은 "검출 결과"가 아니라, 검출 실패·점등불량에도 유지되는 **측정 좌표의 기준 자산**이다.

## 2. 용어를 코드 관점으로 번역하기

| 용어 | 코드에서의 실체 | 왜 필요한가 |
|---|---|---|
| object | threshold 및 connected component를 통과한 blob | dot으로 추정되는 실측 후보를 얻는다. |
| 실측 centroid | object의 카메라 좌표 | 맵 정합·검증·잔차 계산에 사용한다. |
| dense map | `StandardDenseMapChannel` 또는 확정된 좌표 사전 | 모든 유효 dot index에 카메라 좌표를 제공한다. |
| 맵생성검사 | `InspectAndConfirmMap` 중심의 검출 기반 흐름 | 표준맵을 처음 만들거나, 자동정합의 후보를 얻는다. |
| 표준맵 검사 | `InspectWithFixedPlacement` 중심의 흐름 | 빠르고 결손에 강한 운영 검사 경로다. |
| 고정배치 | 소수 표본 검출 후 similarity 변환을 적용 | 전 dot 검출을 생략하면서 셀 위치 차이를 보정한다. |
| 자동정합 | `InspectWithAutoMatching` | 고정배치 검증 실패 때만 쓰는 복구 수단이다. |
| phase 파생 | `StandardDenseMapChannel.WithOffset` 및 RGB phase offset | R 기준 좌표에서 G/B 좌표를 만든다. |

> NOTE: 최종 레벨은 object centroid가 아니라 **확정된 맵 좌표**에서 샘플링한다. 따라서 어두워서 blob이 검출되지 않은 dot도 레벨값을 가져 암점 판정의 근거가 될 수 있다.

**핵심 요약:** object는 측정 좌표가 아니라 좌표를 믿을 수 있는지 판단하는 관측값이다.

## 3. 전체 구조와 책임 분리

```text
uLedAoiConsole
├─ RecipeEditorViewModel
│   ├─ 현재 버퍼 검사 실행
│   ├─ 표준맵 생성 UI/확인
│   └─ CellMap 보정 편집
├─ StandardMapBuilder
│   ├─ R 좌표 맵 구성
│   ├─ 이웃 이상치 보정
│   └─ G/B-R phase offset 계산
└─ ULedIpConnection
    └─ std_map.csv를 recipe metadata로 IP에 전달

uLedIp
├─ IpNodeRuntimeService
│   └─ metadata를 PanelInspectionJobModel로 해석
└─ PointGridInspectionAlgorithm
    └─ 표준맵/맵생성 경로를 선택하고 RGB 결과를 조정

uLedInspection.Algorithms
├─ CorrectedDenseMapInspector
│   ├─ blob 검출 및 맵 생성
│   ├─ 고정배치 및 배치 검증
│   └─ 자동정합
└─ StandardDenseMap
    ├─ CSV 저장·로드
    ├─ R→G/B offset 파생
    └─ 이상화(계단 제거 + 2D fit)
```

| 계층 | 책임 | WinForms와 비교 |
|---|---|---|
| View/XAML | 버튼·상태·입력 표시 | Form 디자이너 UI |
| ViewModel | Command, 화면 상태, 사용자 확인 | Form event handler에 있던 UI 제어 부분 |
| Console service | recipe, motion 좌표, IP 업로드 | 별도 application service |
| IP runtime | job metadata를 실행 파라미터로 변환 | 통신 서버/장비 실행 서비스 |
| Algorithms | 영상·좌표·검사 계산 | UI와 분리된 순수 비즈니스 로직 |

**핵심 요약:** Console은 레시피와 장비/사용자 흐름을 맡고, IP와 알고리즘은 좌표를 계산한다.

## 4. 실행 흐름

### 4.1 표준맵 생성 흐름

```text
RecipeEditor에서 기준 양품 셀 선택
  → CurrentBuffer 입력 검사
     └─ console.standardDenseMapDisabled=true
        (기존 표준맵을 쓰지 않고 검출 기반으로 수행)
  → FinalPanelResult.PixelBlocks
  → StandardMapBuilder.Build
     ├─ R 좌표 수집
     ├─ 이웃 일관성 이상치 보정
     └─ G/B-R median phase offset 계산
  → StandardDenseMapIdealizer.Idealize
     └─ 계단 제거 + 2차 2D fit
  → std_map.csv 저장
  → 사용자 승인 시 RGB phase offset과 UseStandardDenseMap 적용
```

주요 구현은 **`uLedAoiConsole/ViewModels/RecipeEditorViewModel.cs`**의 `CreateStandardMapForCellAsync`와 **`uLedAoiConsole/Services/StandardMapBuilder.cs`**의 `Build`다.

### 4.2 운영 검사 흐름

```mermaid
flowchart TD
    A[IP job 수신] --> B{UseStandardDenseMap?}
    B -->|아니오| C[맵생성검사]
    C --> D[기준 채널 R→G→B 검출]
    D --> E[확정 맵 + RGB phase 파생]
    B -->|예| F[채널별 고정배치]
    F --> G{배치 검증 통과?}
    G -->|예| H[RGB 대표 offset으로 일원화]
    G -->|아니오| I[자동정합 후보 생성]
    I --> J{RGB 재검증 통과?}
    J -->|예| K[fixed(realigned)]
    J -->|아니오| L[fixed-prior(unverified)]
    E --> M[확정 좌표에서 레벨 샘플링]
    H --> M
    K --> M
    L --> M
```

실제 분기는 **`uLedIp/Inspection/PointGridInspectionAlgorithm.cs`**의 `InspectDensePointSet`에 있다. `UseStandardDenseMap` 또는 표준맵 생성 전용 `verifier.channelIndependentDetection`이 참이면 채널별 검출을 수행하며, 표준맵 사용 시 이후 `ApplyStandardMapPlacementLadder`가 최종 배치 상태를 결정한다.

**핵심 요약:** 표준맵 검사는 먼저 빠른 고정배치를 시도하고, 자동정합은 독립 운영 모드가 아닌 검증 실패의 폴백이다.

## 5. 좌표 확정 알고리즘

### 5.1 맵생성검사

```text
배경 평탄화
  → blob 검출
  → seed consensus
  → chain 확장
  → MatchShift
  → object 검증/기각/라인 기반 보정
  → 기준 채널 맵 확정
  → G/B는 phase offset만큼 평행이동
```

- 기준 채널은 R→G→B 순서로 시도한다.
- 세 채널 모두 실패하면 `BuildCenterMapCoordinates`가 ROI 중심의 격자를 만들어 측정 자체는 계속한다.
- `DisplayPixelPositionTolerancePx`는 이 경로에서 전역 fit 대비 object 기각 기준이다.

### 5.2 표준맵 고정배치

`CorrectedDenseMapInspector.InspectWithFixedPlacement`는 표준맵 전체를 영상에서 다시 검출하지 않는다.

1. 표준맵에서 16×12 영역에 분산된 표본을 고른다.
2. 각 예상 위치 주변에서 spot detection을 한다.
3. 표본 대응쌍으로 회전·배율·이동을 포함한 similarity 변환을 구한다.
4. 최대 두 번 재측정해 변환을 수렴시킨다.
5. 변환된 표준맵 좌표로 전체 dot의 레벨을 샘플링한다.
6. 가장자리와 바깥 가드 영역을 검사해 pitch 정수배 밀림을 검증한다.

`fixed-prior(detect-fail)`은 표본이 최소 개수에 못 미친 상태다. 이 경우 배치 검증을 생략하고 상위 RGB 폴백 사다리로 넘긴다.

### 5.3 자동정합과 RGB 교차 검증

- 자동정합은 검출 기반으로 표준맵과의 대응쌍을 다시 만든다.
- median offset 주변의 유효 쌍만 골라 similarity 또는 translation을 추정한다.
- 채널별 후보 offset을 만든 뒤, 각 후보를 R/G/B 고정배치로 재실행한다.
- 하나 이상의 채널이 배치 검증을 통과한 후보만 `fixed(realigned)`로 채택한다.
- 끝까지 실패하면 prior 배치를 유지하되 `fixed-prior(unverified)`를 남긴다.

> TIP: `fixed`, `fixed(realigned)`, `fixed-prior(unverified)`는 단순 로그 문구가 아니라 결과의 신뢰 경위를 설명하는 상태값이다. 결과 분석 시 반드시 함께 확인해야 한다.

**핵심 요약:** 표준맵은 빠른 추정만 하는 것이 아니라, 정수 pitch 밀림을 엣지·가드와 RGB 재검증으로 방어한다.

## 6. Console의 물리 보정과 IP의 이미지 정합

두 보정은 비슷해 보여도 책임이 다르다.

| 구분 | 소유자 | 단위 | 적용 시점 | 목적 |
|---|---|---|---|---|
| CellMap 보정 | Console `ConsoleCellMapCorrectionPlan` | um | 검사/CA410 셀 이동 전 | 장비 축 target의 물리 위치 보정 |
| 표준맵 배치 | IP `StandardDenseMapAlignment` | px | 이미지 검사 중 | 카메라 영상 안에서의 좌표 배치 검증·정합 |

`RecipeEditorViewModel.ApplyCellMapCorrection`은 `YIndex`별 UnitY 보정을 axis X에, `XIndex`별 StageX 보정을 axis Y에 더한다. 따라서 운영 Console은 표준맵 prior offset을 전송하지 않으며, IP는 기본 prior `(0, 0)`에서 고정배치를 시작한다.

**핵심 요약:** um CellMap 보정은 설비 기하 문제이고, px 표준맵 정합은 영상 좌표 문제다. 둘을 자동으로 서로 대입하지 않는다.

## 7. WPF에서 집중해서 볼 개념

| 개념 | 이 기능에서 보이는 위치 | WinForms와의 연결 |
|---|---|---|
| MVVM | `RecipeEditorViewModel` | Form 코드에 섞이기 쉬운 상태/명령을 ViewModel로 이동 |
| Data Binding | `Document.StandardMapPlan.UseStandardDenseMap` | Control 값을 필드에 직접 넣는 대신 속성을 연결 |
| Command | 표준맵 생성 버튼 → ViewModel 비동기 메서드 | Button Click handler의 대체 진입점 |
| `INotifyPropertyChanged` | `ConsoleStandardMapPlan.UseStandardDenseMap` | 값 변경 시 UI가 자동 갱신되게 함 |
| Service 분리 | `StandardMapBuilder`, `ULedIpConnection` | UI 없는 재사용 가능한 업무 단위 |
| 비동기 실행 | `CreateStandardMapForCellAsync` | UI thread를 멈추지 않고 검사/저장을 기다림 |

**핵심 요약:** 표준맵 생성은 ViewModel이 흐름을 조율하고, 계산과 통신은 Service/알고리즘으로 위임하는 전형적인 MVVM 구조다.

## 8. 문서와 현재 코드의 대조 결과

| 항목 | 판정 | 근거 |
|---|---|---|
| 표준맵이 있으면 고정배치부터 시작 | 일치 | `InspectDensePointSet` → `ApplyStandardMapPlacementLadder` |
| 자동정합은 검증 실패 때만 사용 | 일치 | 상위 사다리에서 anchor 부재 시 `InspectWithAutoMatching` 호출 |
| RGB 결과를 대표 배치로 일원화 | 일치 | `ApplyStandardMapPlacementLadder` |
| R 맵 저장, G/B phase offset 파생 | 일치 | `StandardMapBuilder.Build`, `ResolveStandardMapChannel` |
| CellMap 보정은 Console의 um 보정 | 일치 | `ConsoleCellMapCorrectionPlan`, `ApplyCellMapCorrection` |
| 표준맵 생성 시 기존 표준맵을 끄고 검사 | 일치 | `console.standardDenseMapDisabled=true` |
| `console.standardDenseMapPath`를 Console/IP 공통 metadata로 사용 | **불일치** | 현재 Console은 `console.standardDenseMapData`에 CSV 원문을 넣고, IP는 이를 캐시 파일로 만들어 `job.StandardDenseMapPath`에 설정한다. |

> NOTE: 매뉴얼의 metadata 표기는 `console.standardDenseMapPath` 대신 현재 구현 기준으로 `console.standardDenseMapData`로 읽어야 한다. `PanelInspectionJobModel.StandardDenseMapPath`는 IP 내부에서 캐시된 로컬 CSV 경로다.

1. **`uLedAoiConsole/Recipes/ConsoleRecipeDocument.cs`**

   - PixelBlocks가 R 맵과 G/B offset으로 변환되는 과정을 확인한다.

   - 표준맵 CSV가 IP 업로드 metadata로 포장되는 지점을 본다.

   - metadata가 `PanelInspectionJobModel`로 해석되는 지점을 본다.
6. **`uLedIp/Inspection/PointGridInspectionAlgorithm.cs`**
   - 두 검사 경로와 RGB 폴백 사다리의 오케스트레이션을 읽는다.

   - `InspectWithFixedPlacement`, `VerifyFixedPlacement`, `InspectWithAutoMatching` 순서로 핵심 알고리즘을 본다.
8. **`uLedInspection.Algorithms/StandardDenseMap.cs`**
   - CSV 형식, 채널 offset, 이상화 알고리즘을 확인한다.

**핵심 요약:** UI부터 시작하되, 실제 좌표 판정의 핵심은 마지막 두 알고리즘 파일에 있다.

## 10. 버튼 하나를 추적하는 방법

표준맵 생성 버튼을 예로 들면 다음 순서로 추적한다.

```text
RecipeWindow.xaml의 Button
  → Binding된 ICommand
  → RecipeEditorViewModel의 Command/메서드
  → CreateStandardMapForCellAsync
  → RunSelectedCellInputFlowAsync
  → IP final result 수신
  → StandardMapBuilder.Build
  → StandardDenseMapIdealizer.Idealize
  → StandardDenseMapFile.Save
  → Document.StandardMapPlan 및 RGB phase offset 갱신
```

디버깅할 때는 다음 값을 함께 기록·확인하면 좋다.

- 기준 셀 이름과 `std_map.csv` 저장 경로
- R/G/B phase offset 및 pair 수
- `StdMap` alignment mode
- measured shift, theta, scale
- residual p50/p95와 deviated 수
- `fixed-prior(unverified)` 발생 여부

**핵심 요약:** WPF 버튼에서 시작해도 최종 동작은 ViewModel → IP → 알고리즘 → 결과 반영이라는 긴 경로를 가진다.

## 11. 분석 범위와 주의점

- 이 문서는 좌표 확정과 표준맵 사용 흐름을 다룬다. 명점·암점·명선의 최종 결함 분류 정책은 범위 밖이다.
- `PanelInspectionJobModel.StandardDenseMapPath`의 XML 주석에는 과거 폴더/채널별 CSV 표현이 남아 있으나, 현재 Console 통합 흐름은 단일 `std_map.csv` 원문을 metadata로 전달하는 구현이다.
- 문서가 설명하는 "표준맵 파일이 없으면 recipe 계수로 재생성" 동작은 `ULedIpConnection.AddStandardMapMetadata`에서 확인했다.

**최종 요약:** 이 시스템의 목적은 "잘 보이는 dot만 정확히 재는 것"이 아니라, 좋은 셀에서 확정한 좌표 기준을 모든 셀에 유지해 결손·암점 상황에서도 일관된 위치에서 검사하도록 만드는 것이다.

## 12. 코드 구조와 아키텍처 — 표준맵은 어디서 만들어지고 쓰이는가

표준맵 기능은 하나의 알고리즘 클래스에만 들어 있지 않다. recipe를 편집하는 Console, recipe를 전송하는 통신 계층, job을 준비하는 IP runtime, 실제 좌표를 계산하는 알고리즘 계층으로 분리돼 있다.

```text
Console UI / ViewModel
  RecipeEditorViewModel
    ├─ 기준 셀 CurrentBuffer 검사 실행
    └─ std_map.csv 생성 요청
       ↓
Console Service
  StandardMapBuilder
    ├─ PixelBlocks → R standard map
    └─ G/B-R phase offset 계산
  StandardDenseMapIdealizer
    └─ 계단 제거 + 2D calibration fit
       ↓
Recipe / Upload
  ConsoleStandardMapPlan + std_map.csv
  ULedIpConnection.AddStandardMapMetadata
       ↓
IP Runtime
  IpNodeRuntimeService.TryApplyStandardDenseMap
    └─ metadata → PanelInspectionJobModel
       ↓
IP Inspection Orchestrator
  PointGridInspectionAlgorithm
    ├─ 맵생성검사
    └─ 표준맵 고정배치·자동정합 사다리
       ↓
Algorithm Core
  CorrectedDenseMapInspector / StandardDenseMap
    └─ 최종 dot 좌표 확정 → 레벨 샘플링
```

| 계층 | 주요 코드 | 책임 | 하지 않는 일 |
|---|---|---|---|
| ViewModel | `RecipeEditorViewModel` | 사용자가 선택한 기준 셀로 표준맵 생성 흐름을 조율하고 recipe 값을 갱신한다. | dense map 수학 계산을 직접 하지 않는다. |
| Console service | `StandardMapBuilder` | IP 결과 `PixelBlocks`를 R 좌표 맵·G/B phase 권장값으로 변환한다. | 장비 이동이나 IP 통신을 직접 하지 않는다. |
| Recipe/전송 | `ConsoleStandardMapPlan`, `ULedIpConnection` | 표준맵 사용 여부와 CSV/계수를 recipe에서 IP로 전달한다. | 최종 배치 정합을 수행하지 않는다. |
| IP runtime | `IpNodeRuntimeService` | metadata를 cell job의 실행 파라미터로 해석하고 CSV 캐시 파일을 준비한다. | 표준맵을 편집하거나 UI를 보여 주지 않는다. |
| IP orchestration | `PointGridInspectionAlgorithm` | 표준맵·맵생성 경로를 고르고 RGB 결과의 배치 일관성을 결정한다. | 물리 축 보정을 수행하지 않는다. |
| Algorithm core | `CorrectedDenseMapInspector`, `StandardDenseMap` | 검출, fixed placement, 검증, 자동정합, 샘플링 좌표 생성 | Console의 recipe 저장·장비 제어를 알지 못한다. |

> NOTE: CellMap 보정은 표준맵 알고리즘의 일부가 아니다. Console의 `ConsoleCellMapCorrectionPlan`이 stage/unit 축 target에 적용하는 **um 물리 보정**이고, 표준맵은 IP 영상 내부에서 수행하는 **px 좌표 정합**이다.

**핵심 요약:** 표준맵은 알고리즘 파일 하나가 아니라, Console이 자산을 만들고 IP가 소비하는 end-to-end 기능이다.

## 13. 코드를 읽는 권장 순서 — UI에서 수학까지

### A. 표준맵을 만드는 Console 흐름

1. **`uLedAoiConsole/Recipes/ConsoleRecipeDocument.cs`**
   - `ConsoleStandardMapPlan`과 `ConsoleCellMapCorrectionPlan`을 먼저 읽는다.
   - 무엇이 recipe에 저장되는지 알면 이후 코드가 만드는 값의 목적이 보인다.
2. **`uLedAoiConsole/ViewModels/RecipeEditorViewModel.cs`**
   - `CreateStandardMapForCellAsync`를 읽는다.
   - `console.standardDenseMapDisabled=true`로 기준 셀을 표준맵 없이 검사하는 이유를 확인한다.
3. **`uLedAoiConsole/Services/StandardMapBuilder.cs`**
   - `Build`, `BuildChannel`, `ComputeChannelMedianOffset` 순서로 읽는다.
   - IP PixelBlocks가 R map과 G/B phase offset으로 바뀌는 가장 짧은 변환 경로다.
4. **`uLedInspection.Algorithms/StandardDenseMap.cs`**
   - `StandardDenseMapFile.Save/Load`, `FilterOutliersByNeighborConsistency`, `StandardDenseMapIdealizer.Idealize`를 읽는다.
   - 파일 형식·이웃 이상치 보정·이상화의 실제 구현을 확인한다.

### B. Console이 표준맵을 IP에 전달하는 흐름

5. **`uLedAoiConsole/Services/Ip/ULedIpConnection.cs`**
   - `AddStandardMapMetadata`를 읽는다.
   - `std_map.csv`가 없을 때 calibration coefficient로 파일을 재생성하는 처리도 이곳에 있다.
6. **`uLedIp/Services/IpNodeRuntimeService.cs`**
   - `TryApplyStandardDenseMap`을 읽는다.
   - `console.standardDenseMapData`를 IP 로컬 캐시 파일로 저장하고, `PanelInspectionJobModel.UseStandardDenseMap`을 켜는 곳이다.
7. **`uLed.Contracts/Models/InspectionModels.cs`**
   - `PanelInspectionJobModel`의 `UseStandardDenseMap`, `StandardDenseMapPath`, prior offset, margin을 확인한다.

### C. 실제 검사와 좌표 확정

8. **`uLedIp/Inspection/PointGridInspectionAlgorithm.cs`**
   - 아래 순서로 읽는다.

```text
InspectDensePointSet
  → InspectDenseWithConfirmedMap              [표준맵 없음]
  → InspectDensePattern                       [채널 단위 검사]
  → ApplyStandardMapPlacementLadder           [표준맵 사용]
  → ResolveStandardMapChannel
  → BuildCorrectedDenseMapRecipe
```

9. **`uLedInspection.Algorithms/CorrectedDenseMapInspector.cs`**
   - 아래 순서로 읽으면 핵심 수학을 잃지 않는다.

```text
InspectAndConfirmMap          [검출 기반 맵 확정]
  → InspectWithDetection
  → ValidateDenseMapObjects

InspectWithFixedPlacement     [표준맵 운영 기본]
  → SelectFixedPlacementSamples
  → TrySpotDetectDot
  → SolvePlacementTransform
  → VerifyFixedPlacement

InspectWithAutoMatching       [고정배치 실패 폴백]
  → ApplyStandardMap
  → StandardDenseMapMatcher.SolveSimilarity
```

10. **`uLedInspection.Algorithms/StandardDenseMap.cs`**의 `StandardDenseMapMatcher`
    - translation/similarity 계산, R→G/B `WithOffset`, CSV load/save를 마지막에 연결한다.

**핵심 요약:** `RecipeEditorViewModel`에서 시작해 `PointGridInspectionAlgorithm`까지 내려가면, UI 동작과 알고리즘의 연결이 끊기지 않는다.

## 14. 실제 코드 기준 데이터 흐름

```text
양품 기준 셀 CurrentBuffer
  → IP 검사 결과 FinalPanelResult.PixelBlocks
  → StandardMapBuilder.Build
      ├─ R: final index → camera (x,y)
      ├─ neighbor consistency 보정
      └─ G/R, B/R median offset
  → StandardDenseMapIdealizer.Idealize
  → recipe 옆 std_map.csv 저장
  → ConsoleStandardMapPlan에 계수/진단값 기록
  → recipe upload
  → console.standardDenseMapData (CSV 원문)
  → IP cache std_map.csv
  → PanelInspectionJobModel.StandardDenseMapPath
  → PointGridInspectionAlgorithm
  → CorrectedDenseMapInspector
  → final dot 좌표에서 level sampling
  → FinalPanelResult / PixelBlocks / defect 결과
```

### metadata와 경로를 정확히 구분하기

| 이름 | 실제 역할 |
|---|---|
| `std_map.csv` | Console recipe 파일 옆에 저장되는 표준맵 정본 파일이다. |
| `console.standardDenseMapData` | Console이 IP에 보내는 CSV 원문 metadata다. |
| `PanelInspectionJobModel.StandardDenseMapPath` | IP runtime이 metadata 원문을 캐시 파일로 저장한 뒤 넣는 **IP 로컬 파일 경로**다. |
| `console.standardDenseMapDisabled` | 표준맵 생성용 기준 셀 검사에서 표준맵 사용을 일시 해제하는 job metadata다. |
| `verifier.channelIndependentDetection` | 표준맵 생성 도구에서 G/B phase 실측을 위해 채널 독립 검출을 강제하는 metadata다. |

> NOTE: 이전 설명의 `console.standardDenseMapPath`는 현재 Console→IP 통합 흐름의 metadata 키가 아니다. 실제 전송 키는 `console.standardDenseMapData`다. `StandardDenseMapPath`는 IP 내부 job 속성이다.

## 15. 코드와 문서에서 읽히는 제작자의 설계 의도

다음은 코드 구조, 주석, 강제 규칙에서 도출한 해석이다. 개인적 동기는 코드만으로 확정할 수 없으므로 **추정**을 명시한다.

| 관찰된 사실 | 설계 의도 해석 |
|---|---|
| 표준맵 생성이 `RecipeEditorViewModel`의 명시적 사용자 흐름이고, 기준 셀을 양품 source로 둔다 | 표준맵을 자동으로 계속 바꾸는 값이 아니라, 사용자가 관리·승인하는 **품질 기준 자산**으로 취급하려는 의도다. |
| R만 저장하고 G/B는 phase offset으로 파생 | 어두운 채널의 검출 노이즈를 기준 좌표에 박제하지 않고, 리소그래피상 고정 관계는 상수로 분리하려는 의도다. |
| 표준맵 검사에서 fixed placement를 먼저 시도 | 운영 검사에서 전체 blob 검출을 매 cell마다 반복하지 않아 검사 시간을 줄이고, 결손·점등불량으로 인한 좌표 붕괴를 피하려는 의도다. |
| fixed placement 검증에 edge와 guard를 둔다 | 주기 격자에서 발생하는 pitch 정수배 alias를 단순 offset fit만으로 통과시키지 않으려는 의도다. |
| 자동정합 뒤 RGB 재검증을 수행한다 | 한 채널의 우연한 검출 결과보다 동일 stage에서 촬영된 RGB의 공통 물리 배치를 신뢰하려는 의도다. |
| prior 0과 CellMap um 보정을 분리한다 | 장비 기하 오차를 검사 이미지의 임시 px 보정으로 숨기지 않고, 물리 원인과 영상 잔차의 책임을 분리하려는 의도다. |
| `fixed-prior(unverified)`로도 좌표/레벨을 만든다 | 검사 불능으로 결과를 잃기보다, 결함 판단에 필요한 데이터를 남기고 신뢰도 상태를 명시하려는 의도다. |
| calibration coefficient를 recipe에 병행 저장하고 CSV가 없으면 재생성한다 | **추정:** 표준맵 파일 유실·배포 환경에서도 검사 자산을 recipe와 함께 복원 가능하게 하려는 의도다. |
| `main-glass-inspection-flow.md`와 Console/IP 계약이 결과 수신을 설비 진행과 분리한다 | **추정:** 고속 검사에서 결과 계산·이미지 저장 때문에 다음 cell의 motion/capture가 막히지 않도록 처리량을 보장하려는 의도다. |

**핵심 요약:** 표준맵 설계는 "좌표를 더 예쁘게 맞추기"보다, 양품 기준을 자산화하고 불량 셀에서도 일관된 검사 좌표를 유지하려는 설계다.

## 16. 표준맵 기능을 이해했는지 확인하는 질문

1. 표준맵 생성의 source cell에서는 왜 `console.standardDenseMapDisabled=true`가 필요한가?
2. `std_map.csv`에는 왜 R 채널만 저장하는가?
3. CellMap 보정과 standard map alignment가 각각 um/px 중 무엇을 다루는가?
4. fixed placement가 검출하는 것은 전 dot인가, 표본인가?
5. 표본 정합만으로 pitch 정수배 shift를 검출할 수 없는 이유는 무엇인가?
6. guard hit가 의미하는 물리적 상황은 무엇인가?
7. 자동정합 후보를 한 채널 결과만으로 확정하지 않는 이유는 무엇인가?
8. `EndJob ACK`와 표준맵 좌표가 포함된 final result 사이에서 누가 무엇을 처리하는가?

이 질문에 관련 클래스와 메서드까지 함께 답할 수 있으면, 표준맵 기능의 UI·recipe·통신·runtime·알고리즘 연결을 이해한 것이다.

## 17. 확장된 최종 요약

```text
Console은 양품 셀에서 좌표 기준 자산(std_map.csv)을 만든다.
Recipe/통신 계층은 그 자산을 IP 검사 job에 전달한다.
IP runtime은 job과 cache를 준비한다.
PointGridInspectionAlgorithm은 검사 경로와 RGB 배치 사다리를 결정한다.
CorrectedDenseMapInspector는 최종 측정 좌표를 확정한다.
모든 채널의 레벨·결함 결과는 그 확정 좌표를 기준으로 생성된다.
```

**최종 요약:** 표준맵은 별도 파일 기능이 아니라, Console recipe·IP job·영상 알고리즘을 관통하는 좌표 기준 아키텍처다. 이 관점으로 코드를 읽으면 왜 기준 셀, R 기준, physical CellMap 보정, fixed placement, 자동정합, RGB 재검증이 모두 함께 존재하는지 이해할 수 있다.
