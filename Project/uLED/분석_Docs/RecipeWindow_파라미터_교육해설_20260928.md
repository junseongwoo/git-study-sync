# Recipe Window 파라미터 교육 해설

분석 기준: 2026-09-28, 현재 로컬 저장소의 RecipeWindow UI → ViewModel → 계약 모델 → IP 알고리즘/Control 사용 코드. 실행 중인 설비의 배포 버전과 일치하는지는 별도 확인이 필요하다. 실제 장비 명령이나 레시피 변경은 수행하지 않았다.

## 1. 가장 먼저 설명할 것

Recipe는 다음 네 가지를 함께 저장한다.

1. **어디서 촬영할지**: 셀 위치, IP 배정, 장비 좌표, Align, 컨택 위치.
2. **어떤 영상을 얻을지**: PG 패턴/전압, 카메라 노출, 촬영 방향.
3. **영상에서 어디를 어떻게 측정할지**: ROI, dot 배열, 표준맵, 검출 임계값, 크기 필터.
4. **측정값을 어떻게 판정할지**: Ref, 상대/절대 판정, A/B/C 경계, 등급별 결함 타입.

사용자 설명: “위치를 정하고 → 조건에 맞춰 촬영하고 → 정해진 위치의 밝기를 측정하고 → 기준에 따라 등급을 매깁니다. 지금 바꾸는 값이 이 네 단계 중 어느 단계에 속하는지 먼저 보시면 됩니다.”

### 단위와 좌표

| 구분 | 의미 | 혼동하면 안 되는 것 |
|---|---|---|
| 카메라 pixel, px | 영상의 좌표·거리 | 셀의 dot 개수와 다름 |
| dot | R/G/B 각각의 발광 위치를 포함한 논리 배열 단위 | 색상 하나의 위치와 구분 |
| 색상별 발광점 | 사용자 교육에서 sub dot 대신 사용할 표현. 내부 용어는 sub dot | 내부 dot index와 결과 표시 column은 다름 |
| µm | 셀 치수, 장비 위치 및 보정 거리 | px와 직접 더하거나 비교하지 않음 |
| LV | 영상에서 산출한 밝기 값 | CA410 휘도 값과 동일한 물리량이라고 설명하지 않음 |
| % | 발광점 LV / Ref LV × 100 또는 화면에 명시된 다른 비율 | 노출 시간·전압과 다름 |

현재 IP 실행 단위는 **Pattern × Point**이며 Point 집합은 모든 Pattern이 공유한다. 검사 패턴 탭에 ROI가 보여도 패턴별 독립 ROI라고 설명하면 안 된다.

## 2. 검사 영역과 밝기 측정: 필수 교육

| 화면 항목 / 연결 속성 | 의미 | 바꾸면 생기는 영향 | 사용자 설명 |
|---|---|---|---|
| ROI X/Y / `PrimaryPoint.RoiX`, `RoiY` | 영상 안 검사 사각형의 시작 위치, px | 검사 대상 위치가 이동. 셀의 가장자리나 일부 영역이 빠질 수 있음 | “영상 중 어느 위치부터 볼지 정합니다.” |
| ROI Width/Height / `RoiWidth`, `RoiHeight` | 검사 사각형 크기, px | 측정 대상 집합이 바뀌어 Ref와 등급도 간접적으로 달라질 수 있음 | “검사할 범위의 가로·세로 크기입니다.” |
| 가로/세로 dot 수 / `DisplayPixelWidthCount`, `HeightCount` | 셀의 논리 배열 크기 | 맵 구조와 좌표 개수가 달라짐. 영상 크기가 아님 | “이 셀에 dot가 몇 열·몇 행 있는지입니다.” |
| dot 치수 / `DisplayPixelWidthUm`, `HeightUm` | dot 배열의 물리 간격에 쓰는 치수 | 물리 거리 환산 등 모델 해석에 영향 | “영상의 픽셀 수가 아니라 제품의 실제 치수입니다.” |
| 카메라 dot pitch X/Y / `DisplayPixelPitchCameraPixelX/Y` | dot 간격이 영상에서 몇 px인지 | 격자 배치·주변 탐색·위치 판단에 영향. 틀리면 멀리 갈수록 좌표가 어긋날 수 있음 | “옆 dot까지 영상에서 몇 칸 떨어져 있는지입니다.” |
| map.txt | 논리 배열에서 존재/사용하는 dot 위치를 나타내는 맵 | 측정 대상 논리 위치가 달라짐 | “어느 dot가 있는지 나타내는 설계도입니다.” |
| 표준맵 / `UseStandardDenseMap` | 실제 영상 좌표를 담은 std_map.csv 기반 검사 선택 | ON은 표준 좌표 배치·검증, OFF는 검출 기반 맵 생성 경로 | “발광점의 기준 위치표를 사용할지 정합니다.” |

ROI에는 양수 크기를 명시해 교육하는 것이 좋다. 현재 코드에 0 이하 크기에 대한 전체 영상 사용 처리가 있지만, X/Y까지 섞이면 정상적인 명시 ROI와 다르게 동작할 수 있으므로 ‘0은 언제나 안전한 전체 영역’으로 가르치지 않는다.

**‘현재 위치 적용’ 버튼 주의:** ROI 근처에 있지만 실제 연결은 Point의 StageX/StageY/FocusZ 저장이다. ROI를 자동으로 찾거나 X/Y/Width/Height를 자동 설정하는 버튼이 아니다.

### 검출과 측정은 다른 단계다

- 검출 임계값과 면적/폭/높이 필터는 발광점 후보를 찾는 데 사용한다.
- 표준맵 경로도 주변 발광점 검출로 배치를 검증하므로 검출 파라미터가 전혀 무관한 것은 아니다.
- 현재 밝기는 좌표 중심 주변 **7×7 영상 pixel의 가우시안 가중값**으로 산출한다. 기본 방식은 소수점 좌표의 보간을 포함한다.
- 따라서 ‘검출한 blob 내부의 단순 평균’이나 ‘가장 밝은 한 pixel’로 설명하면 현재 구현과 다르다.
- 중심 좌표가 달라지면 같은 원본 영상에서도 측정 LV가 달라질 수 있다. 큰 반복 편차를 보면 영상 자체의 변화와 측정 좌표의 변화를 나누어 확인해야 한다.

## 3. 검사 패턴 탭

| 항목 | 연결 / 단위 | 변경 영향 및 설명 |
|---|---|---|
| 번호·이름·유형 | PatternIndex / PatternName / PatternType | 패턴 식별과 RGBW 역할. 번호는 기본 설정의 PG 패턴 번호와 다름 |
| R/G/B 전압 | 패턴별 Voltage 값 | PG 점등 조건 변경. 실제 영상과 전류가 바뀔 수 있음. 결과 LV를 소프트웨어로 나누는 기능이 아님 |
| 노출 | ExposureUs, µs | 실제 카메라 노출 설정으로 전달. 빛을 받는 시간이 바뀜. 기존 파일 재검사에서는 원본 밝기가 바뀌지 않음 |
| Gain | Gain | 계약/촬영 설정 객체에는 전달되나 현재 Matrox 촬영 서비스에서 Gain을 장비에 적용하는 호출은 확인되지 않음. “올리면 실제로 밝아진다”를 현재 구현의 확정 동작으로 교육하지 말 것 |
| Timeout | TimeoutMs, ms | 시간 제한 의도의 필드. 현재 카메라 서비스에는 별도 CameraGrabTimeoutMs 설정이 있음. 이 값을 촬영 노출시간이나 실제 카메라 timeout의 단일 기준으로 설명하지 말 것 |
| 공통 설정 사용 | UseCommonRecipe | 해당 패턴이 공통 검사 파라미터를 사용하도록 동기화. 노출·전압까지 공통이 되는 것은 아님 |
| 공통 설정 값 복사 | InspectionConfig 복사 | 공통 임계값·크기·Ref/등급 설정 등을 패턴에 복사. 복사 후 공통 연결 유지 여부는 체크 상태로 구분 |
| 검출 임계값 | ThresholdInput / ThresholdCandidates, LV | 높이면 약한 후보를 놓칠 수 있고, 낮추면 배경/잡음과 연결되거나 큰 blob으로 합쳐질 수 있음. 불량 밝기 경계와 다름 |
| 최소/최대 면적 | MinArea / MaxArea, px² | 검출 blob의 면적 허용 범위. 최소를 키우면 작은 후보가 제외되고, 최대를 줄이면 큰 후보가 제외됨 |
| 최소/최대 폭·높이 | BlobMin/MaxWidth/Height, px | 검출 후보의 모양 크기 제한. 물리적인 dot 치수나 7×7 측정창 크기를 바꾸는 값이 아님 |
| 정상 기준 상위 % | NormalLevelPercentile로 변환 | Ref를 정하는 밝기 분포의 위치. 상위 10% → P90 |
| 절대값 사용 | UseAbsoluteLevel | OFF는 LV/Ref×100, ON은 원래 LV를 A/B/C 경계와 비교 |
| A/B/C 기준 | GradeAMinRatioPercent 등 | 해당 등급의 하한. 상대 모드에서는 %, 절대 모드에서는 LV로 해석. 화면의 % 표기와 속성명만 보고 절대 모드도 %라고 설명하면 안 됨 |

여러 임계값 후보를 넣으면 맵 생성 경로는 후보별 검출 결과를 비교한다. 현재 코드는 단순히 검출 개수만 최대화하지 않고, 큰 blob으로 합쳐져 사라진 것으로 추정되는 dot 개수도 감점한다. 표준맵의 국소 spot 검출은 단일 임계값을 사용하므로 모든 경로에서 후보 목록이 같은 방식으로 작동한다고 설명하면 안 된다.

### Ref와 등급: 숫자로 설명하기

‘상위 10%’는 **밝은 10%의 평균이 아니다.** 측정 밝기를 순서대로 놓았을 때 90% 위치의 값(P90)을 보간해 Ref로 사용한다. UI는 상위 %를 0~50 범위로 변환하므로 대응 분위수는 P100~P50이다.

예를 들어 Ref=200이고 어떤 발광점 LV=120이면 상대 밝기는 60%다. Ref=160이고 같은 발광점이 LV=96이면 역시 60%다. **영상 밝기 자체를 낮추거나 보정해서 바꾸는 것이 아니라, Ref에 대한 상대적인 밝기로 등급을 비교하는 것이다.**

반대로 Ref=160인데 그 점만 LV=64가 되면 40%다. 전체 밝기에 따라 함께 변한 부분은 비율이 유지되지만, 개별 위치만 달라진 변화는 비율에도 남는다. 따라서 비율 판정이 안정적이라는 사실만으로 원본 영상의 반복성이나 플리커가 양호하다고 결론내리면 안 된다.

상대 모드 A≥50%, B≥30%, C≥10%라는 **설명용 예**에서는 60%는 A, 40%는 B, 15%는 C, 5%는 D다. 실제 교육에는 해당 모델의 승인된 경계를 사용한다. 같은 밝기에서 등급 하한을 높이면 그 등급을 받기 어려워진다. A≥B≥C 순서를 유지한다.

상위 비율을 10%에서 30%로 늘리면 P90에서 P70으로 바뀐다. 같은 측정 집합이라면 Ref는 낮아지거나 같고, 상대 밝기는 커지거나 같아진다. 이는 밝기를 개선하는 행위가 아니라 **판정 기준을 바꾸는 행위**다.

## 4. 고급 설정 전체 항목

고급 창은 RecipeModel의 최상위 숫자/문자/체크 속성을 자동으로 표시하고, 표준맵 사용을 추가한다. 모든 하위 설정을 펼쳐 보여 주는 창은 아니다.

| 표시 속성 | 교육용 의미 | 적용 및 변경 영향 |
|---|---|---|
| DisplayPixelWidthCount / HeightCount | dot 배열 가로·세로 개수 | 기본 설정과 같은 레시피 값 |
| DisplayPixelWidthUm / HeightUm | dot 물리 치수 | 물리 단위 환산과 모델 정보 |
| DisplayPixelPitchCameraPixelX / Y | 영상상의 dot 간격 | 격자·탐색 크기에 영향. 임의 조정 대신 검증된 pitch 사용 |
| DisplayPixelBlobMinWidth / MaxWidth / MinHeight / MaxHeight | 레시피 최상위 후보 크기 필드 | **주의:** 현재 PointGrid → CorrectedDenseMap 검사 구성은 패턴별 InspectionConfig의 Blob 필드를 사용. 이 고급 필드와 패턴 필드를 같은 실제 조절점으로 가르치면 안 됨 |
| DisplayPixelMapShiftMargin | 논리 맵 배치 탐색 여유 | 단위는 격자 칸 수. 주로 맵 생성 경로. 카메라 px나 장비 이동량 아님 |
| DisplayPixelObjectSearchRadius | 주변 object 탐색 반경 | 단위 px. 맵 생성/관련 재구성 경로. 표준맵 고정 배치의 spot 창 크기는 pitch 기반이라 이 값으로 직접 정하지 않음 |
| DisplayPixelPositionTolerancePx | 위치 적합에서 허용하는 차이 | px. 맵 생성의 이상 위치 판단, 표준맵 정합의 표본 선별·편차 평가에 관여. 크게 하면 위치 이탈을 더 허용. 장비 Align 허용오차와 다름 |
| DisplayPixelBackgroundFlattenEnabled | 검출용 배경 평탄화 체크 | ON이면 white top-hat 처리 영상에서 후보를 찾음. threshold의 의미가 배경 위 상대적인 밝기로 바뀜. 원본 밝기 측정의 시간적 플리커 제거 기능이 아님 |
| StandardMapMaxSearchMarginPx | 표준맵 자동 정합의 최대 탐색 여유 | px. 자동 정합 경로에서 사용. 고정 배치 자체의 탐색창을 이 값으로 넓히는 것은 아님 |
| ThumbnailWidth | 결과 썸네일 폭 | 검사 원본의 해상도·LV와 무관. IP에서는 없거나 300 이하이면 300으로 처리 |
| DisplayPixelMapText | 논리 맵의 문자 표현 | 맵 내용 자체를 변경. 일반 운영자의 수치 튜닝 항목이 아님 |
| UseStandardDenseMap | 표준맵 사용 체크 | 셀 목록 탭과 같은 설정. ON은 std_map 좌표 기반, OFF는 검출 기반 맵 생성 |

표준맵 ON도 좌표를 무조건 신뢰하는 뜻은 아니다. 현재 코드는 배치 검증과 정합 단계를 가지며 조건에 따라 자동 정합 경로가 작동한다. 파일이 없을 때의 캘리브 계수 재생성 및 파일·계수 모두 없을 때 업로드 거부도 현재 코드에 구현되어 있다. 표준맵을 썼다는 이유만으로 좌표 오차가 완전히 없어졌다고 설명하지 않는다.

고급 창의 **굵은 글씨는 코드 기본값과 다르다는 뜻**이다. 저장되지 않았다는 뜻이 아니다. ‘기본값 복원’도 해당 모델에서 승인된 셋업으로 돌아가는 기능이 아니라 코드 기본값 복원이다. 적용, 파일 저장, IP 업로드는 구분한다.

## 5. 각 탭 교육표

### 기본 설정

| 항목 | 설명 / 변경 효과 |
|---|---|
| 버전·이름·모델 연결 | 레시피 식별 및 모델 기준 확인. 읽기 전용 표시와 편집 항목 구분 |
| 모델 편집/적용/복원·동기화 상태 | 레시피가 사용하는 모델/스냅샷의 관계 확인. ROI 조절과 달리 셀 배열·치수 전반에 영향 가능 |
| PG 패턴 번호 PatternNo | 일반 검사에서 사용하는 PG 패턴 번호, 현재 1~25 검증. 검사 PatternIndex나 PG 장치 번호와 다름 |

| 등급→타입 및 결함 타입 체크 | 등급을 OK/Repair/Reject 등 타입에 연결하고 어떤 타입을 결함 집계할지 결정. 측정 LV는 그대로여도 NG 수가 달라질 수 있음 |

**현재 결함 판정은 Grade → Type → 결함 타입 선택의 순서**다. 공통 설정 창에 남아 있는 DefectCutoffGrade를 현재 주 검사 경로의 최종 NG 기준으로 가르치면 안 된다. 현재 소스의 기본 예는 A/B→OK, C→Repair, D→Reject이며 실제 레시피 매핑이 우선한다.

### WD

| WD 임계값 % | 예: R 점등 영상에서 G/B 좌표를 읽어, 꺼져 있어야 할 발광점이 밝은지 확인. 해당 색상의 정상 기준에 대한 비율이 경계 이상이면 후보. 낮추면 더 약한 명점을 잡지만 잡음 후보도 증가 가능 |

현재 WD 교차 샘플링은 다른 색상 검사에서 얻은 실제 좌표를 현재 영상에서 읽는다. ‘WD는 모든 좌표를 phase offset만으로 추정한다’는 설명은 현재 구현과 다르다. 일반 암점 등급 경계와 WD 임계값은 별개다.

현재 효율 계산에는 `ILED(µA)=측정전류(mA)×1000 / LED수 / Duty`가 들어간다. 목표 ILED 주변 두 점으로 보간하므로 측정 데이터 범위가 부족하면 효율을 산출하지 못할 수 있다. 잘못된 Duty는 원래 측정값을 바꾸지 않으면서 보고서의 해석을 바꾼다.

### Aging

Use, StepNo, Type, 이름, PgPatternIndex, DurationSec가 단계 목록을 구성한다. 켜기/끄기 등 단계와 지속 시간을 정한다. Duration은 카메라 노출시간이 아니다. Aging 실행 여부와 실행 위치는 실제 실행 옵션/시퀀스에 의존한다. Recipe에 목록이 있다는 이유만으로 모든 검사에서 실행된다고 설명하지 않는다.

### PG 매핑

YIndex별로 사용할 PG 장치의 PgIndex를 지정한다. “이 셀 그룹을 어느 PG에 연결할지”이다. RGB 색상 선택이나 1~25 PG 패턴 번호와 구분한다. 잘못된 연결은 의도한 셀에 점등 조건이 적용되지 않는 문제로 이어질 수 있다.

### CellMap 보정

StageX 보정은 XIndex 그룹, UnitY 보정은 YIndex 그룹에 적용한다. 변환된 셀 이동 목표에 보정값을 더하는 **장비 이동 보정**이다. 개별 발광점 LV나 이미지 ROI를 고치는 값이 아니다.

예: StageX 그룹 보정 +10 µm면 그 그룹의 StageX 목표에 +10 µm가 더해진다. 실제 화면에서 어느 방향으로 보이는지는 카메라/축 좌표 관계에 따라 달라지므로 ‘+면 영상에서 무조건 오른쪽’이라고 가르치지 않는다.

µm/px 선택은 입력·표시 환산이다. 내부 저장은 µm이며 dot 물리 치수와 카메라 pitch의 환산이 정확해야 한다. 해당 그룹 여러 셀에 함께 영향이 생긴다는 점을 먼저 교육한다.

### 컨택 확인

이름과 Y(µm)는 ContactorCameraY 촬영 위치 목록이다. 현재 위치 추가, 촬영 시험, Ready/End Flow 및 전체 확인 실행이 연결된다. 메인 검사에서는 UseContactCheck 실행 옵션 조건에 따라 사용한다. 컨택 확인 영상을 찍는 기능을 전기적 접촉 저항 합격 판정과 동일시하지 않는다.

## 6. 적용·저장·전송·실행의 차이

- 입력/적용: 현재 편집 중인 Recipe 값 변경. LostFocus 바인딩은 입력칸을 벗어나야 반영되는 항목도 있다.
- 저장: 파일로 보존. 연결된 검사 동작에는 별도 자동 동기화 경로도 있으므로 ‘저장만 하면 모든 장비에 즉시 적용’이라고 일반화하지 않는다.
- IP 업로드: 검사 실행에 필요한 Recipe와 관련 정보를 선택 IP로 전달. Pitch 분석 등 일부 기능은 실행 전 자동 업로드한다.
- Control 테스트 설정 전송: Control 테스트용 설정을 보냄. 전체 IP Recipe 전송이나 생산 검사 실행과 다르다.
- 이동/점등/촬영/Align/컨택 실행 버튼: 실제 장비 동작. 편집/읽기 버튼과 분리해서 설명한다.

왼쪽의 IP·패턴·셀·이동 도구 선택은 이후 명령의 대상을 정한다. 검사 카메라/CA410/Align 카메라는 같은 셀이라도 사용하는 도구·좌표 관계가 다르다.

## 8. 교육 전에 따로 정리해야 하는 사항

1. **실제 영향이 확인되는 항목과 UI만 있는 항목 구분:** 패턴 Blob 필드와 고급 Blob 필드, Gain, Timeout, DefectCutoffGrade를 동일 수준의 유효 조절값으로 나열하지 않는다.
2. **ContactX 우클릭 읽기 축 불일치:** 교육 전 수정 여부를 검토해야 할 구체적인 UI 연결 문제다. 별도 현재값 읽기와 혼용하지 않는다.
3. **오래된 알고리즘 문서 주의:** rgb-level-inspection-algorithm.md 일부 설명의 등급·측정 방식은 현재 CorrectedDenseMap 구현과 다르다. 현재 코드는 A/B/C 경계와 D 나머지, 좌표 주변 7×7 측정을 기준으로 설명한다.
4. **설비별 적정값은 이 분석만으로 정하지 않음:** 승인 Recipe·정상 영상·정상 셀 반복성으로 설정값을 검증한다. 코드 기본값을 양산 추천값으로 전달하지 않는다.
5. **분석 범위:** 로컬 dist-lib/docs/README.md가 없어 해당 라이브러리 문서는 확인하지 못했다. 현재 Console/Contracts/IP/Algorithm 코드 연결을 기준으로 분석했다. 배포 프로그램에서의 UI·장비 실동작 검증은 하지 않았다.
