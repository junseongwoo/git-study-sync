# 3점 Align Mark 기반 자동 Align 설계

## 1. 목적

이 문서는 현재 프로젝트의 2점 자동 Align 동작을 정리하고, 아래 조건의 세 번째 Align Mark를 추가하여 자동 Align을 확장하는 방법을 정의한다.

- `Mark1`, `Mark2`는 현재 좌/우 Align Mark와 동일하게 사용한다.
- `Mark3`는 `Mark1`과 Glass Y 좌표가 같고 Glass X 좌표만 다르다.
- 회전 오차(`Theta`)는 `Mark1-Mark3` 선분으로 측정한다.
- `Mark1-Mark3`을 다시 측정하고 UVW Theta 보정을 반복하여 각도를 수렴시킨다.
- 각도 수렴 후 병진 오차(`X/Y`)는 기존 `Mark1-Mark2` 로직으로 보정한다.

이 설계는 Console 소유의 Align/Control 구조만 확장한다. IP 실행 계약인 `ULed.Contracts.Models.RecipeModel`은 변경하지 않는다.

## 2. 용어와 Mark 역할

이 문서에서는 다음 매핑을 사용한다.

| 문서 용어 | 현재 코드/UI 용어 | 카메라/브리지 | 역할 |
|---|---|---|---|
| `Mark1` | Left / Align2 | CAM2 / InspectionUnit2Y | Theta 기준점 및 기존 병진 계산점 |
| `Mark2` | Right / Align1 | CAM1 / InspectionUnit1Y | 기존 병진 계산과 좌우 일관성 검증점 |
| `Mark3` | 신규 Align3 | 원칙적으로 Mark1과 같은 CAM2/Align2 | Mark1과 함께 Theta 전용 기준선 구성 |

하드웨어 배치가 위 매핑과 다르면 Mark 번호 자체를 바꾸지 말고, 향후 추가할 Mark 취득 설정에서 사용할 카메라/브리지를 명시적으로 지정한다.

## 3. 370×470 현재 기준

현재 운영 모델:

```text
C:\elp\uLedAoi\Data\GlassSizes\370x470_1.33_Model.json
```

주요 값:

| 항목 | 값 |
|---|---:|
| Glass 크기 | `370000 × 470000 um` |
| PanelAngle | `270 deg` |
| Mark1(Left/Align2) | `(170000, -220000) um` |
| Mark2(Right/Align1) | `(-170000, -220000) um` |
| Align 기준 StageX | `1231483.82` |
| Align2 Unit2Y | `419589.97` |
| Align1 Unit1Y | `414711.19` |
| 기준 U/V/W | `421.7 / 31.5 / 170.1` |
| MaxIteration | `5` |
| X/Y tolerance | `3 um / 3 um` |
| Theta tolerance | `0.001 deg` |
| 좌/우 match threshold | `0.8 / 0.8` |

현재 `Mark1`, `Mark2`를 270도 Stage 좌표로 회전하면 다음과 같다.

```text
Mark1 Glass ( 170000, -220000) -> Stage (-220000, -170000)
Mark2 Glass (-170000, -220000) -> Stage (-220000,  170000)
```

신규 `Mark3`의 Glass 좌표는 다음 조건을 만족해야 한다.

```text
Mark3.X != Mark1.X
Mark3.Y == Mark1.Y
```

예를 들어 Mark3가 `(100000, -220000)`이면 270도 회전 후 Stage 좌표는 `(-220000, -100000)`이다. Glass에서는 수평 기준선이지만 270도 안착 후 Stage에서는 수직 기준선이 된다. 따라서 구현은 "Glass X 방향이므로 Stage X 차이"라고 가정하지 말고 반드시 `PanelAngleDeg`를 적용한 Stage 기준 벡터를 사용해야 한다.

## 4. 현재 2점 자동 Align 동작

현재 자동 Align 중심 코드는 다음 파일에 있다.

```text
uLedAoiConsole/ViewModels/AlignViewModel.cs
```

현재 처리 순서:

1. Recipe `ControlPlan`의 Align 기준 pose로 이동한다.
   - `StageX`
   - `InspectionUnit2Y`
   - `InspectionUnit1Y`
   - `StageU/V/W`
2. CAM2와 CAM1을 동시에 촬영한다.
3. 각 영상에서 저장된 template을 `CCoeffNormed` 방식으로 매칭한다.
4. template 기준 중심과 현재 match 중심의 pixel 차이를 카메라 geometry로 Stage 이동량으로 변환한다.
5. Mark1/Mark2의 nominal Stage 좌표와 좌우 측정 이동량으로 `DeltaX`, `DeltaY`, `DeltaTheta`를 계산한다.
6. Theta 오차가 크면 `XYT -> UVW`로 변환하여 상대 이동한다.
7. 다시 촬영한 후 XY 오차를 반대 방향으로 UVW 상대 이동한다.
8. 최종 재촬영 결과가 tolerance 이내인지 확인한다.
9. 최대 반복 횟수 안에 수렴하지 않으면 실패로 기록한다.

주요 코드 위치:

| 기능 | 파일/메서드 |
|---|---|
| 자동 Align 전체 루프 | `AlignViewModel.RunThetaThenXyAlignCoreAsync` |
| Mark 영상 측정 | `AlignCameraPaneViewModel.MatchCurrentToReference` |
| 기존 2점 XYT 계산 | `AlignViewModel.BuildAlignErrorSnapshot` |
| image delta -> stage delta | `AlignViewModel.ConvertImageDeltaToStageDelta` |
| Glass mark -> Stage 회전 | `AlignViewModel.RotateGlassToStage` |
| XYT -> UVW | `CenterPivotUvwConverter.ToUvw` |
| UVW Control 이동 | `AlignViewModel.SendRelativeUvwMoveAsync` |
| Align 기준 pose 이동 | `RecipeEditorViewModel.MoveAlignReferencePositionOrThrowAsync` |

## 5. 기존의 “3점 Calibration”과 신규 “3점 Align Mark” 구분

현재 `GlassSizeModel.LeftAlignCameraCalibration`과 `RightAlignCameraCalibration`에 있는 `P1/P2/P3`, `R1/R2/R3`는 Align Mark 세 개가 아니다.

이 점들은 다음 affine 변환을 계산하기 위한 좌표 calibration 점이다.

```text
Glass XY -> InspectionUnit2Y/InspectionUnit1Y + StageX
```

각 축은 다음 형태로 계산된다.

```text
AxisX = a * GlassX + b * GlassY + c
AxisY = d * GlassX + e * GlassY + f
```

신규 `Mark3`는 이 affine calibration 점을 재사용하는 것이 아니라, 실제 Glass 위의 세 번째 Align Mark로 별도 등록해야 한다. 다만 Mark3 촬영 위치의 축 target을 계산할 때 기존 affine calibration을 사용한다.

## 6. 목표 Align 시퀀스

권장 시퀀스는 `Mark1-Mark3 Theta`와 `Mark1-Mark2 XY`의 책임을 분리한다.

```text
Align 기준 6축 pose 이동
-> template/camera/mark 설정 검증
-> [Theta 반복]
   -> Mark1 촬영/매칭
   -> Mark3 촬영 위치로 이동
   -> Mark3 촬영/매칭
   -> Mark1 기준 위치로 복귀
   -> Mark1-Mark3 Theta 계산
   -> Theta tolerance 이내이면 Theta 반복 종료
   -> DeltaTheta를 UVW로 변환
   -> StageU/V/W 상대 이동
   -> Mark1-Mark3 재측정
-> [기존 XY 보정]
   -> Mark1/Mark2 촬영/매칭
   -> 기존 방식으로 TranslateX/TranslateY 계산
   -> XY tolerance 밖이면 UVW 상대 이동
-> [최종 검증]
   -> Mark1-Mark3 Theta 재검증
   -> Mark1-Mark2 XY/매칭/일관성 재검증
-> 성공 결과 저장
```

Theta 보정과 XY 보정을 한 번의 UVW 이동으로 합치지 않는다. 현재 장비에서 검증된 `ThetaThenXY` 순서를 유지한다.

## 7. Mark3 촬영 방법

### 7.1 기본 원칙

Mark3는 Mark1과 같은 Align2 카메라로 촬영한다. Mark3 목표 축 위치는 `CoordinateTransformService.BuildBridgeCalibration()`과 `ResolveToolAxisTarget()`으로 계산한다.

Mark3 촬영을 위해 이동할 수 있는 축:

- `InspectionUnit2Y`
- 필요한 경우 `StageX`

Mark3 촬영 중 다음 축은 현재 보정 상태를 유지해야 한다.

- `StageU`
- `StageV`
- `StageW`

Mark3 촬영 후에는 반드시 Mark1 촬영 pose로 복귀한 뒤 UVW 보정 명령을 보낸다. Mark3 관측을 위해 바뀐 `StageX/InspectionUnit2Y` 위치에서 UVW를 보정하면 기준 pose와 회전 중심 해석이 섞이므로 금지한다.

### 7.2 촬영 pose 계산

```csharp
BridgeCalibration calibration = coordinateTransformService
    .BuildBridgeCalibration(glassSizeModel)
    .Calibration;

BridgeAxisTarget mark1Target = coordinateTransformService.ToBridgeAxes(
    new UmPoint(mark1.X, mark1.Y),
    calibration.Left);

BridgeAxisTarget mark3Target = coordinateTransformService.ToBridgeAxes(
    new UmPoint(mark3.X, mark3.Y),
    calibration.Left);
```

실제 구현에서는 `ToBridgeAxes` 입력이 Glass 좌표임을 유지한다. 변수 이름에 `Stage`를 섞지 않는다.

### 7.3 전용 template

Mark3가 Mark1과 같은 모양이어도 template을 암묵적으로 재사용하지 않는다. 다음 파일을 명시적으로 등록한다.

```text
align_mark1.png  또는 현재 align_left.png
align_mark2.png  또는 현재 align_right.png
align_mark3.png
```

Mark3 설정값도 별도로 둔다.

- match threshold
- template rect
- search area rect

Mark3 설정이나 파일이 없으면 자동으로 Mark1 값을 대입하지 않고 명확히 실패시킨다.

## 8. Mark1-Mark3 Theta 계산

### 8.1 좌표 정의

GlassSize에 저장된 nominal mark를 PanelAngle만큼 회전하여 Stage 기준 nominal 점을 만든다.

```text
P1 = RotateGlassToStage(Mark1.GlassUm, PanelAngleDeg)
P3 = RotateGlassToStage(Mark3.GlassUm, PanelAngleDeg)
```

template match 결과의 pixel 차이를 카메라 geometry로 변환한다.

```text
D1 = ConvertImageDeltaToStageDelta(Mark1 image delta)
D3 = ConvertImageDeltaToStageDelta(Mark3 image delta)
```

측정 기준선은 다음과 같이 구성한다.

```text
Vref = P3 - P1
Vmeasured = (P3 + D3) - (P1 + D1)
```

### 8.2 권장 각도 수식

작은 각도 근사만 사용하지 않고 `atan2(cross, dot)`으로 signed angle을 구한다.

```text
cross = Vref.X * Vmeasured.Y - Vref.Y * Vmeasured.X
dot   = Vref.X * Vmeasured.X + Vref.Y * Vmeasured.Y

thetaRad = atan2(cross, dot)
thetaDeg = thetaRad * 180 / PI
```

장점:

- Mark1-Mark3 기준선이 Stage X 또는 Stage Y 어느 방향이든 동일하게 동작한다.
- 270도 모델에서도 별도 축 분기 없이 동작한다.
- 단순 `deltaY / distance`보다 큰 초기 각도에 안정적이다.

### 8.3 기본 유효성 검사

```text
abs(Mark3.Y - Mark1.Y) <= MarkCoordinateToleranceUm
abs(Mark3.X - Mark1.X) >= MinimumThetaBaselineUm
|Vref| >= MinimumThetaBaselineUm
Mark1 score >= Mark1 threshold
Mark3 score >= Mark3 threshold
```

권장 초기값:

```text
MarkCoordinateToleranceUm = 1 um
MinimumThetaBaselineUm = 10000 um
```

실제 최소 baseline은 카메라 분해능과 요구 Theta tolerance를 기준으로 확정한다. 기준선이 길수록 동일 pixel 오차에 대한 각도 오차가 작아진다.

### 8.4 기존 UVW 부호 규칙 유지

현재 실측으로 확정된 코드 규칙은 측정된 `thetaSnapshot.ThetaDeg`를 그대로 UVW 변환기에 전달하는 것이다.

```csharp
UvwDelta thetaMove = uvwConverter.ToUvw(
    new XytDelta(0.0, 0.0, thetaErrorDeg),
    uvwParameters);
```

일반적인 수학식만 보고 임의로 `-thetaErrorDeg`로 바꾸면 안 된다. 기존 코드 주석과 같이 반대 부호는 오차가 반복마다 두 배로 증가한 실측 이력이 있다.

## 9. 370×470 UVW 계산

현재 장비 config:

```text
PositiveThetaDirection = CW
GlassMinusXEdgeStageXUm = -460000
GlassCenterStageYUm = 0
U axis line StageX = -380000, TranslationAxis = PlusY
V axis line StageX =  380000, TranslationAxis = PlusY
W axis line StageY = -280000, TranslationAxis = MinusX
```

370×470 모델은 `PanelAngle=270`이므로 Stage X 방향 길이는 Glass width가 아니라 Glass height `470000 um`이다.

```text
GlassCenterStageX = -460000 + 470000 / 2
                  = -225000 um
```

따라서 effective 변환식은 다음과 같다. Theta 단위는 rad이다.

```text
U = Y + 155000 * Theta
V = Y - 605000 * Theta
W = -X - 280000 * Theta
```

예를 들어 `DeltaTheta=+0.001 deg`이면:

```text
U =  +2.705 um
V = -10.559 um
W =  -4.887 um
```

이 계산은 직접 복제하지 않고 `UvwParameterResolver`와 `CenterPivotUvwConverter`를 재사용한다.

### 11.1 계산 전용 타입

```csharp
public readonly record struct AlignMarkObservation(
    string MarkId,
    UmPoint NominalStageUm,
    UmPoint ImageDeltaStageUm,
    double Score);

public readonly record struct MarkPairThetaResult(
    double ThetaDeg,
    double BaselineUm,
    double Mark1Score,
    double Mark3Score);
```

### 11.2 Theta estimator

```csharp
public sealed class AlignThetaEstimator
{
    public MarkPairThetaResult Calculate(
        AlignMarkObservation mark1,
        AlignMarkObservation mark3,
        double minimumBaselineUm)
    {
        double refX = mark3.NominalStageUm.X - mark1.NominalStageUm.X;
        double refY = mark3.NominalStageUm.Y - mark1.NominalStageUm.Y;
        double baseline = Math.Sqrt((refX * refX) + (refY * refY));
        if (baseline < minimumBaselineUm)
        {
            throw new InvalidOperationException(
                $"Mark1-Mark3 baseline이 너무 짧습니다. Baseline={baseline:F3}um");
        }

        double measuredX = refX
            + mark3.ImageDeltaStageUm.X
            - mark1.ImageDeltaStageUm.X;
        double measuredY = refY
            + mark3.ImageDeltaStageUm.Y
            - mark1.ImageDeltaStageUm.Y;

        double cross = (refX * measuredY) - (refY * measuredX);
        double dot = (refX * measuredX) + (refY * measuredY);
        double thetaDeg = Math.Atan2(cross, dot) * 180.0 / Math.PI;

        return new MarkPairThetaResult(
            thetaDeg,
            baseline,
            mark1.Score,
            mark3.Score);
    }
}
```

계산 클래스는 카메라, Control, UI를 참조하지 않게 하여 좌표 단위 테스트가 가능해야 한다.

### 11.3 Theta 반복 의사 코드

```csharp
private async Task<MarkPairThetaResult> RunMark13ThetaLoopAsync(
    ConsoleAlignPlan plan,
    GlassSizeModel glassSizeModel,
    CenterPivotUvwParameters uvwParameters,
    CancellationToken cancellationToken)
{
    MarkPairThetaResult last = default;

    for (int iteration = 1; iteration <= plan.Mark13MaxIteration; iteration++)
    {
        cancellationToken.ThrowIfCancellationRequested();

        AlignMarkObservation mark1 = await CaptureMark1Async(cancellationToken);
        AlignMarkObservation mark3 = await CaptureMark3AndReturnAsync(cancellationToken);

        last = _thetaEstimator.Calculate(
            mark1,
            mark3,
            plan.Mark13MinimumBaselineUm);

        _log.Info(
            "AlignTheta13",
            $"Iter={iteration}, Theta={last.ThetaDeg:F6}deg, "
            + $"Baseline={last.BaselineUm:F3}um, "
            + $"Score1/3={last.Mark1Score:F4}/{last.Mark3Score:F4}");

        if (Math.Abs(last.ThetaDeg) <= plan.Mark13ToleranceThetaDeg)
        {
            return last;
        }

        UvwDelta thetaMove = _uvwConverter.ToUvw(
            new XytDelta(0.0, 0.0, last.ThetaDeg),
            uvwParameters);

        await SendRelativeUvwMoveAsync(
            thetaMove,
            "theta-mark13",
            cancellationToken);
    }

    throw new InvalidOperationException(
        $"Mark1-Mark3 Theta가 {plan.Mark13MaxIteration}회 안에 수렴하지 않았습니다. "
        + $"FinalTheta={last.ThetaDeg:F6}deg");
}
```

### 11.4 전체 Align 루프 변경 예

```csharp
await MoveAlignPositionCoreAsync(cancellationToken);

MarkPairThetaResult thetaResult = await RunMark13ThetaLoopAsync(
    plan,
    glassSizeModel,
    uvwParameters,
    cancellationToken);

// Mark1/Mark2는 기존 방식으로 촬영한다.
await GrabBothAsync(cancellationToken);
AlignErrorSnapshot xySnapshot = BuildAlignErrorSnapshot();

if (Math.Abs(xySnapshot.TranslateXUm) > plan.ToleranceXUm
    || Math.Abs(xySnapshot.TranslateYUm) > plan.ToleranceYUm)
{
    UvwDelta xyMove = _uvwConverter.ToUvw(
        new XytDelta(
            -xySnapshot.TranslateXUm,
            -xySnapshot.TranslateYUm,
            0.0),
        uvwParameters);

    await SendRelativeUvwMoveAsync(xyMove, "xy", cancellationToken);
}

// XY 이동 뒤 Mark1-Mark3 Theta와 Mark1-Mark2 XY를 모두 다시 검증한다.
MarkPairThetaResult finalTheta = await MeasureMark13ThetaAsync(cancellationToken);
AlignErrorSnapshot finalXy = await MeasureMark12Async(cancellationToken);

if (Math.Abs(finalTheta.ThetaDeg) > plan.Mark13ToleranceThetaDeg
    || Math.Abs(finalXy.TranslateXUm) > plan.ToleranceXUm
    || Math.Abs(finalXy.TranslateYUm) > plan.ToleranceYUm)
{
    throw new InvalidOperationException("3점 Align 최종 오차가 tolerance를 벗어났습니다.");
}
```

실제 구현에서는 XY 보정 뒤 Theta가 다시 벗어나는 경우를 위해 전체 outer iteration을 둘 수 있다. 단, `Mark13MaxIteration`과 전체 `MaxIteration`을 이중으로 무제한 중첩하지 않는다. 총 UVW 이동 횟수의 상한을 명시한다.

## 13. 안전 및 실패 처리

다음 경우 UVW를 움직이지 않고 실패해야 한다.

- Mark3 좌표가 없음
- Mark3가 두 개 이상 등록됨
- Mark1과 Mark3의 Y 좌표가 허용 오차 이상 다름
- Mark1과 Mark3의 X 좌표가 같거나 baseline이 너무 짧음
- Mark1 또는 Mark3 template 파일이 없음
- Mark1 또는 Mark3 match score가 threshold 미만
- CAM2 연결 실패
- Mark3 위치 이동 또는 Mark1 위치 복귀 실패
- UVW 변환 행렬이 singular
- Control move 응답 실패/timeout
- 최대 반복 횟수 내 미수렴
- 좌우 Mark1/Mark2 병진 결과의 일관성 초과

실패 시 임의 좌표, Mark1 template, 이전 Align 결과 또는 legacy 설정으로 fallback하지 않는다.

Mark3 촬영 pose에서 예외가 발생하더라도 가능한 경우 `finally`에서 Mark1 기준 pose 복귀를 시도한다. 복귀 실패는 원래 예외보다 낮은 수준으로 숨기지 말고 함께 기록한다.

## 15. 검증 계획

### 15.1 계산 단위 검증

1. 오차 없음
   - `D1=(0,0)`, `D3=(0,0)` -> `Theta=0`
2. 알려진 `+0.01 deg` 회전
   - nominal 두 점을 수학적으로 회전한 측정점을 입력
   - 계산 결과가 `+0.01 deg`인지 확인
3. 알려진 `-0.01 deg` 회전
4. 두 점에 동일 병진만 적용
   - Theta가 0인지 확인
5. 0°, 90°, 180°, 270° PanelAngle 각각 같은 결과인지 확인
6. baseline 부족/동일점/NaN 입력이 실패하는지 확인

### 15.2 UVW 검증

370×470, 270도 모델에서:

```text
Theta +0.001 deg -> U/V/W 약 +2.705/-10.559/-4.887 um
```

UVW Test에서 실제 축 방향을 확인하고, 재측정 Theta 절대값이 이전보다 감소해야 한다.

필수 수렴 조건:

```text
abs(theta[n+1]) < abs(theta[n])
```

부호가 반대여서 오차가 증가하면 즉시 중단한다. 반복 횟수 끝까지 계속 움직이지 않는다. 권장 발산 감지 조건은 이전 오차 대비 `1.5배 이상 증가`가 1회 발생하면 중단하는 것이다.

### 15.3 실장비 시나리오

1. 기준 pose에서 Mark1/Mark3 측정값 확인
2. UVW Test로 의도적으로 `+0.01 deg` 회전
3. Mark1-Mark3 측정 Theta 부호 확인
4. 자동 Theta 1회 보정 후 오차 감소 확인
5. 최대 5회 안에 `0.001 deg` 이내 수렴 확인
6. XY를 의도적으로 이동 후 기존 Mark1-Mark2 XY 보정 확인
7. 최종 Mark1/Mark2/Mark3 score 및 X/Y/Theta 확인
8. 카메라 해제, template 누락, Control timeout에서 정직한 실패 확인
9. 검사 시작 `UseAlign=true` 경로에서 Align 성공 후에만 검사 flow 진입 확인

## 16. 구현 완료 판정 기준

다음 조건을 모두 만족해야 구현 완료로 판단한다.

- Mark3가 GlassSize 정본 좌표로 저장된다.
- Mark3 촬영용 template/search/threshold가 recipe에 명시된다.
- Mark1-Mark3 signed Theta가 PanelAngle과 무관하게 계산된다.
- Theta 보정 후 Mark1-Mark3을 실제로 재촬영한다.
- 최대 반복 횟수와 발산 감지가 적용된다.
- Theta 수렴 후 기존 Mark1-Mark2 XY 보정이 실행된다.
- 최종 검증에서 Mark13 Theta와 Mark12 XY가 모두 tolerance 이내다.
- Mark3 촬영을 위해 이동한 축이 기준 pose로 복귀한다.
- 성공/실패 결과와 Mark3 score가 `align_result.json` 및 운영 로그에 남는다.
- `RecipeModel` 및 IP 실행 계약은 변경되지 않는다.
- 기존 2점 Align을 유지할 필요가 있다면 명시적 mode로만 선택하고, Mark3 누락 시 자동으로 2점 방식으로 전환하지 않는다.

## 17. 핵심 결론

신규 3점 Align은 "세 점 전체로 한 번에 affine 보정"하는 방식이 아니다.

```text
Mark1-Mark3 = 회전(Theta) 전용 기준선
Mark1-Mark2 = 기존 병진(X/Y) 및 좌우 일관성 기준
```

구현 핵심은 다음 세 가지다.

1. Mark1과 Mark3의 nominal/측정 기준선 각도를 `atan2(cross, dot)`으로 계산한다.
2. 계산된 Theta를 기존 `CenterPivotUvwConverter`로 변환하여 UVW 상대 이동한다.
3. Mark1-Mark3 재촬영을 반복하여 Theta를 먼저 수렴시킨 뒤 기존 Mark1-Mark2 XY 보정을 수행한다.
