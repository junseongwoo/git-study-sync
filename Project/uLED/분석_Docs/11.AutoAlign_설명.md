# AutoAlignWindow 단계별 TEST 설명

## 1. 구현 목적

현장에서 기존 Align 위치를 잡을 때 다음 작업을 사람이 반복한다.

```text
Align 위치 이동
→ Align Mark 좌표 확인
→ UVW Jog로 T 회전
→ 다시 Mark 좌표 확인
→ T가 맞을 때까지 반복
→ Align Image 등록
→ Contactor X와 UV Align
→ Align 위치 등록
```

이번 `AutoAlignWindow`는 전체 Align을 자동화하는 기능이 아니다. 가장 어려운 `Mark 좌표 확인 → T 계산 → UVW Jog` 부분을 먼저 단계별로 시험하기 위한 화면이다.

작업자가 각 버튼을 누른 뒤 이미지와 계산값을 확인할 수 있도록 자동 반복을 사용하지 않는다.

## 2. 최종 버튼 순서

```text
CAM2 연결
  ↓
1. Align 위치 이동
  ↓
2. Mark1 촬영
  ↓
3-1. Mark3 StageX 이동
  ↓
3-2. Mark3 이미지 촬영
  ↓
3-3. Mark3 좌표 분석
  ↓
3-4. Align1 복귀
  ↓
4. 좌표 비교
  ↓
5. 계산된 T Jog
  ↓
2번부터 다시 반복
  ↓
Mark1/2 최종 확인 창
  ↓
기존 Align Image 등록
```

Mark3 관련 버튼은 반드시 다음처럼 한 기능만 수행한다.

| 버튼 | 수행하는 기능 | 수행하지 않는 기능 |
|---|---|---|
| Mark3 StageX 이동 | StageX를 Align3 위치로 이동 | 촬영, 좌표 분석 |
| Mark3 이미지 촬영 | 현재 위치에서 CAM2 촬영 | 축 이동, 좌표 분석 |
| Mark3 좌표 분석 | 촬영된 메모리 이미지에서 Mark 중심 검출 | 축 이동, 촬영 |
| Align1 복귀 | StageX를 Align1 위치로 이동 | 촬영, 좌표 분석 |

## 3. Align3 고정 위치

Align3 위치는 사용자가 입력하지 않는다.

```text
Align3 Glass X = Align1 Glass X
Align3 Glass Y = Align1 Glass Y + 430000um
```

`430mm = 430000um`이다.

현재 `370x470_Model` 예시는 다음과 같다.

```text
Align1 Glass = (170000, -220000)um
Align3 Glass = (170000,  210000)um

Glass Y 차이 = 430000um
StageX 이동량 = +430000um
CamY2 이동량 = 0um
```

실제 StageX 목표는 단순히 `430000`이라는 절대 위치가 아니다.

```text
Align3 StageX 목표
= 기존 Align1 StageX
+ CAM2 calibration으로 계산한 430mm StageX 이동량
```

현재 모델에서는 다음 값이다.

```text
Align1 StageX = 1231483.82um
StageX 이동량 = 430000um
Align3 StageX = 1661483.82um
```

CamY2는 Align1 위치에 계속 고정한다.

## 4. AutoAlignViewModel 구조

주요 코드는 `uLedAoiConsole/ViewModels/AutoAlignViewModel.cs`에 있다.

사용한 주요 클래스:

| 클래스 | 역할 |
|---|---|
| `AutoAlignViewModel` | 단계 버튼, 상태, 장비 이동, 촬영, 비교 흐름 관리 |
| `AlignTemplateMatchService` | 임시 Template을 현재 이미지에서 찾아 중심 Pixel 계산 |
| `AlignMarkPairThetaEstimator` | Align1/Align3 기준선과 영상 편차로 Theta 계산 |
| `CoordinateTransformService` | Glass 좌표와 CAM2 장비 축 좌표 변환 |
| `CenterPivotUvwConverter` | 계산된 Theta를 U/V/W 이동량으로 변환 |
| `AlignCameraPaneViewModel` | CAM2 연결과 단일 이미지 촬영 |

MVVM 명령:

```text
MoveAlignCommand       → MoveAlignAsync
CaptureMark1Command   → CaptureMark1Async
MoveMark3Command      → MoveMark3Async
CaptureMark3Command   → CaptureMark3Async
AnalyzeMark3Command   → AnalyzeMark3
ReturnMark1Command    → ReturnMark1Async
CompareCommand        → Compare
ApplyThetaCommand     → ApplyThetaAsync
ResetCommand          → ResetSession
```

## 5. Step 1 - Align 위치 이동 코드

`MoveAlignAsync`가 기존 Recipe의 Align 기준 위치 이동 기능을 호출한다.

```csharp
await _recipe.MoveAlignReferencePositionOrThrowAsync();
```

이동 후 다음 축의 실제 위치를 확인한다.

```text
StageX = Align1 StageX
CamY2  = Align1 CamY2
```

목표와 실제 위치 차이가 `10um`보다 크면 다음 단계로 진행하지 않는다.

## 6. Step 2 - Mark1 촬영과 임시 기준

`CaptureMark1Async`가 다음 순서로 동작한다.

```text
Align1 위치 이동과 확인
→ CAM2 새 이미지 촬영
→ 첫 Mark1 이미지를 메모리에 임시 기준으로 보관
→ Template Matching
→ Mark 중심 Pixel 좌표 계산
→ Viewer 표시
```

첫 Mark1 이미지는 파일로 저장하지 않는다.

- `align_left.png`를 생성하지 않는다.
- 기존 Align Image를 덮어쓰지 않는다.
- 창을 닫거나 TEST 초기화를 하면 사라진다.
- T Jog 후 재촬영에서도 같은 첫 임시 기준을 사용한다.

Template/Search ROI가 비어 있어도 Mark1 촬영 이미지는 먼저 표시한다. 작업자가 이미지를 보고 ROI 값을 입력한 뒤 Mark1 촬영을 다시 누르면 좌표 분석을 진행한다.

Mark1 Viewer 표시:

- 청록색 중심선: 카메라 중심
- 녹색 십자가: 검출된 Mark 중심
- 주황색 선: 카메라 중심에서 Mark 중심까지의 차이
- 주황색 사각형: Template ROI
- 파란색 사각형: Search ROI

## 7. Step 3-1 - Mark3 StageX 이동 코드

`MoveMark3Async`는 위치 계산과 StageX 이동만 한다.

```csharp
await MoveStageXAsync(setup.Mark3StageX, "Mark3 위치");
```

Control에 보내는 축 명령은 한 개뿐이다.

```csharp
new AxisMove
{
    Axis = Axis.StageX,
    Mode = MoveMode.Abs,
    Value = mark3StageX
}
```

`Axis.InspectionUnit2Y`, 즉 CamY2 이동 명령은 없다.

이 버튼은 카메라 촬영과 Template Matching을 실행하지 않는다. 이동 완료 후 StageX는 Mark3 위치에 그대로 남는다.

## 8. Step 3-2 - Mark3 이미지 촬영 코드

`CaptureMark3Async`는 StageX가 Mark3 위치인지 확인한 뒤 CAM2 촬영만 실행한다.

```csharp
await GrabFreshAsync("Mark3 촬영");
mark3Raw = Camera.CurrentMat.Clone();
```

이 단계에서는 다음 기능을 실행하지 않는다.

- StageX 이동
- Align1 자동 복귀
- Template Matching
- 중심 좌표 계산
- Theta 계산

Viewer에는 촬영된 원본 이미지와 카메라 중심선만 표시하며 상태에 `좌표 분석 미실행`을 표시한다.

## 9. Step 3-3 - Mark3 좌표 분석 코드

`AnalyzeMark3`는 메모리에 보관된 Mark3 이미지에 대해서만 실행한다.

```csharp
mark3Match = matcher.Match(
    mark3Raw,
    temporaryMark1Reference,
    templateRect,
    searchRect,
    threshold);
```

이 버튼은 축 이동이나 카메라 촬영을 하지 않는다.

분석 결과:

```text
Mark3 현재 중심 Pixel X/Y
임시 Mark1 기준 중심 Pixel X/Y
Template Match Score
```

분석된 Mark3 이미지에는 녹색 십자가와 Template/Search ROI를 그린다.

## 10. Step 3-4 - Align1 복귀 코드

`ReturnMark1Async`는 StageX만 Align1 위치로 복귀시킨다.

```csharp
await MoveStageXAsync(setup.Mark1StageX, "Align1 복귀");
```

복귀 후 실제 StageX 위치를 읽어 목표 위치 도착을 확인한다.

StageX가 Mark3 위치에 있는 동안에는 다음 기능을 막는다.

- 좌표 비교
- 계산된 T Jog
- TEST 초기화

창을 닫을 때도 StageX가 Mark3 위치라면 안전을 위해 Align1 복귀를 시도하고 로그를 남긴다.

## 11. Step 4 - Mark1/Mark3 좌표 비교

`Compare`는 계산만 수행하고 장비를 움직이지 않는다.

### Pixel 편차

```text
Mark1 Pixel 편차 = Mark1 현재 중심 - 임시 기준 중심
Mark3 Pixel 편차 = Mark3 현재 중심 - 임시 기준 중심
```

CAM2의 Pixel Size와 영상 속 Stage 축 방향으로 Pixel 편차를 Stage `um` 편차로 변환한다.

```text
상대 Stage 편차 = Mark3 Stage 편차 - Mark1 Stage 편차
```

Glass 전체가 같이 밀린 X/Y 값은 서로 빼는 과정에서 제거된다.

### 정상 기준선

```text
기준선 = Align3 정상 Stage 좌표 - Align1 정상 Stage 좌표
현재선 = 기준선 + 상대 Stage 편차
```

기준선은 Glass 기준 고정 430mm이다.

### Theta 식

현재 TEST는 기존 Align과 같은 작은 각도 선형식을 사용한다.

```text
Theta radian
= (기준선 X × 상대 편차 Y - 기준선 Y × 상대 편차 X)
  ÷ 기준선 길이 제곱
```

비교 Viewer 표시:

- 청록색 선: 정상 430mm 기준선
- 녹색 선: 현재 측정선
- 두 선 사이의 차이: Theta
- 하단 숫자: Theta, U, V, W, Mark 거리 오차

## 12. Step 5 - 계산된 T Jog 코드

`ApplyThetaAsync`는 기존 AlignWindow와 UVW Jog가 사용하는 `CenterPivotUvwConverter`를 사용한다.

```csharp
UvwDelta uvw = uvwConverter.ToUvw(
    new XytDelta(0.0, 0.0, calculatedTheta),
    uvwParameters);
```

X와 Y는 0이고 Theta만 전달하므로 Glass 중심 회전만 수행한다.

```text
U = U축 회전 계수 × Theta radian
V = V축 회전 계수 × Theta radian
W = W축 회전 계수 × Theta radian
```

실제 이동 전 확인창에 Theta와 U/V/W를 표시한다. 사용자가 확인해야만 StageU/V/W 상대 이동을 한 번 실행한다.

안전 조건:

- 한 번의 계산 Theta가 `0.1deg`를 초과하면 이동 금지
- StageX가 Mark3 위치라면 이동 금지
- 좌표 비교를 다시 하지 않고 같은 T Jog를 두 번 실행하지 못함
- 이동 후 자동 재촬영 또는 자동 반복하지 않음

T Jog 후 Mark1 촬영부터 다시 진행하여 남은 Theta를 확인한다.

## 13. UI 이미지와 값

AutoAlignWindow는 세 Viewer를 동시에 표시한다.

| Viewer | 표시 내용 |
|---|---|
| Mark1 | 촬영 이미지, 카메라 중심, 검출 중심, ROI, Pixel 좌표, Score |
| Mark3 | 촬영 이미지, 분석 전/후 상태, 검출 중심, ROI, Pixel 좌표, Score |
| 좌표 비교 | 정상 기준선, 현재 측정선, Theta, Pair Error |

화면 하단에는 현재 눌러야 할 다음 버튼과 실행 상태를 표시한다.

## 14. Align Image가 없어도 비교할 수 있는 이유

등록된 Align Image 파일은 없어도 된다. 다만 아무 기준도 없이 Mark를 찾는 것은 아니다.

첫 Mark1 촬영 이미지의 Template ROI를 창 내부 메모리 기준으로 사용한다.

```text
첫 Mark1 Template
→ 현재 Mark1 이미지에서 같은 형상 검색
→ 현재 Mark3 이미지에서 같은 형상 검색
→ 두 중심 좌표 계산
```

필요 조건:

- Mark1과 Mark3의 형상이 같거나 Template Matching이 가능해야 한다.
- Template ROI가 Mark 형상을 정확히 포함해야 한다.
- Search ROI 안에 Mark가 있어야 한다.
- Match Score가 Threshold 이상이어야 한다.

임시 기준은 Align Image 등록과 다르며 창 종료 시 사라진다.

## 15. 어떤 기준으로 T축을 돌리는가

단순히 Mark1 Pixel X와 Mark3 Pixel X만 비교하지 않는다.

다음 기준을 모두 사용한다.

1. Align1과 Align3의 정상 Glass 거리 430mm
2. CAM2 Pixel Size
3. 영상에서 Stage X/Y가 향하는 방향
4. Glass의 Panel Angle
5. Glass 중심 회전을 UVW로 변환하는 파라미터

```text
Mark 중심 Pixel 검출
→ Stage X/Y um 편차 변환
→ 정상 430mm 선과 현재선 비교
→ Theta 계산
→ U/V/W 상대 이동량 계산
→ 사용자 확인
→ T Jog 1회
```

기존 Align의 실측 부호 규칙과 동일하게 측정된 `+Theta`를 UVW 변환기에 전달한다.

## 16. 최종 Mark1/Mark2 확인과 Align Image 등록

Theta가 허용오차 안에 들어오면 `Mark1/2 최종 확인 창` 버튼으로 기존 `AlignWindow`를 연다.

최초 셋업에서 Align Image가 없다면 기존 Template Matching 기준도 없으므로 등록 전에 자동 평가는 할 수 없다.

```text
Mark1/Mark2 촬영 또는 Live 확인
→ 두 영상과 카메라 중심선을 육안 확인
→ 정상 상태에서 Align Image 등록
→ 등록 후 촬영 평가로 재검증
```

표준 Align Image는 Left/Right 이미지가 같은 Align 상태인 한 세트여야 한다. 따라서 AutoAlignWindow의 CAM2 Mark1/Mark3 이미지는 표준 Align Image로 저장하지 않는다.

## 17. 실패와 차단 조건

- CAM2 또는 Control 미연결
- Align1 StageX/CamY2 누락
- CAM2 calibration 누락
- 고정 Align3가 Glass 범위를 벗어남
- 430mm 계산 결과 CamY2가 고정되지 않음
- Template/Search ROI 누락 또는 범위 오류
- Match Score 미달
- 새 촬영 이미지 없음
- Mark3 이동 전에 Mark1 분석이 없음
- Mark3 위치가 아닌데 촬영 실행
- 촬영 이미지 없이 좌표 분석 실행
- StageX 이동 또는 복귀 실패
- StageX가 Mark3 위치인데 좌표 비교/T Jog/초기화 실행
- Mark1/Mark3 측정 거리 오류
- 계산 Theta가 0.1deg 초과
- UVW 이동 응답 실패

각 단계의 시작, 완료, 실패, Pixel 좌표, Theta, U/V/W는 Auto Align 전용 Caller 로그에 기록한다.

## 18. 현장 TEST 순서

1. CAM2를 연결한다.
2. Align 위치로 이동한다.
3. Mark1을 촬영하고 녹색 십자가가 실제 중심인지 확인한다.
4. Mark3 StageX 이동 버튼만 눌러 CamY2가 움직이지 않는지 확인한다.
5. Mark3 이미지 촬영 버튼을 누르고 아직 좌표가 분석되지 않았음을 확인한다.
6. Mark3 좌표 분석 버튼을 누르고 녹색 십자가 위치를 확인한다.
7. Align1 복귀 버튼을 눌러 StageX가 원래 위치로 돌아오는지 확인한다.
8. 좌표 비교 그림과 Theta 부호를 기존 수동 판단과 비교한다.
9. 작은 Theta에서 계산된 T Jog를 한 번 실행한다.
10. Mark1부터 다시 측정하여 Theta가 감소하는지 확인한다.
11. 허용오차 통과 후 기존 AlignWindow에서 Mark1/2를 확인한다.
12. 정상 상태에서 Align Image를 등록한다.
