# Auto Align 기능 설명

## 1. 이번 기능의 목적

`AutoAlignWindow`는 CAM2 한 대로 Align1과 Align3을 차례로 보고 Glass의 회전 오차인 Theta를 자동으로 맞추는 TEST 화면이다.

중요한 장비 동작은 다음과 같다.

- CAM2의 CamY2 축은 기존 Align1 위치에 고정한다.
- Align1을 촬영한 뒤 StageX만 움직여 Align3을 CAM2 화면으로 가져온다.
- Align3을 촬영한 뒤 StageX만 Align1 위치로 되돌린다.
- Align1과 Align3의 중심 좌표로 Theta를 계산한다.
- 계산한 Theta만큼 UVW를 움직인다.
- 다시 촬영해서 남은 Theta를 확인하고 허용오차 안에 들어올 때까지 반복한다.

기존 `AlignWindow`와 `AlignViewModel`은 변경하지 않았다.

---

## 2. 장비가 움직이는 모습

```text
CamY2는 Align1 위치에 고정

             Glass 위쪽
        ┌───────────────────┐
        │                   │
        │                   │
        │  Align1    Align3 │
        └───────────────────┘
             Glass 아래쪽

Align1 촬영: StageX = Align1 StageX
Align3 촬영: StageX = Align3 StageX

CamY2 값은 두 촬영에서 동일하다.
```

StageX가 Glass 전체를 좌우로 이동시키기 때문에 CamY2를 움직이지 않아도 Align1 다음에 Align3을 같은 CAM2로 볼 수 있다.

---

## 3. 사용자가 입력하는 값

Align3에는 `StageXUm` 한 값만 입력한다.

```text
Glass Size Model
└─ AlignMarks
   └─ Align3
      └─ StageXUm
```

저장 예시는 다음과 같다.

```json
{
  "alignMarks": {
    "align3": {
      "stageXUm": 250000
    }
  }
}
```

CamY2 입력칸은 없다. CamY2는 Glass Size Model의 기존 Align1 위치인 `AlignBridgeReferencePose.LeftAlignUnitY`를 사용한다.

Align3 StageX 값이 없으면 다른 값으로 추정하지 않고 실행을 중단한다.

---

## 4. 필요한 기준 이미지

이 Auto Align 기능 자체에는 기준 이미지 2개가 필요하다.

| Mark | 파일 | 용도 |
|---|---|---|
| Align1 | `align_left.png` | 정상 상태의 Align1 중심 확인 |
| Align3 | `align_mark3.png` | 정상 상태의 Align3 중심 확인 |

기존 Align1, Align2 기능까지 같이 사용한다면 시스템 전체에는 Align1, Align2, Align3 이미지가 필요하다.

기준 이미지는 Glass가 정상 정렬된 상태에서 한 번 등록한다. Auto Align 실행 때마다 다시 등록하면 안 된다. 틀어진 이미지를 저장하면 그 틀어진 상태가 새로운 정상 기준이 되기 때문이다.

---

## 5. 전체 실행 순서

```text
1. 설정과 연결 상태 확인
2. 기존 Align1 위치로 이동
3. Align1 촬영
4. StageX만 Align3 위치로 이동
5. Align3 촬영
6. StageX만 Align1 위치로 복귀
7. Align1과 Align3 중심으로 Theta 계산
8. Theta를 UVW 이동량으로 변환
9. U, V, W 상대 이동
10. 3번부터 다시 측정
11. Theta가 허용오차 안이면 완료
```

이 흐름은 `AutoAlignViewModel.RunAsync`에 같은 순서로 주석을 달아 두었다.

---

## 6. 코드가 Align1과 Align3을 촬영하는 과정

### 6.1 Align1 위치로 이동

`MoveReferenceAsync`가 기존 Align 기준 위치 이동 기능을 호출한다.

이때 확인하는 값은 다음 두 개다.

- StageX가 Align1 StageX에 도착했는지 확인
- CamY2가 Align1 CamY2에 도착했는지 확인

이 이동이 끝난 뒤에는 CamY2를 더 이상 움직이지 않는다.

### 6.2 Align1 촬영

`CaptureMark1Async`가 다음 작업을 한다.

```text
새 이미지 촬영
→ align_left.png와 Template Matching
→ 기준 중심과 현재 중심의 Pixel 차이 계산
→ Pixel 차이를 Stage 단위 um로 변환
```

촬영 API가 실패해서 이전 이미지가 화면에 남아 있으면 그 이미지를 새 결과로 사용하지 않는다.

### 6.3 Align3 촬영

`CaptureMark3Async`가 `MoveStageXAsync`를 호출한다.

`MoveStageXAsync`가 Control에 보내는 축 명령은 다음 한 개뿐이다.

```text
Axis.StageX = Align3 StageX 절대 위치
```

`Axis.InspectionUnit2Y`, 즉 CamY2 이동 명령은 만들지 않는다.

StageX 도착을 확인한 다음 Align3을 촬영하고 `align_mark3.png`와 비교한다. 촬영이 끝나면 StageX만 Align1 위치로 되돌린다. Align3 촬영 또는 Matching이 실패해도 복귀를 시도한다.

---

## 7. 이미지 중심 좌표를 Stage 편차로 바꾸는 과정

Template Matching 결과는 Pixel 단위다.

```text
Pixel X 차이 = 현재 중심 X - 기준 중심 X
Pixel Y 차이 = 현재 중심 Y - 기준 중심 Y
```

`ToStageDelta`는 카메라 설정에 저장된 다음 값을 사용한다.

- Pixel 크기
- 이미지에서 Stage +X가 향하는 방향
- 이미지에서 Stage +Y가 향하는 방향

그래서 CAM2 영상에서 오른쪽이나 위쪽으로 보이는 차이를 실제 Stage 좌표의 X/Y 편차와 `um` 단위로 바꾼다.

---

## 8. 정상 상태의 Align1-Align3 기준선을 만드는 과정

Theta를 구하려면 정상 정렬 상태에서 Align1과 Align3을 연결한 선이 필요하다.

Align1의 Glass 좌표는 기존 Recipe Align1 좌표를 사용한다.

Align3은 별도 Glass 좌표를 입력하지 않는다. 다음 순서로 계산한다.

```text
CamY2 = Align1 CamY2 고정값
StageX = 입력한 Align3 StageX
        ↓ CAM2 affine calibration 역변환
Align3 Glass 좌표
        ↓ Glass Size의 PanelAngle 적용
Align3 Stage 계산 좌표
```

`BuildSetup`이 이 작업을 한다. 이렇게 만든 Align1과 Align3 좌표는 기존 Align 계산과 같은 Stage 좌표 방향을 사용한다.

```text
기준선 X = Align3 정상 X - Align1 정상 X
기준선 Y = Align3 정상 Y - Align1 정상 Y
```

기준선이 너무 짧으면 작은 영상 오차가 큰 각도로 계산될 수 있으므로 실행을 중단한다.

---

## 9. Theta를 계산하는 코드 설명

Theta 계산은 `AlignMarkPairThetaEstimator.Calculate`에서 한다.

### 9.1 두 Mark의 상대 편차 계산

먼저 Align3 영상 편차에서 Align1 영상 편차를 뺀다.

```text
편차 차이 X = Align3 영상 편차 X - Align1 영상 편차 X
편차 차이 Y = Align3 영상 편차 Y - Align1 영상 편차 Y
```

Glass가 X 또는 Y로 통째로 밀렸다면 Align1과 Align3에 비슷한 편차가 생긴다. 두 값을 빼면 이 공통 이동은 제거된다. 남는 값은 Align1-Align3 선의 기울기가 바뀐 양이다.

현재 측정선은 다음과 같이 만든다.

```text
현재선 X = 기준선 X + 편차 차이 X
현재선 Y = 기준선 Y + 편차 차이 Y
```

### 9.2 기존 선형 계산

`기존 계산 실행` 버튼은 작은 각도용 선형식을 사용한다.

```text
Theta radian
= (기준선 X × 편차 차이 Y - 기준선 Y × 편차 차이 X)
  ÷ 기준선 길이의 제곱
```

기존 Align 방식과 비교하기 위한 계산이다. 회전 오차가 작은 상태에서 사용하기 쉽다.

### 9.3 간단 atan2 계산

`간단 계산 실행` 버튼은 기준선과 현재선의 실제 사이각을 계산한다.

```text
cross = 기준선 X × 현재선 Y - 기준선 Y × 현재선 X
dot   = 기준선 X × 현재선 X + 기준선 Y × 현재선 Y

Theta radian = atan2(cross, dot)
```

`cross`의 부호가 회전 방향을 정한다. `dot`은 두 선이 같은 방향을 향하는 정도를 나타낸다.

마지막에 radian을 degree로 변환해 `ThetaDeg`로 반환한다.

## 10. Theta를 돌리고 맞추는 코드 설명

이 부분이 실제 자동 보정의 핵심이다. `AutoAlignViewModel.RunAsync`의 `while` 반복문에서 실행된다.

### 10.1 현재 Theta 측정

```csharp
AlignThetaMeasurement measurement = await MeasurePairAsync(setup, method);
```

`MeasurePairAsync`는 Align1 촬영, Align3 촬영, Theta 계산을 순서대로 실행한다.

### 10.2 이미 맞았는지 확인

```csharp
if (Math.Abs(measurement.ThetaDeg) <= ToleranceThetaDeg)
{
    완료 처리
}
```

Theta의 절댓값이 Recipe의 허용오차보다 작거나 같으면 UVW를 더 움직이지 않고 성공으로 끝낸다.

예를 들어 허용오차가 `0.005 deg`라면 다음과 같다.

- 측정값 `0.003 deg`: 완료
- 측정값 `-0.004 deg`: 완료
- 측정값 `0.010 deg`: UVW 보정 필요

### 10.3 Theta를 U, V, W 이동량으로 변환

아직 오차가 크면 Theta만 들어 있는 XYT 값을 만든다.

```csharp
new XytDelta(0.0, 0.0, measurement.ThetaDeg)
```

X와 Y가 `0.0`이므로 이 Auto Align은 평행이동을 보정하지 않고 회전만 보정한다.

`CenterPivotUvwConverter.ToUvw`가 Glass 중심 회전에 필요한 U, V, W 값을 계산한다.

```text
U = U축의 회전 계수 × Theta radian
V = V축의 회전 계수 × Theta radian
W = W축의 회전 계수 × Theta radian
```

실제 코드는 축마다 X 계수와 Y 계수도 지원하지만 여기서는 X와 Y가 0이라 회전 계수만 결과에 영향을 준다.

### 10.4 UVW 실제 이동

`MoveUvwAsync`는 다음 세 상대 이동 명령을 한 번에 보낸다.

```text
StageU = 계산된 U, 상대 이동
StageV = 계산된 V, 상대 이동
StageW = 계산된 W, 상대 이동
```

절대 위치로 보내는 것이 아니라 현재 위치에서 계산값만큼 움직이는 상대 이동이다.

### 10.5 다시 촬영하는 이유

UVW 기구 오차, 영상 Matching 오차, calibration 오차 때문에 계산한 각도를 한 번 움직여도 잔여 오차가 남을 수 있다.

그래서 UVW 이동이 끝나면 반복문의 처음으로 돌아간다.

```text
Theta 측정
→ 허용오차 밖
→ UVW 회전
→ Align1/Align3 재촬영
→ 남은 Theta 재계산
→ 허용오차 안이면 완료
```

이전보다 Theta가 1.5배 이상 커지면 회전 부호나 장비 동작이 잘못된 것으로 보고 발산 오류로 중단한다. 설정된 최대 보정 횟수 안에 들어오지 않아도 중단한다.

## 11. 기존 Align 실행과의 차이

| 구분 | 기존 AlignWindow | AutoAlignWindow TEST |
|---|---|---|
| 사용 Mark | Align1 + Align2 | Align1 + Align3 |
| 카메라 | CAM1 + CAM2 동시 사용 | CAM2 한 대 순차 사용 |
| Align3 촬영 이동 | 해당 없음 | StageX만 이동 |
| CamY2 | 기존 방식에 따라 사용 | Align1 위치에 고정 |
| 보정 | Theta 후 X/Y | Theta만 |
| UVW 변환 | CenterPivotUvwConverter | 같은 변환기 사용 |

Auto Align은 기존 전체 Align을 대체한 것이 아니다. 현재 TEST 범위는 Align1-Align3의 Theta 자동 보정까지다.

---

## 12. 실패 시 UVW를 움직이지 않는 조건

- CAM2 또는 Control이 연결되지 않음
- Align3 StageX가 입력되지 않음
- Align1 또는 Align3 기준 이미지가 없음
- Template ROI 또는 Search ROI가 없음
- 새 촬영 이미지가 없음
- Match Score가 기준보다 낮음
- Align1-Align3 기준선이 너무 짧음
- 측정된 두 Mark 사이 거리가 정상 기준과 크게 다름
- StageX가 목표 위치에 도착하지 않음
- StageX가 Align1 위치로 복귀하지 못함
- UVW 이동 응답 실패
- 보정 후 Theta가 커져 발산함
- 최대 보정 횟수 안에 수렴하지 않음

주요 단계는 `AutoAlignViewModel` 전용 Caller 로그에 남는다.

---

## 13. 현재 구현 범위와 다음 단계

현재 구현 범위:

- Align3 StageX 입력과 Glass Size Model 저장
- CamY2를 Align1 위치에 고정
- StageX만 사용한 Align1/Align3 순차 촬영
- 기존 선형식과 간단 atan2 식 제공
- Theta를 Glass 중심 UVW 이동량으로 변환
- UVW 이동 후 반복 측정
- 허용오차, 발산, 횟수 초과 확인
- 단계별 로그와 코드 주석

아직 구현하지 않은 다음 단계:

- Auto Align 성공 후 최종 U/V/W 절대 위치를 Align 위치로 등록
- X/Y 평행이동 자동 보정

---

## 14. 실장비에서 반드시 확인할 내용

1. 입력한 Align3 StageX가 안전 이동 범위인지 확인한다.
2. Align1 촬영 후 Align3 촬영까지 CamY2 실제 위치가 변하지 않는지 확인한다.
3. Align3 촬영 후 StageX가 Align1 위치로 복귀하는지 확인한다.
4. 작은 회전 오차에서 계산된 Theta 부호와 실제 UVW 회전 방향이 맞는지 확인한다.
5. 첫 UVW 보정 후 재측정 Theta가 작아지는지 확인한다.
6. 기존 선형식과 atan2 결과를 비교한다.

실장비 부호가 반대라면 반복 보정을 계속 실행하지 말고 즉시 중단한 뒤 카메라 방향 설정과 UVW 회전 계수를 확인해야 한다.
