# 시작 가이드

이 문서는 **서비스/테스트 엔지니어**가 현재 `uLedAoiConsole` / `uLedIp` 프로그램을 받아
기본 설정, 레시피 준비, 점등/측정 테스트, IP 이미지 준비, 검사 확인까지 진행할 수 있도록 정리한 시작 문서다.

중요:
- 이 문서는 최종 사용자용 매뉴얼이 아니다.
- 화면 캡처 중심의 사용자 매뉴얼은 별도로 다시 작성해야 한다.
- 이 문서는 **현재 구현된 메뉴와 버튼 이름 기준**으로 작성한다.
- 카메라 Exposure 조정은 `uLedAoiConsole`이 아니라 **외부 카메라 프로그램**을 사용한다는 운영 전제를 둔다.

우선 읽을 문서:
1. `docs/README.md`
2. `docs/기본설정.md`
3. `docs/프로젝트 구조.md`
4. `docs/전체 flow.md`
5. 이 문서

---

## 1. 이 문서의 목표

이 문서의 목표는 아래 4가지다.

1. 프로그램이 정상 실행되는지 확인
2. 새로운 제품 또는 새로운 글래스 조건에 맞게 레시피를 준비
3. PG 점등, CA-410 측정, IP 업로드까지 테스트 가능 상태로 만드는 것
4. IP에서 패턴별 이미지를 수동으로 적재하고 ROI/검사를 확인하는 것

---

## 2. 작업 전 전제

시작 전에 아래 전제를 먼저 이해해야 한다.

### 2.1 Glass Model의 의미

이 문서에서 말하는 `Glass Model`은 별도 독립 창 이름이 아니라,
`Recipe Editor > General` 탭에서 설정하는 글래스 관련 실행 기준을 의미한다.

여기에는 아래 의미가 포함된다.

- 사용할 `GlassSizeId`
- 글래스 크기
- 패널 회전
- Align 기준이 되는 글래스 모델

### 2.2 Align mark 기준

- Align mark의 glass 기준 좌표와 affine calibration 데이터는 `Glass Size Model`에서 관리한다.
- 같은 글래스라면 같은 Align mark 위치를 쓴다고 가정한다.
- 따라서 새로운 글래스가 들어오면 먼저 `Glass Size Model`을 준비해야 한다.
- 특정 레시피에서만 mark 위치가 달라질 수 있으면 `Recipe > Align / Control`에서 override를 사용한다.

### 2.3 Point의 현재 운영 의미

현재 운영 기준에서:

- 카메라의 절대 이동 위치는 `Cell` 정보로 해석한다.
- `Point`는 현재 사실상 **단일 ROI 설정**으로 사용한다.
- 다중 point 구조는 모델에는 남아 있지만, 현재 UI/운영 가이드는 단일 ROI 기준이다.

즉, 이 문서에서는 `Point = ROI/검사 위치 설정`으로 이해하면 된다.

### 2.4 Exposure 설정 방식

현재 기준에서는 Exposure를 `uLedAoiConsole`이나 `uLedIp`에서 직접 잡지 않는다.

운영 순서는 아래와 같다.

1. 외부 카메라 전용 프로그램으로 Live 확인
2. Exposure를 먼저 확정
3. 이후 `uLedAoiConsole`에서 레시피와 검사 조건을 맞춤
4. 마지막에 `uLedIp`에서 패턴별 이미지를 수동으로 적재

이 전제를 두지 않으면 Console/IP 쪽에 카메라 관리 기능이 과도하게 추가되어야 한다.

## 3. 프로그램 시작 후 확인할 메뉴

프로그램을 실행하면 `MainWindow`가 열린다.

현재 구현 기준으로:

- 프로그램 시작 시 마지막 레시피를 자동으로 다시 연다.
- 메인 창 로드가 끝난 뒤 연결된 IP가 있으면 현재 레시피를 자동 업로드한다.
- 필요하면 메인 창에서 `Tool > Load Recipe...`로 다른 레시피를 열 수 있다.

상단 메뉴에서 실제로 자주 사용하는 항목은 아래다.

### Tool 메뉴

- `Tool > Load Recipe...`
- `Tool > Config`
- `Tool > Glass Size Model`
- `Tool > Recipe`

### Test 메뉴

- `Test > EEC-P725R2 PG Test`
- `Test > CA-410 Test`
- `Test > Flow Test`

권장 시작 순서:

1. `Tool > Load Recipe...`
2. `Tool > Config`
3. `Tool > Glass Size Model`
4. `Tool > Recipe`
5. `Test > EEC-P725R2 PG Test`
6. `Test > CA-410 Test`

새 제품 또는 새로운 글래스 조건을 테스트할 때 권장 순서는 아래와 같다.

1. Config 확인
2. Glass Size 준비
3. 새 Recipe 생성
4. Recipe General 설정
5. Glass Map / Cells 준비
6. Align 기준 등록
7. 점등 위치 확인
8. Pattern 등록
9. 외부 카메라 프로그램에서 Exposure 확정
10. PG 점등 테스트
11. CA-410 측정 테스트
12. IP 연결 및 Recipe 업로드
13. IP에서 Pattern별 이미지 로드
14. ROI 조정 및 검사 확인

기존 레시피를 이어서 테스트할 때는 아래처럼 시작하면 된다.

1. 프로그램 실행
2. 마지막 레시피 자동 복원 여부 확인
3. 필요하면 `Tool > Load Recipe...`로 다른 레시피 로드
4. 연결된 IP가 있으면 현재 레시피 자동 업로드 여부 확인
5. 이후 PG / CA-410 / IP 이미지 작업 진행

아래부터 각 단계를 실제 메뉴/버튼 기준으로 설명한다.

## 6. Glass Size 준비

메인 화면에서 `Tool > Glass Size Model`을 연다.

이 창에서 실제로 사용하는 버튼:

- `Add`
- `Remove`
- `Load`
- `Save`
- `Save As...`

### 6.1 새 Glass Size를 만드는 순서

1. `Add`를 눌러 새 항목을 만든다.
2. 아래 항목을 입력한다.
   - `GlassSizeId`
   - `Name`
   - `GlassWidth(um)`
   - `GlassHeight(um)`
   - `PanelAngle(deg)`
3. 방향이 맞는지 확인한다.
   - `X+ Right`
   - `Y+ Down`
4. Align 기준 좌표를 입력한다.
   - `Left Align X(um)`
   - `Left Align Y(um)`
   - `Right Align X(um)`
   - `Right Align Y(um)`
5. 실제 장비를 `Left Align` 위치로 이동시킨다.
   - 좌측 Align 카메라가 `Left Align` mark 중심을 보도록 맞춘다.
   - 이때의 실제 축값 `InspectionUnit2Y`, `StageX`를 읽는다.
6. `Left Align Camera Calibration`의 `P1`에 아래 값을 입력한다.
   - `GlassX(um)` = `Left Align X(um)`
   - `GlassY(um)` = `Left Align Y(um)`
   - `InspectionUnit2Y` = 현재 좌측 검사 유닛 Y 축값
   - `StageX` = 현재 Stage X 축값
7. `Left Align Camera Calibration` 헤더의 `1행 기준 2/3행 계산` 버튼을 누른다.
   - `P2`는 `P1`에서 Glass X 방향 `+1000um`
   - `P3`는 `P1`에서 Glass Y 방향 `+1000um`
   - 축 해상도 `1um : 1um` 가정과 `PanelAngle(deg)`를 사용해 `InspectionUnit2Y`, `StageX`가 자동 계산된다.
8. 필요하면 자동 계산된 `P2`, `P3` 값을 실제 장비 기준에 맞게 수동 보정한다.
9. 실제 장비를 `Right Align` 위치로 이동시킨다.
   - 우측 Align 카메라가 `Right Align` mark 중심을 보도록 맞춘다.
   - 이때의 실제 축값 `InspectionUnit1Y`, `StageX`를 읽는다.
10. `Right Align Camera Reference`의 `R1`에 아래 값을 입력한다.
   - `GlassX(um)` = `Right Align X(um)`
   - `GlassY(um)` = `Right Align Y(um)`
   - `InspectionUnit1Y` = 현재 우측 검사 유닛 Y 축값
   - `StageX` = 현재 Stage X 축값
11. `Save` 또는 `Save As...`로 저장한다.

### 6.2 Affine Calibration 입력 시 확인할 항목

- `Glass X(um)`
- `Glass Y(um)`
- `Axis X`
- `Axis Y`

의도:
- 같은 글래스면 같은 Glass 기준과 축 변환 기준을 계속 재사용할 수 있게 한다.

### 6.3 권장 입력 방법

가장 단순한 작업 순서는 아래와 같다.

1. `P1`은 반드시 실측값으로 넣는다.
   - 좌측 Align 카메라를 실제 mark 중심에 맞춘 상태의 `InspectionUnit2Y`, `StageX`를 사용한다.
2. `P2`, `P3`는 우선 자동 계산으로 만든다.
   - 대부분 장비는 X, Y 축 해상도가 사실상 `1um` 기준이므로 초기값으로 충분하다.
3. 실제 구동 결과를 보고 필요하면 `P2`, `P3`만 미세 수정한다.
4. `R1`은 우측 Align 카메라 실측값으로 넣는다.

이 방식의 장점:

- 3점을 전부 실측하지 않아도 초기 affine를 빠르게 만들 수 있다.
- `PanelAngle`이 0도가 아니어도 바로 반영할 수 있다.
- 좌측 기구 기준과 우측 기준점을 분리해서 관리할 수 있다.

### 6.4 자동 계산 버튼의 의미

`Left Align Camera Calibration` 헤더의 `1행 기준 2/3행 계산` 버튼은 아래 식으로 동작한다.

- `P2 = P1 + Glass X 방향 1000um`
- `P3 = P1 + Glass Y 방향 1000um`
- `PanelAngle(deg)` 만큼 회전된 축 변화량을 사용한다.
- `InspectionUnit2Y`, `StageX` 축은 `1um : 1um` 배율로 계산한다.

즉 `P1`만 정확히 실측해 두면, 장비 기구가 정상이라는 전제에서 `P2`, `P3`의 초기값을 빠르게 만들 수 있다.

### 6.5 입력 후 확인할 항목

저장 전에 아래를 확인한다.

1. `P1`의 Glass 좌표가 `Left Align X/Y`와 같은지
2. `R1`의 Glass 좌표가 `Right Align X/Y`와 같은지
3. `P2`, `P3`가 `P1`과 같은 점이 아닌지
4. `P1`, `P2`, `P3`가 일직선이 아닌지
5. 좌측 Left Align은 `InspectionUnit2Y`, 우측 Right Align는 `InspectionUnit1Y`만 입력되어 있는지
6. `StageX` 값이 두 카메라 기준에서 같은 방향 해석으로 들어갔는지

## 7. 새 Recipe 생성

메인 화면에서 `Tool > Recipe`를 열고 `Recipe Editor`를 연다.

새 레시피를 시작할 때는 상단 `File > New` 또는 왼쪽 Workspace의 `New` 버튼을 사용한다.

### 7.1 기본 순서

1. `New`를 누른다.
2. `Glass Size Model Selection` 창이 열리면 사용할 모델을 선택한다.
3. `Select`를 누른다.
4. 프로그램이 새 `Recipe Id`를 자동 생성하고 새 편집 문서를 연다.
5. 이후 `General` 탭부터 나머지 항목을 입력한다.

중요:
- 새 레시피의 시작점은 반드시 `Glass Size Model` 선택이다.
- Align 기준과 셀 전개 기준은 이 단계에서 선택한 모델을 따른다.
- `New` 직후의 `Save`는 `Save As...`처럼 동작한다.

## 8. Recipe General 설정

메인 화면에서 `Tool > Recipe`를 열고, `General` 탭으로 이동한다.

여기서 실제로 먼저 확인/입력할 항목:

- `Recipe Id`
- `Recipe Name`
- `Recipe Version`
- `Glass Size Id`
- `Display Pixel Width Count`
- `Display Pixel Height Count`
- `Display Pixel Width (um)`
- `Display Pixel Height (um)`

### 8.1 권장 절차

1. `Recipe Id`, `Recipe Name`, `Recipe Version`을 입력한다.
2. `Glass Size Id`가 선택한 모델과 맞는지 확인한다.
3. `Display Pixel Width Count`, `Display Pixel Height Count`를 입력한다.
4. `Display Pixel Width (um)`, `Display Pixel Height (um)`를 입력한다.
5. `Validate`를 한 번 눌러 기본 오류가 없는지 본다.

주의:
- 이 단계의 `Display Pixel Count / Pixel Size`는 Glass Size 자체가 아니라 Recipe/IP 실행 조건이다.

## 9. Glass Map / Cells 준비

같은 `Recipe Editor` 창에서 `Cells` 탭과 `Cell Map` 탭을 사용한다.

### 9.1 Cells 탭에서 자주 쓰는 버튼

- `Add Cell`
- `Remove Cell`
- `Use All`
- `Auto Assign IP`
- `Apply Split`
- `Move Selected IP To Cell`

확인할 항목:

- `CellId`
- `Name`
- `Use`
- `IpNo`
- `Line`
- `Column`
- `X`, `Y`, `Width`, `Height`

### 9.2 기본 순서

1. 현재 글래스 기준으로 셀 구성이 맞는지 확인한다.
2. 필요하면 셀을 추가/삭제한다.
3. `Use All`로 사용 셀 상태를 정리한다.
4. `Auto Assign IP` 또는 `Split Column + Apply Split`으로 IP 분배를 적용한다.
5. `Cell Map` 탭에서 미리보기 결과를 확인한다.

중요:
- 현재 운영 기준에서 카메라 절대 위치는 Cell 기준으로 본다.
- 따라서 셀 배치가 잘못되면 이후 검사 위치 전체가 어긋난다.

## 10. Align 기준 등록

`Recipe Editor > Align / Control` 탭으로 이동한다.

### 10.1 Align 영역에서 사용하는 항목

- `Enabled`
- `MaxIteration`
- `Tolerance X / Y / T`
- `Template Files`
- `Left Override X / Y`
- `Right Override X / Y`
- `Apply Current To Align`
- `Open Action Window`

### 10.2 작업 순서

1. 장비를 Align 가능한 상태로 만든다.
2. `Open Action Window`로 현재 축 상태를 보거나 장비를 이동한다.
3. 양쪽 Align 카메라가 각 mark 중심을 보도록 위치를 맞춘다.
4. 필요하면 `Template Files`에 좌/우 템플릿 파일명을 입력한다.
5. 특정 레시피에서만 mark 위치를 바꿔야 하면 `Left/Right Override X / Y`를 입력한다.
6. `Apply Current To Align`을 눌러 현재 기준을 반영한다.

의도:
- 같은 글래스라면 mark 위치는 Glass Size 기준을 재사용하고,
  현재 장비 기준의 Align 위치만 등록한다.

## 11. 점등 위치 확인

점등 자체는 주로 PG와 장비 위치 확인 단계로 본다.

현재 구조상 점등/컨택 관련 기준은 `Recipe Editor > Align / Control`의
`Control` 영역에서 관리한다.

사용하는 항목:

- `Forbid Y Move While Contact`
- `Inspect Profile`
- `Align / Contact Profile`
- `Apply Current To Contact`
- `Open Action Window`

### 11.1 작업 순서

1. 첫 번째 카메라를 기준 셀 위치로 보낸다.
2. 실제 점등 위치에서 `StageX`, 검사 유닛 Z, 카메라 Z, `ContactorZ` 등 필요한 축을 조정한다.
3. 위치가 맞으면 `Apply Current To Contact`를 눌러 현재 위치를 반영한다.

주의:
- 현재 문서 기준에서 이 단계는 장비 접촉/점등 기준을 잡는 단계다.
- 검사 ROI를 잡는 단계와는 분리해서 이해한다.

## 12. Pattern 등록

`Recipe Editor > Patterns` 탭으로 이동한다.

사용하는 버튼:

- `Add Pattern`
- `Remove Pattern`
- `Open Pattern Table`

주요 입력 항목:

- `Index`
- `Name`
- `Type`
- `PG Pattern Index`
- `TimeoutMs`
- `ExposureUs`
- `Gain`
- `Threshold`
- `MinArea`
- `MaxArea`
- `Metric`
- `Normal %`
- `A %`
- `B %`
- `C %`
- `D %`
- `Defect Cutoff`

### 12.1 기본 순서

1. `Add Pattern`으로 필요한 패턴 수만큼 추가한다.
2. `Index`를 입력한다.
   - 현재 운영 기준에서 0-based 사용을 권장한다.
3. `Name`을 입력한다.
4. PG에 대응되는 `PG Pattern Index`를 입력한다.
5. 초기 검사 조건을 입력한다.
   - `Threshold`
   - `MinArea`
   - `MaxArea`
   - `Metric`
6. 외부 카메라 프로그램에서 결정한 Exposure 값을 나중에 `ExposureUs`에 반영한다.

보조 기능:
- `Open Pattern Table`을 누르면 전체 패턴 설정을 표 형태로 한 번에 검토/편집할 수 있다.

## 13. Exposure 설정

Exposure는 `uLedAoiConsole`이 아니라 **외부 카메라 전용 프로그램**에서 먼저 맞춘다.

권장 순서:

1. 외부 카메라 프로그램에서 Live를 본다.
2. 원하는 패턴과 셀 조건에서 Exposure를 조정한다.
3. 값이 확정되면 `Recipe Editor > Patterns`의 `ExposureUs`에 반영한다.

이 방식을 쓰는 이유:

- Console/IP에 카메라 관리 기능을 과도하게 넣지 않기 위해
- 현재 테스트 단계에서 카메라 튜닝을 외부 툴로 분리하기 위해

## 16. IP 연결 및 Recipe 업로드

레시피 선택과 현재 레시피 전환은 **메인 창 기준**으로 본다.

즉 아래 두 경로를 같이 이해해야 한다.

- 메인 창: `Tool > Load Recipe...`
- `Recipe Editor`: `IP > Connect`, `IP > Refresh Status`, `IP > Upload Recipe`

기존 레시피를 불러올 때는 보통 먼저 메인 창에서 `Tool > Load Recipe...`를 사용한다.
새 레시피를 편집 중이면 `Tool > Recipe`의 `Recipe Editor` 창에서 계속 작업한다.

상단 메뉴 `IP`에서 사용하는 항목:

- `Connect`
- `Refresh Status`
- `Upload Recipe`

### 16.1 권장 순서

1. 메인 창에서 현재 사용할 레시피를 확인한다.
   - 필요하면 `Tool > Load Recipe...`
2. `Tool > Recipe`의 `Recipe Editor`를 연다.
3. `IP > Connect`
4. `IP > Refresh Status`
5. `Validate`
6. 필요하면 `IP > Upload Recipe`
7. 업로드 후 IP 쪽 현재 레시피가 바뀌었는지 확인한다.

현재 구현 기준 추가 동작:

- 프로그램 시작 후 메인 창이 준비되면, 연결된 IP가 있으면 현재 레시피를 자동 업로드한다.
- 메인 창에서 `Tool > Load Recipe...`로 레시피를 바꾸면 현재 레시피가 바뀌고, 연결된 IP가 있으면 자동 업로드한다.
- IP가 나중에 연결되면 연결 직후 현재 레시피를 자동 업로드한다.

즉 수동 `Upload Recipe`는 강제 재전송이나 확인용으로 이해하면 된다.

확인할 항목:

- 업로드 오류가 없는지
- 레시피 ID / Version이 맞는지
- Pattern 목록이 현재 레시피와 맞는지

## 17. IP에서 Pattern 이미지 세트 관리

이 단계는 **현재 레시피의 Pattern 이미지 세트**를 준비하는 단계다.

즉, 레시피를 업로드한 뒤 IP에서 현재 레시피 기준의 pattern 이미지 세트를 읽고,
필요하면 현재 선택 패턴 이미지를 단일 파일로 교체하거나 저장한다.

이 작업은 `uLedIp` 창에서 진행한다.

사용하는 위치:

- `File > Load Folder...`
- `File > Save Folder...`
- `File > Import...`
- `File > Export...`
- 좌측 `Pattern Images` 영역

확인할 항목:

- `Current Folder`
- `Pattern`
- `Pattern Image Status`

### 17.1 작업 순서

1. 현재 레시피가 IP에 올라가 있는지 확인한다.
2. `File > Load Folder...`로 pattern 이미지 세트가 들어 있는 폴더를 연다.
3. 현재 폴더의 이미지가 현재 레시피 패턴 범위 안에서 사용 가능한 상태인지 확인한다.
4. 특정 패턴 이미지를 교체하려면 좌측 `Pattern` 선택 상태를 맞춘다.
5. `File > Import...`를 눌러 현재 선택 패턴의 이미지를 단일 파일로 교체하거나 새로 넣는다.
6. 개별 이미지를 파일로 내보내려면 `File > Export...`를 사용한다.
7. 현재 메모리 상태를 레시피 기준 이름으로 저장하려면 `File > Save Folder...`를 사용한다.

주의:

- `Load Folder...`는 현재 레시피의 pattern 개수 범위 안에서만 이미지를 사용한다.
- 레시피 범위를 벗어나는 이미지는 내부에 남아 있어도 화면/검사/저장 대상에서 제외한다.
- `Import...`와 `Export...`는 현재 선택 패턴 1개에 대한 단일 파일 동작이다.

### 17.2 저장 규칙

- `Import...`는 단일 파일 동작이다.
  - 파일명 규칙을 강제하지 않는다.
- `Export...`는 단일 파일 동작이다.
  - 저장 창에서 기본 파일명으로 아래 규칙을 제안한다.
- `Save Folder...`는 세트 단위 동작이다.
  - 저장 파일명은 아래 규칙을 따른다.
  - `{PatternIndex}_{PointIndex}_{PatternName}.png`
  - 실제 확장자는 선택한 원본 이미지 확장자를 유지한다.
- 같은 `PatternIndex + PointIndex` 조합의 기존 이미지가 있으면 새 이미지로 교체한다.

### 17.3 스크립트 파일 저장

`Save Folder...`를 사용할 때는 같은 폴더에 별도 스크립트 파일도 같이 저장된다.

- 파일명: `{이미지파일명}.script.yaml`

포함 내용:

- `recipe_id`
- `recipe_version`
- `pattern_index`
- `pattern_name`
- `point_index`
- `exposure_us`
- `gain`
- `timeout_ms`
- `threshold`
- `min_area`
- `max_area`
- `metric`
- `roi`
- `source_image`
- `saved_at`

의도:
- 어떤 조건으로 이미지를 저장했는지 나중에 다시 추적할 수 있게 한다.

## 18. ROI 조정 및 검사 확인

현재 운영 기준에서 `Point`는 단일 ROI 편집 대상으로 본다.

ROI 편집 위치:

- `Recipe Editor > Patterns`
- 우측 `Inspection ROI` 영역
- `Recipe Image / ROI` 창

사용하는 항목:

- `ROI X / Y`
- `ROI W / H`
- `Apply Current Position`
- `Open Image Window`
- `ROI > Draw ROI`
- `ROI > Select ROI`
- `ROI > Stop Draw`
- `Profiles`

IP 검사 항목:

- `IP > Inspect Selected Point`
- `IP > Grab Selected Point`
- `IP > Inspect Panel`
- `IP > Clear Defect`

### 18.1 권장 순서

1. IP에 패턴별 이미지를 먼저 로드한다.
2. `Recipe Editor > Patterns`에서 `Open Image Window`를 연다.
3. `Recipe Image / ROI` 창에서 `IP > Preview Image` 또는 `IP > Original Image`로 실제 이미지를 확인한다.
4. `ROI > Draw ROI`로 ROI를 그리거나, `ROI > Select ROI`로 기존 ROI를 다시 선택한다.
5. ROI를 그리거나 수정하면 현재 레시피 ROI에 즉시 반영된다.
6. 필요하면 `Recipe Editor > Patterns`의 `Inspection ROI` 숫자값을 직접 수정한다.
7. 수정 후 `Validate`를 수행한다.
8. 필요하면 `IP > Upload Recipe`로 현재 레시피를 다시 전송한다.
9. `IP > Inspect Selected Point` 또는 `IP > Inspect Panel`로 검사 결과를 확인한다.

주의:

- 현재 UI에서는 `Point`라는 다중 개념보다 `단일 ROI` 개념으로 이해하는 것이 맞다.
- 카메라 절대 위치는 `Cell` 기준으로 해석한다.
- ROI는 실제 이미지를 본 뒤 조정하는 것이 순서상 자연스럽다.
- `Recipe Image / ROI` 창의 `Profiles` 메뉴에서 `Profile`, `XProjection`, `YProjection`, `Histogram`을 사용할 수 있다.

## 19. 권장 검증 순서

서비스/테스트 엔지니어 기준으로는 아래 순서로 검증하는 것이 가장 안전하다.

1. `Config` 확인
2. `Glass Size Model`에서 Glass Size 준비
3. `Recipe`에서 `New`로 새 레시피 생성
4. `Recipe > General`에서 Glass Model/Recipe 기본값 입력
5. `Recipe > Cells`에서 셀 확인 및 IP 분배
6. `Recipe > Align / Control`에서 Align/Contact 기준 등록
7. `Recipe > Patterns`에서 Pattern 등록
8. 외부 카메라 프로그램에서 Exposure 확정
9. `Test > EEC-P725R2 PG Test`로 점등 확인
10. `Test > CA-410 Test`로 측정 확인
11. `Recipe`에서 `Validate`
12. 현재 레시피가 IP에 자동 업로드되었는지 확인하고, 필요하면 `IP > Upload Recipe`
13. IP에서 패턴별 이미지 수동 로드
14. `Recipe > Patterns > Inspection ROI`에서 ROI 조정
15. 필요하면 `IP > Upload Recipe`
16. `Inspect Selected Point`로 검사 확인
