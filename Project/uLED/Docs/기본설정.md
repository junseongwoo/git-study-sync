# 기본설정

이 문서는 현재 저장소의 실제 구현 기준으로 Console 실행에 필요한 기본 설정과 데이터 위치를 정리한다.

우선 확인 순서:
1. `docs/README.md`
2. `docs/프로젝트 구조.md`
3. `docs/전체 flow.md`
4. 이 문서
5. `docs/시작 가이드.md`

## 1. 기본 실행 기준

- 솔루션 진입점: `uLedAoiConsole.sln`
- 기본 실행 프로젝트: `uLedAoiConsole`
- 앱 시작 창: `uLedAoiConsole/Windows/Core/MainWindow.xaml`
- 작업 기준 경로: `Vars.WorkDir`
- 주요 저장 경로는 모두 `Vars.WorkDir` 아래 `Config`, `Data`, `logs`를 사용한다.

## 2. 앱 시작 시 자동 준비되는 항목

`uLedAoiConsole/App.xaml.cs` 기준:

- 설정 저장소 초기화
  - `Config/config.yaml`
  - `Variables.yaml`
- Glass Map Design 저장소 초기화
  - `Data/GlassMaps/glass_map_design.json`
- GlassSize 라이브러리 초기화
  - `Data/glass_size.json`
- IP 런타임 레지스트리 초기화
  - `Vars.EMRConfig.IpEndpoints` 기준
- 기본 Recipe 스토어 초기화
  - `Data/Recipes/Default/Default/recipe.json`
  - 파일이 없으면 기본 `ConsoleRecipeDocument`를 생성

중요:
- 현재 Console은 시작 시 특정 레시피 선택 UI를 띄우지 않는다.
- 기본적으로 `Default` 레시피를 열고, 이후 `Recipe` 창에서 수정/저장하는 흐름이다.

## 3. 설정/데이터 폴더

### 3.1 Config

- `Config/config.yaml`
  - 장비 공통 설정
  - `Vars.EMRConfig`
- `Variables.yaml`
  - 가변 런타임 설정

### 3.2 Data

- `Data/GlassMaps/glass_map_design.json`
  - 셀 배치 설계 원본
- `Data/GlassSizes/{glassSizeId}.json`
  - GlassSize 정의
- `Data/Recipes/{glassSizeId}/{recipeId}/recipe.json`
  - 현재 Console 레시피 저장 포맷
- `Data/Calibrations/{glassSizeId}/axis_hardware.json`
  - 축 하드웨어 상수
- `Data/Runtime/align_result.json`
  - 런타임 Align 결과 저장 위치

### 3.3 로그

- `logs/app_yyyyMMdd.log`
- UI 로그는 `LogViewer`로 표시

로그 구현 기준은 `docs/logging-system.md`와 `dist-lib/docs/logging-system.md`를 따른다.

## 4. GlassSize 기본 규칙

현재 GlassSize 모델은 `uLedAoiConsole/Models/GlassSizeConfigModels.cs` 기준이다.

핵심 필드:
- `GlassSizeId`
- `Name`
- `GlassWidthUm`
- `GlassHeightUm`
- `PanelAngleDeg`
- `AxisDirection`
- `AlignMarks`
  - `Left AlignUm`
  - `Right AlignUm`
- `LeftAlignCameraCalibration`
- `RightAlignCameraReference`

의미:
- GlassSize는 단순 크기만이 아니라, 패널 회전 방향과 Align 마크 기준까지 포함하는 실행 기준 데이터다.
- Recipe는 `GlassSizeId`와 `GlassSizeSnapshot`을 함께 가진다.
- 현재 Console 화면 회전은 `PanelAngleDeg` 영향을 받는다.
- 셀 `XIndex/YIndex`와 IP 셀 분배는 `PanelAngleDeg`가 아니라 물리 이동 좌표 기준으로 계산한다.
- `XIndex/YIndex`는 GlassMap 이름 고정값이 아니라 Unit1 기준 축 target으로 재계산되는 0-base 실행 index다. 단, 축값 자체로 grouping하지 않고 Cell map 내부 관리 X/Y index를 기준으로 먼저 묶는다. StageX target은 실제 `XIndex` 축 선택과 group 순서 결정에 사용하고, InspectionUnit1Y target은 `YIndex` group 순서 결정에 사용한다.

## 5. Recipe 기본 규칙

현재 Console 레시피는 `uLedAoiConsole/Recipes/ConsoleRecipeDocument.cs` 기준이다.

핵심 구조:
- `IpRecipe`
  - `uLed.Contracts.Models.RecipeModel`
- `GlassMap`
  - `GlassSizeId`
  - `GlassSizeSnapshot`
  - `IpSplitColumn`
  - `GlassMapDesignSnapshot`
  - `Cells`
- `AlignPlan`
- `ControlPlan`

중요:
- 현재 기준의 IP 실행 단위는 `Pattern x Point`다.
- `Point`는 `Pattern`에 종속되지 않는다.
- `Cells`는 Console 실행용 셀 리스트이며, `GlassMapDesignSnapshot`에서 재생성할 수 있다.

## 6. 처음 실행 전에 반드시 확인할 항목

### 6.1 Config

- `Vars.WorkDir`가 올바른 작업 폴더를 가리키는지
- `Config/config.yaml`에 장비/통신 기본값이 맞는지
- IP endpoint가 실제 장비 또는 테스트 장비 주소와 맞는지

### 6.2 GlassSize

- 사용할 `GlassSizeId`가 존재하는지
- `GlassWidthUm`, `GlassHeightUm`가 실제 패널 규격과 맞는지
- `PanelAngleDeg`가 현재 투입 방향과 맞는지
- `Left AlignUm`, `Right AlignUm`가 실제 마크 기준과 맞는지
- `LeftAlignCameraCalibration` 3점과 `RightAlignCameraReference` 1점이 올바르게 입력됐는지

### 6.3 Recipe

- `Document.IpRecipe.Descriptor.RecipeId`
- `Document.GlassMap.GlassSizeId`
- `Document.IpRecipe.Patterns`
- `Document.IpRecipe.Points`
- `Document.GlassMap.Cells`

### 6.4 Control 규칙

- `Document.ControlPlan.ForbidStageXMoveWhileContact = true` 유지 여부
- Align/Inspect/Contact profile 이름이 실제 보정 데이터 체계와 맞는지

## 7. 현재 구현에서 특히 중요한 레시피 항목

처음 프로그램을 올렸을 때 실수하기 쉬운 항목은 아래다.

### 필수 확인

- `GlassMap.GlassSizeId`
  - 잘못되면 셀 좌표, 회전, Align 기준이 모두 어긋난다.
- `GlassMap.GlassSizeSnapshot`
  - 외부 파일이 바뀌어도 현재 레시피 안에 저장된 스냅샷이 실제 실행 기준이 될 수 있다.
- `GlassMap.Cells`
  - 셀 개수, line/column, IP 분배 상태를 직접 확인해야 한다.
- `GlassMap.IpSplitColumn`
  - Auto Assign 후에도 결과가 의도와 맞는지 확인이 필요하다.
- `IpRecipe.Patterns`
  - `RequiredPgState`, `ExposureUs`, `Threshold`를 먼저 확인한다.
- `IpRecipe.Points`
  - `StageX`, `StageY`, `FocusZ`, `ROI`가 실제 촬영 기준과 맞아야 한다.
- `AlignPlan.Left/Right Override`
  - 값이 없으면 GlassSize의 기본 Align 위치를 사용한다.
  - 값이 있으면 현재 레시피의 Align 위치를 우선한다.

### 운영 규칙

- Contact 중에는 Y 이동 금지
- Point ROI 크기는 0보다 커야 함
- PatternIndex, PointIndex 중복 금지
- GlassSize가 바뀌면 Cells를 다시 검토해야 함

## 8. 현재 구현과 맞지 않는 과거 해석

아래 해석은 현재 기준 문서에서 제외한다.

- Console authoring의 `Shot -> Pattern -> ROI`를 상위 기준으로 보는 해석
- `RecipeModel`을 Console 전체 레시피로 보는 해석
- 회전/셀 분배를 Glass Map만으로 설명하는 해석

현재 기준은 아래다.

- Console 상위 레시피: `ConsoleRecipeDocument`
- IP 실행 레시피: `RecipeModel`
- 실행 단위: `Pattern x Point`
- 셀/라인/분배/Align/Control 규칙: Console 소유
