# 좌표계 관리 가이드

## 1. 목적
이 문서는 uLedAoiConsole에서 사용하는 좌표계를 통일하고, 셀/카메라/검사 결과 좌표를 일관되게 관리하기 위한 기준을 정의한다.

핵심 원칙:
- 레시피 셀 좌표는 반드시 **Glass 중심 좌표계(um)** 로 저장한다.
- 런타임 정렬(회전/이동)은 레시피가 아닌 런타임 데이터로 분리한다.
- IP 이미지 좌표는 원본을 유지하고, 변환 결과를 별도 필드로 보관한다.

---

## 2. 좌표계 계층

주의:
- `SMDCoordInfo` 계열 입력값(`OFFSET_E_*`, `CELL_DIST_*`, `BLOCK_DIST_*`)은 설계 파라미터이며, 글래스 좌상단 기준 `+X` 오른쪽, `+Y` 아래 방향을 사용한다.
- Recipe 저장 좌표(`CellRectGlassUm`)는 별도로 Glass 중심 기준 `+X` 오른쪽, `+Y` 위 방향을 사용한다.

### 2.1 Glass 좌표계 (기준 좌표계)
- 이름: `GlassCS`
- 원점: 글래스 중심 `(0, 0)`
- 단위: `um`
- 방향: `+X` 오른쪽, `+Y` 위
- 용도: 레시피 셀 저장, 장비/검사 공통 기준

### 2.2 Cell 로컬 좌표계
- 이름: `CellLocalCS`
- 원점: 셀 내부 기준점(아래 5장 참조)
- 단위: `um` (권장)
- 용도: 셀 내부 결함 위치, 셀 기반 마스크/판정

### 2.3 카메라 이미지 좌표계
- 이름: `ImagePxCS`
- 원점: 이미지 좌상단 `(0,0)`
- 단위: `px`
- 용도: IP가 전달하는 ROI/결함 좌표

### 2.4 ROI 좌표계
- 이름: `RoiPxCS`
- 원점: ROI 좌상단 `(0,0)`
- 단위: `px`
- 용도: IP에서 주로 전달되는 결함 좌표 규약

### 2.5 인덱스 좌표계 (Gate/Active)
- 이름: `GlassIndexCS`
- 좌표: `(gate, active)`
- 단위: line index
- 용도: 공정/분석 기준 위치 표현

### 2.6 장비 축 좌표계
- 이름: `AxisCS`
- 좌표: `X1/X2/Y/A1/A2/...`
- 단위: 장비 축 단위(um 또는 pulse)
- 용도: 실제 모션 제어

---

## 3. 저장 규칙

### 3.1 Recipe 저장
- `RecipeCell.CellRectGlassUm`에 저장 (Glass 중심 기준)
- `CellRectGlassUm.X/Y`는 셀의 `top-left` 기준을 사용한다.
- 기존 코너 기준 좌표는 레시피 저장 기준으로 사용하지 않는다.

관련 코드:
- `uLedAoiConsole/Recipes/RecipeModels.cs`
- `RecipeCell.CellRectGlassUm`

### 3.2 런타임 저장
- 정렬 결과(`theta, tx, ty`)는 Run/Lot 또는 Runtime 파일에 저장
- 레시피 자체는 정렬값을 포함하지 않는다.

### 3.3 검사 결과 저장
아래 3종을 함께 저장하는 것을 권장:
1. 원본 좌표: `RoiPxCS` 또는 `ImagePxCS`
2. 변환 좌표: `GlassCS`, `CellLocalCS`
3. 공정 좌표: `GlassIndexCS(gate/active)`

---

## 4. 변환 체인(표준)
권장 변환 순서:

1. `RoiPxCS -> ImagePxCS`
2. `ImagePxCS -> GlassCS(비정렬)`
3. `GlassCS(비정렬) -> GlassCS(정렬)` (Align 변환 적용)
4. `GlassCS(정렬) -> CellLocalCS`
5. `GlassCS(정렬) -> GlassIndexCS`

주의:
- 변환 체인 중간 결과를 로그에 남겨야 디버깅이 가능하다.
- 최소한 원본 좌표와 최종 좌표는 항상 같이 보관한다.

---

## 5. Cell 원점 설정 가이드

셀 원점은 반드시 문서/코드/설정에서 동일해야 한다. 프로젝트 전체에서 하나를 표준으로 고정한다.

권장 선택지:
- `TopLeft`: 영상 처리와 직관적 매핑이 쉬움
- `Center`: 대칭 계산/회전 계산이 단순함

권장 정책:
- 레시피 저장은 `CellRectGlassUm`(셀 외곽, GlassCS)
- 런타임 계산에서 `CellLocalCS` 원점은 설정값으로 관리
- 기본값은 `TopLeft` 또는 `Center` 중 하나로 고정하고, 제품별 오버라이드는 명시적으로만 허용

예시(TopLeft 기준):
- `cellLocalX = glassX - cellRect.Left`
- `cellLocalY = glassY - cellRect.Top`

예시(Center 기준):
- `cx = cellRect.Left + cellRect.Width/2`
- `cy = cellRect.Top + cellRect.Height/2`
- `cellLocalX = glassX - cx`
- `cellLocalY = glassY - cy`

## 6. 카메라 이미지 기준 좌표 설정 가이드

### 6.1 기본 규약
- IP 송신 좌표는 `RoiPxCS`(ROI 좌상단 기준)로 통일
- Console은 ROI 오프셋을 더해 `ImagePxCS`로 변환

### 6.2 필수 보정 요소
- pixel pitch(um/px)
- 카메라 회전/반전
- 렌즈 왜곡(필요 시)
- 카메라-글래스 매핑(호모그래피 또는 affine)

### 6.3 설정 절차(권장)
1. 캘리브 타겟 촬영
2. 이미지 기준점 4점 이상 취득
3. Glass 기준점 대응 매핑 구축
4. reprojection error 검증
5. 카메라별 설정 파일 저장

### 6.4 검증 기준
- 중심/모서리 오차를 분리 측정
- 허용 오차 예시: 평균 < 10um, 최대 < 25um
- 한계 초과 시 재보정 또는 왜곡 모델 고도화

---

## 7. Gate/Active 좌표 설정 가이드

필요 파라미터:
- `UseXAxisForGate` (bool)
  - `true`: Gate는 Glass X, Active는 Glass Y
  - `false`: Gate는 Glass Y, Active는 Glass X
- `GatePitchUm`
- `ActivePitchUm`
- `GateOriginUm` (gate=0 기준점)
- `ActiveOriginUm` (active=0 기준점)
- `GateSign` / `ActiveSign` (`+1`/`-1`)

변환 식(정렬된 Glass 기준):
- `gateBase = UseXAxisForGate ? glassX : glassY`
- `activeBase = UseXAxisForGate ? glassY : glassX`
- `gate = GateSign * (gateBase - GateOriginUm) / GatePitchUm`
- `active = ActiveSign * (activeBase - ActiveOriginUm) / ActivePitchUm`

주의:
- Gate/Active는 물리좌표의 파생 표현이므로, 원본 물리좌표를 항상 함께 저장
- pitch가 0 또는 미설정이면 인덱스 계산 금지
- 축 교환은 `UseXAxisForGate`, 방향 반전은 `GateSign`/`ActiveSign`으로 처리

## 8. 구현 기준 (현재 반영)

### 8.1 좌표 변환 서비스
- `uLedAoiConsole/Services/Coordinates/CoordinateModels.cs`
- `uLedAoiConsole/Services/Coordinates/CoordinateTransformService.cs`

제공 기능:
- 코너기준 셀 rect <-> Glass 중심 rect 변환
- 점 회전/이동 변환(`AlignTransform`)
- Glass um -> Gate/Active 변환

### 8.2 Recipe 셀 저장
- `RecipeCell.CellRectGlassUm` 사용
- `RecipeService`에서 스냅샷 로딩 시 Glass 중심좌표로 셀 생성

---

## 9. 운영 체크리스트

배포 전 점검:
- [ ] 레시피 셀 좌표가 `CellRectGlassUm`에 저장되는가
- [ ] IP 원본 좌표와 변환 좌표를 함께 기록하는가
- [ ] Align 값이 레시피와 분리되어 저장되는가
- [ ] Gate/Active 계산 파라미터가 제품별로 검증되었는가
- [ ] 좌표 변환 로그(원본/중간/최종)가 남는가

문제 발생 시 우선 확인:
1. 좌표계 원점 정의 불일치
2. 축 방향(sign) 불일치
3. 카메라 반전/회전 설정 누락
4. Align 파라미터 적용 순서 오류
5. ROI 기준 좌표를 Image 기준으로 오인

## 10. 권장 확장
- DefectInfo DTO에 좌표계별 필드 명시 추가
  - `ImagePx`, `RoiPx`, `GlassUm`, `CellLocalUm`, `GateActive`
- 좌표 변환 결과에 `transform_version` 부여
- 레시피 Validation에 좌표계 규칙 검사 추가

이 문서는 좌표계 일관성을 위한 기준 문서이며, 새 기능 추가 시 본 규칙을 우선 적용한다.
