제5장
SQL 옵티마이저
장 소개
데이터베이스에 저장된 데이터를 읽어 두 테이블을 조인하고 정릴 또는 그룹별 집계하는 등 복삽한 처리절文卜를
개발자가 직접 프로그래밍하던 시절이 있었다. 물론 지금도 그런 개발 환경이 없진 않지만, 지금은 대부분 SQL을
통해 사용자가 원하는 결과 집합만 정의해 주면 된다. 그러면 그 결과 집합을 얻는 데 필요한 처리절文卜를 SQL
옵EI마이저가 자동 생성해 준다.
옵디마이저에 의해 내부적으로 생성된 SQL 처리절文卜를 '실행계*l(Execut10n Plan)'이라고 하며, 그것에 의해
SQL 성능이 결정된다 따라서 고성능 DB 애플리케이션을 작성하려면 실행계획을 정확히 해석하고 자유자재로
조정할줄 일이야 한다. 그런 능력을 기르기 위해 옵니마이처의 세부 작동 원리를 정확히 숙지해야 함은 물론, 많은
실전 경험을 쌓아야만 한다
본 장은 그런 초석을 다지는 데 도움이 되고자 옵디마이처의 세부 작동 원리를 설명한다 기본 개념부터 시작해
옵E-A미이서의 비용 계산 원리, SQL 공유 및 재사용 방법, 그리고 최근 중요시되고 있는 쿼리 변환 원리까지 상세히
다룬다.
장 구성
본 장은 3개 절로 구성도거 있다 1절에서는 옵티마이처에 대한 기본 개념부터 시작해 옵디마이서 행동에 영향을
미지는 요소, 옵니미o|서의 한계, 옵니마이서의 비용 계산 원리 등을 설명한다 2절에서는 바인드 변수 사용 여부가
데이터베이스 성능에 미치는 영향과 중요성을 자세히 설명한다. 그 외에 라이브러리 개시를 최적화하기 위한 기법들을
소개한다. 3절에서는 옵EI마이저의 서브 엔진 중 하나인 귀리 변환기(Que다 Transformer)에 의해 수행되는 귀리
변환 원리를 자세히 설명한다.
제1절 SQL 옵티마이징 원리
제2절 SQL 공유 및 재사용
제3절 귀리 변환
