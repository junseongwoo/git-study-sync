나. 공유 조건
SQL 수행 절차를 정리해 보면 다음과 같다.
㉦ 문법적 오류와 의미 상 오류가 없는지 검사한다.
@ 해시 함수로부터 반환된 해시 값으로 라이브러리 개시 내 해시버킷을 찾아간다.
㉦ 찾아간 해시버킷에 체인으로 연결된 엔트리를 차례로 스캔하면서 같은 SQL 문장을 찾는다.
㉦ SQL 문장을 찾으면 함께 저장된 실행계획을 가지고 바로 실행한다.
찾아간 해시버킷에서 SQL 문장을 찾지 못하면 최적화를 수행한다.
㉦ 최적화를 거친 SQL과 실행계획을 방금 탐색한 해시버7^1 체인에 연결한다.
방금 최적화한 실행계획을 가지고 실행한다
방금 설명한 SQL 수행 절차에서 중요한 사실 하나를 발견할 수 있다. 하드 파심을 반복하지 않고 개싱된 버전을
찾아 재사용하려면 캐시에서 SQL을 먼저 찾아야 하는데, 개시에서 SQL을 찾기 위해 사용되는 기 값이 'SQL 문장
그 자제라는 사실이다.
SQL 문을 구성하는 전체 문자열이 이름 역할을 한다는 뜻이다. 물론 DBMS나 버전에 따라 별도의 SQL ID를
부여하기도 하지만 이 SQL ID가 SQL 전체 문장과 1:1로 대응되기 때문에 SQL 문장 자체가 식별자로 이용된다는
사실에는 변함이 없다.
이것은 SQL 파심 부하 해소 원리를 이해하는 데 있어 매우 중요한 의미를 갖는다. 즉 SQL 문장 중7`브 작은
공백문자 하나만 추가되더라도 DBMS는 서로 다른 SQL 문장으로 인식하기 때문에 개싱된 버전을 사용하지 못하게
된다.
