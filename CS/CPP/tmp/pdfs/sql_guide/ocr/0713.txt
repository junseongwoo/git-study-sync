뒤 페이지로 이동할수록 엄청나게 많은 Fetch 에l을 유발하게 될 것이괴 전반적으로 이런 패턴으로 구현했다면
시스템에 얼마나 익영향을 끼칠지는 어렵지 않게 침작할 수 있다. 그에 따른 성능 문제를 해결하려면, 페이지 처리를
서버 단에서 완료하고 화면에 출력할 레코드만 Fetch 하도록 프로그램을 고기는 수박에 없다.
위와 같이 비효율적인 방식으로 페이지 처리를 구현하는 경우가 있는가 하면, 아예 페이지 처리 없이 개발하는
시스템도 종종 볼 수 있다 업무 요건이 이에 그렇거나 짧은 개발 기간 때문이라고 하지만, 대량의 결과 집합을
메이지 처리 없이 모두 출력하도록 구현했을 때 시스템 전반에 미치는 영향은 실로 크다 페이지 처리를 하지 않았을
때 발생하는 부하 요인을 요악하면 다음과 같다.
㉦ 다량 발생하는 Fetch 예 부하
㉣ 대량의 결과 집합을 클라이언트로 전송하면서 발생하는 네트워크 부하
㉦ 대량의 데이터 블록을 읽으면서 발생하는 1/0 부하
㉦ AP 서버 및 웹 서버 리소스 사용량 증가
이렇게 여러 가지 부하를 일으키지만 정작 사용자는 앞쪽 일부 데이터만 보고 업무처리를 완료하는 경우가 대부분
이다. 귀리 자체 성능도 문제지만 시스템 전반에 걸쳐 불필요한 리소스를 당비하는 것이 더 큰 문제다. 이들 부하를
해소하는 열쇠는 메이지 처리에 있다.
(0 페이지 단위로, 화면에서 필요한 만큼만 Fetch Call
@ 페이지 단위로, 화면에서 필요한 만큼만 네트워크를 통해 결과 전송
인덱스와 부분범위처리 원리를 이용해 각 페이지에 필요한 최소짠 1/0
㉦ 데이터를 소량,식 나누어 전송하므로 Ape 서버 리소스 사용량 최소화
결론적으로 말해 과할 데이터가 일정량 이상이고 수행빈도가 높다면 필수적으로 페이지 처리를 구현수는 한다.
효과적인 페이지 처리 구현 방안에 대해서는 함 고급 SQL 튜닝에서 설명한다.
