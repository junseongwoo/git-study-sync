가. 버퍼 캐시
DB 버퍼 개시(DB Buffer C한汜)는 데이터 파일로부터 읽어 들인 데이터 ~ 담는 개시 영역이다. 인스턴스에
집속한 모든 사용자 프로세스는 서버 프로세스를 통해 DB 버퍼 개시의 버퍼 블록을 동시에(내부적으로는 버퍼
*을 통해 직렬화) 액세스할 수 있다.
일부 Direct Path Read 메커니즘이 작동하는 경우를 제외하면, 모든 블록 읽기는 버퍼 개시를 통해 이뤄진다.
즉 읽고자 하는 블록을 먼저 버퍼 개시에서 찾아끄 없을 때 디스크에서 읽는다. 디스크에서 읽을 때도 먼저 버퍼
개시에 적재한 후에 읽는다.
데이터 변경도 버퍼 개시에 적재된 블록을 통해 이뤄지며, 변경된 블록(Dirty 버퍼 블록)을 주기적으로 데이터
파일에 기록하는 작업은 DBWR 프로세스의 몫이다.
디스크 I/0는 물리적으로 액세스 0(Am)이 움직이면서 헤드를 통해 이뤄지는 반면, 메모리 I사는 전기적 신호에
불과하기 때문에 디드 I/CPII 비교할 수 없을 정도로 빠르다. 디스크에서 읽은 데이터 볼록을 메모리 상에 보관해
두는 기능이 모든 데이터베이스 시스템에 필수적인 이유다.
1) 버퍼 블록의 상태
모든 버퍼 블록은 아래 세 가지 중 하나의 상태에 놓인다.
Free 버퍼 : 인스턴스 기동 후 아직 데이터가 읽히지 않아 비어 있는 상4(Clean 버퍼)이거나, 데이터가
담겼지만 데이터 파일과 서로 동기화돼 있는 상대여서 언제든지 덮어 써도 무방한 버퍼 볼록을 말한다 데이터
파일로부터 새로운 데이터 블록을 로딩하려면 먼저 Free 버퍼를 확보해야 한다. Free 상태인 버퍼에 변경이
발생하면 그 순간 Dirty 버퍼로 상태가 바뀐다.
Dirty 버퍼 : 버퍼에 개시된 이후 변경이 발생했지만, 아직 디스크에 기록되지 않아 데이터 파일 블록과
동기화가 필요한 버퍼 볼록을 말한다 이 버퍼 불록들이 다른 데이터 볼록을 위해 재사용되려면 디스크에
먼저 기록돼야 하며, 디스크에 기록되는 순간 Free 버퍼로 상태가 바뀐다.
Pinned 버퍼 : 읽기 또는 쓰기 작업이 현재 진행 중인 버퍼 블록을 말한다
2) LRU 알고리즘
버퍼 개시는 유한한 자원이므로 모든 데이터를 개상해 들 수 없다 따라서 모든 DB\ß는 사용빈도가 높은 데이터
블록 위주로 버퍼 개시가 구성되도록 LRU0east recently used) 알고리즘을 사용한q. 모든 버퍼 불룩 헤더를
LRU 체인에 연결해 사용빈도 순으로 위치를 옮겨가다가, Free 버퍼가 필요해질 때면 액세스 빈도가 낮은 *(LRU
end) 데이터 불록부터 밀어내는 방식이다. [그림 III•1최과 같은 컨베이어 벨트를 연상하면 LRU 알고리즘을 쉽게
이해할 수 있다.
