2) 현재 시점 조회

위 쿼리를 이용해 과거-현재-미래 어느 시점이든 조회할 수 있지만, 만약 미래 시점 데이터를 미리 입력하는
예약 기능이 없다면 '현재 시점(즉 현재 유효한 시점)' 조회는 다음과 같이 < 조건으로 만들어 주는 것이 효과적이다.
범위검색 조건이 비효율을 일으키는 원인은 3장 2절에서 자세히 설명했다.

select <,.고객번호, <,고객명, <1.고객등급, <2.전화번호
fron 고객 <, 고객등급변경이력 <1, 전화번호변경이력 2
where ¢ DAME = :cust_num

and C1. DAS = c DAYS

and <2.고객번호 = <.고객번호

and  (1.종료일자 = '99991231"

and <2,종료일자 = '99991231"

미래 시점 데이터를 미리 입력하는 예약 기능이 있다면, 현재 시점을 조회할 때 다음과 같이 조회해야 한다.

Oracle

select <.고객번호, <,고객명, <1,고객등급, <2.전화번호

fron 고객 <, 고객등급변경이력 <1, 전화번호변경이력 2

where <.고객번호 = :cust_num

and (1.고객번호 = <.고객번호

and <2.고객번호 = <.고객번호

and to_char(sysdate, '))))70000') between <1.시작일자 and <1.종료일자
and to_char(sysdate, 'yyyymndd') between <2.시작일자 and <2.종료일자

SQL Server

and convert(varchar(8), getdate(), 112) between <1.시작일자 and <1.종료일자
and convert(varchar(8), getdate(), 112) between <2.시작일자 and <2.종료일자
