1. 설계 원칙과 전체 구조
새 기능은 기존 AlignWindow의 카메라 연결, Camera Geometry, Center Pivot UVW 변환, Control 상대 이동을 재
사용한다. 새로 분리한 것은 도면 벡터와 전역 측정 벡터 사이의 Theta를 계산하는 순수 계산 클래스뿐이다. 장비
제어와 수학 계산을 분리하여 계산은 단위 테스트로 검증하고, 실제 이동은 이미 검증된 기존 경로를 사용하도록
했다.
TemplateMatchAlignWindow
사용자 입력과 결과 표시

TemplateMatchThetaCalc
Pixel->Stage / Vdesign / Vmeasure / Theta
AlignViewModel
Center Pivot UVW 변환 / Control 상대 이동
왜 별도 계산 클래스를 만들었는가?
Template 등록 중심을 정상 T=0 기준에서 구조적으로 배제하고, Camera/Control 없이도 수학과 안전 조건을 단위 테스
트하기 위해서다. Interface, Factory, Manager는 추가하지 않았다.

4.1 입력 준비
현재 영상과 등록 영상을 Gray로 변환한 뒤 등록 영상의 Template ROI와 현재 영상의 Search ROI를 잘라낸다.
Template이 Search보다 크면 즉시 실패한다.
4.2 OpenCV Matching
Cv2.MatchTemplate(search, template, result,
                  TemplateMatchModes.CCoeffNormed);
Cv2.MinMaxLoc(result, out _, out double maxVal,
              out _, out Point maxLoc);
CCoeffNormed는 평균 밝기 성분을 제거한 정규화 상관계수 방식이다. 단순 밝기 차이보다 Mark 패턴의 형태 유
사도를 비교하기 적합하다.
4.3 Score와 중심
maxVal이 Match Score이고 maxLoc이 가장 높은 점수의 좌측 상단이다. 중심은 maxLoc에 Template 크기의 절반
과 포물선 기반 Subpixel 보정값을 더해 계산한다.
CenterX = matchRect.X + subpixel.X + template.Width / 2
CenterY = matchRect.Y + subpixel.Y + template.Height / 2
Subpixel 보정은 정수 Pixel 단위 계단 현상을 줄이기 위해 사용한다. Mark 간 거리가 약 393,000 um이므로 작은
Pixel 오차도 미세 Theta 측정에 영향을 줄 수 있다.

6. Pixel 중심을 전역 Stage 좌표로 변환
Mark1과 Mark3은 서로 다른 Stage 위치에서 촬영하므로 두 영상의 Pixel 중심을 바로 빼지 않는다. 각 중심을 같은
 Stage 전역좌표계로 변환한 뒤 차이를 계산한다.
현재 Mark 중심 C
CurrentCenter Pixel
CameraOrigin 차감
dxPixel, dyPixel
Camera Geometry 방향 벡터 투영
Stage +X / +Y 이미지 방향
PixelSize 평균으로 um 변환
StageOffsetX / StageOffsetY
촬영 Encoder S와 합산
P = S + StageOffset
구현 수식
dx = CurrentCenter.X - CameraOrigin.X
dy = CurrentCenter.Y - CameraOrigin.Y
pixelSize = (PixelSizeXUm + PixelSizeYUm) / 2
offsetX = (dx * StagePlusXImageUnitX
         + dy * StagePlusXImageUnitY) * pixelSize
offsetY = (dx * StagePlusYImageUnitX
         + dy * StagePlusYImageUnitY) * pixelSize
P = (EncoderX + offsetX, EncoderY + offsetY)
왜 Camera Geometry가 필요한가?
이미지의 오른쪽/아래쪽 방향이 실제 Stage +X/+Y와 일치한다는 보장이 없다. 카메라 회전, 축 교환, 반전 상태를
기존 보정 방향 벡터로 해석해야 한다. 기존 Align과 동일한 Pixel Size 평균을 사용해 기존 Geometry의 의미를 바
꾸지 않았다.

7. 도면 기준 벡터 생성
Recipe의 Mark 좌표는 Glass 도면 좌표이고 측정값은 Stage 좌표다. 두 벡터를 비교하려면 같은 좌표계로 변환해
야 한다.
Glass 도면 Q1 / Q3
GlassSizeModel.PanelAngleDeg 적용
Q1Stage / Q3Stage
Vdesign = Q3Stage - Q1Stage
QStage.X = Q.X * cos(angle) - Q.Y * sin(angle)
QStage.Y = Q.X * sin(angle) + Q.Y * cos(angle)
Vdesign = Q3Stage - Q1Stage
Mark3 이동은 변환된 Stage 선분의 X 성분을 사용한다. CAM2 고정 + StageX 단독 이동 구조이므로 Stage Y 성분
이 1 um보다 크면 측정 불가능 상태로 판단해 이동하지 않는다.

8. Theta 계산
Vdesign
Vmeasure
cross = Vdesign.X * Vmeasure.Y
        - Vdesign.Y * Vmeasure.X
dot = Vdesign.X * Vmeasure.X
      + Vdesign.Y * Vmeasure.Y
Theta = atan2(cross, dot)
Vdesign  = Q3Stage - Q1Stage
Vmeasure = P3 - P1
cross = Vdesign.X * Vmeasure.Y
      - Vdesign.Y * Vmeasure.X
dot = Vdesign.X * Vmeasure.X
    + Vdesign.Y * Vmeasure.Y
thetaErrorDeg = atan2(cross, dot) * 180 / PI
왜 atan2(cross, dot)인가?
작은 각도 근사식은 기준선이 특정 축과 평행하고 각도가 매우 작다는 전제가 필요하다. atan2 방식은 PanelAngle
이 있거나 Vdesign에 X/Y 성분이 모두 있어도 같은 수식으로 방향과 크기를 계산할 수 있다.
길이 안전 검증
도면 선분 또는 측정 선분이 0이면 계산하지 않는다. 또한 측정 길이/도면 길이 비율이 0.8-1.2 밖이면 Mark 오검출,
 Encoder 오류 또는 Geometry 오류 가능성이 높으므로 이동을 금지한다.
예시: 393,000 um 기준에서 횡방향 100 um
atan2(100, 393000)의 절대값은 약 0.014579 deg이다. 따라서 0.001 deg 허용 오차를 사용하려면 Pixel 중심과
Geometry, Encoder 정착 반복성이 모두 중요하다.

9. 보정 부호와 Center Pivot UVW 이동
측정 Theta Error
Correction = -Error * 0.5
부호 반전은 여기서 단 1회
XYT 입력 = (0, 0, Correction)
X/Y 평행 이동 금지
기존 Center Pivot UVW 변환
StageU / StageV / StageW Relative Move
왜 반대 부호인가?
thetaError는 현재 Glass가 도면 기준에서 돌아간 물리적 방향이다. 보정은 그 반대 방향이어야 하므로 -thetaError
를 사용한다. 여러 계층에서 임의로 부호를 뒤집지 않고 CalculateThetaCore() 한 곳에서만 반전한다.
왜 50%만 적용하는가?
UVW 기구 오차와 보정 파라미터 오차 때문에 100% 이동 시 목표를 지나칠 수 있다. 50%씩 이동하고 재측정하면
보수적으로 수렴하며, 방향이 틀렸을 때도 한 번의 이동량을 제한할 수 있다.
기존 UVW 로직 재사용
AlignViewModel.CalculateThetaUvwForStepTest()는 X=0, Y=0, T=보정각을 기존 Center Pivot 변환기에 전달한다.
ApplyThetaUvwForStepTestAsync()는 검증된 기존 Control 상대 이동 경로로 StageU/V/W를 전송한다.
