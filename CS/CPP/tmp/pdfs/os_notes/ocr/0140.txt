Chapter 4 스레드와 병행성
1`尸M과 호스트 운명체제(The 11/M and the Host Operating System)
JVM은 일반적으로 호스트 운영체제 위에 구현된디(그림 18.10 참조). 이 설정을
통해 JVM은 하부 운영체제의 구현 세부 사형을 숨기고 Java 프로그램이 JVM을
지원하는 모든 플랫폼에서 작동할 수 있는 일관되고 추상적인 환경을 제공할 수 있
다. JVM 명세는 Java 스레드가 히부 운영체제에 매핑되는 방법을 명시하지 않고
대신 각 JVM의 구현에 맡긴다. 예를 들어, Windows 운영체제는 일대일 모델을
시용한다. 따라서 Windows에서 실행 중인 JVM의 각 Java 스레드는 커널 스레
드에 매핑된다. 또한 Java 스레드 라이브러리와 호스트 운영체제의 스레드 라이브
러리 간에 관계가 있을 수 있다. 예를 들어, Windows 운영체제 제품군의 JVM 구
현은 Java 스레드를 작성할 때 Windows API를 시용할 수 있다. Linux 및 ma-
cOS 시스템은 Pthreads API를 시용할 수 있다.
또한 이 접근 방식은 스레드 생성과 스레드가 만든 결괴를 분리한다. 결괴를 확인하기
전에 스레드 종료를 기다리는 대신 부모는 결과가 가용해지는 것만 기다리면 된다. 마지
막으로 4.5.1절에서 보겠지만 이 프레임워크를 다른 기능과 결합하여 대량의 스레드를
관리하기 위한 강력한 도구를 만들 수 있다.
4.5 암묵적 스래팅 lmplicit Threading
나중 코어 처리의 지속적 성장에 따라 수백 또는 심지어 수천 개의 스레드를 가진 용돈
이 등장하게 되었다. 그러한 응용을 설계하는 것은 사소한 일이 아니며 프로그래머는
4.2절에서 설명한 도전과제뿐 아니라 추가의 어려움을 극복해야 한다. 이러한 어려움 중
프로그램의 정확도와 관계된 것들은 6장과 8장에서 논의된다.
이러한 어려음을 극복하고 병행 및 병렬 핑공의 설계를 도와주는 한 가지 방법은 스
레딩의 생성과 관리 책임을 응용 개발자로부터 컴파일러와 실행시간 라이브러리에게 넘
겨주는 것이다. 암묵적 스레딩이라고 불리는 이 전략은 점점 널리 시용되고 있다. 이 절
에서는 암묵적 스레딩을 이용하여 다중 코어 처리기를 활용할 수 있는 응용 프로그램을
설계하는 4가지 접근법을 탐구한다. 앞으로 살펴보겠지만, 이러한 전략은 일반적으로 응
용 프로그램 개발자가 병렬로 실행할 수 있는 스레드가 아닌 작업을 식별해야 한다. 작
업은 일반적으로 함수로 작성되며, 런타임 라이브러리는 일반적으로 다대다 모델(4.3.3
절)을 시용하여 별도의 스레드에 매핑된다. 이 방법의 장점은 개발지는 병렬 작업만 식
별하면 되고 라이브러리는 스레드 생성 및 관리에 대한 특정 세부 사항을 결정한다는 것
이다.
