시기는 것은 페이지의 수를 중가시기고, 결국 페이지 테이블의 그기를 증가시킨다. 예를
들어, 4 MB (222) 가상 메모리에서는 페이지 크기가 1,024바이트인 경우 4,096페이지가
존재하나 8,192바이트인 경우에는 512페이지만이 존재한다. 모든 활성 프로세스는 각자
의 페이지 테이블을 유지해야 하므로, 큰 페이지가 좋다.
반면에 할당해 준 메모리 시용 효올을 위해서는 작은 페이지가 좋다. 어떤 프로세스
가 00000번지부터 시작하여 메모리를 할당믿아 필요한 만큼 A卜岳하게 되었다면, 많은
경우에 페이지 경계에 딱 맞추니 끝나지는 않을 것이다. 따라서, 마지막 페이지의 일부는
할당할 수밖에는 없지만 (할당 단위가 페이지이므로) 시용되지는 않을 것이다(이에 따라
내부 단편화가 발생). 프로세스 크기와 페이지 크기 사이에 어떤 연관도 존재하지 않을
때, 평균적으로 각 프로세스 주소 공간의 마지막 페이지의 절반가량이 당비된다고 볼 수
있다. 이러한 당비는 페이지 그기가 512바이트인 경유는 256바이트에 그치지만, 8,192
바이트인 경유는 4,096바이트에 이른다. 이처럼 내부적 단편회(internal fragmenta-
tion)를 최소화하기 위해서 작은 페이지 크기가 좋다.
다른 문제는 페이지를 읽거나 쓰는 데 필요한 시간이다. 11.1절에서 볼 수 있듯이 저
장장치가 HDD인 경우 I/O 시간은 탐색, 지연시간 및 전송 시간으로 구성된다. 전송
시간은 전송된 연즉, 페이지 크기)에 비례한다. 즉, 작은 페이지 크기를 옹호하는 사실
처럼 보인다. 그러나 지연시간과 탐색 시간은 일반적으로 전송 시간의 비중을 줄인다. 초
당 50 MB의 전송 속도에서 512바이트를 전송하는 데 0.01밀리초만 걸린다. 그러나 지
연시간은 아마도 3밀리초이며 탐색 시간은 5밀리초이다. 따라서 총 1/0 시간 (8.01 밀리
초) 중 약 0.1%만이 전송 시간이다. 페이지 크기를 두 배로 늘리면 I/O 시간이 8.02밀
리초로 증가한다. 1,024바이트의 페이지 하니를 읽는 데 8.02밀리초가 걸리고 같은 양을
512바이트 페이지 두 개로 읽는 데 16.02밀리초가 걸린다. 따라서 I/O 시간을 최소화하
려는 목적은 더 큰 페이지 크기를 옹호한다.
그러나, 작은 페이지 크기를 갖는 경우 지역성이 향상되어 전체 I/O는 더 줄어들 것
이다. 작은 페이지는 각 페이지가 프로그램의 지역성을 더욱 정확히 추적하도록 해 준다.
예를 들에 200 KB 중 실제로 100 KB만이 실제로 A卜혐되는 프로세스를 생각해 보자.
시스템에 매우 큰 페이지 하나만 존재하는 경우 200 KB의 전체 페이지를 읽어 들어야
한다. 반대로 1바이트 단위의 페이지를 시용한다면 실제로 사용될 100 KB만을 정확히
읽어 들일 수 있다. 작은 페이지 시스템에서는 실제로 필요한 정보만을 선별하여 메모리
로 가져오게 되어 정밀도(resolution)가 좋아진다고 볼 수 있다. 큰 페이지 시스템에서
는 꼭 필요한 내용뿐 아니라 우연히 같은 페이지에 속하게 된 모든 정보도 함께 반입되
게 되므로 메모리 내용이 알차지 못하게 된다. 따라서, 작은 페이지 시스템이 I/O를 덜
수행할 것이며 메모리 총량도 덜 사용하게 된다.
