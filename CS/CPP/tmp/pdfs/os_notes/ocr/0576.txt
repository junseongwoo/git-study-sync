어, 시스템 성능에 대한 인공적인 제약을 제거하였다. 물론 운영체제가 테이블 항목-끌
동적으로 할당하고 반납해야 하므로 이들 테이블을 조작하는 알고리즘이 보다 복잡하고
운영체제가 약간 느려졌지만 이러한 불편은 더욱 일반성을 가진 기능을 제공하기 위해
피할 수 없는 것이다.
14.6.2 성능 Performance
기본적인 파일 시스템 알고리즘이 결정되었다 하더라도 시스템 성능-을 言끈0+할 수 있는
방법들이 몇 가지 더 있다. 12장에서 살펴보았던 저장장치 컨트롤러들은 전체 트랙 또는
블록의 내펑-을 전부 저장할 수 있을 만큼 충분한 크기의 개시(on-board cache)를 가지
고 있다. HDD에서는 일단 탐색(seek)이 디스크 헤드를 원하는 트랙으로 가져가면 디
스크 헤드가 위치하는 섹터부터 곧바로 디스크 개시로 읽어 후에 요구되는 디스크 섹터
를 운영체제에 전달한다. 따라서 요청된 섹터가 헤드 밑에 오기까지 회전 지연을 하지
않는다. 디스크 제어기는 요구된 섹터를 운영체제에 전송한다. 일단 블록들이 디스크 제
어기로부터 메인 메모리로 옮겨지면, 운영체제는 이들을 메인 메모리에 개시 할 수 있다.
어떤 시스템은 메인 메모리에서 별도의 구역을 버퍼 개시용으로 유지한다. 다른 시
스템은 파일 데이터를 페이지 개시를 久卜&하여 개시 한다. 페이지 개시는 가상 메모리
기법을 시용하여 파일 데이터를 파일 시스템 지향의 블록이 아니라 페이지로 개시한다.
파일 데이터를 가상 주소로 개시 하는 것은 물리 블록으로 개시 하는 것보다 훨씬 효율
적이다. Solaris, 다수의 새로운 Linux 릴리즈 및 Windows NT와 2000을 포함하여
다수의 시스템이 페이지 개성을 사용하여 프로세스 페이지와 파일 데이터 모두를 개시
한다. 이 기법은 통합 가상 메모리(umfied virtual memory)로 알려져 있다.
UNIX의 몇 버전들은 통합 버퍼 캐시(unified buffer cache)를 제공한다. 파일을
오픈하고 접근하는 두 가지 대안을 생각해 보자. 하나는 메모리 매핑(13.5절)을 시용하
는 것이며, 다른 하나는 표준 시스템 콜인 read()와 vrite()를 사용하는 것이다. 통
