10.9.4 역 페이지 테이블 Table
9.4.3절에서 역 페이지 테이블의 개념을 소개했다. 이 페이지 관리 방식의 목적은 가상-
물리 주소 변환을 추적하는 데 필요한 물리 메모리의 양을 줄이는 것이다. 이 테이블은
〈process-id, page-number〉에 의해 색인되며 각 물리 메모리마다 한 항목을 갖는다.
각 페이지 프레임에 어떤 가상 메모리 페이지가 저장되어 있는지의 정보만 유지하면
되므로 필요한 물리 메모리 양을 줄인다. 그렇지만 역 페이지 테이블이 전체 가상 주소
공간에 대한 정보는 더는 유지하지 않으므로, 참조된 페이지가 현재 메모리에 없을 때에
는 문제가 된다. 요구된 페이지가 디스크 내 어디에 있는지를 알 수가 없기 때문이다. 이
정보를 공급하기 위해서는 프로세스당 하나씩 확장된 페이지 테이%(extended page
table)을 유지해야 한다.
그렇다면 이 확장된 페이지 테이블은 원래 페이지 테이블과 같으므로 역 페이지 테
이불의 유용성이 무엇인가?라고 반문할 수도 있다. 그러나 이 확장된 테이블은 단지 메
이지 폴트 시에만 참조되기 때문에 빨리 읽어야 할 필요가 없다(원래의 페이지 테이블은
매번 메모리 참조 때마다 사우된다). 그러므로 확장된 테이블은 필요에 따라 그 자체가
페이징될 수도 있다. 이때 페이지 폴트 처리 과정에서 확장된 페이지 테이블을 읽어 들
이기 위해 또 다른 페이지 폴트를 발생시길 수 있다. 이러한 특별한 경우는 커널에서 조
심스럽게 처리해야 하며 페이지 lookup 처리 시에 시간 지연이 발생한다.
