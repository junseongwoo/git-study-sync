시스템마다 볼룸을 위해 다른 구문을 쓰기도 한다. 예를 들면, Windows 볼륨은 글
자 뒤에 콜론( : )을 붙여서 나타낸다. 따라서 피일 지칭은 c:\userb\test와 같은 형식
을 따른다. 어떤 시스템들은 파티션, 디렉터리 이름, 파일 이름들을 분리하여 표시한다.
예를 들면, OpenVMS에서 파일 10모n• com 파일은 u: [sst • crissmeyer] login•
com;1으로 풀어쓸 수 있다. 여기에서 u는 파티션의 이름이고, sst는 디렉터리의 이름,
crissmeyer는 서브니렉터리의 이름이고 맨 뒤의 1은 버전을 나타낸다. UNIX와 Linux
와 같은 다른 시스템들은 파티션 이름을 디렉터리 이름 일부로 취급한다. 예를 들면, /
u/pgalvin/test에서 u는 파티션 이름이고, pgalvin는 디렉터리, 그리고 test는 파
일을 나타낸다.
운영체제는 어셈블러, 컴파일러, 유틸리티 루틴, 라이브러리 등의 시스템 프로그램을
일반적인(이진 프로그램) 파일 형대로 가지고 있다. 그러다가 사용자가 터미널에서 명령
어를 넣어주면 운영체제는 명령 해석기(interpreter)라는 프로그램에 자기가 방금 받은
명령을 넘겨준다. 시스템에서 우리가 시용하는 명령은 보통 실행 파일의 이름과 동일하
다. 위에서 정의한 디렉터리 시스템에서 이 파일 이름은 현재 UFD에서 검색될 것이다.
한 가지 해결책은 시스템 파일을 각 UFD로 복사하는 것이다. 하지만, 모든 시스템 파일
을 복사하는 것은 거대한 공간 당비를 가져온다. (만약 시스템 파일이 5 MB이고 12명의
사용자가 있다면 시스템 파일의 복사본으로 5 x 12 = 60 MB의 공간이 필요하다)
일반적인 해결책은 검색 절차를 약간 복잡하게 하는 것이다. 시스템 파일을 가지는
특정한 사용자 디렉터리를 정의한다(예를 들어, 사용자 0). 시스템에 적재될 파일 이름이
주어질 때마다, 운영체제는 먼저 현재 UFD를 검색한다. 만약 파일을 찾으면, 사용되지
만, 찾지 못하면, 시스템은 자동으로(이러한 시스템 명령 파일들만 별도로 모이놓은) 특
수한 사용자 디렉터리를 탐색한다. 이처럼 명령이 주어질 때마다 일정하게 디렉터리를
탐색하는 순서를 탐색 경로(search path)라고 한다. 탐색 경로는 수시로 변경할 수가 있
는데 UNIX와 Windows 시스템이 이러한 방법을 사용한다. 또한 시스템은 각 사용자
가 자신만의 탐색 경로를 가질 수 있도록 설계될 수 있다.
