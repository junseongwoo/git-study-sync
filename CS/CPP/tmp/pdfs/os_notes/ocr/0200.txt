시간은 각각의 CPU 버스트(burst)와 같다고 가정한다. 즉, 프로세스가 CPU를 자지한
시간은 각각의 CPU 버스트 시간과 같다.
예를 들어 보자. 두 개의 프로세스 터, P2가 있다고 할 때, 터의 주기는 50, P2의 주
기는 100이라고 하자. 즉 = 50, P2 = 100이다. PI의 수행 시간 = 20, P2의 수행 시
간 t2 = 35이다. 각 프로세스의 마감시간은 다음 주기가 시작하기 전까지이다.
먼저 두 프로세스가 모두 마감시간을 충족시기도록 스게줄링 가능한지 생각해 보아
야 한다. 각 프로세스의 CPU 이용률, 즉 주기에 대한 수행 시간 tl/PI를 구해보면 PI의
CPU 이용률은 20/50 = 0.40이고, P2의 CPU 이용률은 35/100 = 0.35이다. 총 CPU
이용률은 75%가 된다. 따라서 두 프로세스 모두 마감시간을 충족시기고도 여유시간이
수 있을 것으로 보인다.
P2의 우선순위가 터보다 높다고 가정하자. 두 프로세스의 수행 모습이 그림 5.21에
표현되어 있다. 그림에서 보듯이, P2가 먼저 수행을 시작해 시간 35에 수행을 끝낸다. 이
때 PI이 시작해서 시간 55에 수행을 끝낸다. 그러나 PI의 마감시간이 50이기 때문에, 스
게줄러는 PI의 마감시간을 충족시카지 못한다.
Rate-monotonic 스케줄링을 새콤하면, PI의 주기가 P2의 주기보다 짧기 때문에
PI의 우선순위가 P2의 우선순위보다 높다. 이 스케줄링 정책을 적용했을 때, 두 프로세
스의 수행 모습이 그림 5.22에 표현되어 있다. PI이 먼저 수행을 시작하여 시간 20에 수
행을 끝낸다. 따라서 첫 번째 마감시간을 만족시킨다. 바로 P2가 수행을 시작해서 시간
50까지 수행을 끝낸다. 이때 5밀리초의 CPU 할당 시간이 남아 있기는 하지만, PI에게
선점된다. PI은 시간 70까지 수행을 하고, 스케줄러는 다시 P2를 수행시킨다. P2는 시간
75에 수행을 끝내고, 자신의 첫 번째 마감시간을 만족시킨다. 시스템은 시간 100까지 유
휴 시간을 갖다가 PI이 다시 스케줄 된다.
