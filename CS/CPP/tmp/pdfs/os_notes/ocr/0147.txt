compute() 메소드는 각 작업이 수행하는 계산을 지정한다. compute() 메소드는 할당
된 부-분집합의 합계를 직접 기|산할 수 있을 따ly가지 호출된다. join() 호출은 작업이 완
료될 때까지 중단되며, join()은 compute()에서 계산된 결괴를 반환한다.
그림 4.18의 SumTask는 RecursiveTask를 확장한다. Java fork-join 전략은
추상 기본 클래스 ForkJoinTask를 중심으로 구성되며 RecursiveTask 및 Recurs-
iveAction 클래스는 이 클래스를 확장한다. 이 두 클래스의 근본적인 차이점은 Recurs-
iveTask가 (compact()에 지정된 반환 값을 통해) 결과를 반환하고 RecursiveAction
은 결과를 반환하지 않는다는 것이다. 세 클래스 사이의 관계는 그림 4.19의 UML 클래스
다이어그램에 설명되어 있다.
고려해야 할 중요한 쟁점은 문제가 직접 해결할 만큼 “충분히 작은” 크기여서 더 이
상 추가 작업을 만들 필요가 없는 때가 언제인가를 결정하는 것이다. sumTask에서 이
는 합산되는 원소의 수가 THRESHOLD 값보다 작을 때 발생한다(그림 4.18에서 임의로
1,000으로 설정함). 실제로, 구현에 따라 값이 달라질 수 있기 때문에 언제 문제가 직접
해결될 수 있는지 결정하는 것은 신중하게 타이밍을 시험해 봐야 한다.
Java의 fork-join 모델에서 흥미로운 점은 라이브러리가 작업자 스레드 풀을 생성
하고 사용 가능한 작업자 간 부하의 균형을 조정하는 작업 관리에 있다. 어떤 상황에서
는 수천 개의 작업이 있지만 작업을 수행하는 소수의 스레드면, CPU마다 하나의 개별
스레드)만 있다. 또한 ForkJoinP001의 각 스레드는 fork된 작업의 큐를 유지 관리하
며, 스레드의 큐가 비어 있으면 work stealing 알고리즘을 사용하여 다른 스레드 큐에
서 작업을 가져올 수 있으므로 모든 스레드 간에 부十를 분산시킬 수 있다.
