바깥 페이지 테이블은 여전히 234바이트(16 GB)의 그기를 요구한다.
다음 단계는 2번재 바깥 테이블 자체를 페이징하는 등의 4단계 페이징 기법을 久卜&할
수 있을 것이다. 64비트 UltraSPARC 구조는 7단계 페이징을 해야 하며 각 논리 주소를
사상하기 위해 너무 많은 메모리 접근을 필요로 하기 때문에 비현실적이다. 이 예에서 일
반적으로 64비트 구조에서는 계층적 페이지 테이블이 부적합하다는 것을 알 수 있다.
9.4.2 해시 페이지 테이블 Hashed Tab1es
주소 공간이 32비트보다 커지면 가상 주소를 해시로 사용하는 해시 페이지 테이블-을 많
이 쓴다. 해시 페이지 테이블의 각 항목은 연결 리스트를 가지고 있다. 이곳에는 충돌을
일으켜서 모두 이곳으로 해시되는 원소들이 매달리게 된다. 각 원소는 세 개의 필드근
가진다: (1) 가상 페이지 번호 (2) 사상되는 페이지 프레임 번호 (3) 연결 리스트상의 다
음 원소 포인터.

째 원소와 가상 페이지 번호를 비교해본다. 일치되면 그에 대응하는 페이지 프레임 번호
