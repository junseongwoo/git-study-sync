하나만 알려지면 모든 파일 접근이 가능하여 보호가 전부 아니면 전무 형태가 된다. 일

사용하도록 하고 있다. 보다 일반적으로 파티션 또는 개별 파일의 암호화는 강력한 보호
기능을 제공하지만 암호 관리가 핵심이다.
여러 단계의 디렉터리를 가지는 구조에서는 각각의 파일의 보호뿐만이 아니라 각
subdirectory (즉, subdirectory 밑의 모든 파일)를 보호하는 directory protection
기능이 있어야 한다. 디렉터리용 연산은 일반 파일용 연산과 다르므로, directory 연산
은 파일 연산과 다르게 보호되어야 한다. 우리는 한 디렉터리 내에 파일을 생성하거나
제거하는 일을 제어하기를 원한다. 또한 아마도 사용자가 한 디렉터리 내에 파일의 존재
부를 확인하는 일을 제어하려 할 수도 있다. 때로는 파일의 존재 여부와 이름을 아는
것 자체가 중요할 수 있다. 따라서 디렉터리의 내용을 열거하는 연산은 보호되어야 한다.
그러므로 사용자가 한 파일의 230 named 제시하면, 그는 그 디렉터리와 파일을 둘
다 접근할 수 있게 해야 한다. 만일 한 파일이 여러 7H] path name 가지는 경우라면
(acylic 또는 general graph 경우) 한 사용자가 사용하는 path 1ㅠ2106에 따라 서로
른 액세스 권한으로 이 파일에 접근할 수 있다.

가 발생한다. 이때 그 파일 내용 중 페이지 크기만큼의 해당 부분이 파일 시스템으로부
터 메모리 페이지로 읽혀 들어오게 된다(시스템에 따라서는 이처럼 읽어 들일 때 페이지
크기보다 더 큰 단위로 읽어 들일 수도 있다). 그 이후의 파일 read/write 일반적인
메모리 액세스와 같이 처리된다. 6389()와 ##166()를 사용하는 오버헤드 없이 파일을
