다. 후자의 경우 많은 양의 데이터를 만들어 낸다(초낭 백만 개 단위의 주소로). 데이터

먼저, 페이지 크기가 주어졌을 때(페이지 크기는 내개 하드웨어나 시스템에 의해 결
정되어 있다), 주소 전체를 고려하기보다 페이지 번호만을 고려하면 된다. 다음으로, 페
이지 poll 대한 참조가 발생하면, 작후에 poll 접근하는 모든 참조는 페이지 폴트를 발생
시키지 않는다. A 번째 참조 후에 페이지는 메모리에 존재할 것이므로 다음 참조들은
부재 오류를 발생시키지 않을 것이다.

예를 들어, 특정 프로세스를 추적하면, 다음과 같은 주소 열을 얻을 수 있다.

0100, 0432, 0101, 0612, 0102, 0103, 0104, 0101, 0611, 0102, 0103,
0104, 0101, 0610, 0102, 0103, 0104, 0101, 0609, 0102, 0105

페이지 크기가 100바이트라면, 이 열은 다음과 같은 참조열로 줄일 수 있다.
1,8,1,6,1,6,1,6,1,6,1

페이지 폴트 횟수를 알고자 하면 페이지 교체 알고리즘 외에도 이 프로세스가 현재
사용할 수 있는 페이지 프레임의 수를 알 필요가 있다. 프레임의 수가 많으면 페이지 폴
트 횟수가 감소할 것이다. 예를 들어, 위 참조열에 대해 3개 이상의 프레임을 가지면 각
페이지의 첫 번째 참조 때마다 한 번씩, 3번의 페이지 폴트만이 발생한다. 이에 반해 프
레임이 하나만 있다면, 참조 때마다 부재가 발생하고 총 11번의 페이지 폴트가 발생한
다. 일반적으로 가용 페이지 프레임 수와 페이지 폴트율은 그림 10.11과 같은 상관관계
를 나타낸다. 프레임의 수가 증가함에 따라 페이지 폴트 수는 어떤 최숫값으로 떨어진다.
물론, 물리 메모리를 추가하면 프레임의 수가 증가한다.

아래에서는 페이지 교체 알고리즘을 설명하기 위하여 3개의 프레임을 가진 메모리
를 가정하고 페이지 참조열은 아래와 같다고 가정한다.

7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1

10.4.2 FIFO 페이지 2X| _FiFo Page Replacement
가장 간단한 페이지 교체 알고리즘은 FIFO (first-in first-out) 알고리즘이다. FIFO 교
체 알고리즘은 어떤 페이지를 교체해야 할 때, 메모리에 올라온 지 가장 오래된 페이지
를 내쫓는다. 페이지가 올라온 시간을 페이지마다 기록해도 되고, 아니면 페이지들이 올
라온 순서로 F(FIFO 400640)를 만들어 가지고 있어도 된다. 그러면 큐의 머리 부분 페
이지를 교체하고 새로 올라온 페이지는 큐의 끝에 삽입하면 된다.
