13.1.3   파일 유형 _File Types
파일 시스템은 물론 전체 운영체제 설계 시 중요한 사항 중 하나는 운영체제가 파일 유형
들을 인식하고 지원할 것인지를 결정하는 것이다. 만일 운영체제가 파일 유형을 지원한다
면, 운영체제는 파일에 대해 합리적인 연산을 수행할 수 있다. 예를 들어, 시스템이 텍스트
파일과 목적 코드 파일을 다르게 인식할 수 있다면 이진 목적 코드를 출력하려는 엉뚱한
AEE 미리 막을 수 있을 것이다. 이 시도는 통상 쓰레기를 생산할 것이다. 만일 운영체
제가 이진 목적 프로그램이라는 것을 미리 알고 있다면 이러한 일은 방지될 수 있다.
흔히 잘 알려진 방법은 파일 이름의 한 부분이 파일 유형을 나타내도록 하는 것이
다. 파일 이름이 마침표로 구분되는 이름과 확장자(660ㅁ5100) 두 부분으로 나뉘게 된다
(그림 13.3). 이 방식에서는 이것만으로도 파일의 유형이 무엇인지 알 수 있게 된다. 대
부분 운영체제에서 사용자는 마침표와 추가적인 확장자의 파일 이름을 사용할 수 있다.
resume .docx, server.c, ReaderThread.cpp/} 그와 같은 예이다.

시스템은 파일 유형에 따라 파일 연산 명령을 결정한다. 예를 들면, com, .exe,
.sh 확장자를 가진 파일들은 수행 파일로서 이 확장자를 가진 파일만이 실행 가능하다.
.com, .exe 파일은 이진 형태의 수행 파일이지만 sh 파일은 운영체제에 전달되는 명
령을 ASCII 형식으로 저장하고 있는 A 스크립트이다. 응용 프로그램들 자신들에게 필
요한 파일 유형을 나타내기 위하여 확장자를 사용한다. 1308 컴파일러는 소스 파일의
이름에 java 확장자가 들어 있다고 가정하고, Microsoft Word .doc 또는 .docx
확장자를 가져야 한다. 이러한 확장자는 필수적인 것은 아니며, 따라서 사용자가 (타이
핑을 절약하기 위해) 확장자 없이 파일을 지정하면 응용 프로그램이 주어진 이름과 자
신이 기대하는 확장자를 가진 파일을 찾는다. 이들 확장자는 운영체제가 지원하는 것
은 아니기 때문에, 이들은 응용 프로그램이 동작하는 파일들에 대한 “힌트”로 생각될 수
