그림 2.11 • 웹 개시를 통한 클라이언트의 객체 요청
2.2 • 벨과 HTTP
기점
서버
기점
서버
브라우저는 웹 개시와 TCP 연결을 설정하고 웹 개시에 있는 객체에 대한 HITP
요청을 보낸다.
2. 웹 개시는 객체의 사본이 자기에게 저장되어 있는지 확인한다. 만일 저장되어 있다
면 웹 개시는 클라이언트 브라우저로 HTTP 응답 메시지와 함께 객체를 전송한다.
3. 만약 웹 개시가 객체를 가지고 있지 않다면, 웹 개시는 원출처의 서버인 www.
someschool . edu로 TCP 연결을 설정한다. 그리고 나서 웹 개시는 개시와 서
버 간의 TCP 연결로 객체에 대한 HTTP 요청을 보낸다. 이러한 요청을 받은 후에
기점 서버는 웹 개시로 HTTP 응답 메시지와 함께 객체를 보낸다.
4. 웹 개시가 객체를 수신할 때, 객체를 지역 저장장지에 복사하고 클라이언트 브라
우저에 HITP 응답 메시지와 함께 객체의 사본을(클라이언트 브라우저와 웹 개시
사이에 이미 설정된 TCP 연결을 통해) 보낸다
개시는 서버이면서 클라이언트라는 점을 유의해야 한다. 브라우저로부터 요구를 받고
응답을 보내는 것은 서버이고, 출처 서버에게 요구를 보내거나 응답을 받는 것이 클라
이언트이다.
일반적으로 웹 개시는 ISP가 구입하고 설치한다. 예를 들어, 대학교는 캠퍼스 네
트워크에 웹 개시를 설치하고 모든 캠퍼스의 브라우저가 이 개시로 요청을 보내도록
설정한다. 또한 컴개스트(comcast)와 같은 주요 가정 ISP는 하나 이상의 개시를 네트
워크상에 설치하고 설치된 개시를 가리키도록 브라우저를 미리 설정한다.
웹 개성은 인터넷상에서 다음과 같은 이유로 즐겨 사용되어 왔다. 첫째, 웹 개시는
클라이언트의 요구에 대한 응답 시간을 줄일 수 있다. 특히 클라이언트와 원출처 서버
사이의 병목 대역폭이 클라이언트와 개시 사이의 병목 대역폭에 비해 매우 작을 때 더
욱 효과적이다. 클라이언트와 개시 사이에 높은 속도의 연결이 설정되어 있고(보통 그
러하듯이) 개시가 요청된 객체를 가지고 있다면, 개시는 그 객체를 클라이언트로 매우
신속하게 전달할 수 있다. 둘째, 웹 개시는 한 기관에서 인터넷으로 접속하는 링크상의
웹 트래픽을 대폭으로 줄일 유있다(이후에 예와 함께 설명할 것이다). 트래픽을 줄여
