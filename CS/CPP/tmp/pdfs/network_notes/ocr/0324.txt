대APTER04 • 네트워크 계층 . 데이터 평면
WAN에서 같은 목적지 IP 주소를 갖는 NAT 라우터(구체적으로는 NAT 라우터의
WAN 쪽 인터페이스며 모든 데이터그램이 도착하면, 라우터가 주어진 데이터그램을
전달하는 내부 호스트를 알 수 있는 방법은 무엇인가? 비결은 NAT 라우터에서 NAT
변환 데이*(NAT translation table)을 시용하고, 그 테이블에 IP 주소와 포트 번호를
포함하는 것이다.
그림 4.25의 예를 생각해 보자. A卜&자 입장에서 호스트 10.0.0.1인 홈 네트워크가
IP 주소 128.119.40.186인 웹 서버(포트 80)에게 웹 페이지를 요청한다고 가정하자.
호스트 10.0.0.1은 임의의 출발지 포트 번호 3345를 할당하고 LAN에 데이터그램을
보낸다. NAT 라우터는 데이터그램을 믿아서, 데이터그램에 대한 새로운 출발지 포트
번호 5예1을 생성하고, WAN 쪽 IP주소 138.7629.7과 출발지 IP 주소를 변경하괴
새 출발지 포트 번호 5001과 원래 출발지 포트 번호 3345를 변경한다. 새 출발지 포트
번호를 생성할 때, NAT 라우터는 NAT 변환 테이블에는 없는 모든 출발지 포트 번호
를 선택할 수 있다(포트 번호의 필드가 16비트로 길기 때문에 NAT 프로토콜은 라우터
에 대한WAN 쪽 한 IP 주소에 대해 60,0(尠개 이상의 동시 접속을 지원한다). 라우터
내부의 NAT에는 NAT 해석 테이블의 엔트리도 추가된다. NAT 라우터에 의해 처리된
HITP 요청이 들어 있는 데이터그램의 도착을 의식하지 못한 웹 서버는 NAT 라우터
의 IP 주소인 목적지 주소와 5001 인 목적지 포트 번호에 대해 응답한다. 이 데이터그
램이 NAT 라우터에 도착했을 때, 라우터는 홈 네트워크 브라우저의 IP 주소(10.0.0.1)
와 목적지 포트 번호(3345)로부터 얻은 목적지 IP 주소와 목적지 포트 번호를 사용해
서 NAT 변환 테이를을 작성한다. 라우터는 데이터그램의 목적지 주소와 포트 번호를
다시 기록하고, 홈 네트워크 내부로 데이터그램을 전달한다.
NAT는 최근에 폭넓게 쓰이지만 반대하는 사람이 없는 건 아니다. 그들은 주장은
다음과 같다. 포트 번호가 호스트 주소 지정이 아닌 프로세스 주소 지정에 사용된다는
것이다. 2장 애플리케이션 계층에서 보았듯이 서버 프로세스는 잘 알려진 포트 번호에
서 요청이 올 때까지 기다리고 P2P 프로토콜의 피어는 서버로서의 역할을 할 때 들어
오는 연결을 수락해야 하기 때문에 홈 네트워크에서 실행되는 서버에 문제가 발생할
수 있다. 이 문제의 기술적인 해결책으로는 NAT 순회(traversal) 도구[RFC 5389]와
호스트가 가까운 NAT lUPnP Forum 201 이를 발견하고 구성하게 해주는 프로토콜인
범용 플러그 앤 플레이(UPnP)가 있다.
구성 순수주의자들은 NAT에 반대하여 많은 “철학적” 논쟁을 제기하였다. 여기서
라우터는 3계층(네트워크 계층) 장지를 의미하며 네트워크 계층까지만 패킷을 처리해
야 한다는 점이 중요하다. NAT는 IP 주소를 수정하는 노드를 간섭하지 않고 수
보다 훨씬 적은 수의 호스트가 서로 직접 소통해야하는 원칙을 위반한다. 그러나 이것
과 상관없이 NAT는 네트워크 계층에서 작용하지만 라우터와 상당히 다른 기능-을 가
지는 미들박±[Sekar 2011]와 마찬가지로 인터넷의 중요한 구성요소가 되지 않는다.
미들 박스는 기존의 데이터그램 전달을 수행하지 않지만 대신 트랙픽 흐름 부하
분산과 트래픽 방화벽(사이드 바 참조) 등의 기능-을 수행한다. 4.4절에 곧 공부할 일반
화된 전달 패러다임을 미들박스의 많은 기능을 기존의 라우터 전달과 마찬가지로 공통
의 통합된 방법으로 달성할 수 있게 한다.
