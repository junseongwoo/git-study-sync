위에 구글이 직접 설계한 SDN 제어 평면을 가지고 있다. 구글 네트워크는 장기적으로 약 70 %

용들의 우선 순위와 현재 플로우들의 요구사힝에 기반하여 여러 개의 경로로 나눌 수 있다(Jain
20131.
구글 B4 네트워크는 다음의 세 가지 이유로 특별히 SDN과 잘 어울린다: (i) 구글은 IXP와
ISP의 에지 서버부터 그들의 네트워크 중심 부분의 라우터까지 모든 장치들을 제어한다; (li) 대역
폭을 많이 사용하는 대부분의 응용들은 사이트 간에 대량의 데이터를 복사하는데 이는 자원의 혼
잡 상황에서 높은 우선순위의 대화형 응용에 지연을 일으킨다; (iii) 수십 개의 데이터 센터만 연결
되어 있어서 중앙 집중식 제어가 가능하다.
구글 B4 네트워크는 주문 제작한 스위치를 사용하는데, 각 스위치는 그림 5.2에서 보았던 제
어 에이전트와 유사한 로컬 오픈 플로우 에이전트 (Open Flow Agent; OF시를 가지고 있고
오픈플로우의 약간 확장된 버전을 구현하고 있다. 이어서 각 OFA는 데이터 센터 사이의 데이터
센터 트래픽을 전달하는 네트워크와 구별되는 별도의 “대역 외(out-of-band)” 네트워크를 이용
해 네트워크 제어 서버(NCS)의 오픈플로우 컨트롤러(OFC)에 연결된다. OFC는 NCS가 제어받
는 스위치와 통신하기 위해 사용하는 서비스를 제공하며, 이는 그림 5.15에 나와 있는 SDN 아키
텍처의 최하위 계층과 유사하다. B4에서는 OFC가 상태 관리 기능까지 수행하면서 노드와 링크
의 상태를 Network lnformation Base (NIB)에 유지한다. 구글의 OFC 구현 방식은 ONIX
SDN 컨트를러[Koponen 201이에 기반한다. 두 가지 라우팅 프로토콜 BGP(데이터 센터 간
라우팅을 위해)와 IS-IS (OSPF의 가까운 친척으로 데이터 센터 내 라우팅을 위해 사용)가 구현
되어 있다. 장애 대응 목적으로 NCS의 복사본을 만들기 위해 Paxos [Chandra 200기가 사용
된다.
트래픽 조정을 위한 네트워크 제어 응용은 논리적으로 네트워크 제어 서버 집합의 상부에 위치
하면서 이 서버들과 상호 작용하여 응용 플로우 그룹들에 네트워크 전역의 대역폭 정보를 제공한
다. B4를 통해 SDN은 글로벌 네트워크 제공 업체의 운영 네트워크로 중요한 도약을 이루었다.
B4에 대한 자세한 설명은 [Jain 201 이을 보기 바란다.
엔트리와 일치한 패것 중에서도 일부는 그에 대한 작업을 수행하기 위해 컨트롤러
에게 보내지기도 한다. 이 메시지는 그러한 패킷을 컨트롤러에게 보내기 위해 사
