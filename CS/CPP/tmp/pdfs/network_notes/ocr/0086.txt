작성할 것이다.
클라이언트-서버 구조(clicnt-scrvcr architccture)에서 형상 켜져 있는 호스트르
서버(sen,e,)라고 부르는데, 이 서비스는 클라이언트(c/ie,it)라는 다른 많은 호스트의 요
청을 받는다. 클리-ÖI언트 호스트는 가꿈 혹은 항상 거져 있을 수 있다. 고전적인 예는
클라이언트 호스트에서 실행되는 브라우저가 항상 켜진 웹 서버로 서비스를 요청하는
웹 애플리케이션이다. 웹 서버가 클리이언트 호스트로부터 객체를 요청받으면 웹 서버
는 클라이언트 호스트로 요청된 객체를 보내어 응답한다. 글리이언트-서버 구조에서
클라이언트는 서로 직접적으로 통신하지 않는다는 것에 주목하라. 예를 들이, 웹 애플
리게이션에서는 2개의 브라우저가 직접적으로 통신하지 않는다. 클라이언트-서버 구
조의 다른 특징은 서버가 고정 IP 주소라는 잘 알려진 주소를 갖는다는 것이다. 서버는
항상 동작하므로 클라이언트는 서버 주소로 패것을 보내서 항상 서버에 연결할 수 있
다. 클라이언트-서버 구조를 가지고 더 잘 알려진 에플리게이션으로는 웹, 파일 전송,
원격 로그인, 전자메일이 있다. 이 클라이언트-서버 구조는 그림 2.2(a)에 나타나 있다
때때로 클라이언트-서버 에플리게이션에서 하나의 서버 호스트가 자신의 클라이
언트로부터의 모든 요청에 응답하는 것은 불기능하다. 예를 들어, 인기 있는 새로운 웹
사이트가 하나의 서버로만 요청을 처리한다면 급속히 서버가 제대로 작동하지 못할 수
있다. 이러한 이유로 많은 수의 호스트를 갖춘 데이터 센터(data center)가 강력한 가
상의 서버를 생성하는 데 흔히 시용된다. 검색 엔진(예: 구글과 빙, 바이두), 인터넷 상
거래(예: 아마존과 이베이, 알리바바), 웹 기반 전자메일(예: 지메일과 야후메일), 소설
네트워킹(예: 페이스북, 인스타그램, 트위터, 그리고 위챗)과 같은 인기 있는 서비스들
은 하나 이상의 데이터 센터를 시용한다. 1.3.3절에서 논의한 바와 같이, 구글은 전 세
계적으로 분산된 30~50개의 데이터 센터를 갖고 있으며, 집단적으로 검색, 유튜브,
지메일, 그리고 다른 서비스들을 다룬다. 데이터 센터는 전력이 공급되어야 하고 관리
되어야 하는 10만 개 정도의 서버를 갖추고 있다. 추가적으로 서비스 제공자들은 데이
터 센터로부터 데이터를 보내기 위해 상호연결과 대역폭에 대한 비용을 지불해야 한다.
P2P 구조에서는 항상 켜져 있는 기반구조 서버에 최소로 의존한다(혹은 전혀 의
존하지 않는 다). 대신에 애플리게이션은 피어(peer)라는 간혈적으로 연결된 호스트 쌍
이 서로 직접 통신하도록 한다. 피어는 서비스 제공자(service provider)가 소유하지
않고, 사용자들이 제어하는 데스크톱과 랩톱이다. 대부분의 피어들은 가정, 대학 그리
고 사무실에 한한다. 특정 서버를 통하지 않고 피어가 통신하므로 이 구조를 피어-
투-피어(peer-to-peer, P2P)라고 한다. 오늘날의 많은 인기 있고 트래픽 집중적인 애
