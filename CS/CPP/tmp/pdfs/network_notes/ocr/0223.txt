3.52 TCP 세그먼트 구조
TCP 연결을 간단히 살펴보0갔으므로, 이제 TCP 세그먼트 구조를 검토해 보자. Tcp
세그먼트는 헤더 필드와 데이터 필드로 구성되어 있다. 데이터 필드는 한 줌의 애플리
게이션 데이터를 담는다. 위에서 언급된 것처럼, MSS는 세그먼트의 데이터 필드의 그
기를 제한한다. TCP가 웹 문서의 이미지와 같은 큰 파일을 전송할 때, 일반적으로
MSS 크기로 파일을 쪼갠다(MSS보다 작은 마지막 묶음은 제외). 그러나 많은 대화식
애플리케이션은 MSS보다 작은 데이터 덩어리를 전송한다. 예를 들면, 텔넷과 같은 원
격 로그인에서는 종종 TCP 세그먼트 안의 데이터 필드는 오직 1바이트를 가진다.
TCP 헤더는 일반적으로 20바이트(UDP 헤더보다 12바이트 크다)이므로, 텔넷에 의해
전송되는 세그먼트는 단지 21 바이트 길이가 된다.
그림 3.29는 TCP 세그먼트의 구조를 보여 준다. UDP처럼 헤더는 상위 계층 애플
리게이션으로부터 다중화와 역디중회를 하는 데 A卜&하는 출발지(source)와 목적지
(destination) 포트 번호를 포함한다. 또한 UDP처럼 헤더는 체zå}(checksum) 필드
를 포함한다. TCP 세그먼트 헤더는 또한 다음과 같은 필드를 포함한다.
32비트 순서번호 필드(sequence number field)와 32비트 확인응답번호 필드(ac-
knowledgement number field)는 전에 논의한 것처럼 신뢰적인 데이터 전송 서
비스 구현에서 TCP 송신자와 수신자에 의해서 시용된다.
16비트 수신 원도우(receive window) 필드는 흐름제어에 久卜용된다. 이는 수신자
가 받아들이려는 바이트의 크기를 나타내는 데 A卜&된다는 것을 곧 보게 될 것이
다.
4비트 헤더 길이(header length) 필드는 32비트 워드 단위로 TCP 헤더의 길이를
나타낸다. TCP 헤더는 이전에 논의한 TCP 옵션(叩tion) 필드 때문에 가변적인 길
이가 될 수 있다(일반적으로, 옵션 필드는 일반적인 TCP의 길이가 20바이트가 되
도록 비어 있다).
선택적이고 가변적인 길이의 옵션(option) 필드는 송신자와 수신자가 최대 세그
먼트 크기(MSS)를 협상하거나 고속 네트워크에서 사용하기 위한 원도우 확장 요
소로 이용된다. 타임스탬프 옵션 또한 정의된다. 부가적인 자세한 사항은 RFC
854와 RFC 1323을 참조하라.
