기7 • 소켓 프로그래밍: 네트워크 0H를리게이션 생성
한다. TCP 연결의 한쪽은 클라이언트 소켓에 연결되고 다른 쪽은 서버 소켓에 연결된
다. TCP 연결을 생성할 때 클라이언트 소켓 주소(IP 주소와 포트 번호)와 서버 소켓
주소(IP 주소와 포트 번화를 연결과 연관시킨다(associate). TCP 연결이 설정된 후,
한쪽에서 다른 쪽으로 데이터를 보내려면 소켓을 통해 데이터를 TCP 연결로 보내면
된다. 이것이 UDP와 다른 부분이며, UDP에서는 서버가 패것을 소켓에 제공하기 전
에 패킷에 목적지 주소를 붙여야 한다.
이제 TCP에서의 클라이언트와 서버 프로그램의 상호작용에 대해 보다 자세히 살
펴보자. 클라이언트는 서버로의 접속을 먼저 시도한다. 서버는 클라이언트의 초기 접
속에 응대할 수 있도록 준비하고 있어야 한다. 여기에는 두 가지 의미가 있다. 첫째,
UDP에서와 마찬가지로, TCP 서버는 클라이언트가 접속을 시도하기 전에 프로세스를
먼저 수행하고 있어야 한다. 둘째, 서버 프로그램은 임의의 컴퓨터에서 수행되고 있는
클라이언트로부터의 초기 접속을 처리하는 특별한 출입문(즉, 특별한 소켓)을 가져야
한다. 프로세스/소켓에 대한 집과 출입문의 비유를 이용해서 종종 클라이언트의 초기
접속을 “출입문을 두드리는 것"으로 표현한다.
서버 프로세스가 수행되면 클라이언트 프로세스는 서버로의 TCP 연결을 시도한
다. 이는 클라이언트 프로그램에서 TCP 소켓을 생성함으로써 가능하다. 클라이언트는
TCP 소켓을 생성할 때 서버에 있는 환영(welcome) 소켓의 주소, 즉 서버의 IP 주소와
소켓의 포트 번호를 명시한다. 소켓을 생성한 후 클라이언트는 세 핸
드세이그를 하고 서버와 TCP 연결을 설정한다. 전송 계층에서 일어나는 세 방향 핸드
세이그를 클라이언트와 서버 프로그램은 전혀 인식하지 못한다.
세 핸드세이크 동안 클라이언트 프로세스는 서버 프로세스의 출입문을 두드
린다. 서버가 노크(knokmg)를 “들으면”, 서버는 새로운 출입문(door)-즉, 해당 클라
이언트에게 지정되는 새로운 소켓을 생성한다. 다음 예에서 출입문은 serversock-
et이라는 TCP 소켓 객체이다. 연결을 시도하는 클라이언트에게 지정된 새로 생성된
소켓을 connectionsocket이라 한다. 처음으로 TCP 소켓을 접하는 학생들은 가
꿈 (서버와 통신하고자 하는 모든 클라이언트가 초기에 접속하는 곳인) 환영 소켓과 각
클라이언트와 통신을 위해 차후에 서버 쪽에 새롭게 생성되는 연결 소켓을 혼동한다.
애플리케이션 관점에서 볼 때 클라이언트의 소켓과 서버의 연결 소켓은 파이프
(pipe)에 의해 직접 연결된다. 그림 2.28에 보인 것처럼, 클라이언트 프로세스는 자신
의 소켓으로 임의의 바이트를 보낼 수 있으며 보낸 순서대로 서버 프로세스가 바이트
를 (연결 소켓을 통해) 수신하도록 TCP가 보장한다. 따라서 TCP는 클라이언트와 서
버 프로세스 간에 신뢰적(reliable) 서비스를 제공한다. 또한 사람이 같은 문으로 드나
드는 것처럼, 클라이언트 프로세스는 소켓으로 바이트를 보낼 수 있을 뿐만 아니라 소
켓으로부터 바이트를 수신할 수 있다. 마찬가지로, 서버 프로세스도 연결 소켓으로부
터 바이트를 수신할 수 있을 뿐만 아니라 연결 소켓으로 바이트를 보낼 수 있다.
TCP 소켓 프로그래밍을 보여 주기 위해 앞서와 같은 간단한 클라이언트-서버 애
플리게이션을 시용한다. 클라이언트는 서버로 한 라인의 데이터를 보내고 서버는 그것
을 대문자로 변환해서 다시 클라이언트에게 보낸다. 그림 2.29는 TCP 전송 서비스를
통해 통신하는 클라이언트와 서버의 주요 소켓 관련 동작을 보여준다.
