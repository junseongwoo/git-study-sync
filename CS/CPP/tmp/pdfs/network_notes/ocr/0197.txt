그림 3.8 • 신뢰적인 데이터 전송: 서비스 모델과 서비스 구현
rdt rcv()
비신뢰적인 채널
b. 서비스 구현
이 절에서는 점점 복잡해지는 하위 채널 모델을 고려하는 신뢰적인 데이터 전송
프로토콜의 송신자 측면과 수신자 측면을 점진적으로 개발해 나갈 것이다. 예를 들면,
하위 채널에서 비트가 손상되거나 또는 전체 패킷을 손실하는 경우, 어떠한 프로토콜
메커니즘이 필요할지를 고려할 것이다. 우리가 여기서 논의하는 과정에서 채택한 한
가지 가정은 보내어진 패킷은 일부 손실될 수도 있겠지만 보내어진 순서대로 전달될
것이라는 것이다. 즉, 하부 채널은 패킷의 순서를 바꾸지 않는다는 것이다. 그림 33(b)
는 데이터 전송 프로토콜에 대한 인터페이스를 나타낸다. 데이터 전송 프로토콜의 송
신 측은 rdt send() 호출에 의해서 위쪽으로부터 호출될 것이다. 수신 측에서는
상위 계층으로 전달될 데이터를 넘길 것이다. [여기에서 rdt는 신뢰적인 데이터 전송
(reliable data transfer) 프로토콜을 나타내고 send는 rdt의 송신 측이 호출되고
있다는 것을 나타낸다. 어떤 프로토콜을 개발하는 데 있어 첫 번째 단계는 좋은 이름을
선택하는 것이다.] 수신 측에서 rdt rcv()는 패킷이 채널의 수신 측으로부터 도착
했을 때 호출된다. rdt 프로토콜이 상위 계층에 데이터를 전달하려고 할 때 deliv-
er-data()를 호출한다. 이제부터 프로토콜 데이터 단위에 대해 “세그먼트보다는
“패킷”이라는 용어를 시용한다. 왜냐하면 이 절에서 전개된 이론은 대체로 컴퓨터 네
트워크에 적용하는 것이고, 단지 인터넷 트랜스 포트 계층에만 적용하는 것이 아니므
로, 여기에서는 일반 용어인 “패것”이 더 적절하다고 본다.
