2.4 • DNS-인터넷의 디렉터리 서비스
이 예로부터 DNS는 DNS# 사용하는 인터넷 에플리게이션에게 추가 지연을 준
다는 것을 볼 수 있다. 다행스럽게도. 다음에 논의하는 것처럼 원하는 IP 주소는 “가까
운” DNS 서버에 개시(cache)되어 있어서 평균 DNS 지연뿐 아니라 PNS—tdl트위三L트
래픽 감소에 도움을 준다.
DNS는 호스트 네임을 IP 주소로 변환하는 것 외에 다음과 같은 중요한 추가 서비
스를 제공한다.
호스트 엘리어성(host aliasing): 복잡한 호스트 네임을 가진 호스트는 하나 이상
의 별명을 가질 수 있다. 예를 들어, relayl.west-coast.enterprise.
com 같은 호스트 네임은 enterprise. com과 www. enterprise. com 같
은 2개의 별칭을 가질 수 있다. 이 경우에 호스트 네임 relayl .west-coast•
enterprise. com은 정식 호스트 네임(canonical hostname)이라고 한다. 별
칭 호스트 네임은 정식 호스트 네임보다 대체로 기억하기 쉽ch DNS는 호스트의
1P 주소뿐만 아니라 제시한 별칭 호스트 네임에 대한 정식 흐人E,. 네임을 얻71우
해 이용될 수 있다.
메일 서버 엘라어성(mai| server aliasing): 전자메일 주소는 기억하기 쉬운 것이
좋다. 예를 들어, 밥이 핫메일에 계정을 가졌다면, 밥의 전자메일 주소는 bob@
hotmail . com처럼 간단할 것이다. 그러나 핫메일 서버의 호스트 네임은 더 복
잡하고, 간단한 hotmail • com보다 기억하기가 쉽지 않다며: 정식 호스트 네임
이 relayl .west-coast . hotmail . com과 같을 수 있다). DNS는 호人E
의 IP 주소뿐만 아니라 제공된 별칭 호스트 네임에 대한 정식 호스트 네임을 얻기
위해 메일 애플리케이션에 의해 수행된다. 사실 MX 레코드는 기업의 메일 서버와
웹 서버가 같은 호스트 네임(별칭)을 갖는 것을 허용한다. 예를 들어, 기업 웹 서버
와 메일 서버는 enterprise . com 스타일이라고 부를 수 있다.
부하 분산(load distribution): DNS는 중복 웹 서버 같은 여러 중복 서버 사이에
부하를 분산하기 위해서도 사용되고 있다. cnn. co飜과 같은 인기 있는 사이트는
여러 서버에 중복되어 있어서, 각 서버가 다른 종단 시스템에서 수행되고 다른 IP
주소를 갖는다. 중복 웹 서버의 경우, 여러 IP 주소가 하나의 정식 호스트 네임과
연관되어 있다. DNS 데이터베이스는 이 IP 주소 집합을 갖고 있다. 클라이언트가
주소 집합으로 매핑하는 호스트 네임에 대한 DNS 질의를 하면, 서버는 IP 주소
집합 전체를 가지고 응답한다. 그러나 각 응답에서의 주소는 순환식으로 보낸다.
클라이언트는 대체로 주소 집합 내부의 첫 번째 IP 주소로 HTTP 요청 메시지를
보내므로, DNS의 순환 방식은 여러 중복 서버들 사이에서 트래픽을 분산하는 효
과를 낸다. DNS 순환 방식은 전자메일에서도 사용되어 여러 메일 서버가 동일한
별칭을 가질 수 있다. 아가마이(Akamai)와 같은 컨텐츠 분배 회사는 웹 컨텐츠 분
산을 제공하기 위해 좀 더 세련된 방법으로[Dilley 2Ⅸ)21 DNS를 이용하고 있다
(2.6.3절 참조).
