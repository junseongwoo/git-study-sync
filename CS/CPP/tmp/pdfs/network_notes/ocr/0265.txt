공평성과UDP
우리는 오로지 혼잡 윈도우 메커니즘을 통해 TCP 혼잡제이가 어떻게 애플리케이션의
전송률을 조절하는지를 살펴보았다. 많은 멀티미디어 애플리케이션이 이러한 이유 때
문에 TCP를 이용하지 않는다. 이들은 비록 네트워크가 혼잡하더라도 자신의 전송률이
조절되는 것을 원하지 않는다. 대신에 이들 에플리게이션은 오히려 혼잡제이를 가지고
있지 않은 UDP상에서 동작하는 것을 좋아한다. UDP상에서 동작할 때, 애플리케이션
은 혼잡할 때 “공평한” 레벨로 그들의 등급을 낮추고 어떠한 패것도 손실하지 않기보
다는 일정한 속도로 네트워크에 오디오와 비디오를 공급하기를 좋아하고 가끔 패킷을
손실한다. TCP의 관점에서 보면 UDP상에서 수행되는 멀티미디어 애플리케이션은 공
평하지 못하다. 이것은 다른 연결들과 협력하지도 않으며, 그들 의 전송률을 적당하게
조절하지도 않는다. TCP 혼잡제어는 혼잡(손실) 증가에 대하여 전송률을 감소시기고,
UDP 출발지는 그렇게 할 필요가 없으므로 TCP 트래픽을 밀어낼 기능성이 있다. 오늘
날 연구의 주요 분야는 UDP 트래픽으로 인해 인터넷이 마비되는 것을 방지하는 인터
넷을 위한 혼잡제어 방식을 개발하는 것이다[Floyd 1999; Floyd 20%; Kohler 2Ⅸ)6

공평성과 병렬 TCP 연결
만약 우리가 UDP 트래픽이 공평하게 행동하도록 강요하더라도, 공평성 문제는 여전
히 완전하게 해결되지 않았을 것이다. 이것은 TCP 기반 애플리케이션이 다중 병렬연
결의 시용을 막을 방법이 없기 때문이다. 예를 들어, 웹 브라우저는 종종 웹 페이지에
다중 객체를 전송하기 위해 다중 병렬 TCP 연결을 시용한다(니중 연결의 정확한 수는
큰 브라우저에서 설정된다). 에플리게이션이 다중 병릴연결을 사용할 때, 혼잡한 링크
밴드폭의 큰 부분을 얻는다. 예를 들어, 9개의 진행 중인 클라이언트/서버 이1플리게이
션을 지원하는 전송률 R의 링크를 고려하자. 각 애플리케이션은 하나의 TCP 연결을
시용한다. 만약 새로운 애플리케이션이 만들어지고, 또한 하나의 TCP 연결을 시용한
다면, 각 애플리케이션은 대체로 같은 전송률 R/10을 얻는다. 그러나 만약 이 새로운
애플리케이션이 11개의 병렬 TCP 연결을 시용한다면, 새 애플리케이션은 R/2보다 많
은 불공평한 할당을 얻는다. 웹 트래픽이 인터넷에 널리 퍼져 있으므로 다중 병렬연결
은 흔히 있다.
