CHAPTER 03 • 트랜스포트 계층
보안초점
스캐닝
우리는 서버 프로세스가 원격 클라이언트의 접속을 위해 열려 있는 포트(open p酊t)에서 지속적
으로 기다리는 것은 보았다. 일부 포트들은 잘 알려진 애플리케이션을 위해 예약되어 있다(예.
Web, FTP, DNS, SMTP 서버). 또 다른 포트들은 관례에 따라 인기 있는 애플리케이션들에
의해 사용된다(마이크로소.프트 2000 SQL 서버는 UDP 포트 1434를 사용한다). 그러므로 한
포트를 호스트에서 열기로 결정하면, 그 포트를 호스트에서 실행되는 특정 애플리케이션에 매핑시
길 수 있다. 이것은 네트워크 애플리케이션이 그들의 네트워크에 있는 호스트에서 실행되고 있는
것을 아는 데 관심을 갖는 시스템 관리자에게 매우 유익하다. 그러나 “사전 모의”를 위한 공격자들
또한 어떤 포트들이 목표 호스트에서 열려 있는지 알기를 원한다. 이미 알려진 보안결점을 가진 애
플리케이션을 실행하는 호스트가 발견되면(포트 1434로 듣는 SQL 서버는 원격 사용자가 공격받
기 쉬운 호스트에 임의의 코드(SIammer worm [CERT 2003-04M 의해 이용되는 결점)를
실행시킹으로씨 버퍼 오버플로를 겪는다) 그 호스트는 공격에 쉽게 노출된다.
어떤 애플리케이션이 어떤 포트로 듣고 있는지 알아내는 것은 상대적으로 쉬운데, 실제로 포트
스캐너라고 불리는 수많은 공용 도메인 프로그램들을 단지 실행만 하면 된다. 아마도 이런 것 중에
가장 많이 사용되는 것은 nmap일 것이다. http://nmap.org/서 무료로 사용할 수 있으며 대
부분 리눅스 배포판에 들어 있다. TCP에서 nmap은 순차적으로 포트를 스캔하여, TCP 연결을
수락하는 포트를 찾는다. UDP에서, nmap 역시 순차적으로 포트를 스캔하여, 전송된 UDP 세
그먼트에 반응하는 UDP 포트를 찾는다. 두 경우 모두 nmap은 열려 있는 포트, 닫혀 있는 포트
또는 도달할 수없는 포드의 목록을 알려준다. nmap을 실행하는 호스트는 인터넷에 어디든지 어
떤 목표 호스트든지 스캔을 시도할 수 있다. 우리는 TCP 연결 관리를 설명하는 3.5.6절에서
nmap을 다시 살펴볼 것이다.
그림 3.5에서는 호스트 c가 서버 B로 2개의 HITP 세션을 시작하고, 호스트 A가
호스트 B로 하나의 HTTP 세션을 시작하는 상황이 설명되어 있다. 호스트 A와 호스트
c, 그리고 서버 B는 각자 유일한 IP 주소인 A, c, B를 각각 가지고 있다. 호스트- c는
2개의 다른 출발지 포트 번호(26145와 7532)를 자신의 HITP 연결에 할당한다. 호스
트 A는 C와 독립적인 출발지 포트 번호를 선택하므로, 이것 또한 HTTP 연결에 출발
지 포트로 26145를 할당할 수도 있다. 그렇게 하더라도, 2개의 연결은 다른 출발지 IP
주소를 가지므로, 서버 B는 동일한 출발지 포트 번호를 가진 두 연결을 여전히 올바르
게 역다중화할 수 있다.
웹 서버와 TCP
이 주제를 끝내기 전에, 웹 서버와 이 웹 서버가 어떻게 포트 번호를 八卜&하는지에 대
해서 몇 가지 유익한 사항을 살펴보자. 아파치 웹 서버(Apache web server)와 같은 웹
서버가 포트 번호 80상에서 동작하는 호스트를 고려해 보자. 클라이언트(예: 브라우
저)가 서버로 세그먼트를 보내면, 모든 세그먼트는 목적지 포트 번호 80을 가지고 있을
것이다. 특히, 초기 연결 설정 세그먼트들과 HTTP 요청 메시지를 전달하는 모든 세그
먼트들은 목적지 포트 번호 80을 가질 것이다. 앞에서 살펴본 것처럼, 서버는 각기 다
른 클라이언트가 보낸 세그먼트를 출발지 IP 주소와 출발지 포트 번호로 구별한다.
