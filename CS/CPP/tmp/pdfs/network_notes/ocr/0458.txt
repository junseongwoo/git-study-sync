그림 6.28을 보면 MPLS WMPLS-enhanced) 프레임이 MPLS 기능 라우터들
사이에서만 전송될 수 있음을 알 수 있디-(MPLS가 기능하지 않은 라우터는 IP 헤더가
존재해야 할 곳에서 MPLS 헤더를 발견하게 되면 매우 혼란스러울 것이다). MPLS 가
능 라우터는 MPLS 레이블을 포워팅 테이블에서 찾아 적당한 출력 인터페이스로 데이
터그램을 전달하여 MPLS 프레임을 전달하므로 종종 레이블 스위치 라우터(label•
switched router)라고 부른다. 그러므로 MPLS 기능 라우터는 목적지 IP 주소를 꺼내
볼 필요도 없괴 포워팅 테이블에서 최장 프리픽스 대응을 찾을 필요도 없다. 그런데
라우터는 어떻게 이웃 노드가 실제 MPLS 기능이 있는지 알 수 있을까? 그리고 라우
터는 주어진 목적지 IP 주소와 연계된 레이블이 무엇인지 어떻게 알 수 있을까? 이러
한 질문에 답하기 위해, MPLS 가능 라우터 간 상호동작에 대해서 알아보겠다.
그림 6.29의 예에서, RI부터 R4까지의 라우터들은 MPLS 기능이 있으며, 라우터
R5와 R6은 표준 IP 라우터이다. RI은 자신(RI)이 목적지 A까지 라우팅할 수 있고,
MPLS 레이블 6을 포함하는 프레임을 목적지 A로 전달할 수 있음을 R2와 R3에게 광
고한다. 라우터 R3은 자신이 목적지 A와 따지 라우팅할 수 있고, MPLS 레이를 10
과 12를 포함하는 입력 프레임을 각각 이들 목적지를 향해 스위칭할 수 있음을 라우터
R4에게 광고한다. 또한 라우터 R2는 목적지 A에 도달할 수 있고, MPLS 레이를 8을
포함하는 수신 프레임을 A로 스위칭할 수 있음을 라우터 R4에게 광고한다. 이제 라우
터 R4는, 출력 MPLS 레이를 10은 인터페이스 0, 출력 MPLS 레이를 8은 인터페이스
1을 통해 A에 도달할 수 있는 2개의 MPLS 경로를 갖게 된다. 스위치 랜 또는 ATM
네트워크가 IP 장치들을 연결해 주는 것과 같이, IP 장치 R5, R6, A, D가 MPLS 기반
구조(MPLS 가능 라우터들 RI, R2, R3, R4)를 통해 서로 연결되는 것이 그림 6.29에
나타나 있다. 스위치 랜 또는 ATM 네트워크처럼 MPLS 가능 라우터인 RI부터 R4는
패킷의 IP 헤더를 건드리지 않고 동작한다.
