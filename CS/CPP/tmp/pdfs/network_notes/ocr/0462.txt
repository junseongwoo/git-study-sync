플리게이션에 대한 요청을 받은 부하 균등화기는 해당 애플리케이션을 처리하는 호스
트 중 하나로 요청을 전달한니(그러면 호스트는 요청을 처리하기 위해서 다른 호스트
에게 도우을 청한다). 요청 처리를 마친 호스트는 부하 균등화기로 응답을 보내며, 부
하 균등화기는 응답을 외부 클라이언트로 전달한다. 부하 균등화기는 호스트 간 부하
균등화를 수행할 뿐만 아니라 호스트의 공용 외부 IP 주소를 내부 IP 주소로 변환해 주
고 클라이언트 쪽으로 역방향으로 가는 패킷의 내부 IP 주소를 공용 외부 IP 주소로 변
환해 주는 NAT와 유사한 기능을 제공한다. 이렇게 해서 클라이언트가 호스트와 직접
통신하지 못하게 하며, 내부 네트워크 구조를 숨기고 클라이언트가 호스트와 직접 상
호작용하지 못하게 함으로써 보안을 제공한다.
계층적 구조
단지 수천 개의 호스트만 갖고(housing) 있는 소규모 데이터 센터는 경계 라우터 1대,
부하 균등화기 1대, 단일 이더넷 스위치만으로도 모두 연결 기능한 수십 개의 랙으로
구성된 간단한 네트워크만으로도 충분할 수 있다. 수십만 대의 호스트까지 확장하기
위해서 데이터 센터는, 그림 6.30에 있는 토폴로지처럼 라우터와 스위치의 계층구조言
채택한다. 계층구조의 최상단에서는 경계 라우터가 접속 라우터들(그림 6.30에는 丁
대만 있지만 더 많이 있을 수 있다)에 연결된다. 접속 라우터 아래에는 세 단(tier)의 스
위치들이 있다. 접속 라우터는 최상단 스위치에 연결되고 최상단 스위치는 여러 개의
두 번째 단 스위치들과 부하 구등화기에 연결된다. 두 번째 단 스위치는 랙의 TOR 스
위치(세 번째 단 스위치)를 통해 여러 랙으로 연결된다. 일반적으로 모든 링크는 링크
계층 및 물리 계층 프로토콜로 이더넷(동선과 광게이블을 혼용)을 사용한다. 이러한 계
층구조 설계를 시용함으로써 데이터 센터는 수십 만 대의 호스트까지 확장할 수 있다.
클라우드 애플리케이션 제공자 입장에서는 애플리케이션의 가용성을 높게 유지하
는 것이 중요하기 때문에 데이터 센터 설계에 여분의 네트워크 장비와 링크를 포함시
킨다(그림 6.30에는 여분의 장비가 안 나타나 있다). 예를 들어, TOR 스위치는 2개의
2단 스위치에 연결되며, 접속 라우터, 1단 스위치, 2단 스위치를 이중으로 구성해서 통
합할 수 있다[Cisco 2012; Greenberg 2009b]. 그림 6.30의 계츄구조 설계에서 접속
라우터 밑의 호스트들이 하나의 서브넷을 형성하는 것을 볼 수 있다. ARP 브로드캐스
트 트래픽을 지역 내로 한정시기기(localize) 위해서 서브넷은 다시 작은 VLAN 서브
넷(수백 대의 호스트들로 구성)들로 분할된다[Greeberg 200%].
기존의 계층적 구조는 확장성 문제를 해결하기는 하지만 호스트-호스트(host•to•
host) 간 용량을 제한하는 문제가 있다[Greenberg 2009b]. 이러한 제한사항을 이해하
기 위해서 그림 6.30의 스위치들은 10 Gbps 이더넷 링크로 연결되어 있는 반면 호스
트는 1 Gbps 링크로 TOR 스위치에 연결되어 있다고 가정해 보자. 같은 랙에 있는 두
호스트는 1 Gbps 최대 속도로 항상 통신할 수 있다(호스트의 네트워크 인터페이스 카
드의 속도에 의해서만 제한된다). 그러나 데이터 센터 네트워크에 동시에 여러 개의 플
로우가 있는 경우 다른 랙에 있는 두 호스트 간 최대 전송률은 훨씬 작아질 수 있다. 이
러한 문제를 좀 더 깊이 이해하기 위해서 다른 랙에 있는 40개의 호스트쌍(host pmr)
