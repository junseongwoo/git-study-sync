CHAPTER04 • 네트워크 계층 • 데이터 평면
직접 제어해서 입력 포트와 출력 포트 사이에서 패킷을 스위칭하는 전-통적인 컴퓨
터이다. 입력 포트와 출력 포트는 전통적인 운영 체제에서 전통적인 1/0 장치처럼
작동한다. 패킷이 도착하면 입력 포트는 라우팅 프로세서에게 인터럽트를 보내 패
것을 프로세서 메모리에 복사한다. 그 다음 라우팅 프로세서는 헤더에서 대상 주
소를 추출하고 포워팅 테이블에서 적절한 출력 포트를 찾은 다음 패킷을 출력 포
트의 버퍼에 복사한다. 이 시나리오에서 메모리 대역폭이 초당 최대 B인 패킷을
메모리에 쓰거나 메모리에서 읽을 수 있는 경우 전체 전달 처리랑(패것이 입력 포
트에서 출력 포트로 전송되는 총 속도)은 B/2보다 작이야 한다. 또한 목적지 포트
가 다른 경우라도 공유 시스템 버스를 통해 한 번에 하나의 메모리 읽기/쓰기 작업
을 수행 할 수 있기 때문에 두 패킷을 동시에 전달할 수 없다.
최근 라우터 중 일부는 메모리를 통해 스위칭한다. 그러나 초기 라우터와의 주요
차이점은 대상 주소를 검색하고 해당 메모리 위지에 패킷을 저장하는 것이 입력
회선 카드에서 처리함으로써 수행된다는 것이다. 어떤 면에서 메모리를 통해 스위
칭하는 라우터는 공유 메모리 멀티 프로세서와 매우 흡사하다. 라인 카드에서 패
깃을 처리하여 적절한 출력 포트의 메모리로 스위칭(쓰기)한다. 시스코의 catalyst
85% 시리즈 스위치[Cisco 85% 2이6]는 내부적으로 공유 메모리를 통해 패킷을
스위칭한다.
버스를 통한 교환: 이 접근 방식에서, 입력 포트는 라우팅 프로세서의 개입 없이 공
유 버스를 통해 직접 출력 포트로 패킷을 전송한다. 이는 일반적으로 미리 준비된
입력 포트 스위치 내부 라벨(헤더)이 로컬 출력 포트를 나타내는 패킷에게 전송되
거나 버스에 패킷을 전송하여 수행된다. 모든 출력 포트에 패킷이 수신되지만 라
벨과 일치하는 포트만 패킷을 유지한다. 라벨은 스위치 내에서 버스를 통과하기
위해서만 시용되므로 출력 포트에서 제거된다. 동시에 여러 패킷이 다른 입력 포
트로 라우터에 도착하면 한번에 하나의 패킷만 버스를 통과할 수 있기 때문에 하
나를 제외한 모든 패킷이 대기해야 한다. 모든 패킷이 하나의 버스를 건너가야 하
口로, 라우터의 교환 속도는 버스 속도에 의해 제한된다. 원형 교차로에서 한번에
하나의 자동차만이 돌 수 있는 것과 유사하다. 그럼에도 불구하고 버스를 통한 스
위청은 종종 작은 지역 및 엔터프라이즈 네트워크에서 작동하는 라우터에서 사용
하기에 충분하다. 시스코 6500 라우터[Cisco 6500 2016]는 내부적으로 32 Gbps
백플레인 버스를 통해 패것들을 교환한다.
인터커넥션 네트워크를 통한 교환: 공유 버스의 대역폭 제한을 극복하는 한 가지 방
법은 이전의 다중 프로세서 컴퓨터 구조에서 프로세서를 인터커넥션하는 데 사용
된 것과 같은 보다 복잡한 인터커넥션 네트워크를 사용하는 것이다. 크로스바 스
위치는 그림 4.6에서와 같이 N개의 입력 포트를 N개의 출력 포트에 연결하는 2N
버스로 구성된 인터커넥션 네트워크이다. 각 수직 버스는 교차점에서 각 수평 버
