5.6 • 인터넷 제어 에시지 프로토콜(|CMP)
리와 유사하게 ONOS 컨트를러에서는 세 개의 계층을 구분할 수 있다.
• 노스바운드 추상화와 프로토콜. ONOS의 독특한 한 가지 특징은 의도(intent) 프레임워크
인데, 이는 응용이 해당 서비스가 구체적으로 어떻게 구현되는지 몰라도 높은 레벨의 서비스
(예를 들면, 어떤 호스트 A와 B 사이에 연결을 설정하거나, 반대로 호스트 A와 B의 통신을 허
락하지 않을 수 있음)를 요청할 수 있도록 해준다. 상태 정보가 노스바운드 API를 통과하여 네
트워크 제어 응용들에게 동기적(직접 질의를 통해) 또는 비동기적(예를 들어 네트워크 상태가
변화했을 때 알림 기능)으로 제공된다.
• 분산 코어. 네트워크 링크, 호스트, 장치들의 상태는 ONOS의 분산 코어에 유지된다.
ONOS는 상호 연결된 서버들의 집합에 서비스로서 설치되는데, 이들 서벽 각각은 ONOS 소
프트웨어의 동일한 사본을 수행한다. 서버의 개수가 늘어날수록 서비스 용량도 증가한다.
ONOS 코어는 서비스 복제와 인스턴스 간 협력 메커니즘을 제공함으로써 상부의 응용들과 하
부의 네트워크 장치들에게 논리적으로 중앙 집중화된 코어 서비스의 추상화를 제공한다.
사우스바운드 추상화와 프로토콜. 사우스바운드 추상호는 하부의 호스트 링크, 스위치 및
프로토콜의 이질성을 숨겨주어 분한 코어가 장치나 프로토콜 종류에 상관없이 동작할 수 있게
한다. 이 추상화 때문에 분산 코어 아래의 사우스바운드 인터페이스는 그림 5.14의 표준 컨트
롤러나 그림 5.17의 ODL 컨트롤러보다 논리적으로 높다.
인터넷 제어 메시지 프로토却CMP)
5.6
[RFC 792]에 정의된 인터넷 제어 메시지 프로토*(lnternet Control Message Proto-
col, ICMP)은 호스트와 라우터가 서로 간에 네트워크 계층 정보를 주고받기 위해 사
용된다. 가장 전형적인 사& 형태는 오류 보고이다. 예를 들어, HITP 연결을 수행할
때 “목적지 네트워크에 도달할 수 없음(Destination network unreachable)” 같은 오류
메시지를 본 적이 있을 것이다. 이 메시지는 ICMP가 만든 것이다. 네트워크의 어떤 지
점에서 IP 라우터가 HTTP 요청 메시지에 명시된 호스트로 가는 경로를 찾을 수 없었
다. 그 라우터가 여러분 호스트에게 오류가 발생했음을 알리기 위해 ICMP 메시지를
만들어서 보낸 것이다.
ICMP는 종종 1P의 한 부분으로 간주되지만, ICMP 메시지가 IP 데이터그램에 담
겨 전송되므로 구조적으로는 IP 바로 위에 있다. 즉, TCP나 UDP 세그먼트가 IP 페이
로드로 전송되는 것처럼 ICMP 메시지도 IP 페이로드로 전송된다. 비슷하게 호스트가
상위 계층 프로토콜이 ICMP라고 표시된(상위 계층 프로토콜 번호가 1 번인) IP 데이
터그램을 받으면 TCP나 UDP로 데이터그램 내용을 역다중화하는 것처럼 ICMP로 내
용을 역 다중화한다.
ICMP 메시지에는 타입과 코-드 필드가 있고, ICMP 메시지가 처음 생성되도록 한
IP 데이터그램의 헤더와 첫 8바이트를 가진다(송신자가 오류를 발생시킨 패킷을 식별
할 수 있도록 하기 위해). 중요한 ICMP 메시지 타입들이 그림 5.19에 나와 있다.
ICMP 메시지가 오류 상태를 알리기 위해서만 사용되는 것은 아니라는 점을 알아야
한다.
