5.4 • 인터넷 서비스 제공업자(|SP) 간의 라우팅: BGP
한 물리적 위치로의 서로 다른 경로에 대한 정보를 제공받고 있는 것처럼 생각한다 (사
실은 서로 다른 물리적 위치로의 서로 다른 경로이다). 각 라우터는 라우팅 테이블을
설정하면서 BGP 경로 선택 알고리즘을 수행하여 해당 IP 주소로의 “최고의” 경로(예
를 들면, AS 흡카운트 측면에서 가장 가까운 경로)를 골라낸다. 예를 들어 (어떤 위치
로의) 한 BGP 경로가 라우터로부터 단지 한 AS 홀 길이이고, (다른 위지로의) 모든
다른 경로가 두 AS 홀 이상의 길이라면 BGP 라우터는 한 떨어져 있는 위치로 패것
을 전송할 것이다. 이러한 최초의 BGP 주소 알림 단계 이후에 CDN은 주된 작업인 킨
텐츠 배포를 할 수 있다. 사岳자가 비디오를 요청하면 CDN은 사용자가 어디에 위치해
있든 상관없이 지리적으로 분산되어 있는 서버들이 공통적으로 A卜%하는 IP 주소를 사
용자에게 돌려준다. 사용자가 그 주소로 요청을 보내면 인터넷 라우터는 그 요청 패것
을 BGP 경로 선택 알고리즘이 정의한 가장 “가까운" 서버로 전달한다.
CDN을 이용한 위의 예가 IP 애니캐스트가 어떻게 사용되는지 잘 설명해 주기는
하지만, 실제로 CDN은 일반적으로 IP 에니개스트를 사용하지 않는다. 이유는 BGP
라우팅이 변경되면 하나의 TCP 연결에 속한 패것들이 웹서버의 서로 다른 복제본으로
도착될 수 있기 때문이다. 그러나 DNS 시스템에서는 DNS 질의를 가장 가까운 루트
DNS 서버로 전달하기 위해 IP 애니개스트가 광범위하게 사용된다. 2.4절에서, 현재
13개의 루트 DNS 서버 IP 주소가 있음-을 배웠다. 그러나 이들 주소 각각에 대해서도
여러 개의 DNS 루트 서버가 있다. 몇 개의 주소에 대해서는 1%개도 넘는 DNS 루트
서버들이 세계 곳곳에 흩어져 존재한다. DNS 질의가 13개의 IP 주소 중 하나로 전달
되면, 그 질의를 해당 IP 주소를 담당하는 DNS 루트 서버들 중 가장 가까운 서버에 전
달하기 위해 IP 애니개스트가 사용된다.
