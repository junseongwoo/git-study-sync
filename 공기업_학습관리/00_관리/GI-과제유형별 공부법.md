# 과제 유형별 공부법과 완료 기준

| 공부 | 먼저 할 일 | 직접 남길 근거 | 완료 판단 |
|---|---|---|---|
| 이론 | 용어3개와 예제1개를 먼저 읽기 | 중간 계산·코드 추적표 | 책을 닫고 조건과 결과 설명 |
| NCS | 대상·조건·분모·단위 표시 | 식과 보기별 근거 | 맞힌 이유와 틀린 보기 이유 설명 |
| 코딩 | 입력·출력·제약 적기 | 내 코드·실패 입력·복잡도 | 경계값 검증 후 독립성공/해설참고 구분 |
| SQL | 입력표와 결과표 예상 | SQL·행 수·NULL·동률 검산 | 조건을 바꿔도 맞는 이유 설명 |
| 서술형 | 조건→식→결론 작성 | 내 최초 답안과 항목별 점수 | 모범답안 문장을 외우기보다 근거로 자가채점 |
| 복습 | 답 없이 이전문제부터 재풀이 | 반복오류와 다음 행동 | 다음 공부에서 고칠 오류1개 선택 |

## 막혔을 때의 순서

1. 모르는 용어를1개로 좁히고 연결 장을 읽습니다.
2. 입력 크기나 조건을 줄여 손으로 추적합니다.
3. 힌트를 본 뒤 다시 시도합니다.
4. 해설을 봤다면 덮고 같은 예제를 재현합니다.
5. 새로운 쉬운 문제에 적용해야 이해를 확인할 수 있습니다.

## 난도 조정

처음 보는 기본문제10개 중8개와 풀이근거 설명을 진행 기준으로 사용합니다. 미달하면 다음 새 범위를 줄이고 오답·기초예제로 바꿉니다. 2시간을 늘리는 방식으로 보충하지 않습니다.

## 기록 예시

“JOIN 문제 틀림”보다 “고객1명과 주문3건의 1:N관계를 한 행으로 생각했다. 먼저 결과행3개를 그리기”라고 적습니다. “코딩 성공”보다 “음수만 있는 입력에서 최댓값 초기값0이 틀렸다. 첫 원소로 초기화해 재검사”라고 적습니다.
