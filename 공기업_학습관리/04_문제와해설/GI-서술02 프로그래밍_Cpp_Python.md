## W02Q01

C++17과 Python3에서 -5를 2로 나눈 몫·나머지를 비교하라. 또한 C++17 부호 있는 오버플로와 Python 큰 정수에 대한 안전/비용 차이를 설명하라.

연결 장: [[GI-C02-01 언어 실행·자료형·정수 연산·비트 연산]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> C++17은 -5/2=-2,-5%2=-1이고 Python3은 -5//2=-3,-5%2=1이다. 각각 q*2+r=-5를 만족한다. C++17 정수 나눗셈은 0 방향 버림, Python //는 음의 무한대 방향 내림이다. C++ 부호 있는 오버플로는 정의되지 않은 동작이므로 모든 중간 연산이 범위 안이어야 한다. Python int는 더 큰 값을 정확히 표현하지만 비트 길이가 커지면 연산·메모리 비용도 커져 모든 연산을 고정 O(1)로 보지 않는다.
> - 두 언어의 몫·나머지 4개 값: 4점
> - 관계식과 버림 방향: 2점
> - C++ 중간 범위/정의되지 않은 동작: 2점
> - Python 임의 정밀도와 비트 길이 비용: 2점

## W02Q02

Python3에서 s=0으로 시작해 [1,2,3,4]를 순회하며 x==3이면 continue, 그 외 s+=x 한다. 각 회차의 s와 최종값을 적어라. continue를 break로 바꾼 결과, 빈 목록의 for-else 동작도 설명하라.

연결 장: [[GI-C02-02 조건·반복·입출력·코드 추적]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> x=1 후 s=1, x=2 후 3, x=3은 건너뛰어 3, x=4 후 7이다. continue는 현재 회차만 건너뛰므로 최종 7이다. break로 바꾸면 x=3에서 전체 루프 종료하여 최종 3이다. Python for-else에서 빈 목록은 break 없이 정상 종료하므로 else를 실행한다. else는 본문 수행 횟수보다 break로 종료했는지에 달려 있다.
> - 네 회차 s 추적: 4점
> - 최종 7과 continue 의미: 2점
> - break 최종 3과 종료 범위: 2점
> - 빈 목록 else 실행과 근거: 2점

## W02Q03

Python 함수 def f(x, bag=[]): bag.append(x); return bag 의 상태 공유 문제를 설명하고, 호출마다 새 목록을 만드는 수정 코드를 제시하라. f(1),f(2)의 수정 전·후 결과도 적어라.

연결 장: [[GI-C02-03 함수·전달 방식·스코프·재귀]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 수정 전 bag=[]는 함수 정의 시 한 번 평가되므로 f(1) 후 같은 객체에 [1], f(2) 후 [1,2]가 된다. 앞 결과 참조도 [1,2]로 바뀐다. 수정 코드는 다음과 같다. 초기화만 if 내부에 두고 append와 return은 if 밖에 둔다.
> 
> ```python
> def f(x, bag=None):
>     if bag is None:
>         bag = []
>     bag.append(x)
>     return bag
> ```
> 
> 인수 생략 호출 f(1),f(2)는 서로 다른 [1],[2]를 돌려준다. 호출자가 목록을 명시하면 그 목록을 수정한다는 계약은 유지한다. None 자체가 유효 입력이면 별도 sentinel 정책이 필요하다.
> - 정의 시 한 번 생성과 참조 공유: 3점
> - 수정 전 두 결과와 앞 참조 변화: 2점
> - None 검사 후 새 목록 생성 코드: 3점
> - 수정 후 [1]/[2] 및 명시 목록 계약: 2점

## W02Q04

a=[[1],[2]], b=a.copy()에서 b[0].append(9), b[1]=[7]을 수행한다. 객체 공유 관계와 최종 a,b를 설명하라. 독립된 내부 목록까지 필요한 경우의 방법과 일반 deepcopy의 한계도 적어라.

연결 장: [[GI-C02-04 메모리·수명·참조·얕은 복사와 깊은 복사]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> a,b는 별도 바깥 목록이고 내부 [1],[2] 객체는 공유한다. append는 공유 첫 목록을 [1,9]로 바꾸고 b[1]=[7]은 b의 참조만 바꾼다. 최종 a=[[1,9],[2]], b=[[1,9],[7]]다. 단순 정수 목록 행이라면 [row.copy() for row in a]로 행까지 복제할 수 있다. 더 깊은 일반 객체 구조는 copy.deepcopy를 검토하지만 파일/연결/사용자 정의 객체 등 모든 외부 자원을 독립 복제한다고 보장하지 않는다.
> - 바깥 별도/내부 공유 구조: 3점
> - 두 연산 역할과 최종 값: 4점
> - 행 복사 또는 적절한 deepcopy 방법: 2점
> - 외부 자원/사용자 정의 객체 한계: 1점

## W02Q05

Python3 str "가A", UTF-8 bytes, 같은 UTF-8 데이터를 담은 C++ std::string의 길이를 각각 적어라. 코드 포인트 수/바이트 수/사용자에게 보이는 문자 수를 같은 개념으로 봐도 되는지 설명하라.

연결 장: [[GI-C02-05 문자열·배열·컨테이너와 반복자의 계약]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> Python str len은 코드 포인트 2개를 센다. UTF-8 encode 결과는 가 3바이트+A 1바이트로 4바이트다. 해당 바이트를 담은 C++ std::string size도 4다. 코드 포인트는 Unicode 식별 단위이고 UTF-8 바이트는 인코딩 저장 단위다. 결합 문자나 여러 코드 포인트로 이루어진 표현 때문에 사용자가 보는 문자 묶음의 수와 코드 포인트 수도 항상 같지 않다. 필요한 길이 단위를 입력/출력 계약에 명시해야 한다.
> - 세 표현의 길이 2/4/4: 4점
> - 코드 포인트와 바이트 단위 설명: 3점
> - 사용자 문자 묶음과 코드 포인트 차이: 2점
> - 길이 단위를 계약에 명시: 1점

## W02Q06

C++에서 virtual 함수 재정의와 virtual 소멸자의 목적을 구분하라. Base*로 Derived를 참조하는 함수 호출/삭제 상황에서 필요한 계약과 위험을 설명하라.

연결 장: [[GI-C02-06 객체지향·상속·다형성·추상화]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> virtual 함수는 기반 포인터/참조 호출에서 동적 형의 재정의 구현을 선택하기 위한 것이다. Base::f가 virtual이고 Derived::f가 올바르게 override하면 p->f()는 Derived 구현을 호출한다. 기반 포인터로 파생 객체를 delete할 설계는 기반 소멸자를 virtual로 두어 파생·기반의 소멸이 안전하게 연결되도록 한다. 비가상 기반 소멸자로 Derived를 삭제하면 정의되지 않은 동작이다. 함수 f를 virtual로 했다는 것만으로 소멸자가 자동 virtual이 되지는 않는다.
> - 함수 동적 디스패치 목적과 Derived 호출: 4점
> - 기반 삭제와 virtual 소멸자 필요: 3점
> - 비가상 삭제는 정의되지 않은 동작: 2점
> - 일반 함수 virtual과 소멸자 virtual 별도: 1점

## W02Q08

C++17에서 int a=b=50000, int 32비트·long long 64비트이다. long long p=a*b;와 long long p=static_cast<long long>(a)*b;의 차이를 설명하라. Java에서 같은 문제를 피하는 식과 누적 합 안전 계약도 적어라.

연결 장: [[GI-C02-08 C·Java 코드 읽기와 C++·Python 실전 구현 연결]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 첫 식은 a*b를 int에서 먼저 계산하며 2,500,000,000은 32비트 signed int 범위 밖이므로 정의되지 않은 동작이다. 둘째 식은 곱셈 전에 a를 long long으로 바꾸어 b도 확대되고 정확한 2,500,000,000을 계산한다. Java는 long p=1L*a*b;처럼 연산 전 long을 사용한다. int 곱셈 후 long 캐스트는 이미 계산된 값을 고치지 못한다. 누적 합은 모든 입력뿐 아니라 각 중간 합도 선택한 정수 형 범위 안이어야 한다.
> - C++ 첫 식의 int 선계산과 UB: 3점
> - 사전 확대 식과 정확한 값: 3점
> - Java 1L 식과 사후 캐스트 한계: 2점
> - 모든 중간 누적 합 안전 계약: 2점
