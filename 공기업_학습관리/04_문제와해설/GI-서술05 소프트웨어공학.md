# 소프트웨어공학 기초 - 요구사항에서 운영·유지보수까지 서술형

자체 제작 연습문항입니다. 먼저 내 답안을 작성한 뒤 모범답안을 펼치세요.

## W05Q01

가상 기준은 20응답의 최근접 순위 95백분위가 2초 이하이다. 평균 1.3초·95백분위 4초의 판정과 응답 유실 재시도 계약·시험을 설계하라.

연결 장: [[GI-C05-01 요구사항  무엇을 만들고 어떻게 확인할 것인가]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 최근접 순위 ceil(20×0.95)=19의 값이 4초이므로 실패다. 동일 요청 키·동일 내용은 기존 결과를 반환하고 같은 키·다른 내용은 충돌로 처리한다. 유일성 확인·실제 거래 저장·결과 기록을 원자적 계약으로 연결한다. 저장 성공 뒤 응답 유실, 동시 동일 재시도, 실패 후 재시도를 시험해 한 거래와 결과 일관성을 관찰한다.
> - 3점: 최근접 순위 19를 1점, 4초와 기준 2초 비교 및 실패 판정을 2점으로 계산한다.
> - 3점: 같은 키·같은 내용의 기존 결과 반환 2점, 같은 키·다른 내용의 충돌 처리 1점을 쓴다.
> - 4점: 확인과 저장의 경쟁을 막는 원자성 2점, 응답 유실 및 동시 재시도 시험을 각각 1점으로 제시한다.

## W05Q02

Done 조건이 기능 시험·보안 검토 모두 통과일 때 기능 시험만 끝난 항목과 위험 조사용 시제품을 어떻게 다룰지 설명하라.

연결 장: [[GI-C05-02 개발 생명주기와 애자일  변화와 위험을 다루는 방식]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 보안 검토가 남았으므로 미완료 항목을 Done으로 계산하지 않는다. 시제품의 위험 실험 결과와 제품의 완료 증거를 구분한다. 운영 제품에 재사용하려면 계약·보안·유지보수·배포 조건을 재검토하고 실제 제품 조건으로 다시 검증한다.
> - 3점: 두 필수 조건을 1점, 기능 시험만으로 Done이 아니라는 판정을 2점으로 쓴다.
> - 3점: 위험 조사용 증거와 제품 품질 완료 증거의 차이를 3점으로 설명한다.
> - 4점: 재사용 검토 항목 두 가지를 각각 1점, 실제 제품 조건의 추가 검증을 2점으로 제시한다.

## W05Q03

두 업무 테스트가 변경 가능한 저장소를 공유하고 실행 순서에 따라 실패한다. 설계 경계와 검증 계획을 설명하라.

연결 장: [[GI-C05-03 설계·아키텍처  응집도와 결합도로 변경 비용 줄이기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 업무 서비스는 저장소 계약에 의존하고 DB 제품별 처리는 어댑터에서 변환한다. 인터페이스가 있어도 공유 상태는 남으므로 테스트마다 독립 상태를 만들거나 확실하게 초기화한다. 대역으로 업무 성공·실패 분기를 검증하고 실제 DB에서 유일성·트랜잭션·동시 요청을 통합 검증한다.
> - 3점: 업무 정책과 DB 세부의 경계를 2점, 어댑터의 변환 책임을 1점으로 설명한다.
> - 3점: 공유 상태가 원인임을 1점, 독립 상태 또는 확실한 초기화 방법을 2점으로 제시한다.
> - 4점: 대역 시험의 한계를 2점, 실제 DB의 경쟁·원자성 통합 검증을 2점으로 설명한다.

## W05Q04

허용 전이는 D→S, D→C, S→R, S→C, R→S, R→F이며 다른 요청은 거절·상태 유지다. D→S→R→S→C만 시험했다. 커버리지·추가 허용 시험·금지 시험을 작성하라.

연결 장: [[GI-C05-04 UML과 디자인 패턴  그림과 구조에서 책임 읽기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 방문한 서로 다른 허용 전이는 4/6이다. 누락은 D→C와 R→F이며 추가 경로 D→C, D→S→R→F로 모두 방문할 수 있다. R→C 또는 F→S를 요청해 거절과 기존 상태 유지를 확인한다. 허용 전이 100% 방문만으로 금지 요청의 거절을 증명하지 못한다.
> - 3점: 방문 4/6을 1점, 누락 D→C·R→F를 각각 1점으로 식별한다.
> - 3점: 두 누락을 포함하는 실행 가능한 경로를 각각 1점, 초기 상태 D에서 연결됨을 1점으로 확인한다.
> - 4점: 금지 전이 예시 1점, 거절 관찰 1점, 상태 유지 관찰 1점, 허용 방문의 한계 1점을 쓴다.

## W05Q05

C# A&&B에 (참,참), (거짓,거짓)을 시험했다. 실행 기반 원자 조건 결과 네 개를 분모로 정한다. 조건·분기 커버리지와 보완 입력을 설명하라.

연결 장: [[GI-C05-05 테스트 설계와 커버리지  정상 동작을 넘어 경계를 찾기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 전체 결정은 참·거짓이 모두 나와 분기 2/2=100%다. A 참·거짓과 B 참만 실제 평가되어 조건 3/4=75%다. 두 번째 입력의 B 거짓은 단락 평가로 실행되지 않는다. (참,거짓)을 추가하면 B 거짓도 실행되어 조건 결과 4/4를 채운다.
> - 3점: 전체 결정의 참·거짓을 1점, 분기 2/2=100%를 2점으로 계산한다.
> - 4점: B 단락 생략을 2점, 실제 조건 결과 A참·A거짓·B참과 3/4=75%를 2점으로 설명한다.
> - 3점: 추가 입력 (참,거짓)을 2점, A참이라 B가 실행됨을 1점으로 설명한다.

## W05Q06

정상 운전 48시간·복구 2시간 모형에서 복구만 1시간으로 줄였다. 이전·이후 가용성과 신뢰성 향상 단정의 한계를 설명하라.

연결 장: [[GI-C05-06 품질·유지보수·신뢰성  출시 후의 소프트웨어 이해하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 이전은 48/50=96%, 이후는 48/49 약 97.959%다. 복구 시간 단축으로 가용성이 개선됐지만 정상 운전 시간과 고장 빈도가 개선됐다는 증거는 없다. 실제 관측 비교에서는 측정 기간·계획 중단 포함·서비스 가용 기준 등 동일한 규약을 사용해야 한다.
> - 4점: 이전 식과 값 2점, 이후 식과 값 2점을 계산한다.
> - 3점: 복구 시간 개선 1점, 고장 빈도 또는 정상 운전 시간 개선 증거 부재 2점을 구분한다.
> - 3점: 측정 기간 1점, 중단 포함 규약 1점, 동일한 서비스 가용 기준 1점을 제시한다.

## W05Q07

A 3일 후 B 4일·C 6일 병렬, D 2일은 둘 완료 뒤다. 자원 제한 없이 초기 기간과 B 총여유, C를 4일 뒤 3일로 줄인 전체 기간을 계산하라.

연결 장: [[GI-C05-07 규모 산정·일정·위험  프로젝트 수치를 계산하는 법]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 처음 A-C-D는 11일, A-B-D는 9일이다. B의 가장 이른 시작은 3일, 가장 늦은 시작은 5일로 총여유 2일이다. C가 4일이면 두 경로가 9일로 함께 임계가 된다. C를 3일로 더 줄여도 B 경로 9일이 남아 전체는 9일이다. 단축 후 임계경로를 다시 계산해야 한다.
> - 3점: A-C-D 11일과 A-B-D 9일을 2점, 초기 전체 11일을 1점으로 쓴다.
> - 3점: B의 이른/늦은 시작 또는 두 경로 차이를 2점, 총여유 2일을 1점으로 계산한다.
> - 4점: C4일의 공동 임계 9일을 2점, C3일에도 B 경로로 최종 9일인 이유를 2점으로 설명한다.

## W05Q08

새 버전 200건 중 실패 6건·기존 1,800건 중 실패 9건이며 새 오류율 1% 이하가 승인 조건이다. 판정과 DB 열 삭제를 포함한 복구 검증을 설명하라.

연결 장: [[GI-C05-08 형상관리·배포·운영  변경을 추적하고 안전하게 적용하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 새 오류율은 3%, 기존은 0.5%, 전체는 0.75%다. 새 버전 기준이 실패하므로 전체 비율로 승인하지 않는다. 새 코드가 삭제한 열을 옛 코드가 읽으면 실행 파일 복귀만으로 복구되지 않는다. 옛 코드와 현재 스키마·자료·설정·메시지 호환성을 검증하고 핵심 거래·권한·오류율로 실제 복구를 확인한다.
> - 4점: 세 오류율 각각 1점, 새 버전 보류 판정 1점을 계산한다.
> - 3점: 옛 코드가 읽는 열 삭제의 불일치 2점, 코드 복귀만으로 자료 복구가 안 됨 1점을 설명한다.
> - 3점: 핵심 거래·권한·오류율 등 실제 관찰 두 가지를 2점, 복구 시 코드와 자료 계약을 함께 확인함을 1점으로 쓴다.
