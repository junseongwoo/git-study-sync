# 네트워크: 계층·주소·전송·웹을 연결하는 전산 보강 서술형

자체 제작 연습문항입니다. 먼저 내 답안을 작성한 뒤 모범답안을 펼치세요.

## W07Q01

10Mbps의 동일 두 링크,store-and-forward,전체600바이트 패킷3개에서 기타 지연0인 최종 도착시간을 계산하라. 각 링크 전파2ms를 추가할 때도 계산하고 가정을 두 가지 적어라.

연결 장: [[GI-C07-01 계층·캡슐화·지연  통신을 서로 다른 문제로 나누기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 직렬화 T=600×8/10^7=0.48ms다. 첫 패킷 2T, 추가 두 개가 각각 T이므로 최종 4T=1.92ms다. 전파 합 4ms를 더하면 5.92ms다. 헤더 포함 전체 길이, 링크별 전송 중첩 가능, 큐·처리·응답 비용 없음 등의 가정을 쓴다.
> - bit/byte·초/ms 변환 3점
> - 파이프라인 최종시간 3점
> - 전파 추가 계산 2점
> - 명시적 가정 두 가지 2점

## W07Q02

H=192.0.2.10/24,게이트웨이192.0.2.1에서198.51.100.8로 전송하는 첫 구간의 목적IP·목적MAC과 ARP 대상을 설명하라. unknown unicast flooding과 IP브로드캐스트도 구분하라.

연결 장: [[GI-C07-02 Ethernet·스위치·ARP·VLAN  같은 망에서 전달하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> IP 목적지는 198.51.100.8, 프레임 목적 MAC은 게이트웨이의 MAC이다. 목적지가 로컬 망 밖이고 NAT가 없다는 조건이다. MAC이 없으면 로컬 링크에서 게이트웨이 IP에 ARP한다. unknown unicast flooding은 스위치의 미학습 목적 MAC 전달이며 IP 목적지가 브로드캐스트임을 뜻하지 않는다.
> - 최종 IP·다음 홉 MAC 4점
> - ARP 대상·로컬 범위 3점
> - flooding과 IP 구분 3점

192.0.2.130/26의 블록 크기·네트워크·브로드캐스트·일반 호스트 범위와 수를 구하라. /31에 같은 총주소-2 식을 무조건 적용하면 안 되는 이유를 설명하라.

연결 장: [[GI-C07-03 IPv4·CIDR·서브넷·VLSM  주소 범위를 계산하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 호스트 비트 6, 블록 크기 64, 경계 128~191이므로 네트워크는 192.0.2.128, 브로드캐스트는 192.0.2.191이다. 다중 접근 모델의 호스트는 129~190으로 62개다. /31 점대점은 별도 규칙으로 두 주소를 사용할 수 있어 그 모델과 구분한다.
> - 비트·블록·경계 3점
> - 네트워크·브로드캐스트 3점
> - 호스트 범위·수 2점
> - /31 모델 예외 2점

## W07Q04

IPv4 데이터1300바이트,헤더20,MTU600,DF=0,옵션없음에서 단편별 데이터·전체길이·Offset·MF를 표로 쓰고 합계로 검산하라. IPv6 라우터와도 비교하라.

연결 장: [[GI-C07-04 라우팅·IP 단편화·ICMP·DHCP·NAT  다른 망으로 이동하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 비마지막 데이터는 floor(580/8)×8=576이다. 세 단편의 (데이터,전체 길이,Offset,MF)는 (576,596,0,1), (576,596,72,1), (148,168,144,0)이다. 데이터 합은 1300, 전체 합은 1360이다. 마지막은 8의 배수일 필요가 없고 Offset은 8바이트 단위다. IPv6 라우터는 전달 중 단편화하지 않는다.
> - 576 계산·헤더 고려 2점
> - 세 단편 표 4점
> - 데이터·전체 합계 검산 2점
> - IPv6 비교 2점

## W07Q05

TCP seq1000 데이터120의 누적ACK와 cwnd20KiB/rwnd12KiB/RTT40ms의 단순 속도 상한을 계산하라. 흐름 제어·혼잡 제어·실제 goodput 한계를 구분하라.

연결 장: [[GI-C07-05 TCP·UDP·신뢰성·흐름 혼잡 제어  무엇을 보장하는가]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 랩어라운드·SYN·FIN·누락이 없으면 다음 기대 바이트 ACK는 1120이다. 작은 윈도 12KiB=12288바이트, 12288×8/0.04=2457600bit/s=2.4576Mbps다. rwnd는 수신 버퍼의 흐름 제어, cwnd는 혼잡 제어 상태다. 실제 goodput은 손실·헤더·혼잡 변화·준비 비용 등으로 더 작을 수 있다.
> - ACK 바이트 계산 2점
> - 작은 윈도·단위 계산 4점
> - rwnd/cwnd 목적 2점
> - 모델 한계 2점

## W07Q06

t=0에 DNS TTL60초로 저장하고 갱신없음일 때 t=20·59의 남은TTL과 만료를 구하라. NXDOMAIN·NODATA와 주소 변경 직후의 과거 캐시를 설명하라.

연결 장: [[GI-C07-06 DNS·이름 해석·캐시  도메인이 IP가 되는 흐름]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 남은 TTL은 t=20에 40초, t=59에 1초이며 만료는 t=60이다. 조회 때 원래 TTL을 재설정하지 않는다. NXDOMAIN은 이름 없음, NODATA는 이름은 있으나 질의 유형의 답 데이터 없음이다. 권한 주소 변경 후에도 기존 캐시 수명 및 애플리케이션 캐시 때문에 이전 주소가 남을 수 있다. DNS 성공은 이후 TCP/TLS/업무 성공을 보장하지 않는다.
> - 잔여 TTL·만료 계산 3점
> - 조회 연장 오해 교정 2점
> - NXDOMAIN/NODATA 구분 3점
> - 주소 변경 캐시와 계층 한계 2점

## W07Q07

결제 요청 후 응답 유실이 생겼다. 처리 여부와 재시도를 어떻게 판단할지 설명하고 HTTP 멱등성·TLS·503 응답 주체를 각각 구분하라.

연결 장: [[GI-C07-07 HTTP·TLS·웹 서비스  연결·암호화·업무 응답을 구분하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 응답 유실은 미처리를 확정하지 못하므로 업무 거래 ID 조회·중복 제어 계약으로 판단한다. 멱등성은 반복 동일 요청의 의도한 효과에 관한 것이며 모든 응답·로그 동일성을 뜻하지 않는다. TLS는 통신 인증·암호화와 관련하고 업무 중복·권한 오류를 자동 해결하지 않는다. 503은 프록시도 만들 수 있어 원본 애플리케이션 생성으로 단정하지 않는다.
> - 응답 유실·업무 ID 대책 4점
> - 멱등성 정의 2점
> - TLS 보장 경계 2점
> - 503 주체 추가 확인 2점

## W07Q08

4바이트 big-endian 길이 접두+본문,최대본문4096 계약의 TCP 파서를 설계하라. 부분 접두·부분 본문·다중 프레임·과대 길이·연결 종료를 설명하라.

연결 장: [[GI-C07-08 소켓·프레이밍·장애 진단  코드 경험을 전산 문제로 연결하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 수신 바이트를 누적하고 4바이트가 모이면 길이를 파싱해 상한을 검사한다. 본문 길이까지 모이면 프레임을 전달하고 잔여 버퍼로 반복한다. 미완성 자료는 다음 수신까지 보관하고 시간·버퍼 상한을 둔다. 4096초과는 큰 할당 전에 거부한다. 종료 때 미완성 프레임이 남으면 정상 프레임 종료와 구분해 절단 오류를 처리한다.
> - 접두·본문 부분 수신 3점
> - 다중 프레임·잔여 보관 3점
> - 상한·시간·할당 계약 2점
> - 종료 미완성 판정 2점
