## W06Q01

자산 1,000만원·노출계수 0.2·연간 기대 0.4회이다. 통제 A는 연 35만원·잔여 0.1회, B는 연 10만원·잔여 0.3회다. SLE·ALE·통제별 비용 합과 모형의 한계를 설명하라.

연결 장: [[GI-C06-01 보안 목표와 위험  자산·위협·취약점을 분리하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> SLE=1,000×0.2=200만원, ALE=200×0.4=80만원/년이다. A는 잔여 20+비용 35=55, B는 잔여 60+비용 10=70만원/년이다. 통제 비용과 잔여 기대 손실의 합만 최소화하는 목표에서는 A가 낫다. 기대 횟수 0.4와 한 번 이상 사고 확률은 자동으로 같지 않다. 실제 의무·극단 손실·추정 오차는 이 단순 비용 모형 밖에서도 검토한다.
> - 3점: SLE 식과 200만원 1점, ALE 식과 80만원/년 2점을 계산한다.
> - 4점: A55·B70의 비용 합 각각 1점, A 선택 1점, 비용 합 최소라는 목표 조건 1점을 쓴다.
> - 3점: 기대 횟수와 발생 확률의 차이 1점, 극단 손실·의무·추정 오차 등 모형 밖 조건 두 가지 각각 1점을 설명한다.

## W06Q02

가상 승인은 승인자 AND 같은 지역 AND 요청 작성자와 다른 사람일 때만 가능하다. 로그인된 같은 지역 승인자가 본인 요청을 처리할 때 판정과 시험을 설명하라.

연결 장: [[GI-C06-02 인증·인가·접근통제  로그인 뒤에도 권한을 검사하기]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 작성자 분리 조건이 거짓이므로 거절한다. 로그인은 신원을 확인하지만 승인 조건은 서버가 현재 사용자·역할·지역·객체 작성자를 확인해야 한다. 정상적인 타인 요청은 허용하고 자기 요청·다른 지역 요청·권한 철회 뒤 직접 API 호출은 거절하는 시험을 작성한다.
> - 3점: 세 AND 조건을 1점, 자기 승인 거절과 그 조건을 2점으로 설명한다.
> - 3점: 인증과 인가 구분 1점, 서버의 현재 역할·객체 조건 검사 2점을 쓴다.
> - 4점: 정상 타인 요청 1점, 거절 사례 두 가지 각각 1점, 직접 API 경계 확인 1점을 제시한다.

## W06Q03

같은 XOR 마스크로 만든 C1=1010, C2=0110이고 P1=0110이다. P2를 구하고 재사용 위험, MAC과 서명의 증거 조건을 설명하라.

연결 장: [[GI-C06-03 암호의 기초  암호화·해시·MAC·전자서명]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> C1 XOR C2=1100=P1 XOR P2이므로 P2=1100 XOR 0110=1010이다. 같은 마스크는 평문 관계를 노출한다. MAC 공유 키는 두 보유자 모두 생성할 수 있으므로 한 보유자만의 작성이라는 제3자 증거와 다르다. 서명은 서명 개인키 통제와 검증 공개키의 신원·신뢰 조건을 확인해야 하며 서명 존재만으로 모든 법적 효과를 확정하지 않는다. 실제 암호는 검증된 방식과 nonce·키 조건을 사용한다.
> - 4점: 중간 XOR 1100을 2점, P2=1010을 2점으로 계산한다.
> - 3점: 같은 마스크가 상쇄됨 1점, 평문 XOR 관계 노출 1점, 알려진 P1으로 P2 계산 가능 1점을 설명한다.
> - 3점: MAC 양쪽 생성 가능 1점, 서명 개인키 통제 1점, 검증키 신뢰 조건 1점을 구분한다.

## W06Q04

TLS 호스트 이름 불일치와 같은 GCM 키 아래 동일 nonce 카운터 재시작 문제를 설명하라. DEK는 유지하고 KEK만 바꿀 때 확인할 조건도 쓰라.

연결 장: [[GI-C06-04 PKI·TLS·키 관리  안전한 통신의 조건]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 신뢰된 발급자라는 사실만으로 다른 호스트 이름의 인증서를 허용하지 않는다. 같은 키와 생성 규칙에서 카운터를 초기화하면 과거 또는 다른 프로세스의 nonce와 중복될 수 있다. KEK 재포장은 DEK 교체와 다르며 DEK 사용 이력이 자동 초기화되지 않는다. 키 식별자·이행 상태·복호·백업 복원 가능성을 검증한다.
> - 3점: 요청 호스트 이름 검사 1점, 발급자 신뢰만으로 이름 불일치 허용 불가 2점을 설명한다.
> - 4점: 동일 키 조건 1점, 카운터 초기화 1점, 과거/다중 프로세스 중복 가능성과 유일성 설계 2점을 쓴다.
> - 3점: 재포장과 DEK 교체 구분 1점, DEK 이력 유지 1점, 복호·복원 검증 1점을 제시한다.

## W06Q08

준식별자 집단 A·B·C의 크기는 3·4·5, 민감 속성 서로 다른 값 수는 1·2·2다. 가상 조건은 집단별 3명 이상 AND 서로 다른 값 2개 이상이다. 최대 k와 공개 판정·학습 한계를 설명하라.

연결 장: [[GI-C06-08 개인정보·안전한 데이터 처리와 종합 문제 풀이]]

### 내 답안


> [!note]- 모범답안과 자가 채점 기준
> 모든 집단의 최소 크기가 3이므로 최대 k는 3이다. A는 서로 다른 민감 값이 1개라 가상 공개 조건에 실패하고 B·C는 두 조건을 만족한다. 이름 삭제나 집단 크기만으로 민감 속성 추론 위험이 없어지지 않는다. 목적에 필요한 항목·외부 결합·권한을 검토한다. 가상 기준은 법률 면책이나 실제 보관기한을 대신하지 않는다.
> - 3점: 최소 집단 크기 정의 1점, 최대 k=3과 그 근거 2점을 쓴다.
> - 4점: A의 다양성 실패 2점, B·C 통과 1점, 동일 민감 값의 추론 한계 1점을 설명한다.
> - 3점: 목적/결합/권한 중 두 가지 검토 2점, 가상 조건과 실제 법의 구분 1점을 쓴다.
