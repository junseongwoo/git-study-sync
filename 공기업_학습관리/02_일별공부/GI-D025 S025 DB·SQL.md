### B03Q01

직원 번호와 이메일은 각각 업무 규칙상 유일·비NULL이고 이름은 중복 가능하다. 후보키 설명으로 옳은 것은?

1. 직원 번호와 이메일은 각각 후보키다.
2. 직원 번호와 이름의 조합은 최소 후보키다.
3. 현재 표에서 이름이 겹치지 않으면 이름은 반드시 후보키다.
4. 모든 후보키는 열 수가 서로 같아야한다.

- 내 선택과 근거:

> [!note]- 정답과 이유 확인
> 정답 1번
> 
> ① 각 속성이 단독으로 유일 식별하므로 최소 슈퍼키다. ② 직원 번호만으로 식별되어 이름이 불필요하다. ③ 현재 샘플과 앞으로도 지켜야하는 업무 규칙은 다르다. ④ 서로 다른 열 수의 최소 슈퍼키가 공존할 수 있다. 최소성은 부분 집합 기준이다.

### B03Q02

account.customer_id가 customer의 기본 키를 참조하는 NOT NULL 외래키이고 별도 UNIQUE는 없다. 허용 가능한 것은?

1. 존재하지 않는 고객 ID를 참조하는 계좌
2. 같은 고객 ID를 참조하는 서로 다른 계좌 두 개
3. NULL 고객 ID를 가진 계좌
4. 외래키이므로 모든 고객에게 계좌가 반드시 한 개 이상 있음

- 내 선택과 근거:

> [!note]- 정답과 이유 확인
> 정답 2번
> 
> ② 1:N을 구현할 수 있어 같은 고객을 여러 계좌가 참조한다. ① 참조 무결성 위반, ③ NOT NULL 위반이다. ④ 외래키는 계좌에서 고객 참조를 검사하며 모든 고객의 역방향 참여까지 강제하지 않는다.
