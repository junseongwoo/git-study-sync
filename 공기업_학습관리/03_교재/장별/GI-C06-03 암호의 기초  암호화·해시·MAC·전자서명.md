# 06-03 암호의 기초: 암호화·해시·MAC·전자서명

[[GI-교재06 정보보안|과목 목차]] · [[GI-문제06 정보보안|문제]] · [[GI-해설06 정보보안|해설]]

### 대칭키와 공개키
대칭키 암호는 암호화와 복호화에 같은 비밀키 또는 쉽게 연관되는 비밀키를 사용한다. 많은 데이터를 효율적으로 보호할 때 사용하지만 키를 안전하게 공유하는 문제가 있다. 공개키 암호체계는 공개키와 개인키를 사용한다. 암호화·전자서명·키 합의는 목적과 알고리즘이 다르므로 모든 공개키 연산을 "개인키로 암호화"라고 부르면 부정확하다.

기밀성 목적의 전형적 설명에서는 수신자의 공개키로 보호한 정보를 수신자의 개인키로 복호화한다. 전자서명에서는 서명자의 개인키로 서명하고 대응 공개키로 검증한다. ECDSA와 EdDSA 같은 서명 알고리즘은 RSA 암호화와 같은 연산이 아니다. 시험의 단순 설명을 이해하되 실제 구현에서는 검증된 라이브러리와 표준 프로토콜을 사용한다.

### 해시와 MAC
암호학적 해시는 임의 길이 입력을 고정 길이 값으로 매핑하는 함수다. 역상 저항성, 제2역상 저항성, 충돌 저항성의 개념을 구별한다. 압축된 출력 공간이 유한하므로 수학적으로 충돌은 존재한다. 보안 목표는 현실적으로 유효한 충돌이나 역상을 찾기 어렵게 만드는 것이다.

키 없는 해시만 파일 옆에 두면 공격자가 파일과 해시를 함께 바꿀 수 있다. HMAC 등 MAC는 비밀키를 가진 주체가 메시지의 무결성과 인증을 확인하게 한다. MAC는 공유키를 가진 모든 사람이 만들 수 있어서 제3자에게 서명자 한 명의 행위를 입증하는 전자서명과 같은 부인방지 특성을 일반적으로 제공하지 않는다.

전자서명은 무결성과 서명자 인증, 조건이 갖추어진 경우 부인방지에 기여한다. 서명만으로 메시지 내용의 기밀성이 생기는 것은 아니다. 실제 부인방지에는 개인키 보호·인증서·신뢰할 수 있는 시간·감사 체계 등 운영 조건도 영향을 준다.

### 비밀번호와 해시 저장
비밀번호 저장에는 일반적인 빠른 해시 한 번보다 salt와 적절한 작업 비용을 갖춘 전용 비밀번호 해시 기법이 필요하다. Argon2id·bcrypt·PBKDF2 등의 선택은 환경·정책·표준을 확인한다. salt는 사용자별 값으로 사전 계산과 동일 비밀번호 패턴을 어렵게 하지만 공개될 수 있다. pepper는 별도로 보호하는 비밀값이라는 점에서 구별한다. 특정 최소 파라미터는 변할 수 있으므로 이 교재에 고정 숫자로 암기하지 않는다.

### 단계별 예제: 파일의 세 보호 방식
거래 파일과 SHA-256 값만 공개 저장소에 둔다. 값이 일치하면 우발적 전송 손상 탐지에 도움은 되지만 악의적인 두 값의 동시 변경을 막지 못한다. 공유키로 MAC를 붙이면 키 없는 공격자의 변경을 탐지할 수 있다. 담당자의 개인키로 서명하면 공개키를 가진 검증자가 서명을 확인할 수 있다. 파일 내용까지 숨기려면 별도의 암호화가 필요하다.

### 키 공간 계산
가상 키 길이가 8비트라면 가능한 키는 2^8=256개다. 9비트는 512개라서 한 비트 증가 시 두 배가 된다. n비트는 2^n개다. 실제 보안 강도는 키 길이뿐 아니라 알고리즘의 구조·취약점·모드·난수·키 관리에 영향을 받으므로 128비트 대칭키와 128비트 RSA를 같은 안전성으로 비교하지 않는다. 무작위 추측으로 평균 절반의 키를 시도한다는 단순 모형도 문제에서 가정할 때만 쓴다.

### 자가 연습과 풀이
전자서명이 검증되었으니 파일 내용을 아무도 읽지 못한다는 말은 틀리다. 서명과 암호화의 목적을 혼동했다. salt를 비밀키처럼 숨겨야만 안전하다는 주장도 정확하지 않다. salt의 역할과 별도 비밀 관리의 역할이 다르다.

### 완료 기준
네 가지 도구를 목적별로 배치해보자. 내용 숨김은 암호화, 비키 해시의 주요 역할은 지문·손상 탐지, 공유 비밀 기반 인증은 MAC, 공개 검증 가능한 서명은 전자서명이다.

### 응용 계산: 키 탐색과 해시 충돌은 다르다
n비트 키의 전체 공간은2^n이다. 이상적인 n비트 해시에서 생일 역설에 따른 충돌 탐색 규모는 대략2^(n/2) 관점으로 설명한다. 이것은 특정 입력의 역상을 찾는 문제와 다르다. 16비트 가상 해시는65536개 출력을 갖지만 충돌은 대략 수백 개 규모의 무작위 표본에서 가능성이 커지는 현상을 볼 수 있다. '256개면 반드시 충돌'처럼 결정적 보장으로 쓰지는 않는다.

역상 저항성은 주어진 해시값의 입력 찾기, 제2역상은 주어진 입력과 다른 같은 해시 입력 찾기, 충돌 저항성은 같은 해시의 임의 두 입력 찾기다. 시험 문장의 '입력이 이미 정해져 있는가'를 확인하면 세 개념을 구분하기 쉽다.

### 강화 손풀이: 무결성 증거와 공유키의 한계
파일과 키 없는 해시를 같은 수정 가능한 경로에 두면 공격자가 둘을 바꿀 수 있다. 수신자는 별도 신뢰 경로의 해시나 키 기반 검증 등 신뢰 기준이 필요하다. MAC은 공유키를 아는 상대 사이의 변조 검증에 쓰이지만 양쪽 모두 유효 MAC을 만들 수 있어 어느 쪽이 작성했는지 제 3자에게 구별하는 서명과 같은 증거가 아니다. 서명도 키 신뢰·보관·유출 여부를 확인해야 한다.
실제 암호 대신 4비트 XOR 연습을 한다. C1=P1 XOR K, C2=P2 XOR K이고 C1=1010,C2=0110이면 C1 XOR C2=1100=P1 XOR P2다. P1=0110을 알면 P2=1100 XOR 0110=1010으로 드러난다. 같은 마스크를 재사용하면 키를 직접 몰라도 두 평문의 관계가 남는 반례다.
실무 암호는 검증된 라이브러리와 올바른 모드·키·nonce 조건을 따른다. GCM에서는 같은 키의 IV/nonce 유일성 조건을 지켜야 한다. 인증 태그 검증 실패를 성공으로 바꾸거나 검증되지 않은 평문을 업무에 사용하지 않는다. XOR 예제는 실제 암호 구현 처방이 아니다.
