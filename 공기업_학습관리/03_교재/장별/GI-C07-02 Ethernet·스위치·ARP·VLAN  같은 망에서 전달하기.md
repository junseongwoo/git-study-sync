# 07-02 Ethernet·스위치·ARP·VLAN: 같은 망에서 전달하기

[[GI-교재07 네트워크|과목 목차]] · [[GI-문제07 네트워크|문제]] · [[GI-해설07 네트워크|해설]]

## 학습 목표
목적지 IP를 알더라도 같은 링크에서 사용할 MAC 주소를 알아야하는 이유를 설명한다. 스위치의 MAC 학습과 라우터의 IP라우팅을 구분한다. 실제 경로에서는 링크마다 MAC 헤더가 달라질 수 있다.

## 1. MAC과 IP의 역할
Ethernet MAC 주소는 전형적으로 48비트이며 링크에서 프레임 전달에 사용한다. IP 주소는 네트워크 간 경로 선택에 사용한다. MAC이 모든 네트워크에서 끝까지 같은 프레임을 안내하는 세계 공통 경로 번호라는 해석은 틀리다. 일부 가상화·무선·터널에서는 표면적 구조가 달라져도 역할을 나눠 이해한다.

스위치는 수신 프레임의 출발지 MAC을 해당 포트에서 학습하여 테이블을 만든다. 목적지 MAC을 알면 해당 포트로 전달하고, 모르면 같은 VLAN 내의 다른 포트로 flood할 수 있다. 브로드캐스트도 같은 브로드캐스트 영역으로 전달한다. '목적지 MAC을 보고 출발지 위치를 학습'하는 것은 방향을 반대로 외운 오류다.

### 손풀이 예제 4: 스위치 학습
초기 테이블이 비어 있다. 포트 1의 A가 포트 2의 B로 프레임을 보낸다. 스위치는 A->1을 학습하고 B를 모르므로 다른 해당 VLAN 포트로 보낸다. B가 응답하면 B->2를 학습하고 A->1 을 이미 알아포트 1로 전달한다. flood는 IP 라우터가 모든 인터넷으로 패킷을 무조건 복제한다는 뜻이 아니다.

## 2. ARP
ARP는 IPv4 기반 같은 링크에서 다음 홉 IP에 대응하는 링크 주소를 찾는 대표 프로토콜이다. 캐시에 없으면 ARP 요청을 브로드캐스트하고 해당 IP 소유자 등이 응답하여 MAC을 알린다. 캐시가 있으면 매번 요청할 필요는 없다. ProxyARP·중복 IP 등 예외는 기본 동작을 이해한 뒤 다룬다. IPv6는 ARP 대신 NeighborDiscovery를 사용한다.

### 손풀이 예제 5: 로컬 목적지
PC A =192.168.1.10/24, 서버 B =192.168.1.20/24다. A는 마스크로 B가 같은 서브넷임을 판단한다. ARP 캐시에 없으면 B의 IP에 대한 MAC을 찾고 B 목적지 MAC으로 Ethernet 프레임을 보낸다. IP 목적지도 B다. 기본 게이트웨이가 설정되어 있어도 같은 망 B로 보내는 기본 경로에서 반드시 게이트웨이를 거치지는 않는다.

### 손풀이 예제 6: 원격 목적지
A =192.168.1.10/24, 게이트웨이192.168.1.1, 원격 서버203.0.113.20이다. 원격 IP는 같은 서브넷이 아니어서 라우팅 테이블의 다음 홉을 선택한다. 첫 링크의 목적지 MAC은 게이트웨이 MAC이며, IP 목적지는 원격 서버203.0.113.20이다. ARP로 찾는 것은 원격 서버의 세계 반대편 MAC이 아니라 첫 다음 홉 MAC이다.

게이트웨이는 수신 링크 프레임을 해석하고 IP 경로를 선택한 다음 송신 링크의 새 프레임을 만든다. NAT가 없고 일반 라우팅인 모델에서 IP 출발지·목적지는 끝점 주소를 유지하지만 TTL 등 일부 IP 헤더는 변한다. MAC 출발지·목적지는 링크마다 바뀐다.

## 3. 브로드캐스트 영역과 충돌 영역
스위치 포트가 분리하면 전통적인 충돌 영역을 나누는 효과가 있다. 현대전 이 중 Ethernet에서는 같은 링크에서 고전적인 CSMA/CD 충돌 처리를 사용하지 않는 것으로 이해한다. 허브는 공유 매체 모델로 다른 동작이다. 'Ethernet이면 항상 패킷 충돌을 CSMA/CD로 해결'이라는 절대 명제는 현재 네트워크와 다르다.

라우터는 일반적으로 링크 브로드캐스트를 다른 망으로 그대로 전달하지 않는다. VLAN은 같은 물리 스위치를 논리적인 서로 다른 브로드캐스트 영역으로 나누는 방법이다. VLAN10과 VLAN20 사이 통신에는 라우팅 기능과 정책이 필요하다. VLAN 번호가 IP 주소의 네트워크 부분과 항상 동일한 숫자라는 규칙은 없다.

## 4. 루프와 STP
스위치 사이에 중복 링크를 만들면 장애 대응 경로가 생기지 만 루프에서 브로드캐스트가 반복될 수 있다. Ethernet 헤더에는 IP의 TTL 같은 일반 홉 제한이 없어 루프 억제 기술이 필요하다. STP 계열은 일부 경로를 논리적으로 막아 루프 없는 구조를 만드는 대표 기술이다. 실제 환경에는 다양한 변형이 있어 기본 목적을 먼저 배운다.

## 5. 보안 연결
ARP는 기본적으로 강한 상대 인증을 제공하는 프로토콜이 아니어서 가짜 응답에 의한 ARP 스푸핑위험을 이해해야 한다. VLAN만으로 모든 공격이 차단되는 것은 아니다. 접근 제어·스위치 보호 기능·호스트 보안을 함께 검토한다. 이 교재에서는 공격 실행 절차 대신 주소 신뢰·구역 분리 원리를 배운다.

### 직접 풀기와 확인
A가 원격 서버에 접속하고 첫 홉이 게이트웨이다. 패킷의 IP 목적지와 프레임의 MAC 목적지를 같은 장치라고 써야하는가? 아니다. IP는 원격 서버, 첫 링크 MAC은 게이트웨이다. 두헤더의 계층과 전달 범위가 다르다.

완료: 같은 망과 다른 망 각각의 ARP 대상과 첫 프레임 MAC을 적는다. 참고: [ARP RFC826](https://www.rfc-editor.org/rfc/rfc826.html), [IPv4 RFC791](https://www.rfc-editor.org/rfc/rfc791.html). 주소·학습 흐름은 자체 예제이며203.0.113.0/24는 문서 예시 대 역으로 사용했다.

## 강화 조건 비교: 최종 IP 대상과 다음 홉 MAC은 다르다
호스트H=192.0.2.10/24,기본 게이트웨이G=192.0.2.1이다. 목적지198.51.100.8로 보내면 H는 목적지가 자기 /24 밖임을 판단하고 G로 Ethernet 프레임을 보낸다. 이 구간의 목적 MAC은 G의 MAC이고 IP 목적지는 원격198.51.100.8이다. NAT 등 주소 변경은 이 구간에 없다고 가정한다.

ARP 캐시에 G의 MAC이 없으면 로컬 링크에서 ARP로 G를 찾는다. 원격 목적 호스트의 MAC을 모든 라우터 너머로 직접 ARP하지 않는다. 라우터가 다음 링크로 내보낼 때 링크 헤더는 새 링크에 맞게 바뀐다.

**스위치 반례:** 스위치가 특정 목적 MAC을 아직 학습하지 못한 unknown unicast는 같은 VLAN의 관련 포트들로 flooding할 수 있다. 이것을 IP 목적지가 브로드캐스트라는 뜻으로 해석하면 안 된다. 학습은 수신 프레임의 출발 MAC과 수신 포트로 이루어지는 대표 모델이다. VLAN 분리는 L2 브로드캐스트 영역을 나누지만 암호화나 애플리케이션 접근 권한을 자동 보장하지 않는다.
