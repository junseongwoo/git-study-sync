# 02-05 문자열·배열·컨테이너와 반복자의 계약

[[GI-교재02 프로그래밍_Cpp_Python|과목 목차]] · [[GI-문제02 프로그래밍_Cpp_Python|문제]] · [[GI-해설02 프로그래밍_Cpp_Python|해설]]

## 인덱스는 구간 정의와 함께 사용한다
0 기반 인덱스의 유효 범위는 길이 n에서0..n-1이다. 빈 배열에는 유효 원소 인덱스가 없다. Python은 음수 인덱스를 끝 기준으로 해석하지만 C++ vector의 -1 접근은 그런 규칙이 아니다. Python의 슬라이스와 정수 인덱스가 경계를 처리하는 방식도 다르다.

### 1. 배열·슬라이스·문자열
Python a[1:4]는 인덱스1,2,3을 새 목록으로 만든다. 리스트 슬라이스는 원소 참조의 얕은 복사다. a[100]은 범위 밖이면 IndexError지만 a[:100]은 가능한 구간까지만 반환한다. slice가 무조건 O(1)이라는 주장은 일반 목록 복사 비용을 빠뜨린다.

손풀이 예제 A: a=[10,20,30,40,50], a[-1]=50, a[1:4]=[20,30,40], a[::2]=[10,30,50], a[::-1]=[50,40,30,20,10]. 마지막의 새 목록과 a.reverse()의 원본 변경은 구별한다. 문자열 s="ABCD"에서 s[1:3]="BC"지만 s[0]="Z"는 허용되지 않는다.

C++ vector의 []는 일반적으로 범위 검사를 제공하지 않고 at는 범위를 검사해 out_of_range를 낼 수 있다. 존재하지 않는 인덱스를 읽은 결과를 특정 숫자로 추측하지 않는다. C의 배열이 함수 인자로 전달될 때 일반적인 매개변수 선언은 포인터로 조정되므로 크기를 따로 전달해야 하는 상황이 많다. 함수 인자 a에서 sizeof(a)가 원래 배열 전체 크기를 알려준다고 일반화하지 않는다.

### 2. 문자의 저장 단위
ASCII는 기본7비트 부호 체계이고 Unicode는 문자에 코드 포인트를 부여하는 체계다. UTF-8은 가변 길이 인코딩이다. Python str의 길이와 UTF-8로 인코딩한 byte 길이는 다를 수 있다. 화면에 보이는 한 글자와 코드 포인트 하나도 결합 문자·이모지 때문에 항상 같지 않다.

예제 B: s="가A"는 Python에서 코드 포인트 두 개라 len(s)=2, UTF-8에서 "가"3바이트+"A"1바이트이므로 len(s.encode("utf-8"))=4다. C++ std::string으로 UTF-8 바이트를 저장하면 size는 여기서4이고 한 바이트 인덱스 접근이 “한국어 글자 하나”를 반환하지 않는다. C# string은 UTF-16 코드 단위 모델이라 보조 평면 문자에서 Length와 표시 문자 수가 다를 수 있다. 본 교재의 단순 코드 출력 문제는 ASCII로 제한할 때 가정을 명시한다.

### 3. 집합·사전·맵
Python set은 중복 없는 집합이며 정렬 순서를 보장하지 않는다. dict는 키→값 관계이고 Python3.7부터 언어 수준의 삽입 순서 보장이 있다. 같은 키에 새 값을 넣으면 기존 값이 바뀐다. 없는 키를 []로 읽으면 KeyError, get으로 기본값을 제공하면 다른 정책을 구현한다.

예제 C: d={"A":2,"B":1};d["A"]=5;d["C"]=3이면 값은A5,B1,C3이다. 기존 A값을 바꾼 것이 새 A키를 추가한 것은 아니다. 빈 집합은 set(), {}는 빈 dict다. Python list는 일반적으로 해시 가능하지 않으므로 dict 키로 사용할 수 없다. tuple도 내부에 list를 포함하면 해시 가능성을 잃을 수 있다.

C++ map은 정렬 비교 순서에 따라 키를 관리하는 연관 컨테이너, unordered_map은 해시 기반 구조다. map과 dict가 항상 같은 순서·비용·삽입 부작용을 갖는다고 생각하지 않는다. Python Counter와 defaultdict를 써도 “값을 세는 연산”과 “처음 본 키 초기화”의 논리를 먼저 이해한다.

### 4. 반복 중 수정과 무효화
컨테이너를 순회하면서 구조를 변경하면 방문 누락·반복자 무효화·오류가 생길 수 있다. 언어마다 규칙이 다르므로 안전한 기본 패턴은 삭제할 대상을 따로 모으거나 새 결과를 만드는 것이다. 무조건 어떤 수정도 불가능하다는 말 대신 구조 변경 종류와 반복자 계약을 읽는다.

예제 D: [1,2,3,4]를 순회하며 짝수를 지우려는 의도는 `[x for x in a if x%2!=0]`로 새 목록을 만들어[1,3]을 얻을 수 있다. 다른 이름과 원본을 공유 중이면 a의 재바인딩과 a[:]의 내용 교체는 효과가 다르므로 요구를 확인한다.

C++ vector의 재할당은 원소를 가리키는 반복자·포인터·참조를 무효화할 수 있다. erase는 삭제 위치 이후의 반복자 등에 영향을 준다. 연결 리스트에서는 삽입·삭제의 무효화 범위가 다르다. “STL 반복자는 전부 안전/전부 위험”으로 한 문장에 묶지 않는다.

### 5. 정렬·비교 함수의 전제
사용자 비교는 일관된 순서 관계를 제공해야 한다. C++ sort 비교에서 `a<=b`처럼 동일 값도 참으로 반환하면 strict weak ordering 조건을 깨뜨릴 수 있다. Python key 함수는 비교할 키를 만들며 `key=lambda item:item[1]`처럼 사용한다. 키가 같을 때 원래 순서가 유지되는 안정성은 정렬 라이브러리의 보장과 연결한다.

### 직접 연습·완료 기준
슬라이스 [l,r)의 길이 r-l과 UTF-8 바이트 길이를 구별한다. 컨테이너를 고를 때 인덱스 접근·존재 확인·순서·중복이라는 요구를 각각 적는다. a=b, a=b.copy(), a[:]=b가 객체 공유에 미치는 효과를 그림으로 말하면 다음 장으로 이동한다.

### 보강 손풀이: 문자열 처리의 목적부터 정하기
문자열 "  A B  "에 strip()을 적용하면 "A B"이고 split()을 적용하면["A","B"]다. 앞뒤 공백 제거와 공백 기준 분리는 다른 연산이다. split(" ")처럼 구분자를 명시하면 연속 공백 처리도 달라질 수 있다. 로그 줄의 원문을 보존하는 문제와 토큰을 추출하는 문제를 구별한다.

C 문자열 char s[]="ABC"는 널까지 저장하지만 Python str "ABC"의 len은3이라는 문자 단위 계약이다. C++ std::string("ABC").size()는3이다. C의 sizeof(s)4와 C++ 문자열 길이3을 동일한 자료구조의 동일 연산처럼 비교하면 안 된다.

검색 값이 없을 때 Python list.index는 ValueError,dict[key]는 KeyError를 낼 수 있다. C++ find는 보통 end()를 반환한다. 원하는 실패 정책에 맞게 조건을 작성하고,end()를 역참조하지 않는다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
문자열의 길이 단위를 확인한다. Python3 str인 '가A'의 len은 Unicode 코드 포인트 두 개를 세어 2다. 이 문자열을 UTF-8로 인코딩한 bytes의 길이는 '가' 3바이트와 'A' 1바이트를 더한 4다. C++ std::string에 같은 UTF-8 바이트열을 저장하면 size()는 바이트 수 4다. 코드 포인트 개수도 사용자가 보는 글자 묶음과 항상 같지는 않으므로 '화면 글자 수' 계약은 별개다.

C++ 정렬 비교자는 엄격한 순서 계약을 지켜야 한다. comp(a,b)를 a<=b로 쓰면 comp(x,x)=true여서 비반사성 조건을 위반한다. 오름차순 기본 비교는 a<b다. 비교자로 단순 a-b를 반환하는 것도 bool 변환 때문에 양·음 모두 true가 되고 정수 오버플로 위험까지 생길 수 있다. 비교자는 '첫 값이 앞서는가'를 bool로 반환해야 한다.

순회 중 목록의 길이나 위치를 바꾸는 코드는 별도 검토한다. Python에서 a=[1,2,3,4]; for x in a: a.remove(x)를 수행하면 1을 지운 뒤 다음 인덱스가 현재 3을 읽고, 3을 지운 뒤 끝나므로 [2,4]가 남는다. 원래 항목을 모두 지우려면 clear()를 쓰거나, 조건 필터링이면 새 목록을 만들어 교체한다. 라이브러리가 컴파일/실행을 허용한다는 사실은 의도대로 모든 원소를 검사했다는 보장이 아니다.
