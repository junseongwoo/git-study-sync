# 08-04 성능 계산: CPI·클럭·처리량·암달의 법칙

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## 성능은 같은 작업의 실행 시간으로 비교한다
한 작업의 응답 시간(지연)과 단위 시간당 완료 작업 수(처리량)를 구별한다. 동시에 여러 요청을 받아 처리량을 늘렸다고 개별 요청의 지연까지 같은 비율로 줄었다고 단정하지 않는다. 가격·전력 등의 제약도 있지만 이 장의 기본 성능 기준은 같은 작업의 실행 시간이다.

### 1. CPU 시간 공식
CPU time=instruction count×CPI×clock cycle time=명령 수×평균 CPI/클럭 주파수다. CPI는 명령당 평균 사이클 수이고, 주파수 f의 한 사이클 시간은 1/f다. 메모리 대기·파이프라인 stall이 평균 CPI에 포함되었는지는 문제의 모델을 확인한다.

손풀이 예제 A: 명령 수 2×10^9,CPI=1.5,클럭 3GHz=3×10^9cycles/s이면 총 사이클은 3×10^9, CPU 시간은 1초다. 3GHz가 3×10^9instructions/s라는 뜻은 CPI=1이라는 조건 없이는 성립하지 않는다. instructions×cycles/instruction×seconds/cycle=seconds로 단위를 없애며 검산한다.

예제 B: 같은 프로그램이 A에서 명령 수 1억,CPI2,2GHz이면 0.1초다. B에서 명령 수 1억,CPI3,3GHz도 0.1초다. B의 높은 클럭만 보고 더 빠르다고 결론 내릴 수 없다. 컴파일러에 따라 명령 수가 달라지면 CPI·클럭뿐 아니라 명령 수도 다시 계산한다.

### 2. 가중 평균 CPI
명령 종류의 비중이 p_i,CPI_i라면 평균 CPI=Σp_i×CPI_i다. 종류별 CPI 숫자를 단순 산술평균하지 않는다. 명령 횟수가 n_i이면 총 사이클 Σn_i×CPI_i를 총 명령 수로 나눈다.

예제 C: 산술 50%·CPI1,load 30%·CPI2,branch 20%·CPI3이면 평균 CPI=0.5+0.6+0.6=1.7이다. 종류별 1,2,3의 평균 2는 비중이 다른 입력에 맞지 않는다. 총 1000명령이면 1700사이클이다.

추가 연습: 산술 800개·CPI1,load 100개·CPI4,branch 100개·CPI2라면 총 1400사이클, 평균 CPI1.4다. load 횟수는 적어도 사이클 비중은 400/1400 약 28.57%다. 명령 비중과 시간 비중은 다를 수 있다.

### 3. 속도 향상과 시간 감소율
speedup=기존 시간/새 시간이다. 기존 10초,새 6초이면 향상 배수 10/6 약 1.667배, 시간 감소율은 (10-6)/10=40%다. 속도 66.7% 향상과 시간 40% 감소는 같은 현상을 서로 다른 분모로 표현한다.

여러 프로그램의 성능을 합치는 문항은 지정된 산술평균·기하평균 등 측정 방식을 따른다. 다른 명령을 수행하는 프로그램들에 MIPS 값만 적용해 성능을 대신할 수는 없다. 더 많은 단순 명령을 실행하는 프로그램이 높은 MIPS를 기록하면서 더 오래 걸릴 수 있다.

### 4. 암달의 법칙
개선 전 전체 시간 중 개선 가능한 부분의 비중 p를 s배 빠르게 하면 전체 시간 비는 (1-p)+p/s, 향상 배수는 1/[(1-p)+p/s]다. p는 개선 전 시간의 비중이다. 개선 후 바뀐 시간 비중을 그대로 넣지 않는다.

예제 D: 전체 10초 중 6초를 3배 빠르게 한다. 나머지 4초+개선 부분 2초=6초로 총 향상 1.667배다. 그 부분을 무한히 빠르게 해도 나머지 4초가 남아 최대 2.5배다. 부분 향상 3배를 전체 향상으로 쓰지 않는다.

예제 E: 병렬화 가능한 비율 80%,처리 장치 4개,추가 비용이 없고 해당 부분이 완전히 4배 빨라지는 이상 모델에서 향상은 1/(0.2+0.8/4)=2.5배다. 통신·동기화·메모리 경합이 있으면 이상적인 분담보다 더 느릴 수 있다. 작업 크기를 고정한 암달 모델과 문제 크기도 늘리는 다른 모델을 섞지 않는다.

### 5. 두 부분을 동시에 개선하기
서로 겹치지 않는 기존 시간의 p1,p2 부분을 각각 s1,s2배 개선하면 새 시간 비는 (1-p1-p2)+p1/s1+p2/s2다. 중첩된 작업이나 이미 전체에 포함된 비용을 두 번 세지 않는다.

예제 F: 읽기 60%,계산 20%,나머지 20%에서 읽기 2배·계산 4배이면 새 시간 비 0.6/2+0.2/4+0.2=0.55, 전체 향상 약 1.818배다. 계산만 4배 개선했으면 시간 비 0.85, 향상 약 1.176배다. 가장 눈에 잘 보이는 연산만 고치기보다 시간이 걸리는 부분을 측정하는 이유다.

### 6. 단위와 완료 기준
GHz=10^9Hz,ms=10^(-3)s,ns=10^(-9)s다. 메모리의 1KiB=1024바이트,1MiB=2^(20)바이트다. KB·MB를 문제에서 1024계열로 정의했다면 그 정의를 따르되 이 교재는 혼동을 줄이기 위해 이진 용량에 KiB·MiB를 쓴다. 각 문항에서 명령 수·CPI·클럭·개선 비중의 기준을 적고 단위 소거까지 하면 완료한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
성능식을 단위와 함께 쓴다. CPU 시간=명령 수×평균 CPI/클럭 주파수다. 명령 5,000,000개, CPI 1.6, 2GHz라면 사이클 8,000,000, 시간 0.004초=4ms다. 2GHz를 2사이클/초로 다루면 10^9배 오류가 생긴다. 평균 CPI는 명령 비율의 가중 평균으로 구하며 단순히 종류별 CPI를 더하고 종류 수로 나누지 않는다.

같은 프로그램에서 클럭이 두 배가 되어도 CPI가 40% 증가하면 시간 비는 1.4/2=0.7이고 속도 향상은 1/0.7=10/7 약 1.43배다. 클럭 하나만 비교해 두 배 빠르다고 말할 수 없다. 명령 수까지 바뀌면 세 요인을 모두 넣는다. 비교 성능 수치가 어떤 워크로드와 실행 조건에서 나왔는지 확인한다.

암달의 법칙에서 원래 시간의 60% 부분을 3배 빠르게 만들면 새 시간 비는 0.4+0.6/3=0.6, 전체 향상은 5/3배다. 개선 부분을 무한히 빠르게 만들어도 남는 40% 때문에 최대 2.5배다. 비율 60%는 개선 전 전체 실행 시간 비율이며 개선 후 비율로 다시 대입하지 않는다.
