# 04-01 운영체제 역할·권한·인터럽트: 프로그램과 하드웨어 사이

[[GI-교재04 운영체제|과목 목차]] · [[GI-문제04 운영체제|문제]] · [[GI-해설04 운영체제|해설]]

## 학습 목표와 경력 연결
검사 장비 프로그램에서 카메라 대기·이미지 연산·파일 저장을 동시에 처리해 본 경험을 전산 용어로 정리한다. OS는 프로그램이 자원을 안전하게 공유하고 하드웨어를 일관된 인터페이스로 사용하도록 돕는다. 이 장은 '왜 커널이 필요한가'를 설명하는 출발점이다.

## 1. 가상화·동시성·지속성
CPU 가상화는 여러 프로그램이 각자 실행 기회를 얻도록한다. 메모리 가상화는 각 프로세스가 독립된 주소 공간을 사용하는 것처럼 보이게한다. 동시성은 여러 실행 흐름 사이 공유 데이터와 순서를 관리하는 문제다. 지속성은 종료·재부팅 이후에도 필요한 정보를 저장하는 문제다. 가상화가 반드시 클라우드 VM만 뜻하는 것은 아니다.

OS는 CPU 스케줄링, 메모리 관리, 파일 시스템,I/O 장치, 권한과 자원 보호, 오류 처리를 맡는다. 자원 관리의 목표는 효율·응답성·공정성·보호처럼 서로 충돌할 수 있다. 처리량 최대가 곧 모든 사용자 응답 시간 최소라는 뜻은 아니다. 시스템 호출 API와 실제 장치 레지스터 접근을 구분한다.

## 2. 사용자 모드와 커널 모드
사용자 모드의 프로그램은 임의의 모든 메모리·장치 명령을 실행할 수 없도록 제한한다. 커널 모드에서는 OS가 필요한 특권 연산을 수행한다. 시스템 호출은 프로그램이 파일 읽기·소켓·프로세스 생성 등 서비스를 요청하는 통제된 경로다. C#의 메서드 호출이 모두 시스템 호출인 것은 아니다. 문자열 길이 계산은 사용자 공간에서 끝날 수 있고 파일 읽기는 런타임·라이브러리를 거쳐 OS 서비스를 이용한다.

모드 전환은 권한 수준의 변경이고 문맥 교환은 CPU 실행 대상을 다른 프로세스·스레드로 바꾸면서 상태를 저장·복원하는 과정이다. 시스템 호출을 처리하고 동일 스레드로 돌아오면 모드 전환은 있지만 다른 스레드로의 문맥 교환이 없을 수 있다. 시스템 호출이 블로킹되어 다른 스레드가 실행되면 둘 다 생길 수 있다.

### 손풀이 예제 1: 두 가지 전환
프로그램 A가 get-time 서비스에 요청하고 즉시 반환했다. 같은 스레드가 계속 실행한다고 가정하면 사용자->커널->사용자 모드 전환이며 다른 실행 대상으로의 문맥 교환은 없다. A가 파일 읽기를 요청한 뒤 장치 완료를 기다리는 동안 B가 실행되면 A에서 B로 문맥 교환이 발생한다. 문제에서 단순히 '커널 진입'이라고 했다는 이유만으로 모든 문맥 교환 비용을 추가하지 않는다.

## 3. 인터럽트·예외·트랩
하드웨어 인터럽트는 장치 완료나 타이머처럼 외부 사건을 CPU에 알린다. 예외는 현재 명령의 실행과 관련된 사건이며 0으로 나누기·잘못된 메모리 접근 등이 예다. 시스템 호출을 위한 동기적 진입을 트랩이라고 설명하는 교재도 있다. 아키텍처마다 예외·인터럽트·트랩 명칭 범주가 조금 달라 공통 동작과 문제의 정의를 함께 본다.

타이머는 프로그램이 CPU를 영원히 독점하지 못하게 선점 기회를 제공한다. 장치 인터럽트는 I/O 완료를 알려 바쁜 반복 검사보다 효율적인 처리를 가능하게한다. 인터럽트가 도착했다고 매번 반드시 다른 프로세스로 전환하는 것은 아니다. 처리 후 기존 실행 흐름으로 돌아갈 수 있다.

## 4. I/O 방식의 차이
폴링은 상태를 주기적으로 읽어 완료를 확인한다. 인터럽트 방식은 완료 통지를 받는다. DMA는 장치와 메모리 간 전송의 많은 부분을 DMA 하드웨어가 수행하여 CPU가 모든 바이트 복사를 직접 지휘하지 않도록한다. 초기 설정·완료 처리·캐시 일관성 등에서 CPU·OS의 역할은 남는다. DMA가 CPU를 완전히 필요 없게 만든다는 명제는 틀리다.

### 손풀이 예제 2: 바쁜 대기와 대기 상태
장치가 10ms 뒤 완료되고 프로그램이 10ms 동안 반복적으로 상태를 확인하면 CPU 시간을 소모한다. OS가 스레드를 blocked로 옮기고 완료 시 ready로 옮기면 기다리는 동안 다른 일을 실행할 수 있다. 단순 모델에서 다른 일의 CPU 시간이 6ms라면 장치 대기 중 수행할 여지가 있다. 실제 겹침 정도는 장치·스케줄링·동기화 비용에 달린다. 항상 4ms가 남는다고 실제 성능을 보장하지 않는다.

## 5. 구조 비교
모놀리식 커널은 주요 OS 서비스가 커널 내부에서 함께 실행하는 구조다. 마이크로커널은 최소 기능을 커널에 두고 다른 서비스를 사용자 공간으로 분리하는 방향이다. 모듈형·하이브리드 구조도 있다. 분리는 장애 격리와 설계에 장점이 있을 수 있지만 IPC 전환 비용이 늘 수 있다. 특정 제품을 한 단어로 분류한 사실을 절대 성능 순위로 해석하지 않는다.

## 6. 실시간과 일반 시분할
일반 시분할은 응답성과 공정한 실행 기회를 중시한다. 실시간 시스템은 정해진 마감 시간 조건을 만족하는 것이 핵심이다. 하드 실시간은 마감 위반을 허용할 수 없는 요구, 소프트 실시간은 위반이 품질 저하를 일으키는 요구로 구분한다. '실시간 =무조건 빠름'은 틀리다. 일정 시간 안에 완료를 예측·보장할 수 있는지가 중요하다.

### 직접 풀기와 확인
이미지 저장 완료를 알리는 장치 인터럽트가 발생한 뒤 같은 프로그램이 재개되었다. 이 사실만으로 다른 프로세스 문맥 교환이 발생했는가? 아니다. 인터럽트 처리와 다른 실행 대상으로의 전환은 별개다. 문제에 실제 스케줄링 전환이 주어져야한다.

완료: 시스템 호출·인터럽트·모드 전환·문맥 교환을 각각 사례 하나로 설명한다. 참고: [OSTEP 소개](https://pages.cs.wisc.edu/~remzi/OSTEP/intro.pdf). 장비 경험 연결·시간 예제는 자체 구성이다.

## 강화 조건 비교: 동기 예외·외부 인터럽트·스케줄링은 같은 사건이 아니다
유저 프로그램이 허용되지 않은 페이지에 접근하면 그 명령 실행과 연관된 동기 예외가 발생할 수 있다. 타이머·장치 완료 인터럽트는 실행 명령과 직접 대응하지 않는 외부 사건이다. 시스템 콜은 요청한 OS 서비스를 위해 정해진 경로로 진입한다. 용어는 아키텍처마다 예외·트랩을 다르게 분류할 수 있으므로 문제에서 준 정의를 따른다.

**실행 흐름 반례:** 프로세스 P가 read 시스템 콜을 했지만 요청 자료가 이미 캐시에 있고 즉시 반환되었다고 하자. 유저→커널→유저의 모드 전환은 있었어도 반드시 다른 프로세스 Q로 문맥 전환한 것은 아니다. 반대로 타이머 뒤 P를 준비 상태로 보내고 Q를 실행하면 CPU 레지스터·문맥 교체가 필요하다.

**완료 기준:** 사건 원인,권한 모드 변경,현재 프로세스 상태,다음 실행 주체를 네 칸에 나눠 적는다. '커널 진입=항상 다른 프로세스 실행', '인터럽트=항상 오류', '시스템 콜=항상 대기'는 모두 지나친 일반화다.
