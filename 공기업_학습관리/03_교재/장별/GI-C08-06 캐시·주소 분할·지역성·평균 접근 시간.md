# 08-06 캐시·주소 분할·지역성·평균 접근 시간

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## 빠른 작은 저장 공간을 사용하는 이유
CPU와 메인메모리 사이 속도 차를 완화하려고 최근 또는 가까운 데이터를 캐시에 보관한다. 시간 지역성은 최근 사용한 데이터를 다시 사용하는 경향,공간 지역성은 사용한 주소 주변을 사용하는 경향이다. 배열 순차 읽기는 공간 지역성과 연결되고 반복문의 같은 변수·명령 재사용은 시간 지역성과 연결된다.

### 1. 블록·라인·히트·미스
메모리의 일정 블록을 캐시 라인에 가져온다. 대상 블록이 있으면 hit,없으면 miss다. valid는 내용의 유효 여부,tag는 원하는 메모리 블록인지 판정하는 정보다. 문제의 캐시 KiB가 데이터만인지 tag·valid 등 메타데이터도 포함한 용량인지 확인한다.

직접 사상은 메모리 블록이 갈 수 있는 라인이 하나다. 완전 연관은 아무 라인이나 가능하고,n-way 집합 연관은 지정된 집합의 n개 라인 중 하나에 놓는다. 연관도가 높아진다고 총용량이 자동으로 커지는 것은 아니다. 같은 총용량에서 집합 수와 way 수가 바뀐다.

### 2. 주소 비트 공식과 가정
바이트 주소 M비트,데이터 용량 C바이트,라인 크기 B바이트,way 수 W를 가정하고 관련 값들이 2의 거듭제곱이라고 하자.
- 라인 수=C/B
- 집합 수=C/(B×W)
- offset=log_2B비트
- index=log_2집합 수 비트
- tag=M-index-offset

손풀이 예제 A: 32비트 주소,직접 사상 데이터 캐시 4KiB,라인16바이트. 라인256개=2^8,offset4,index8,tag20이다. 라인 수256과 바이트 수4096을 혼동하지 않는다.
예제 B: 같은4KiB·16바이트를4-way로 바꾸면 집합64개=2^6,offset4,index6,tag22다. 집합마다 라인4개이고 총 라인 수256은 같다.

주소의 라인 내 위치는 address mod B,블록 번호는 floor(address/B),집합 번호는 블록 번호 mod 집합 수다. 예제 A에서 주소0x1234의 offset=4,블록0x123=291,집합291 mod256=35(0x23),tag=1이다. 16진수 하위 비트로 나누어 검산한다.

### 3. 충돌과 교체
직접 사상 캐시에서 다른 블록이 같은 라인으로 가면 번갈아 접근할 때 계속 교체될 수 있다. 용량이 남아도 사상 자리 충돌은 생긴다. 완전 연관·집합 연관에서는 LRU,FIFO,무작위 등 교체 규칙을 둘 수 있다. LRU는 가장 오래 사용하지 않은 블록,FIFO는 가장 먼저 들어온 블록을 고른다.

예제 C: 두 블록을 저장하는 완전 연관 캐시가 빈 상태에서 A,B,A,C를 읽는다. LRU는 두 번째 A 접근으로 A가 최근 사용되어 C 삽입 때 B를 제거한다. FIFO는 A가 먼저 들어왔으므로 A를 제거한다. 교체 기준이 다르면 같은 입력에서도 결과가 다르다.

추가 예제: 직접 사상 2라인에서 블록 번호0,2,0,2를 읽으면 둘 다 index0으로 가서 네 번 모두 miss다. 빈 index1이 있어도 직접 사상은 그 자리에 옮겨 넣을 수 없다. 같은 용량의 완전 연관이라면 처음 두 번 miss 후 나머지 두 번 hit가 가능하다.

기초 미스 분류는 최초 접근의 compulsory,전체 공간 부족의 capacity,사상 자리 충돌의 conflict다. 멀티코어의 일관성 변화 등 다른 미스 원인까지 이 세 종류에 무리하게 넣지 않는다.

### 4. 쓰기 정책은 두 축이다
write-through는 쓰기 때 아래 계층에도 반영하고,write-back은 캐시를 먼저 바꾸며 dirty 라인을 퇴출 등의 시점에 반영한다. 쓰기 miss에서 라인을 가져오는 write-allocate와 가져오지 않는 no-write-allocate는 별도의 선택 축이다. 흔한 조합을 외워도 두 용어가 동의어는 아니다.

예제 D: write-back 캐시에 있는 블록을 수정하면 dirty=1이 된다. 나중에 그 라인을 다른 블록으로 교체할 때 아래 계층에 반영하는 비용이 생길 수 있다. 모든 hit 쓰기마다 메인메모리에 쓰는 write-through 모델과 구별한다.

### 5. 평균 접근 시간의 기준
히트 시간 H,미스율 m,히트 검사 뒤 추가되는 미스 penalty P이면 AMAT=H+mP다. 미스한 경우의 전체 시간 M을 주면 AMAT=(1-m)H+mM이며 M=H+P 조건에서 같은 식이다.

예제 E: H=2ns,미스율5%,추가 penalty60ns이면 AMAT=2+0.05×60=5ns다. 미스 전체 시간60ns이면0.95×2+0.05×60=4.9ns다. “추가”라는 단어가 계산 기준을 결정한다.

2단계 캐시의 예로 L1 시간1ns,L1 miss10%,L2를 확인하는 추가 시간5ns,L2의 local miss20%,메인메모리 추가100ns를 가정하면 AMAT=1+0.1×(5+0.2×100)=3.5ns다. L2 local miss율은 L2 접근 중 비율이다. 전체 요청 기준 global miss율은0.1×0.2=2%다.

### 6. TLB와 page fault
TLB는 주소 변환 결과를 보관하는 캐시이고 일반 데이터 캐시는 데이터 블록을 보관한다. TLB miss면 페이지 테이블에서 변환을 얻을 수 있다. page fault는 유효한 매핑·페이지 존재·접근 권한 등의 문제로 OS 처리가 필요한 별도 사건이다. TLB miss가 언제나 디스크 접근은 아니다. 자세한 가상메모리는 OS 교재와 연결한다.

### 완료 기준
4KiB·16바이트·4-way의 index6·offset4·tag22를 계산한다. LRU/FIFO의 A,B,A,C 결과를 구별하고 AMAT에서 penalty가 추가인지 전체인지 표시한다. 영상 배열 순차 접근의 공간 지역성을 설명하면 완료한다.

### 보강 계산: 메타데이터까지 포함한 캐시 저장량
32비트 주소·직접 사상·데이터4KiB·라인16바이트 모델은 256라인,각 tag20비트다. 라인마다 valid1비트·dirty1비트가 있고 다른 정보는 제외한다고 하자. 데이터32768비트+메타데이터256×22=5632비트로 총38400비트=4800바이트다. 데이터를 저장하는 용량4096바이트와 실제 저장해야 할 총4800바이트는 다르다. 교체 정보·ECC·패리티가 주어지면 그 정보도 추가한다. 이 계산은 지정한 구조의 예이고 모든 제품의 정확한 실물 면적을 계산하는 모델은 아니다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
캐시 주소는 데이터 용량으로 line/set 수를 먼저 계산한다. 데이터 8KiB, 블록 32B, 2-way이면 line=8192/32=256, set=256/2=128이다. 32비트 바이트 주소에서 offset=log_232=5, index=log_2128=7, tag=32-5-7=20비트다. 태그·유효·dirty·교체 정책 비트의 저장 용량은 '데이터 용량'에 포함되지 않은 별도 오버헤드다.

2수준 AMAT의 미스율은 분모가 중요하다. L1 hit 2ns, L1 miss 10%, L2 접근 8ns, L2 local miss 25%, L2 miss의 추가 주기억장치 지연 100ns라고 하자. 순차 접근 가정에서 AMAT=2+0.1×(8+0.25×100)=5.3ns다. 전체 요청 기준의 메모리 도달률은 0.1×0.25=2.5%다. L2 local miss를 전체 요청의 25%로 잘못 계산하지 않는다.

연관도는 충돌을 줄일 수 있지만 어떤 접근열에서도 미스가 반드시 줄어든다고 일반화하지 않는다. 네 line 직접 매핑 캐시에 블록 0,4,0,4를 접근하면 같은 set 충돌로 모두 miss다. 총 네 line을 유지하는 2-way·두 set 캐시에서는 0과 4가 같은 set 두 way에 함께 들어 첫 두 번 miss, 뒤 두 번 hit가 가능하다. 비교에서는 총 데이터 용량·블록 크기·교체 정책을 명시한다.
