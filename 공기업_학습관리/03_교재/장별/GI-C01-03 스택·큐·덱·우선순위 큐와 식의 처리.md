# 01-03 스택·큐·덱·우선순위 큐와 식의 처리

[[GI-교재01 자료구조_알고리즘|과목 목차]] · [[GI-문제01 자료구조_알고리즘|문제]] · [[GI-해설01 자료구조_알고리즘|해설]]

## 핵심 구별
스택은 마지막에 넣은 것을 먼저 꺼내는 LIFO, 큐는 먼저 넣은 것을 먼저 꺼내는 FIFO다. 덱은 양쪽 끝에서 넣고 꺼낼 수 있다. 우선순위 큐는 삽입 순서가 아니라 우선순위에 따라 꺼낸다. 이 규칙들은 추상 자료형의 약속이며 배열이나 연결 구조 등 구현 방식과 구별한다.

### 1. 손으로 스택과 큐를 추적하기
push(2), push(5), pop(), push(7), pop()의 스택에서는 첫 pop이 5, 두 번째 pop이 7, 남은 값은 2다. 같은 입력을 큐에 enqueue/dequeue로 처리하면 첫 dequeue는 2, 두 번째는 5, 남은 값은 7이다. 문항에서 출력으로 묻는지 최종 저장 상태로 묻는지 구별한다.

스택 응용은 괄호 검사·함수 호출·DFS·되돌리기이다. 큐 응용은 도착 순서 처리·BFS·작업 대기이다. OS의 준비 큐가 언제나 단순 FIFO 스케줄링을 뜻하는 것은 아니다. 이름은 대기 집합을 뜻하고 정책에 따라 우선순위나 라운드 로빈 같은 선택 규칙이 붙을 수 있다.

### 2. 괄호 검사에서 불변식 찾기
여는 괄호를 만나면 스택에 넣고 닫는 괄호를 만나면 맞는 종류의 여는 괄호를 꺼낸다. 빈 스택에서 닫는 괄호를 만나거나 종류가 다르면 실패한다. 입력을 다 읽은 뒤에도 스택이 비어야 성공이다.

예제 A: `([{}])`에서 저장 상태는 (, ([, ([{, ([, (, 빈 상태로 바뀐다. `([)]`는 닫는 )를 읽을 때 top이 [이므로 실패한다. 여는 괄호 수와 닫는 괄호 수가 같다는 조건만으로는 충분하지 않다. 모든 접두 구간에서 구조적으로 맞게 닫혀야 한다.

```python
def balanced(text):
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for ch in text:
        if ch in '([{':
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack
```

이 코드는 괄호 외 문자는 무시한다는 전제를 둔다. 모든 문자를 검사해야 하는 다른 문제에서는 허용 문자 조건을 따로 구현한다. n문자를 한 번 읽고 각 괄호가 한 번 들어가고 나와 O(n) 시간, 최악 O(n) 공간이다.

### 3. 후위 표기식
중위식 `(2+3)*4`의 후위식은 `2 3 + 4 *`이다. 후위식에서는 숫자를 스택에 넣고 연산자가 나오면 두 값을 꺼내 계산한다. 먼저 꺼낸 값은 오른쪽 피연산자다. 뺄셈과 나눗셈은 이 순서를 바꾸면 답이 달라진다.

예제 B: `8 3 - 2 *`를 처리한다. 8→[8], 3→[8,3], -→[5], 2→[5,2], *→[10]. 답은 10이다. `3 8 -`는 -5다. 연산자 처리에 필요한 피연산자 수보다 스택이 작거나 마지막에 값이 둘 이상 남으면 잘못된 식이다.

중위식에서 후위식으로 바꿀 때는 연산자 스택을 사용한다. 곱셈은 덧셈보다 우선하며 괄호가 우선순위를 바꾼다. 같은 우선순위의 왼쪽 결합 연산자를 새로 만났다면 스택의 기존 연산자를 먼저 내보낸다. 모든 연산자가 왼쪽 결합이라는 가정은 하지 않는다. 지수 연산을 넣은 문항은 결합 규칙을 별도로 확인한다.

### 4. 원형 큐의 모델을 먼저 확인
배열 길이 m, front가 다음 꺼낼 위치, rear가 다음 넣을 위치인 모델을 가정한다. `(index+1)%m`으로 끝에서 처음으로 돌아온다. 한 칸을 비워 빈 상태와 가득 찬 상태를 구별하면 front=rear가 빈 상태이고 (rear+1)%m=front가 가득 찬 상태다. 이 모델의 유효 용량은 m-1이다. count 변수를 별도로 쓰는 모델이면 m개 모두 저장할 수도 있다. 시험에서 어느 정의를 쓰는지 먼저 읽는다.

예제 C: m=5, front=rear=0에서 10,20,30을 넣으면 rear=3이다. 두 번 꺼내면 front=2이다. 40,50을 넣으면 rear=0으로 순환하고 원소는 30,40,50의 순서다. 물리 슬롯의 번호 순서와 논리적인 꺼내기 순서는 다르다.

### 5. 우선순위 큐와 단조 스택
작은 값부터 꺼내는 우선순위 큐에 5,2,8을 넣으면 2가 먼저 나온다. 먼저 들어온 5를 우선하지 않는다. 일반적인 이진 힙 구현에서 삽입·최솟값 삭제 O(log n), 최솟값 조회 O(1)이다. 동일 우선순위의 순서는 별도 규칙 없으면 보장하지 않는다.

단조 스택은 저장 값의 증가 또는 감소 관계를 유지하는 패턴이다. 예를 들어 다음으로 더 큰 값을 찾을 때 작은 top들을 새 값으로 해결하고 뺀다. 각 원소가 최대 한 번 push·pop되므로 겉으로 중첩 while가 있어도 전체 O(n)이 된다. 이는 1장의 상각 분석과 연결된다.

### 실습과 학습 완료 기준
큐는 Python `collections.deque`의 append/popleft, C++ `queue`의 push/front/pop으로 연습한다. C++ pop은 값을 반환하지 않으므로 front를 먼저 읽는다. 괄호 ([)]가 실패하는 순간과 후위식 9 4 - 3 +의 결과 8을 손으로 적는다. 원형 큐 문항에서는 “한 칸 비움 여부”를 표시할 수 있으면 완료다.

### 보강 실습: C++ 큐·스택의 꺼내기
C++ queue의 pop()은 원소를 제거할 뿐 제거한 값을 반환하지 않는다. front()로 먼저 읽은 뒤 pop()한다. stack도 top()으로 읽고 pop()한다.

```cpp
#include <iostream>
#include <queue>
using namespace std;
int main() {
    queue<int> q;
    q.push(4); q.push(9); q.push(1);
    while (!q.empty()) {
        int value = q.front();
        q.pop();
        cout << value << ' ';
    }
    cout << '\n';
}
```

출력 순서는4 9 1이다. 같은 입력을 stack에 넣고 top/pop하면1 9 4다. 비어 있을 때 front/top을 사용하지 않는 조건이 먼저다. 우선순위 큐는 세 값을 모두 넣고 꺼내는 경우 기본 C++ priority_queue에서9 4 1이다. “먼저 들어온 순서”,“마지막에 들어온 순서”,“큰 값 순서”를 같은 입력으로 비교하면 혼동을 줄일 수 있다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
우선순위 큐는 최대/최소 하나를 빨리 꺼내는 구조다. 임의 원소의 우선순위를 직접 바꾸는 API가 없으면 수정된 새 항목을 넣고 오래된 항목은 나중에 검증하여 버리는 방식이 가능하다. 작업 A의 버전 1 우선순위 7을 넣은 뒤 버전 2 우선순위 2를 넣었다면 (2,A,2)가 유효하고 나중의 (7,A,1)는 현재 버전과 달라 건너뛴다. 단, 각 pop 뒤 검증해야 하고 오래된 항목 때문에 큐 크기가 커진다는 비용도 포함한다.

덱으로 고정 길이 구간의 최댓값을 유지할 때는 값을 감소하는 순서로 두고 원소의 인덱스를 저장한다. [4,2,5,1], 구간 길이 3을 보자. 인덱스 0의 4를 넣고 1의 2를 넣는다. 2의 5를 넣을 때 뒤의 2와 4를 제거한다. 첫 구간 최대는 5다. 3의 1을 넣은 뒤 두 번째 구간도 최대 5다. 각 인덱스는 한 번 들어가고 많아야 한 번 빠지므로 전체 O(n)이다. 구간 밖 인덱스 제거와 뒤의 작은 값 제거는 서로 다른 역할이다.

괄호 검사에서 '개수가 같다'는 필요조건일 뿐이다. 문자열 `)(`는 열고 닫는 개수가 같아도 접두 구간에서 닫는 괄호가 먼저 나온다. 종류가 여러 개인 `([)]`도 개수만 맞는다. 스택의 꼭대기 종류와 닫는 괄호를 비교하고 마지막에 스택이 비었는지 확인해야 한다.
