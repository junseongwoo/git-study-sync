# 04-06 메모리·페이지·주소 변환·TLB: 비트와 바이트를 계산하기

[[GI-교재04 운영체제|과목 목차]] · [[GI-문제04 운영체제|문제]] · [[GI-해설04 운영체제|해설]]

## 학습 목표
가상 주소와 물리 주소를 나누고 페이지 번호·오프셋을 계산한다. TLB 미스와 페이지 폴트를 구분한다. 이 장 수치는 가정이 명시된 자체 모델로 실제 OS 설정을 단정하지 않는다.

## 1. 연속 할당과 단편화
고정 크기 구획·페이지 안에서 남는 공간은 내부 단편화의 예다. 가변 크기 연속 할당에서 전체 빈 공간은 충분하지만 조각이 나 있어 큰 연속 구간을 만들지 못하면 외부 단편화다. 페이징은 가상 페이지를 물리 프레임에 분산 배치해 전형적인 외부 단편화 문제를 줄이지만 마지막 페이지의 내부 낭비와 페이지 테이블 비용이 남는다.

세그먼테이션은 코드·데이터 등 논리적으로 의미 있는 가변 크기 구간을 다룬다. 페이징과 세그먼테이션을 결합할 수도 있다. 둘을 항상 서로 배타적인 구현으로 생각하지 않는다. 주소 변환에는 보호 권한과 유효성 검사도 포함된다.

## 2. 주소 비트 분해
페이지 크기가 2 ^k 바이트이면 가상 주소의 낮은 k 비트가 페이지 안 오프셋이다. 나머지는 가상 페이지 번호다. 물리 주소는 매핑된 프레임 번호와 같은 오프셋으로 구성된다. 페이지 테이블은 가상 페이지를 물리 프레임에 대응시키며 각 항목에는 유효·권한·참조·dirty 등의 정보가 있을 수 있다.

### 손풀이 예제 16:32비트·4KiB
바이트 주소 방식, 가상 주소 32비트, 페이지 4KiB =4096 =2 ^12 바이트다. 오프셋 12비트, 가상 페이지 번호 20비트, 가상 페이지 수 2 ^20이다. 단일 단계 표의 각 항목 4바이트 면 표 크기는 2 ^20×4 =4MiB다. 프로세스가 실제 적은 메모리만 쓴다고 단순 선형 표 전체가 자동 작아지지는 않는다. 다단계 표 등 구조가 필요한 이유다.

물리 메모리 64MiB =2 ^26바이트 면 프레임 수 2 ^26/2^12 =2 ^14이며 프레임 번호 14 비트다. 이 단순 모델의 물리 바이트 주소는 26 비트다. 가상 주소 32비트와 물리 주소 26비트는 다를 수 있다.

### 손풀이 예제 17: 주소 0x12345
0x12345를 4096으로 나누면 가상 페이지 0x12 =18, 오프셋 0x345 =837이다. 페이지 18이 물리 프레임 7에 매핑된다면 물리 주소 7×4096 +837 =29509 =0x7345다. 오프셋은 주소 변환 뒤에도 그대로다. 16 진 수 다섯 자리 중 앞부분을 무작정 프레임 번호로 바꾸지 말고 페이지 크기를 먼저 확인한다.

## 3. TLB와 다단계 페이지 테이블
TLB는 주소 변환 정보를 빠르게 찾는 캐시다. TLB hit이면 페이지 테이블을 메모리에서 매번 찾지 않고 변환할 수 있다. miss이면 표를 탐색해 매핑을 얻을 수 있다. 매핑이 존재하고 페이지가 메모리에 있으면 TLB miss라도 페이지 폴트가 아닐 수 있다. 페이지 폴트는 접근한 가상 페이지의 부재·권한 등 OS가 처리해야하는 조건으로 발생한다. 유효한 첫 접근의 수요 할당도 폴트 원인이 될 수 있다.

다단계 표는 사용하지 않는 주소 범위의 하위 표를 만들지 않아 공간을 줄일 수 있다. 대신 TLB miss에서 여러 단계 메모리 접근이 필요할 수 있다. 거대 페이지는 변환 범위와 표 비용을 줄일 수 있지만 내부 낭비·할당·보호 단위 등 선택이 있다.

### 손풀이 예제 18: 유효 접근 시간
단일 단계 표, TLB 조회 10ns, 메모리 접근 100ns, TLB hit율 0.95, 순차 조회이며 hit 뒤 데이터 1회, miss 뒤 표 1회 +데이터 1회라고 가정한다. hit 비용 110ns, miss 비용 210ns. 평균은 0.95×110 +0.05×210 =115ns다. TLB와 메모리 조회가 병렬이라는 모델이면 다른 식이 된다. 페이지 폴트 비용은 포함하지 않는다.

## 4. 보호·공유·Copy-on-write
페이지 권한은 읽기·쓰기·실행 접근을 제한할 수 있다. 사용자 코드가 커널 공간이나 쓰기 금지 페이지를 수정하려할 때 예외 처리 경로가 필요하다. 주소 공간 분리는 프로세스 사이 보호에 도움을 주지만 공유 메모리로 일부 페이지를 함께 매 핑할 수 있다.

Copy-on-write는 처음에 같은 물리 페이지를 공유하다 실제 쓰기 시 복사하는 전략이다. 읽기만하는 동안 복사를 줄일 수 있다. '공유 페이지에 쓰면 모든 프로세스 값이 동시에 변경된다'는 COW 규칙을 무시한 설명이다. 공유 메모리와 COW의 목적·권한을 구분한다.

## 5. 스와핑과 요구 페이징
요 구 페이징은 페이지를 필요할 때 메모리에 가져 오는 방식이다. fault 처리는 접근 확인, 필요한 페이지 확보, 교체 후보 선택, dirty 페이지 저장, 데이터 적재, 표/TLB 갱신, 명령 재실행 등의 단계로 설명할 수 있다. 모든 폴트가 반드시 디스크에서 읽는 것은 아니다. 이미 캐시된 데이터, zero-fill 같은 경우가 있다.

### 직접 풀기와 확인
페이지 크기 8KiB이고 가상 주소 32비트라면 오프셋 13비트, 페이지 번호 19 비트다. 페이지 크기가 두 배가 되면 오프셋은 1비트 늘고 가상 페이지 수는 절반이 된다. 페이지 테이블 항목 크기가 같다면 선형 표의 크기도 절반이다. 실제 사용 량과 주소 공간 한도는 구분한다.

완료: 4KiB·8KiB 주소를 직접 분해하고, TLB miss와 page fault의 반례를 각각 말한다. 참고: [OSTEP 페이징](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-paging.pdf), [TLB](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-tlbs.pdf). 주소·확률 모델은 자체 제작이다.

## 강화 손풀이: 주소 비트와 TLB 지연을 독립 계산한다
가상 주소 32비트,페이지 4KiB=2^12 바이트면 오프셋은 12비트,가상 페이지 번호는 20비트다. 바이트 주소 0x12345의 페이지 번호는 0x12=18,오프셋은 0x345=837이다. 그 페이지의 물리 프레임이 7이면 물리 주소는 7×4096+837=29509=0x7345다.

**TLB 예제:** TLB 조회 10ns,메모리 접근 100ns,단일 단계 페이지 테이블이 메모리에 있고 TLB 조회와 메모리 접근은 겹치지 않는다. 적중률 80%,페이지 폴트는 없다. 적중 110ns,미스 210ns이므로 평균은 0.8×110+0.2×210=130ns이다. 미스 때는 페이지 테이블 1회와 실제 데이터 1회가 필요하다.

멀티레벨 테이블·페이지 워크 캐시·병렬 조회가 있으면 미스 비용식이 바뀐다. 문제의 단순 모델을 실제 CPU의 고정 성능으로 일반화하지 않는다. 페이지 폴트 확률을 섞을 때는 폴트 처리 시간이 원래 접근까지 포함한 총시간인지 추가시간인지 반드시 확인한다.
