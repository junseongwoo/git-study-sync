# 02-01 언어 실행·자료형·정수 연산·비트 연산

[[GI-교재02 프로그래밍_Cpp_Python|과목 목차]] · [[GI-문제02 프로그래밍_Cpp_Python|문제]] · [[GI-해설02 프로그래밍_Cpp_Python|해설]]

## C# 개발 경력을 공부로 연결하기
이미 알고 있는 변수·조건문을 다시 외우는 대신, 같은 코드처럼 보여도 언어 규칙이 달라지는 지점을 확인한다. 전산 필기에서는 C·Java 등의 출력 해석이 나올 수 있으므로 코딩테스트 주력 언어를 C++·Python으로 정해도 프로그래밍 이론을 두 언어로만 한정하지 않는다. 여기의 C++ 예제는 C++17, Python 예제는 Python3의 기초 기능을 기준으로 한다. 실제 시험의 지원 버전은 해당 공고·시험 안내에서 확인한다.

### 1. 컴파일과 실행
컴파일은 소스의 구조와 의미를 분석해 다른 표현으로 변환하는 과정이다. 전처리·어휘 분석·구문 분석·의미 분석·중간 표현·최적화·코드 생성·링크라는 전형적인 설명을 학습하되 모든 구현이 똑같은 별도 단계로 실행된다고 단정하지 않는다. 링크는 여러 목적 파일과 라이브러리의 기호를 연결한다. 문법이 틀리면 구문 단계의 오류, 없는 함수 정의를 사용하면 링크 오류가 될 수 있다.

C#과 Java는 중간 코드를 런타임이 실행하거나 JIT 컴파일할 수 있다. Python도 CPython에서는 바이트코드로 컴파일해 실행한다. “컴파일 언어는 실행 전에 모두 기계어, 인터프리터 언어는 한 줄씩 읽기만”이라는 이분법은 구현 현실을 지나치게 단순화한다. 정적·동적 타입은 타입 검사 시점의 특성이며 컴파일·인터프리트와 동일한 분류가 아니다.

### 2. 타입·범위·변환
정수·실수·문자·불리언·컨테이너의 역할을 분리한다. C++ int의 정확한 크기는 구현에 따라 달라질 수 있으므로 시험이 32비트를 가정했다면 그 가정을 적는다. Python int는 고정32비트 범위로 제한되지 않지만 메모리·연산 비용이 무한히 공짜인 것은 아니다. C# int와 Java int는32비트 부호 있는 정수다.

손풀이 예제 A: 32비트 부호 있는 정수의 수학적 표현 범위는 -2^(31)..2^(31)-1, 즉 -2,147,483,648..2,147,483,647이다. 1,000,000,000×3의 정확한 값3,000,000,000은 이 범위를 넘는다. C++에서는 긴 정수 변수에 결과를 대입하는 것만으로 중간 int 곱셈 overflow를 방지하지 못한다. `1LL*a*b`처럼 계산 이전에 충분한 타입으로 올리는 방법을 고려한다.

C++ 부호 있는 정수 overflow는 일반적으로 정의되지 않은 동작(UB)이므로 “무조건 음수로 돌아온다”고 답하지 않는다. 부호 없는 N비트 정수 연산은 2^N을 법으로 한 연산으로 설명한다. C#은 checked/unchecked 문맥을 읽어야 하고 Java int의 overflow는 정해진 wrap 규칙이 있다. 서로의 규칙을 옮겨 답하지 않는다.

### 3. 나눗셈과 나머지
C++17에서 정수 나눗셈은0 쪽으로 소수 부분을 버린다. Python의 //는 아래 방향으로 내림한다. 양수에서는 결과가 같지만 음수에서는 차이가 드러난다.

| 식 | C++17 정수식 | Python3 |
|---|---|---|
| 7 / 3 또는 7 // 3 | 2 | 2 |
| -7 / 3 또는 -7 // 3 | -2 | -3 |
| -7 % 3 | -1 | 2 |

손풀이 예제 B: Python에서 -7=(-3)×3+2이므로 나머지2다. C++에서 -7=(-2)×3+(-1)이다. a=q×b+r의 관계는 지키면서 몫의 버림 방향이 다르다. Python의 /는 정수 입력이어도 실수 나눗셈이다. 7/3은 약2.333…, 7//3은2다. 음수 모듈러가 필요한 문제에서는 언어 규칙에 맞게 정규화하고 나눗셈0을 막는다.

### 4. 실수와 비트
이진 부동소수점으로0.1 같은 값이 정확히 표현되지 않을 수 있다. 금융 금액을 무작정 double로 계산하는 것과 정수 단위·십진 자료형으로 계산하는 것의 차이를 이해한다. 작은 오차 허용 여부는 문제의 정답 판정 규칙을 따른다. “모든 실수 비교는 절대로 ==를 쓰면 안 된다”라는 극단적 문장보다 표현과 요구를 확인한다.

AND(&), OR(|), XOR(^), NOT(~), shift는 비트를 대상으로 한다. 논리 연산 &&/|| 또는 and/or와 구별한다. 양의 값5=0101,3=0011을4비트 그림으로 쓰면 AND=0001(1), OR=0111(7), XOR=0110(6)이다. 1<<3은 해당 표현이 유효한 타입·이동 범위에서8이다. 음수 shift나 범위를 넘는 이동 수의 규칙은 언어·버전에 따라 달라질 수 있어 본 교재의 출력 예제에서 피한다.

### 직접 연습·완료 기준
- 32비트 int의 최댓값을 적고 10만개의10만 합10^(10)이 넘는지 확인한다.
- Python -10//3=-4, -10%3=2를 관계식으로 검산한다.
- 6(0110) XOR 3(0011)=5(0101)을 직접 계산한다.
세 언어의 overflow를 한 규칙으로 묶지 않고 나눗셈·타입 변환 시점을 표시할 수 있으면 완료한다.

### 보강 실습: 계산 타입은 대입 전에 결정된다
int a=1000000000,b=3을 충분히 큰 결과 변수에 넣는다고 하자. C++에서 long long result=a*b는 먼저 int끼리 곱하려 하므로 그 타입의 범위를 넘는 중간 계산이 문제가 된다. long long result=1LL*a*b는 첫 곱부터 long long으로 계산한다. 이 예제에서 정확한 값은3000000000이다.

상수 식의 overflow,실행 중 overflow,형 변환의 규칙은 언어마다 다르므로 결과 숫자만 외우지 않는다. C#에서도 checked 문맥의 실행 중 overflow와 unchecked 문맥을 구별하고,컴파일 시 상수 식의 진단은 별도로 확인한다. Python에서는 같은 곱이 정수 값으로 계산되지만 매우 큰 정수를 계속 키우면 비트 길이에 따른 메모리·연산 비용이 생긴다.

추가 비트 연습: 상태의0번·2번 비트를 켜려면0b0101을 만들 수 있다. 상태5와 mask2의 AND는0이므로1번 비트는 꺼져 있다. “비트 번호”는0 기반이라는 계약을 적는다. NOT의 결과를4비트 그림으로 보여 주는 것과 Python의 무한 부호 확장 정수에서 ~5=-6이라는 동작을 혼동하지 않는다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
언어 간 정수 계약을 먼저 정한다. C++17의 부호 있는 정수 덧셈에서 표현 범위를 넘는 오버플로는 정의되지 않은 동작이며 '자동으로 한 바퀴 돈다'고 답하지 않는다. 부호 없는 정수는 해당 형의 범위에 맞춘 모듈러 연산이다. Python3 int는 임의 정밀도지만 비트 수가 커지면 연산 비용과 메모리 사용도 증가한다. 정답의 최종 합만 범위에 들어간다고 중간 합이 안전한 것은 아니다. long long의 최댓값 M에 1을 더하고 나중에 1을 빼면 최종 수학적 값 M과 관계없이 첫 덧셈이 위험하다.

Python3에서 -5//2=-3, -5%2=1이며 (-3)*2+1=-5다. C++17에서 -5/2=-2,-5%2=-1이며 (-2)*2-1=-5다. 두 언어 모두 몫·나머지 관계식은 유지되지만 음수 나눗셈의 몫 버림 규칙이 다르다. 배열 인덱스의 주기 순환에는 언어 차이를 확인하고 음수 나머지를 비음수로 정규화한다.

C++에서 부호 있는 인덱스 -1과 컨테이너의 부호 없는 size()를 비교하면 의도와 다를 수 있다. 64비트 size_t로 변환되는 비교에서는 -1이 큰 부호 없는 값이 되어 -1<3이 false다. '음수니까 당연히 작다'는 수학 판단을 그대로 옮기지 않는다. 인덱스 유효 조건은 i≥0을 먼저 확인한 다음 안전한 형 변환과 i<size를 확인한다.
