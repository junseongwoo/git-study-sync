# 08-03 CPU·명령어 사이클·레지스터·주소 지정

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## CPU는 데이터 경로와 제어를 함께 사용한다
CPU는 산술·논리 연산 장치(ALU), 레지스터, 데이터 이동 경로, 제어 구조를 사용해 명령을 수행한다. CPU를 ALU 하나로 축약하면 명령 가져오기·상태 저장·분기의 역할이 빠진다. 특정 CPU 모델의 실제 레지스터 이름과 일반 학습 모델의 역할을 구별한다.

### 1. 주요 레지스터의 학습 역할
PC는 다음에 가져올 명령 위치를 추적하는 프로그램 카운터, IR은 현재 해석할 명령, MAR은 메모리 주소, MDR/MBR은 메모리와 주고받는 데이터라는 전형적인 모델이다. SP는 스택 위치를 관리하고 상태/플래그 레지스터는 비교·carry·overflow 같은 조건을 저장할 수 있다. 모든 ISA가 똑같은 이름의 물리 레지스터를 공개한다는 뜻은 아니다.

PC가 항상 고정 1만큼 증가하는 것은 아니다. 바이트 주소·명령 길이 4바이트인 고정 길이 모델에서는 보통 4 증가하지만 가변 길이 명령이나 분기에서는 다른 변화가 있다. 주소 단위와 명령 길이를 문제에서 확인한다.

### 2. 명령어 사이클
대표적인 학습 모델은 fetch→decode→execute→memory→write-back이다. 모든 명령이 모든 단계에서 실질적인 일을 하는 것은 아니다. load는 메모리에서 읽고, store는 메모리에 쓰며, 분기는 PC를 바꾼다. 이 단계표는 5단계 파이프라인 모델과 연결되지만 실제 프로세서의 실행이 단순한 한 줄 흐름뿐이라는 뜻은 아니다.

손풀이 예제 A: 바이트 주소, 명령 길이 4바이트, PC=100에서 LOAD R1,[200]을 가져온다. 메모리[200]의 값 7을 R1에 넣고 분기가 없으면 다음 PC=104다. 200은 명령이 놓인 주소가 아니라 명령의 대상 데이터 주소다. PC와 피연산자 주소를 구별한다.

ADD R3,R1,R2는 R1과 R2 값을 더해 R3에 쓰는 가상 ISA 표기라고 정의한다. 어셈블리마다 피연산자 순서가 다를 수 있으므로 실제 문항의 정의를 따른다. R1=7,R2=4이면 R3=11이다. opcode는 무엇을 할지, operand는 대상이나 값의 정보를 나타낸다.

### 3. 주소 지정 방식
| 방식 | 피연산자·유효 주소 계산 | 주의점 |
|---|---|---|
| 즉시 | 명령 안의 값 자체 | 값과 메모리 주소 구별 |
| 레지스터 | 지정한 레지스터의 값 | 메모리 조회와 다름 |
| 직접 | 명령 주소 필드가 유효 주소 | 그 주소의 데이터를 사용 |
| 간접 | 주소 필드가 가리킨 곳에서 유효 주소 읽음 | 한 단계 더 따라감 |
| 레지스터 간접 | 레지스터 값이 유효 주소 | 레지스터 값 자체를 데이터로 읽지 않음 |
| 베이스+변위 | base 레지스터+명령 offset | 바이트/원소 단위 확인 |
| PC 상대 | 지정된 PC 기준+변위 | 기준 PC의 시점 확인 |

예제 B: 주소 필드 100, 메모리[100]=200, 메모리[200]=7이다. 직접 방식의 데이터는 200, 간접 방식의 데이터는 7이다. 주소 필드 100을 즉시 값으로 사용하면 100이다. 같은 숫자라도 방식이 달라지면 의미가 달라진다.

예제 C: 베이스 레지스터 1000, 변위 24인 바이트 모델의 유효 주소는 1024다. PC 상대에서는 “다음 명령 주소를 기준” 같은 정의를 읽는다. 현재 PC=100, 다음 주소=104, 변위=12를 사용하는 모델이면 대상은 116이다. 현재 PC를 기준으로 하는 다른 모델의 112와 섞지 않는다.

### 4. 주소 필드 비트 수와 명령 형식
명령 길이가 32비트이고 opcode가 8비트, 두 레지스터 번호가 각각 4비트라면 나머지 주소/즉시 필드는 16비트다. 4비트 레지스터 번호는 16개 레지스터를 구별할 수 있다. 즉시 필드를 부호 있는 16비트 2의 보수로 해석하는 모델의 범위는 -32768..32767이다. 명령 길이만으로 주소 범위·레지스터 수가 모두 정해지는 것은 아니다.

예제 D: opcode 6비트, 레지스터 필드 5비트 두 개, 즉시 16비트인 형식은 총 32비트다. opcode의 단순 코드 조합은 최대 64개지만 실제 ISA가 64개 명령을 반드시 제공한다는 뜻은 아니다. 예약 코드나 같은 opcode 안 세부 기능 필드도 가능하다.

### 5. ISA와 구현
ISA는 소프트웨어에서 관찰하는 명령·레지스터·데이터형·메모리 동작 등의 계약이다. 마이크로아키텍처는 그 ISA를 실행하는 구현이다. 같은 ISA를 다른 파이프라인·캐시·실행 유닛으로 구현할 수 있다. 컴파일된 프로그램의 명령 수가 같아도 CPU 시간은 달라질 수 있다.

RISC/CISC의 전통적인 설명은 명령 형식, 작업 복잡도, load/store 구조 같은 설계 경향이다. RISC가 항상 빠르거나 CISC가 항상 CPI가 큰 것은 아니다. 현대 프로세서의 내부 변환·분할 등은 이분법을 복잡하게 만든다. 기초 비교표와 실제 성능 결론을 분리한다.

### 6. 스택과 함수 호출
함수 호출은 돌아올 위치와 필요한 상태를 저장해야 한다. 호출 규약은 인자를 어디에 놓고 어떤 레지스터를 누가 보존하며 반환값을 어디에 두는지 정한다. 재귀에서는 활성 호출마다 정보가 필요해 호출 스택을 사용하는 전형적인 모델로 연결된다. 스택이 항상 낮은 주소로만 자라는 것은 모든 ISA의 보편 규칙이 아니다.

### C# 경험 연결·완료 기준
C# 코드가 컴파일·JIT를 거쳐 실행되어도 레지스터와 메모리 사이 이동은 성능에 영향을 준다. 영상 계산에서 메모리 접근이 지배적이면 ALU 추가만으로 전체가 빨라지지 않을 수 있다. PC·IR·주소/데이터 레지스터 역할과 즉시/직접/간접의 숫자 예제를 구별하고 명령 형식의 비트 합을 검산하면 완료한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
주소 지정은 계산 값과 메모리 읽기 횟수를 분리해 적는다. 기반 주소 1024, 인덱스 3, 요소 크기 4바이트, 추가 변위 8이면 유효 주소는 1024+3×4+8=1044다. 메모리에 들어 있는 값을 읽는다는 요구가 없으면 이 계산만으로 데이터 읽기를 추가하지 않는다. 간접 주소 지정에서 주소 200의 값이 900이고 주소 900의 데이터가 42라면 주소 지정에 따른 데이터 메모리 읽기는 두 번이다. 명령어 fetch를 비용에 포함하는지는 문제에서 별도로 명시한다.

PC 상대 분기는 기준 PC와 변위 단위가 필요하다. 현재 명령 주소 100, 길이 4바이트, 기준은 다음 명령 PC=104, 변위 -3이 '명령어 단위 4바이트'라면 목적 주소는 104+(-3)×4=92다. 현재 PC를 기준으로 쓰면 88이라는 다른 값이 되어 틀린다. 변위를 바이트로 주면 101이 되므로 단위도 확인한다.

load/store 모형은 산술 명령이 레지스터 피연산자로 계산하고 메모리 접근은 별도 load/store로 한다는 구조다. 메모리에서 값을 가져오는 load와 주소 수치만 계산하는 명령을 구별한다. 모든 ISA가 같은 명령 길이·레지스터 이름·주소 지정 공식을 가진다는 추정을 피하고 제시 모형 안에서만 추적한다.
