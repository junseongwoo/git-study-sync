# 02-03 함수·전달 방식·스코프·재귀

[[GI-교재02 프로그래밍_Cpp_Python|과목 목차]] · [[GI-문제02 프로그래밍_Cpp_Python|문제]] · [[GI-해설02 프로그래밍_Cpp_Python|해설]]

## 함수의 계약을 적기
함수는 입력 계약과 결과 계약을 갖는다. 입력을 변경하는지, 오류일 때 무엇을 하는지, 빈 입력을 허용하는지 적으면 구현과 호출자가 같은 기대를 갖는다. “함수를 호출하면 인자가 그대로 전달된다” 대신 값 복사·객체 공유·참조 바인딩을 구별한다.

### 1. C++ 값 전달과 참조 전달
C++에서 int x를 매개변수로 받으면 기본적으로 호출 시 값이 복사된다. int&는 기존 객체에 대한 참조이고 수정이 호출자 객체에 반영된다. const vector<int>&는 큰 컨테이너를 불필요하게 복사하지 않고 읽을 때 흔히 사용한다. const는 그 참조를 통한 변경을 제한하지만 모든 외부 경로에서 객체가 영원히 불변이라는 뜻은 아니다.

예제 A:
```cpp
void by_value(int x) { x += 10; }
void by_ref(int& x) { x += 10; }
int n = 5;
by_value(n);  // n == 5
by_ref(n);    // n == 15
```

by_value의 지역 x와 n은 다른 객체다. by_ref의 x는 n을 가리키는 참조다. 포인터를 값으로 전달해도 포인터가 가리키는 객체를 수정할 수 있다. 포인터 변수 자체를 다른 주소로 바꾸는 일과 그 주소의 원소를 바꾸는 일을 나눠 그린다.

### 2. Python의 객체 공유와 재바인딩
Python 함수의 매개변수 이름은 전달된 객체에 연결된다. 이름을 새 객체에 다시 연결하는 일은 호출자의 이름 연결을 바꾸지 않지만 공유 중인 변경 가능 객체 자체를 수정하면 호출자에게도 보인다. 이를 C++의 int& 참조 매개변수와 완전히 같은 의미로 부르면 혼동한다.

예제 B:
```python
def change(xs):
    xs.append(3)
    xs = [9]
    return xs
a = [1, 2]
b = change(a)
print(a)
print(b)
```

처음 xs와 a가 같은 목록을 가리킨다. append 후 그 객체가[1,2,3]이 된다. xs=[9]는 함수 안 이름을 새 목록으로 연결하고 반환한다. 출력 a는[1,2,3], b는[9]다. 매개변수에 대입했다고 호출자 이름까지 새 목록으로 바뀌지는 않는다. C#의 참조 형 매개변수를 일반 값 전달한 상황도 이 두 종류의 변경을 구별해서 읽을 수 있다. C# ref/out은 별도 규칙이다.

### 3. 기본 인자와 스코프
Python의 기본 인자 표현식은 함수 정의 때 평가된다. 변경 가능한 목록을 기본값으로 두면 호출끼리 공유할 수 있다.

```python
def add_bad(x, items=[]):
    items.append(x)
    return items
```

연속해서 add_bad(1),add_bad(2)를 호출하면 같은 기본 목록이[1]에서[1,2]로 변한다. 각 호출마다 새 목록이 필요한 의도라면 기본값 None을 두고 함수 안에서 새 목록을 만든다. 기본 목록을 의도적으로 공유하는 설계가 언제나 문법 오류라는 뜻은 아니다.

지역 이름과 바깥 이름의 범위를 구별한다. Python 함수에서 이름에 대입하면 기본적으로 지역 변수로 취급하므로 바깥 이름을 읽으려던 코드가 UnboundLocalError를 낼 수 있다. global·nonlocal은 바인딩 대상을 명시할 때 사용한다. C++의 블록 스코프, Java·C#의 변수 범위와 같은 이름이 등장해도 세부 규칙은 언어마다 확인한다.

### 4. 재귀의 기저 조건과 진전
재귀는 함수가 같은 함수를 직접 또는 간접 호출하는 구조다. 기저 조건이 있고 입력이 그 조건으로 가까워져야 한다. factorial(n)=n×factorial(n-1), factorial(0)=1은 n>=0에서 정의된다. 음수를 받아 n-1로 계속 내려가면0에 도달하지 않는다.

예제 C: fact(3)는 fact(2),fact(1),fact(0)을 호출하고 반환하며1→1→2→6을 만든다. 호출 깊이가4로 활성 정보가 쌓인다. 재귀 표현이 짧다고 추가 공간이0인 것은 아니다. Python 기본 구현은 일반적인 꼬리 호출 최적화를 보장하지 않으므로 깊이가 큰 입력에는 반복이나 명시적 스택이 필요할 수 있다.

### 5. 중복 부분 문제와 비용
fib(n)=fib(n-1)+fib(n-2)를 그대로 구현하면 같은 fib(3) 등을 여러 경로에서 계산한다. memo에 상태별 답을 저장하면 계산한 상태를 다시 쓰고 n에 비례한 상태만 계산한다. “재귀이면 느리다”가 아니라 중복 상태와 호출 비용을 살핀다. 이진 탐색 재귀는 구간이 반으로 줄어 호출 깊이가 O(log n)이고, 한 원소씩 줄이는 재귀는 O(n)일 수 있다.

함수 오버로딩은 같은 이름에 서로 다른 매개변수 형태를 두어 선택하는 기능이다. C++·Java·C#은 오버로딩 규칙을 제공하지만 Python에서는 같은 이름으로 def를 다시 하면 일반적으로 앞의 이름 바인딩을 새 함수로 덮는다. 동적인 인자 검사나 singledispatch 같은 기능과 문법적 오버로딩을 구별한다.

### 직접 연습·완료 기준
목록 매개변수에서 `append`와 `xs=[...]`를 각각 적용한 그림을 그린다. 기본 인자 목록의 공유를 None 패턴으로 수정한다. fact(0)=1, fact(4)=24를 추적하고 호출 깊이를 적는다. “입력 자체를 바꾸는지”와 “변수 이름을 새 객체로 연결하는지”를 말할 수 있으면 완료한다.

### 보강 실습: 새 기본 목록 만들기
각 호출마다 독립적인 목록이 필요하면 다음과 같이 쓴다.

```python
def add_safe(x, items=None):
    if items is None:
        items = []
    items.append(x)
    return items
a = add_safe(1)
b = add_safe(2)
print(a, b)
```

출력은[1] [2]다. 반대로 호출자가 목록을 직접 전달하면 그 목록을 수정하는 계약이다. “None으로 바꾸면 어떤 경우도 입력 변경이 없다”는 뜻은 아니다.

재귀의 작은 검증은 호출·반환 표로 한다. fact(4)→fact(3)→fact(2)→fact(1)→fact(0),반환1→1→2→6→24다. 일반적인 최적화가 없는 호출 모델에서 최대 활성 호출은5개다. n=0에서도 답1을 내는 초깃값,음수를 허용하지 않는 입력 조건을 함께 적는다. 기저 조건을 if n==1로만 쓰면0에서 종료하지 못하는 문제를 만들 수 있다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
Python 기본 인수는 함수가 호출될 때마다 새로 평가되는 것이 아니다. 다음 예는 호출 사이 목록을 공유한다.

```python
def append_bad(x, bag=[]):
    bag.append(x)
    return bag
```

첫 append_bad(1)의 결과는 [1], 두 번째 append_bad(2)는 같은 객체 [1,2]다. 결과 참조를 저장해 두었다면 첫 결과도 나중에 [1,2]로 보인다. 호출별 독립 목록이 목적이면 bag=None을 기본값으로 하고 함수 안에서 None일 때 []를 만든다. None이 유효한 업무 값이면 별도 sentinel을 써야 한다.

클로저의 늦은 바인딩도 유사한 함정이다. `fs=[lambda: i for i in range(3)]`에서 작성 후 호출한 결과는 [2,2,2]다. 함수가 숫자를 복사해 저장한 것이 아니라 나중에 같은 셀의 i를 읽는다. `lambda i=i: i`처럼 정의 시 기본 인수로 값을 잡으면 [0,1,2]가 된다. 반복 안에서 함수를 즉시 호출하는 사례와 반복 후 호출하는 사례를 구분한다.

꼬리 위치 재귀라도 Python이나 C++17이 호출 스택을 항상 제거해 준다고 계약하지 않는다. 높이 n인 재귀 탐색은 일반적으로 O(n) 호출 공간을 계산한다. 반복으로 바꾸면 변수 몇 개로 처리 가능한 문제인지, 명시적 스택이 필요한 문제인지에 따라 공간이 달라진다.
