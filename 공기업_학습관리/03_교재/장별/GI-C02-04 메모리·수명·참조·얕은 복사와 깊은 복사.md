# 02-04 메모리·수명·참조·얕은 복사와 깊은 복사

[[GI-교재02 프로그래밍_Cpp_Python|과목 목차]] · [[GI-문제02 프로그래밍_Cpp_Python|문제]] · [[GI-해설02 프로그래밍_Cpp_Python|해설]]

## 변수와 객체를 따로 그리기
메모리 문제는 이름이 몇 개 있는지보다 실제 객체가 몇 개 있고 누가 그 객체를 참조하는지가 중요하다. 변수→객체 상자를 그려 대입·복사·변경·수명 종료를 추적한다. 언어 런타임의 구현을 학습 모델과 혼동하지 않는다.

### 1. 자동 수명과 동적 수명
C++ 지역 객체는 일반적으로 블록을 벗어나면 수명이 끝나고 소멸자가 호출된다. 동적으로 할당한 객체의 수명은 별도로 관리해야 한다. 스마트 포인터와 RAII는 수명과 자원 소유를 객체 구조에 연결하는 설계다. 함수의 지역 변수 주소를 반환해 수명이 끝난 객체를 사용하면 유효한 접근을 보장할 수 없다.

“지역 변수는 항상 물리적 스택, new는 무조건 힙”이라는 단순 문장은 최적화·표현·런타임 구현까지 정확히 설명하지 못한다. 시험의 일반적인 실행 모델에서는 호출 스택과 동적 저장 공간을 구별하되, C++에서 중요한 언어 규칙은 저장 기간과 객체 수명이다. C# 값 형이 항상 스택에만 존재하는 것도 아니다. 클래스 객체의 필드나 배열 원소로 저장된 값 형을 생각하면 반례를 만들 수 있다.

### 2. 대입과 얕은 복사
Python에서 a=[1,2], b=a는 새 목록을 만들지 않는다. 두 이름이 같은 목록을 가리킨다. b.append(3)이 a에서도 보인다. b=a.copy()는 바깥 목록을 새로 만들지만 원소 참조를 복사한다. 원소가 변경 불가능한 정수이면 이런 얕은 복사가 독립된 값 목록처럼 보일 수 있지만 중첩된 목록이면 차이가 드러난다.

예제 A:
```python
a = [[1], [2]]
b = a.copy()
b[0].append(9)
b.append([3])
print(a)
print(b)
```

두 바깥 목록은 다르지만 첫 내부 목록을 공유한다. a=[[1,9],[2]], b=[[1,9],[2],[3]]다. 내부 변경은 공유되어 보이고 바깥 append는 b에만 보인다. “얕은 복사는 모든 것이 공유”도 “copy했으니 완전 독립”도 틀린 설명이다.

### 3. 깊은 복사와 예외
깊은 복사는 중첩 객체까지 재귀적으로 복사하는 접근이다. Python copy.deepcopy는 순환·이미 처리한 객체를 메모하여 적절한 복사 구조를 만들며 사용자 정의 객체는 복사 동작을 제어할 수 있다. 파일·소켓·외부 자원을 “완전히 복사하면 항상 독립”이라는 말은 현실적인 자원 의미까지 보장하지 않는다. 여기서는 정수와 목록으로 된 데이터 구조를 대상으로 연습한다.

예제 B: a=[[1],[2]], c=deepcopy(a) 후 c[0].append(9)이면 a는[[1],[2]], c는[[1,9],[2]]이다. 같은 입력에 얕은 복사와 깊은 복사를 비교하는 표를 만든다. C++ vector<vector<int>>를 값 복사하면 각 vector가 보유한 정수 원소들을 복사하는 일반적인 값 의미를 갖는다. 그러나 vector<shared_ptr<T>>를 복사하면 포인터 소유 정보가 복사되어 T 객체를 공유할 수 있다. 컨테이너 종류만 보고 “항상 깊은 복사”라고 하지 않는다.

### 4. 2차원 목록 초기화의 함정
Python `grid=[[0]*3]*2`는 같은 내부 목록을 두 번 참조한다. grid[0][1]=7이면 두 행 모두[0,7,0]으로 보인다. 각 행을 독립적으로 만들려면 `[[0]*3 for _ in range(2)]`로 작성한다. 바깥 반복이 목록 객체를 새로 만드는지를 확인한다.

손풀이 예제 C: 처음 내부 객체 R=[0,0,0], grid=[R,R]이다. R의 인덱스1을 바꾸면 grid의 두 경로 모두 같은 변경을 본다. 원소 대입을 하지 않고 grid[0]=[1,1,1]처럼 첫 행 참조 자체를 바꾸면 두 번째 행은 R을 유지한다. 객체 변경과 참조 교체를 나누어 이해한다.

### 5. 변경 불가능성과 동일성
Python str·int·tuple의 바깥 구조는 불변이다. tuple 안에 목록을 넣으면 목록 자체는 변경될 수 있다. tuple=( [1], ) 후 tuple[0].append(2)는 내부 목록 변경이며 tuple 항목 재대입과 다르다. C# string도 불변이며 새 문자열을 만드는 연산과 원본 문자 배열 수정은 구별한다.

Python ==는 값 비교를 호출하고 is는 동일 객체인지 검사한다. 작은 정수 캐싱이나 문자열 interning은 구현 세부이므로 숫자 두 개의 is 결과를 일반 시험 규칙으로 암기하지 않는다. None 확인은 `x is None`처럼 의미가 명확한 동일성 검사다. 값이 같은지를 원하면 ==를 쓴다.

### 6. GC와 자원 정리
가비지 컬렉션은 더 이상 사용 가능한 참조가 없는 관리 메모리의 회수를 돕는다. 파일·DB연결의 즉시 해제 시점을 무조건 보장하는 의미는 아니다. C# using, Python with, C++ RAII 등은 자원 사용 범위를 명시하는 패턴으로 연결된다. 메모리 누수는 참조를 계속 유지해 필요 없는 객체가 회수되지 않는 경우에도 생길 수 있다.

### 완료 기준
종이에 바깥 컨테이너2개와 공유 내부 컨테이너1개를 그려 예제 A를 재현한다. 얕은 복사·깊은 복사·대입 세 가지를 구분하고, C++의 수명 종료 후 포인터 접근을 정해진 출력으로 단정하지 않으면 완료한다.

### 보강 실습: 얕은 복사와 깊은 복사를 같은 입력으로 비교
한 코드에서 두 복사의 차이를 검증한다.

```python
from copy import deepcopy
original = [[1], [2]]
shallow = original.copy()
deep = deepcopy(original)
shallow[0].append(9)
deep[1].append(8)
print(original)
print(shallow)
print(deep)
```

출력은 original=[[1,9],[2]],shallow=[[1,9],[2]],deep=[[1],[2,8]]다. deep은 shallow 수정 전에 복사했으므로 첫 내부 목록에9가 없다. 복사 시점까지 결과에 영향을 준다. “deep에는 항상 원본의 현재 값이 따라온다”는 오해를 제거한다.

순환 구조 a=[];a.append(a)는 깊은 복사에서 무한히 새 하위 객체를 만들지 않도록 메모 관리가 필요한 이유를 보여 준다. 이 구조의 자세한 repr를 시험 정답으로 외우기보다,같은 객체를 다시 방문한다는 그림을 그린다. 값 복사·공유 소유·고유 소유를 구별하는 습관이 더 중요하다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
2차원 목록의 겉 복사와 내부 객체 복사를 손으로 그린다. a=[[1],[2]], b=a.copy()이면 a와 b는 별도 바깥 목록이지만 a[0] is b[0]은 true다. b[0].append(9)는 a에도 보여 a=[[1,9],[2]]가 된다. 이후 b[1]=[7]은 b의 두 번째 참조만 교체하므로 a[1]=[2]는 그대로다. '얕은 복사는 언제나 원본을 바꾼다'도 지나친 일반화다. 내부 객체 수정과 바깥 참조 교체를 구분한다.

C++ vector는 재할당이 발생하면 기존 원소를 가리키던 포인터·참조·반복자가 무효화된다. size=capacity=3에서 push_back하여 재할당했다면 이전 v[0] 참조를 읽으면 안 된다. 값을 복사한 독립 변수는 살아 있지만 기존 주소를 저장한 변수는 그렇지 않다. reserve를 호출했다는 사실만으로 모든 이후 삽입이 안전한 것은 아니며 실제 새 size가 capacity를 넘는지 확인한다.

소유권과 관찰용 주소도 구분한다. unique_ptr<T>는 하나의 소유자가 자원을 해제하며 복사는 금지되고 이동으로 소유권을 옮긴다. raw pointer를 복사했다고 소유권이 자동 이전되거나 대상 수명이 늘어나지는 않는다. 스택 지역 변수의 주소를 반환한 뒤 그 함수를 벗어나면 대상 수명이 끝나므로 이후 역참조가 안전하지 않다.
