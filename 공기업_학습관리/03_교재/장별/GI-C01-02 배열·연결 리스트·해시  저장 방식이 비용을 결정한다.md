# 01-02 배열·연결 리스트·해시: 저장 방식이 비용을 결정한다

[[GI-교재01 자료구조_알고리즘|과목 목차]] · [[GI-문제01 자료구조_알고리즘|문제]] · [[GI-해설01 자료구조_알고리즘|해설]]

## 핵심 질문
“읽는 일이 많은가, 중간에 넣는 일이 많은가, 키로 찾는가?”라는 질문부터 자료구조를 고른다. 저장 구조와 추상 연산을 구별하면 언어 라이브러리가 달라져도 같은 사고를 사용할 수 있다.

### 1. 배열과 동적 배열
고정 크기 원소를 연속 저장한 배열은 기준 주소와 인덱스로 위치를 계산한다. 원소 크기가 s바이트, 시작 주소가 B라면 0 기반 A[i]의 주소는 B+i×s이다. 따라서 인덱스 접근은 단위 비용 모델에서 O(1)이다. 정렬되지 않은 배열에서 특정 값의 위치를 찾는 것은 최악 O(n)이다. “접근”과 “검색”은 다른 연산이다.

동적 배열은 저장 공간을 늘릴 수 있지만 가운데에 삽입하면 뒤 원소를 이동한다. n개 중 인덱스 k 앞에 넣으면 보통 n-k개를 뒤로 민다. 끝에 넣기는 상각 O(1)이고 중간 삽입은 O(n)이다. Python list는 객체 참조를 저장하는 동적 배열이다. C++ vector<T>는 T 원소를 연속 저장한다. C# List<T>도 배열 기반 동적 컨테이너이지만 T가 값 형인지 참조 형인지에 따라 저장되는 값의 성격이 달라진다.

손풀이 예제 A: [10,20,30,40]의 인덱스 1에 15를 삽입한다. 40→인덱스4, 30→3, 20→2로 세 원소를 이동하고 15를 기록한다. 결과는 [10,15,20,30,40]이다. 인덱스 4 뒤에 붙이는 경우와 비용이 다르다.

### 2. 연결 리스트
각 노드에 값과 다음 노드의 연결 정보를 둔다. 단일 연결 리스트의 k번째 노드로 가려면 앞에서 k개 연결을 따라가므로 O(k), 최악 O(n)이다. 삽입 지점의 이전 노드를 이미 알고 있다면 연결 두 곳 정도를 바꾸어 O(1)에 삽입할 수 있다. 지점을 먼저 찾아야 한다면 검색 비용 O(n)이 포함된다.

예제 B: A→B→D에서 B 다음에 C를 넣으려면 먼저 C.next=D, 다음 B.next=C로 바꾼다. 순서를 잘못 잡아 B.next를 먼저 C로 바꾸고 원래 D를 저장하지 않았다면 뒷부분 연결을 잃을 수 있다. 삭제는 이전 노드의 next를 삭제 대상의 next로 바꾼다. 양방향 리스트는 prev도 관리하므로 노드 정보가 더 필요하다.

| 연산 | 동적 배열 | 단일 연결 리스트 |
|---|---|---|
| 인덱스 접근 | O(1) | O(n) |
| 값 검색 | O(n) | O(n) |
| 가운데 삽입 | 이동 O(n) | 이전 노드를 이미 알면 O(1) |
| 순차 탐색의 지역성 | 일반적으로 유리 | 노드 배치에 따라 불리 |
| 부가 메모리 | 여유 용량 | 노드별 연결 정보 |

리스트라는 이름만으로 연결 리스트라고 판단하지 않는다. Python list와 C# List<T>는 연결 리스트가 아니다. 언어에서 LinkedList나 forward_list 같은 별도 구조가 쓰이는 이유다.

### 3. 해시 테이블
키를 해시 함수로 버킷 위치에 연결한다. 같은 버킷으로 가는 다른 키를 충돌이라고 한다. 충돌을 처리하는 대표 방법은 체이닝과 개방 주소법이다. 체이닝은 버킷에 여러 원소를 연결하거나 모아 저장한다. 개방 주소법은 테이블 안의 다른 빈 위치를 탐사한다. 부하율 α=n/m은 원소 n개와 버킷 m개의 비율이다. 커질수록 충돌이나 탐사 길이 관리가 중요해진다.

예제 C: 크기 5의 테이블, h(k)=k mod 5, 선형 탐사, 키 삽입 순서 12,17,22를 가정한다. 12는 슬롯2, 17은 2가 차 있어 3, 22는 2·3이 차 있어 4에 들어간다. 17을 검색할 때 2→3을 본다. 17 삭제 후 슬롯3을 단순 빈칸으로 바꾸고 검색을 빈칸에서 종료하면 22를 찾지 못할 수 있다. 따라서 삭제 표식 또는 재배치 정책이 필요하다.

해시 테이블은 보통 키 순서 정렬을 제공하지 않는다. Python dict가 삽입 순서를 보존한다는 언어 규칙과 키를 오름차순으로 정렬한다는 보장은 다르다. 집합 출력 순서를 시험 정답으로 고정하지 않는다. 키의 동일성 판정과 해시 일관성이 중요하며, Python의 list처럼 변경 가능한 일반 목록은 dict 키로 사용할 수 없다.

### 4. 같은 문제의 세 가지 설계
회원 번호 n개에서 특정 번호가 있는지 q번 확인한다고 하자. 정렬되지 않은 배열의 반복 검색은 O(nq), 한 번 정렬 후 이분 탐색은 O(n log n+q log n), 적절한 해시 테이블 구축 후 검색은 기대 O(n+q)다. 범위 안의 번호를 순서대로 출력하는 요구가 추가되면 정렬 배열이나 균형 탐색 트리가 편리할 수 있다. 자료구조의 선택은 전체 요구에 달려 있다.

### C++·Python 사용 지침
`vector`와 `list`의 이름을 대응 암기하기보다 비용을 적는다. C++ vector에 원소를 더해 재할당되면 기존 원소를 가리키던 참조·포인터·반복자가 무효화될 수 있다. Python list의 앞 삭제를 반복하는 코드는 큐 역할에 비효율적이다. 키 존재 확인은 Python의 `key in d`, C++ unordered_map의 `find`처럼 목적이 명확한 연산으로 작성한다. 조회를 위해 C++ map의 대괄호를 쓰면 없는 키가 삽입될 수 있다는 부작용에 주의한다.

### 직접 연습과 완료 기준
크기 7, h(k)=k mod 7, 선형 탐사로 10,17,24를 넣으면 슬롯3,4,5다. 배열 [1,2,3,4,5]의 첫 원소를 삭제하면 뒤의 4개를 이동한다. 삽입 위치를 찾는 비용을 제외하고 연결 리스트가 빠르다고 말하는 조건을 한 문장으로 설명하면 이 장을 마친다.

### 보강 손풀이: 전체 처리 비용으로 선택하기
원소 1000개에 존재 확인을 10000회 수행한다고 하자. 정렬되지 않은 배열의 최악 비교 수는 약1000×10000=1000만 회다. 한 번 정렬한 뒤 이분 탐색하면 정렬에 대략 n log_2n의 증가율,질의마다 약 log_21000 약 10단계로 규모를 줄일 수 있다. 정확한 비교 수는 구현·정렬 알고리즘에 따라 다르므로 이 근삿값을 실행 시간 보장으로 쓰지는 않는다.

해시가 항상 정답인 것도 아니다. 키 범위의 최소·최대,순위,구간 출력이 많으면 정렬 구조가 편리하다. 키가0..999의 작은 정수로 제한되고 단순 존재 여부만 필요하면 bool 배열을 쓰는 직접 주소 방식도 생각할 수 있다. 키가 최대10^(12)라면 같은 직접 배열은 공간 문제가 생긴다. “자료구조 이름을 기억”에서 “입력 제약과 전체 작업에 근거해 선택”으로 옮겨 간다.

추가 연습: 오름차순을 유지한 채 인덱스 중간 삽입을 반복하면 동적 배열의 이동 비용이 크다. 연결 리스트로 바꿔도 삽입 위치 탐색이 필요하면 총 비용이 자동으로 O(1)이 되지는 않는다. 이전 노드 핸들을 이미 갖고 있는지 조건을 반드시 표시한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
체이닝과 개방 주소법에서 삭제의 의미는 다르다. 슬롯 7개, h(k)=k mod 7, 선형 탐사로 3,10,17을 순서대로 넣으면 슬롯 3,4,5에 저장된다. 10을 삭제할 때 슬롯 4를 '한 번도 사용하지 않은 빈칸'으로 만들면 17 검색이 중단되어 실패한다. 삭제 표식은 검색을 계속하게 하고, 삽입은 재사용 후보로 기억하게 한다. 삭제 표식을 무조건 첫 발견 즉시 덮어 쓰고 뒤쪽의 동일 키 검사를 생략하면 중복 키를 허용하지 않는 테이블에서 다른 오류를 낳을 수 있다.

연결 리스트 삭제가 O(1)이라는 말도 입력 계약을 확인한다. 단일 연결 리스트에서 삭제 노드의 이전 노드가 주어지고 맨 앞 예외도 처리하면 연결 변경은 O(1)이다. 삭제할 값만 주어지면 이전 노드를 찾는 선형 검색이 포함된다. 주소를 안다는 사실과 이전 노드를 안다는 사실을 혼동하지 않는다. 마지막 노드에서 '다음 노드 값을 복사해 현재 노드를 지운 것처럼 처리'하는 편법은 다음 노드가 없어 적용되지 않는다.

읽기 중심 설계에서 정렬된 n개 키를 보관하고 범위 [L,R]의 키 k개를 출력한다면 두 경계를 이분 탐색하고 결과 k개를 순회해 O(log n+k)로 처리할 수 있다. 키 순서를 따로 보장하지 않는 해시 구조에 범위 출력도 기대 O(1)이라고 옮겨 붙일 수 없다. 결과 자체가 k개면 최소 Ω(k)의 출력 비용이 있다.
