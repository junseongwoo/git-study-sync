# 07-01 계층·캡슐화·지연: 통신을 서로 다른 문제로 나누기

[[GI-교재07 네트워크|과목 목차]] · [[GI-문제07 네트워크|문제]] · [[GI-해설07 네트워크|해설]]

## 위치와 학습 목표
네트워크는 이번 기준에서 IBK IT·기보 전산의 공식 상세 목록에 독립 과목 명으로 따로 적힌 것으로 보장하지 않는다. 전산학·보안·DB·서버 개발을 이해하는 보강 교재다. 공고의 범위가 바뀌면 최신 모집 문서로 우선순위를 조정한다. 학부 기초와 응용의 연결을 목표로 한다.

## 1. 계층이 해결하는 문제
장비의 검사 결과를 서버로 보낼 때 프로그램은 데이터 형식, 누락·순서, 목적지 주소, 실제 케이블 전송을 동시에 해결해야 한다. 계층은 이 문제들을 구분하여 아래 쪽 구현이 바뀌어도 위쪽 서비스를 사용할 수 있게한다. '계층마다 반드시 서로 다른 장비가 하나씩 필요'라는 뜻은 아니다.

OSI 7 계층은 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용이다. TCP/IP는 대표적으로 링크, 인터넷, 전송, 응용 4 계층으로 설명한다. 자료에 따라 물리층을 분리한 5 계층 모델도 있다. 어떤 모델을 사용했는지 먼저 적는다. 실제 프로토콜을 OSI 도식에 대응시킬 때 기능이 여러 층에 걸칠 수 있다.

| 문제 | 대표 층·예 | 핵심 식별자·단위 |
| --- | --- | --- |
| 신호를 매체로 전달 | 물리 | 비트·신호 |
| 같은 링크 안 전달 | Ethernet 링크 | MAC·프레임 |
| 네트워크 사이 전달 | IP | IP 주소·패킷 |
| 프로세스 사이 전송 | TCP/UDP | 포트·세그먼트/ 데이터 그램 |
| 서비스 의미와 형식 | HTTP/DNS 등 | 메시지 |

IP 주소는 호스트에 영원히 고정된 사람 주민 번호가 아니다. 인터페이스·망 설정과 관련된 주소다. 포트는 전송 프로토콜에서 프로세스의 통신 끝점을 구분하는 데 쓰인다. 같은 숫자의 TCP 포트와 UDP 포트는 다른 전송 식별 공간이다.

## 2. 캡슐화와 MTU
응용 데이터에 TCP 헤더, IP헤더, 링크헤더·트레일러 등이 붙는다. 수신에서는 대응하는 계층이 정보를 해석하여 상위로 전달한다. 링크의 MTU는 그 링크에서 전달할 수 있는 상위 패킷 크기의 대표 제한이다. 전체 응용 메시지 크기와 동일하지 않다. 큰 메시지를 여러 TCP 세그먼트로 나누는 것은 IP 단편화와 다르다.

### 손풀이 예제 1: payload와 헤더
Ethernet IP MTU1500바이트, IPv4 헤더 20바이트, TCP 헤더 20바이트, 옵션 없음이면 TCP 데이터는 최대 1460바이트다. IPv6 기본 헤더 40바이트에 같은 조건이면 1440바이트다. 실제 TCP 옵션·터널·추가헤더가 있으면 값이 바뀐다. 'Ethernet 프레임 전체 1500'이라고 외우면 링크 헤더·FCS와 혼동한다.

전형적 VLAN 없는 Ethernet 프레임에서 IP1500 + 헤더 14 + FCS4 =1518 바이트다. 프리앰블·SFD8바이트와 인터 프레임 간격 12바이트 상당 전송 시간은 이 프레임 크기와 별도로 계산한다. 본 예는 전형적 모델이고 제품의 jumbo frame 등을 포함하지 않는다.

## 3. 네 가지 지연
처리 지연은 헤더 검사·분류 등의 시간, 큐잉 지연은 차례를 기다리는 시간, 전송 지연은 패킷의 모든 비트를 링크에 싣는 시간, 전파 지연은 신호가 매체를 이동하는 시간이다. 링크 속도를 높이면 전송 지연은 줄 수 있지만 같은 거리의 전파 지연이 자동으로 줄지는 않는다.

### 손풀이 예제 2: 전송과 전파
1500바이트를 10Mbit/s 링크에 싣는 전송 시간은 1500×8/10,000,000 =0.0012초 =1.2ms다. 거리 200km, 신호 속도 2×10 ^8m/s이면 전파 시간 200,000/(2×10 ^8)=0.001초 =1ms다. 큐·처리 지연 0이면 한 링크의 마지막 비트 도착까지 2.2ms다. byte를 bit로 바꾸는 8 배와 km를 m로 바꾸는 1000 배를 모두 적용한다.

모든 링크가 같은 속도이고 4개의 링크마다 200km,store-and-forward, 패킷하나, 처리·큐 0이면 4×(1.2 +1)=8.8ms다. cut-through 나패킷 연속 전송의 파이프라인은 다른 모델이다. 가정을 생략하고 홉 수만 곱하지 않는다.

## 4. 대역폭·처리량·RTT
대역폭은 링크가 제공할 수 있는 전송 능력이고 실제 처리량은 경쟁·손실·헤더·제어에 따라 낮아질 수 있다. RTT는 왕복 시간으로 한 방향 전파 지연과 동일하지 않다. 지연이 작은 것과 큰 파일 처리량이 높은 것은 관련이 있지만 다른 측정이다.

### 손풀이 예제 3: 대역폭-지연 곱
100Mbit/s,RTT50ms이면 BDP는 100,000,000×0.05 =5,000,000bit =625,000byte다. TCP에서 왕복 응답을 기다리는 동안 전송 파이프를 충분히 채우려면 그 규모의 미확인 데이터와 관련된 윈도 조건을 생각해야 한다. 실제 속도를 이 값 하나로 확정할 수는 없다. decimal MB와 binary MiB를 혼합하지 않는다.

### 직접 풀기와 확인
10MiB를 100Mbit/s로 보내는 순수 전송 시간은 10×2 ^20×8/100,000,000 =0.8388608초다. 10MB라면 0.8초다. 연결 설정·재전송·헤더를 제외한 모델이므로 실제 파일 복사 시간은 더 다를 수 있다.

완료: 계층별 주소,MTU와 메시지, 전송과 전파를 각각 구분한다. 참고: [IPv4 RFC791](https://www.rfc-editor.org/rfc/rfc791.html), [TCP RFC9293](https://www.rfc-editor.org/rfc/rfc9293.html). 지연·헤더 계산은 가정이 명시된 자체 예제다.

## 강화 손풀이: 메시지 크기·패킷 크기·링크 전송을 분리한다
동일한 두 링크가 라우터로 이어지고 각 링크10Mbps,패킷마다 전체 길이600바이트,총3패킷이라고 하자. 저장 후 전달(store-and-forward)이며 전파·큐·처리·프로토콜 추가 비용은0이다. 한 링크에서 한 패킷의 직렬화 시간은600×8/10^7=0.48ms다.

첫 패킷은 두 링크에서 차례로 전송해0.96ms에 도착한다. 이후에는 두 링크가 서로 다른 패킷을 동시에 전송할 수 있어 추가 패킷마다0.48ms가 늘어난다. 마지막 세 번째 패킷 도착은(링크2+패킷3-1)×0.48=1.92ms다. 메시지를 하나의1800바이트 패킷으로 보는 모델과 다르다.

**가정 비교:** 전파 지연이 각 링크2ms라면 위 단순 모델에서 최종 도착에 총4ms를 더해5.92ms다. 패킷 전체 길이에 이미 헤더를 포함했으므로 다시 헤더를 더하지 않는다. 응답이 필요하면 그 응답의 경로·크기·대기 계약을 별도로 계산한다. 링크 전송률만으로 애플리케이션 전체 완료 시간을 보장할 수는 없다.
