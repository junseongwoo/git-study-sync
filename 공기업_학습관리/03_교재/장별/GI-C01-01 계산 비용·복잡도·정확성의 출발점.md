# 01-01 계산 비용·복잡도·정확성의 출발점

[[GI-교재01 자료구조_알고리즘|과목 목차]] · [[GI-문제01 자료구조_알고리즘|문제]] · [[GI-해설01 자료구조_알고리즘|해설]]

## 이번 장에서 할 일
반복문의 모양을 외우기보다 입력 크기가 바뀔 때 실제 작업량이 어떻게 증가하는지 세어 본다. 코딩테스트에서는 정답이라는 사실과 제한 안에 실행된다는 사실을 따로 입증해야 한다. 전산 필기에서는 최악·평균·상각이라는 조건을 읽는 습관이 우선이다.

### 1. 문제를 수학적으로 적기
입력은 길이 n인 정수 배열, 출력은 최댓값이라고 하자. 알고리즘은 유한한 단계로 입력에서 출력을 만든다. 처음 값을 최댓값 후보로 놓고 나머지를 한 번씩 비교하면 n-1번의 비교가 필요하다. 어떤 값이 최대인지 모르는 일반적인 비교 모델에서는 확인하지 않은 값이 더 클 수 있으므로 모든 값을 검토해야 한다.

`O(g(n))`는 충분히 큰 n에서 비용을 어떤 상수배의 g(n) 이하로 제한하는 상한이다. `Ω`는 하한, `Θ`는 상·하한이 같은 차수라는 뜻이다. 이 교재에서 “선형 시간”이라고 쓰면 명시한 모델에서 Θ(n)를 뜻한다. O(n^2)인 알고리즘이 O(n^3)도 만족한다는 이유로 더 느린 차수를 답으로 고르지 않도록 한다. “가장 타이트한 상한”을 요구하면 불필요하게 큰 상한을 제외한다.

| 증가율 | n이 두 배일 때 대략적인 변화 | 흔한 작업 |
|---|---|---|
| O(1) | 일정 | 배열 인덱스 접근 |
| O(log n) | 몇 단계 증가 | 정렬 배열 이분 탐색 |
| O(n) | 2배 | 전체 합 |
| O(n log n) | 2배보다 조금 증가 | 병합 정렬 |
| O(n^2) | 4배 | 모든 쌍 비교 |
| O(2^n) | 입력 1 증가마다 약 2배 | 부분집합 완전 탐색 |

실제 초당 연산 수는 언어·입출력·상수·실행 환경에 따라 다르다. “n=10만이면 반드시 몇 초” 같은 고정 공식 대신 후보 알고리즘의 증가율을 비교한다. Python의 큰 정수 연산도 정수의 비트 길이가 커지면 단위 비용 가정이 깨질 수 있다.

### 2. 손풀이 예제 A: 중첩이라고 모두 n^2는 아니다
다음 반복문의 내부 본문 수행 수를 센다.

```python
count = 0
for i in range(1, n + 1):
    for j in range(i):
        count += 1
```

i가 1부터 n까지이므로 1+2+…+n=n(n+1)/2번이다. n=4이면 1+2+3+4=10번이다. 주요 항은 n^2/2이므로 Θ(n^2)이다. 두 반복문을 연속으로 각각 n번 돌리는 코드는 n+n=2n이어서 Θ(n)이다. 구문에 for가 두 개라는 사실은 차수의 근거가 될 수 없다.

다음은 j가 두 배씩 커진다.

```python
j = 1
while j < n:
    j *= 2
```

n=16이면 j는 1,2,4,8에서 네 번 실행되고 16에서 종료한다. n=17이면 다섯 번이다. 수행 횟수는 n>1에서 ceil(log_2n)이다. 바깥에서 이 반복을 n회 독립적으로 수행하면 Θ(n log n)이다. 반면 두 포인터가 각자 최대 n번만 이동하는 하나의 루프라면 Θ(n)일 수 있다.

### 3. 평균과 상각은 다른 설명이다
해시 탐색의 기대 O(1)은 적절한 해시 분포와 부하 관리 같은 전제를 둔다. 충돌이 극단적으로 몰리면 기본적인 체이닝 구현의 한 번 탐색이 O(n)까지 늘어난다. 동적 배열의 append는 대개 O(1)이지만 재할당하는 한 번은 O(n)이다. 용량을 두 배로 늘리는 전략이라면 전체 n회 append의 복사량을 합쳐 O(n)으로 제한할 수 있어 회당 상각 O(1)이라고 한다. 이는 입력을 확률적으로 평균 낸다는 설명과 다르다.

손풀이 예제 B: 빈 배열의 용량을 1,2,4,8로 늘리며 8개를 넣는다. 확장 때 기존 원소를 복사하는 수는 1+2+4=7이다. 새 원소 쓰기 8회를 더해도 총 15회로 n의 상수배다. 어느 한 번이 비싼 것과 전체가 선형이라는 사실은 동시에 성립한다.

### 4. 추가 공간과 정확성
입력 배열 자체를 제외한 추가 공간을 세는 관례를 사용하되 문제의 기준을 확인한다. 누적 합을 변수 하나로 계산하면 O(1), 길이 n의 결과 배열을 만들면 O(n)이다. 재귀는 호출 스택도 공간이다. 깊이가 n인 재귀를 “배열을 안 만들었으니 O(1)”이라고 답하면 안 된다.

반복 불변식은 매 반복의 시작 또는 끝에 유지되는 사실이다. 최대 찾기의 불변식은 “지금까지 읽은 구간의 최대를 max_value가 담는다”이다. 초기 한 원소에서 성립하고, 다음 원소와 비교하면 보존되고, 전체를 읽으면 전체 최대가 된다. 초기화·유지·종료를 적으면 코드의 정확성 설명이 간결해진다.

### C# 경력 연결
검사 이미지가 n장일 때 전체 픽셀 분석 비용은 이미지 수뿐 아니라 이미지당 픽셀 수도 곱해진다. “한 파일 처리 O(1)”은 파일 크기를 고정했을 때만 맞는 모델이다. UI에 사용한 List<T>의 인덱스 접근과 중간 삽입 비용을 구분하면 Python list와 C++ vector를 이해하기 쉽다.

### 직접 풀고 확인
1. n=5에서 삼각형 반복문의 실행 수를 적는다.
2. n=32에서 두 배 루프의 실행 수를 적는다.
3. n개의 값을 읽고 합·개수·최대만 저장할 때 추가 공간을 적는다.
정답은 15회, 5회, O(1)이다. 단, 수의 크기가 고정된 기계 정수라는 모델이다. 계산식을 말할 수 있으면 다음 장으로 이동한다.

### 보강 실습: 한 입력에서 시간·공간 모델까지 적기
정수 n개를 읽어 합과 최댓값을 구한다. 비어 있지 않은 입력이며 누적 합이 long long 범위 안이라는 계약이다.

```cpp
#include <algorithm>
#include <iostream>
#include <limits>
using namespace std;
int main() {
    int n;
    if (!(cin >> n) || n <= 0) return 0;
    long long sum = 0;
    long long best = numeric_limits<long long>::lowest();
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        sum += x;
        best = max(best, x);
    }
    cout << sum << ' ' << best << '\n';
}
```

n=4,값[-2,7,3,-5]의 답은3과7이다. 값을 모아 저장하지 않아 추가 공간 O(1),값 n개를 읽어 O(n) 시간이다. “최댓값은 best,합은 sum”이라는 각각의 불변식을 적는다. 음수만 있는 [-8,-3]에서도 best=-3이 되어야 한다. 만약 평균까지 필요하면 정수/실수 나눗셈 계약을 별도로 정한다. 입력 크기·값의 범위·유효 입력 조건을 비용 분석과 함께 적는 습관을 시작한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
두 포인터 코드에서 루프가 중첩되어 보인다고 곱셈을 먼저 하지 않는다. 다음 입력은 n≥0인 배열이고 i와 j는 둘 다 0에서 시작한다. i는 바깥 반복마다 1 증가하며 j는 감소하지 않고 최대 n까지만 증가한다고 하자. 내부 while의 총 실행 수는 j의 전체 증가 수인 최대 n이다. 바깥 n회와 합쳐 O(n)이며, 모든 원소를 한 번 읽는 작업이 포함되면 Θ(n)이다. 각 바깥 반복에서 j=0으로 다시 초기화하면 같은 결론을 사용할 수 없다.

반대로 i=1..8에서 j=1부터 시작하여 j≤i 동안 j를 두 배로 만드는 반복의 횟수는 1,2,2,3,3,3,3,4로 합계 21이다. 일반 n에서는 각 i에 대해 floor(log_2i)+1회다. 상한은 n(log_2n+1), 하한은 i≥ceil(n/2)인 약 n/2개 항만으로 Ω(n log n)를 얻어 Θ(n log n)이다. 상한만 적은 후 곧바로 Θ를 주장하지 않는 연습이다.

동적 배열의 용량이 1에서 시작해 꽉 찰 때 두 배가 된다고 하자. 원소 17개를 추가하면 기존 원소 복사는 1+2+4+8+16=31번이다. 새 원소 쓰기 17번까지 세면 총 48번이다. 한 번의 추가가 O(n)이어도 n번의 총비용이 O(n)이어서 상각 O(1)이라는 설명이 맞는다. 매번 용량을 1만 늘리는 다른 정책은 복사 합이 1+…+(n-1)이 되어 이 보장을 잃는다.
