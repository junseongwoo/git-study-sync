# 04-03 CPU 스케줄링: 도착·선점·동률을 명시한 계산

[[GI-교재04 운영체제|과목 목차]] · [[GI-문제04 운영체제|문제]] · [[GI-해설04 운영체제|해설]]

## 학습 목표
FCFS·SJF·SRTF·RR의 간 트 차트를 같은 데이터로 비교한다. 표에 없는 도착 시점·문맥 교환 비용·동률 규칙을 마음대로 가정하지 않는다. 본 장 모든 계산은 CPU1개, CPU버스트 한 번,I/O 없음, 문맥 교환 비용 0이다.

## 1. 지표와 계산 순서
완료 시간 C, 도착 시간 A, 버스트 B, 최초 CPU 배정 F라 하면 반환 시간 =C-A, 대기 시간 =반환 시간-B, 응답 시간 =F-A다. 여러I/O버스트가 있는 문제에서 대기 시간을 계산할 때는 blocked 시간도 구분해야하므로 이 단순 식의 조건을 확인한다. CPU 사용률은 CPU가 실제 작업한 비율이 고처리량은 단위 시간 완료 작업 수다.

| 프로세스 | 도착 A | CPU 버스트 B |
| --- | --- | --- |
| P1 | 0 | 7 |
| P2 | 2 | 4 |
| P3 | 4 | 1 |

동률이면 먼저 도착, 그래도 같으면 프로세스 번호가 작은 쪽이다. SRTF에서 남은 시간이 같으면 현재 실행을 유지한다. RR은 경계 시각에 새로 도착한 작업을 만료 작업의 재삽입보다 먼저 ready 큐에 넣는다. 문제 별다른 규칙이면 그 규칙으로 다시 풀어야한다.

## 2. FCFS: 도착 순서 비선점
### 손풀이 예제 6
간 트 차트 P1[0,7),P2[7,11),P3[11,12)다. 완료는 7,11,12. 반환은 7,9,8. 대기는 0,5,7로 평균 4다. 최초 실행은 0,7,11이므로 응답도 0,5,7이다. 짧은 P3가 긴 작업 뒤에 기다리는 호위 효과를 볼 수 있다. 비선점은 실행 중 작업을 새 짧은 작업 때문에 빼앗지 않는다는 뜻이다.

## 3. SJF: 준비된 작업 중 가장 짧은 전체 버스트
### 손풀이 예제 7
t0에는 P1밖에 없으므로 P1이 0~7을 끝낸다. t7에 P2 버스트 4,P3 버스트 1이 ready 라 P3가 7~8,P2 가 8~12다. 완료는 P1 =7,P2 =12,P3 =8. 대기는 0,6,3, 평균 3이다. 미래에 도착할 P3를 미리 알고 CPU를 t0부터 비워 두는 알고리즘이 아니다. SJF는 버스 트 예측이 필요하고 긴 작업의 기아 가능성이 있다.

## 4. SRTF: 남은 시간이 더 짧으면 선점
### 손풀이 예제 8
P1 0~2를 수행해 남은 5. t2에 도착한 P2의 4가 더 짧아 P2 2~4. t4의 P2 남은 2보다 P3의 1이 짧아 P3 4~5 완료. 다음 P2 5~7 완료,P1 7~12 완료다. 완료 12,7,5, 반환 12,5,1, 대기 5,1,0, 평균 2다. 최초 실행 각각 도착 시점이라 응답 평균 0이다. 모든 문제에서 응답 0이 된다는 뜻은 아니다.

계산할 때는 남은 시간을 도착 사건마다 갱신한다. P1의 원래 버스 트 7과 P2의 남은 2 를 혼합 비교하면 틀린다. 선점 사건이 많으면 실제 문맥 교환 비용이 늘 수 있다. 비용이 주어지면 그 구간도 차트에 표시한다.

## 5. RR: 시간 할당량 q =2
### 손풀이 예제 9
P1[0,2),P2[2,4),P1[4,6),P3[6,7),P2[7,9),P1[9,11),P1[11,12)다. t4 직전에 ready 큐에는 P1이 있고 P3가 새 도착, 그 뒤 P2가 재삽입되어 P1,P3,P2다. 완료 P1 =12,P2 =9,P3 =7. 대기는 5,3,2, 평균10/3이다. 응답은 0,0,2다. 마지막 P1의 연속 타임 슬라이스는 실행 대상이 같아 반드시 새 문맥 교환을 발생시키는 것으로 세지 않는다.

q가 커져 모든 버스트보다 충분히 크면 이 단순 모델의 RR은 FCFS와 비슷해진다. q가 작으면 최초 응답에 좋을 수 있지만 전환 오버헤드가 커질 수 있다. 'q가 0에 가까울수록 언제나 최적'은 틀리다.

## 6. 우선순위·기아·에이징
높은 우선순위 작업이 지속 도착하면 낮은 우선순위 작업이 오래 기다리는 기아가 발생할 수 있다. 에이징은 기다린 작업의 우선순위를 점진적으로 높인다. 숫자가 작을수록 높은 우선순위라는 정의라면 에이 징은 숫자를 줄이는 방식이 된다. 숫자 방향을 문제에서 확인한다.

다단계큐는 작업 범주별 큐를 나눠 스케줄링하고, 다단계 피드백 큐는 행동에 따라 큐 사이를 이동하게할 수 있다. CPU를 오래 쓰는 작업을 낮은 큐로 내리고 상호 작용 작업의 빠른 응답을 돕는 설계를 이해한다. I/O 직전에 자발 양보해 우선순위를 유지하려는 문제를 막으려면 누적 CPU 사용 량 회계 등을 고려한다. 정책 세부는 설명에 따라 다르다.

## 7. 시험 풀이 검산
CPU 버스트합은 7 +4 +1 =12다. 이예의 완료 종료 시각은 모두 12이며 유휴 시간 0이다. 각 작업의 실행 구간 길이 합은 그 버스 트와 같아야한다. 대기 시간이 음수이면 도착·완료·버스트를 잘 못 썼다. 선점형에서 응답 시간과 전체 대기 시간은 같지 않을 수 있다.

### 직접 풀기와 확인
SRTF의 P1은 0에 시작해 12에 끝난다. 응답 시간 0, 반환 12, 대기 5다. '대기 5이므로 응답도 5'라고 하면 최초 응답과 누적 기다림을 혼동한 것이다. FCFS에서는 각 작업이 시작 후 끝까지 실행하므로 이 모델에서 응답과 대기가 같다.

완료: 네 차트를 보지 않고 다시 그리고, RR큐순서와 동률 규칙을 설명한다. 참고: [OSTEP 스케줄링](https://pages.cs.wisc.edu/~remzi/OSTEP/cpu-sched.pdf). 도착·버스트·경계 규칙은 자체 제작이다.

## 강화 손풀이: RR 경계의 동시 도착 순서를 명시한다
단일 CPU,문맥 전환 비용 0,quantum=2다. P1은 t=0에 도착해 CPU 4,P2는 t=2에 도착해 CPU 1을 요구한다. t=2의 양자 종료와 새 도착이 겹치면 새 도착을 먼저 큐에 넣고 미완료 P1을 뒤에 넣는 규칙을 사용한다.

| 구간 | 실행 | 구간 끝 상태 |
| --- | --- | --- |
| [0,2) | P1 | 잔여 2,새 P2 도착 |
| [2,3) | P2 | 완료 C2=3 |
| [3,5) | P1 | 완료 C1=5 |

반환시간은 P1 5-0=5,P2 3-2=1이고 대기시간은 각각 5-4=1,1-1=0이다. 평균 대기는 0.5다. 만약 미완료 P1을 먼저 넣는 다른 규칙이면 P1이 [2,4)를 실행하고 P2가 [4,5)를 실행해 평균 대기 1이 된다. 알고리즘 이름만으로 경계 규칙까지 동일하다고 가정하지 않는다.

SRTF에서 P1 잔여 2와 t=2에 도착한 P2 CPU 2가 동률이면 현재 실행 유지라는 규칙을 명시할 수 있다. 이 경우 P1이 4에 완료하고 P2가 6에 완료한다. 최단 잔여 선택과 동률 정책을 별도로 적는다.
