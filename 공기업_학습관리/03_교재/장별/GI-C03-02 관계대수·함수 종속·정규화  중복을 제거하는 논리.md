# 03-02 관계대수·함수 종속·정규화: 중복을 제거하는 논리

[[GI-교재03 DB_SQL|과목 목차]] · [[GI-문제03 DB_SQL|문제]] · [[GI-해설03 DB_SQL|해설]]

## 학습 목표
SQL 문법을 외우기 전에 행을 선택하고 열을 선택하는 연산을 구분한다. 정규화 문제는 후보키부터 계산한다. 이 장에서는 함수 종속을 명시한 작은 관계만 다루며, 데이터 몇 줄만 보고 모든 종속을 추정하지 않는다.

## 1. 관계대수 기본 연산
선택(selection)은 조건을 만족하는 행을 고른다. 투영(projection)은 필요한 속성만 남긴다. 집합 관계대수의 투영에서는 중복 튜플이 제거된다. SQL `SELECT 열`은 일반적으로 중복을 유지하므로 관계대수 투영과 대응시킬 때 `DISTINCT` 여부를 확인한다.

합집합·교집합·차 집합은 양쪽 속성 수와 대응 도메인이 호환되어야한다. 카티션 곱은 가능한 모든 행 쌍을 만든다. 조인은 곱에서 조건을 만족하는 조합을 고르는 식으로 이해할 수 있다. 자연 조인은 같은 이름 속성들의 동등 비교와 중복 열 정리를 수행한다. 업무상 우연히 같은 이름인 열이 추가되면 의미가 달라질 수 있으므로 실무에서는 명시적 JOIN 조건이 더 안전하다.

### 손풀이 예제 3: 곱과 조인
고객 C ={(1,가),(2,나),(3,다)}, 계좌 A ={(10,1),(11,1),(12,3)}다. C×A는 3×3 =9 행이다. 고객 ID 동등 조인은 (가,10),(가,11),(다,12)의 3 행이다. 계좌 없는 고객까지 LEFT JOIN 하면 (나,NULL)을 추가하여 4 행이다. 1:N에서 조인 결과의 고객 이름은 반복된다. 이를 곧바로 오류나 중복 데이터 저장으로 판단하면 안 된다.

관계 나눗셈은 '주어진 모든 항목과 연결된 대상'을 찾는 연산이다. 예를 들어 대상 강좌 집합이 {DB,OS}이고 수강 관계가 가-DB, 가-OS, 나-DB라면 두 과목을 모두 수강한 사람은 가다. SQL에서는 이 중 NOT EXISTS 또는 대상 수와 일치하는 집계로 표현할 수 있지만 NULL·중복·대상 집합이 빈 경우 조건을 정확히 정해야 한다.

## 2. 함수 종속과 속성 폐포
X -> Y는 동일한 X 값을 갖는 행들이 항상 동일한 Y 값을 가져야한다는 제약이다. 현재 데이터에서 우연히 같은 모습이라는 것과 구별한다. X에 Y가 포함되면 자명 종속이다. 반사·증대·이행 규칙으로 주어진 종속에서 추가 종속을 도출한다.

X +는 주어진 종속 집합 아래 X로 결정할 수 있는 모든 속성이다. 먼저 X 자체를 넣고, 왼쪽 속성이 모두 들어 있는 종속의 오른쪽을 반복해서 추가한다. 더 추가할 속성이 없으면 멈춘다. 전체 속성을 포함하면 X는 슈퍼키이고 X의 진 부분 집합은 전체를 결정하지 못해야 후보키다.

### 손풀이 예제 4: 폐포와 후보키
R(A,B,C,D,E), F ={A -> B, B -> C, CD -> E}가 주어졌다.

1. A +는 {A}에서 B, C를 추가하여 {A,B,C}다. D가 없어서 CD -> E를 적용하지 못한다.
2. AD +는 {A,D}에서 B,C,E를 차례로 추가하여 전체 {A,B,C,D,E}다.
3. A나 D를 빼면 전체가 되지 않는다. AD는 후보키다.
4. A와 D는 어떤 종속의 오른쪽에도 나타나지 않는다. 따라서 모든 후보키는 A와 D를 포함해야 한다. AD 하나만으로 전체를 얻으므로 이 예에서 후보키는 AD뿐이다.

'오른쪽에 없는 속성은 후보키에 반드시 포함'은 유용한 출발점이다. 오른쪽에 있는 속성은 절대 후보키에 못 들어간다는 뜻은 아니다. 상호 결정 관계에서는 후보키가 여러 개 생긴다.

## 3. 삽입·갱신·삭제 이상
수강(학생 ID, 강좌 ID, 학생 이름, 강좌명, 담당 교수, 성적)에 학생 이름과 강좌 정보를 매번 반복하면 강좌명 변경 때 여러 행을 수정해야 한다. 일부만 수정하면 갱신 이상, 수강생 없이 강좌를 저장하지 못하면 삽입 이상, 마지막 수강 행 삭제로 강좌 정보도 잃으면 삭제 이상이다. 정규화는 이 문제를 함수 종속에 따라 분리하는 과정이다. '테이블을 많이 만드는 것' 자체가 목적은 아니다.

## 4. 정규형 판정 순서
1NF는 관계의 각 속성 값이 설계에서 하나의 값으로 다뤄지도록한다. 한 셀의 'DB,OS' 목록은 수강 과목 원소별 질의가 필요한 설계에서 문제가 된다. 문자열이라는 자료형을 썼다는 이유만으로 업무상 원자성이 확보되지 않는다.

2NF는 1NF이고 어떤 후보키의 진 부분 집합에 비주요 속성이 종속되는 부분 종속을 제거한다. 주요 속성(prime attribute)은 어떤 후보키에라도 포함되는 속성이다. 기본 키로 선택한 한 키만 기준으로 판정하지 않는다.

3NF는 비자명한 X -> A마다 X가 슈퍼키이거나 A가 주요 속성인 조건을 만족한다. BCNF는 모든 비자명 종속의 결정자 X가 슈퍼키 여야 한다. 따라서 BCNF이면 3NF지만 역은 항상 성립하지 않는다. '3NF는 무조건 이행 종속이 하나도 없음'이라는 단순 표현은 여러 후보키 사례에서 틀릴 수 있다.

### 손풀이 예제 5: 단계별 분해
R(학생 ID, 강좌 ID, 학생 이름, 강좌명, 교수 ID, 교수실, 성적)에 다음 규칙을 준다.
- 학생 ID -> 학생 이름
- 강좌 ID -> 강좌명, 교수 ID
- 교수 ID -> 교수실
- 학생 ID, 강좌 ID -> 성적

후보키는 (학생 ID, 강좌 ID)다. 이름·강좌 정보는 부분 종속이므로 학생(학생 ID, 학생 이름), 강좌(강좌 ID, 강좌명, 교수 ID, 교수실), 수강(학생 ID, 강좌 ID, 성적)으로 나눈다. 강좌에서 강좌 ID -> 교수 ID -> 교수실은 비키 속성의 이행 경로다. 교수(교수 ID, 교수실)를 분리하고 강좌에는 교수 ID를 남긴다. 네 테이블 모두 주어진 종속 아래 결정자가 해당 테이블 키이므로 BCNF다. 새로운 업무 규칙이 추가되면 판정을 다시 해야 한다.

### 손풀이 예제 6:3NF와 BCNF 차이
R(A,B,C), F ={AB -> C, C -> B}. AB +는 전체, AC +도 C -> B로 전체다. 후보키 AB와 AC에서 A,B,C는 모두 주요 속성이다. C -> B의 C는 슈퍼키가 아니지만 B는 주요 속성이라 3NF 조건은 통과한다. BCNF는 통과하지 못한다. R1(C,B), R2(A,C)로 분해하면 무손실이지만 원래 AB -> C를 두 테이블의 개별 제약만으로 바로 검사할 수 없는 의존성 보존 문제가 생긴다.

## 5. 무손실과 의존성 보존
분해한 테이블을 조인했을 때 원래 관계를 정확히 복원할 수 있으면 무손실이다. 임의 분해는 없던 조합인 가짜 튜플을 만들 수 있다. 이진 분해 R1,R2에서 공통 속성이 R1 또는 R2 전체를 함수적으로 결정하면 무손실 조건을 만족한다. '공통 열이 있기만하면 무손실'은 틀리다.

의존성 보존은 분해 후 각 테이블의 제약을 검사하는 것으로 원래 모든 종속을 검사할 수 있는 성질이다. 무손실과 별개다. BCNF 분해가 항상 의존성 보존인 것은 아니다. 정규화로 읽기 JOIN이 늘 수 있고 성능 요구에 따라 비정규화를 고려할 수 있지만, 무결성 유지 비용과 측정 근거를 함께 따진다.

### 직접 풀기와 확인
R(A,B,C,D), F ={A -> B, B -> C}에서 후보키는? AD다. A +={A,B,C}, D +={D}, AD +는 전체다. D를 빠뜨리면 속성 D를 결정할 규칙이 없다. 후보키와 정규형을 추측으로 쓰지 말고 폐포 과정을 답안에 남긴다.

완료: 폐포를 적어 후보키를 증명하고, 2NF·3NF·BCNF 위반 종속을 각각 지목한다. 참고: [UC Berkeley DB 설계 강의](https://cs186berkeley.net/notes/note13/). 종속 집합과 손풀이 예제는 자체 제작이다.

## 강화 손풀이: BCNF 분해의 무손실성과 종속 보존은 별개다
R(A,B,C), F={AB→C, C→B}를 가정한다. A와 C의 폐포는 각각 A,CB이고 AB와 AC의 폐포는 ABC다. 후보키는 AB와 AC다. 모든 속성이 어떤 후보키에 포함되므로 주요 속성이다. C→B의 결정자 C는 슈퍼키가 아니지만 B는 주요 속성이므로 3NF 조건은 만족하고 BCNF는 위반한다.

C→B를 기준으로 R1(C,B), R2(A,C)로 분해한다. 교집합 C가 R1 전체 CB를 결정하므로 이진 분해의 무손실 조건을 만족한다. 그러나 분해한 두 테이블의 지역 제약만으로 원래 AB→C를 항상 검증할 수는 없다.

**반례 데이터:** R1={(c1,b1),(c2,b1)}, R2={(a1,c1),(a1,c2)}다. R1은 C→B를 만족한다. 조인 결과에는 (a1,b1,c1),(a1,b1,c2)가 생겨 AB→C를 위반한다. 즉 무손실인 분해 방식이라고 해서 모든 원래 종속이 개별 테이블 제약으로 보존되지는 않는다. 종속 보존은 원래 제약을 조인 없이 검사할 수 있는지를 따로 묻는다.

완료 기준: 폐포→후보키→정규형→무손실→종속 보존 순서로 쓰고, 마지막 두 성질을 같은 문장으로 합치지 않는다.
