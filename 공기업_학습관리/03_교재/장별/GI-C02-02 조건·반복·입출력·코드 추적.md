# 02-02 조건·반복·입출력·코드 추적

[[GI-교재02 프로그래밍_Cpp_Python|과목 목차]] · [[GI-문제02 프로그래밍_Cpp_Python|문제]] · [[GI-해설02 프로그래밍_Cpp_Python|해설]]

## 코드 해석은 표를 만드는 작업이다
프로그램을 읽으면서 머릿속으로 계속 수정하지 않는다. 반복 번호, 조건 평가, 바뀐 변수, 출력 시점의 열을 만들어 추적한다. 코드가 요구하는 출력과 최종 변수 값이 다른 경우를 구별하고, 증감 연산의 결과가 모호한 식은 언어 규칙을 먼저 확인한다.

### 1. 조건과 단락 평가
C++의 &&, ||는 왼쪽을 먼저 평가하고 결과가 정해지면 오른쪽을 생략한다. Python의 and, or도 단락 평가를 하지만 반드시 bool만 반환하는 것은 아니다. `0 or 7`은7, `[] and 5`는[]를 반환한다. Python에서 빈 컨테이너·0·None은 거짓으로 해석되며 내용이 있는 목록은 참이다.

손풀이 예제 A: x=0이고 `x != 0 and 10/x > 2`라면 왼쪽이 거짓이어서 오른쪽 나눗셈을 수행하지 않는다. 안전한 순서는 “유효성 검사 먼저→사용”이다. 같은 식에서 and를 비트 연산 &로 기계적으로 바꾸면 단락 평가의 보호를 기대할 수 없다. C++에서는 배열 인덱스 사용 전에 범위 조건을 확인한다.

Python의 `1 < x < 5`는 연쇄 비교이고 x를 한 번 평가하는 언어 의미를 갖는다. C++의 `1 < x < 5`는 같은 수학적 의미가 아니다. C++은 `1 < x && x < 5`처럼 쓴다. 언어의 문법이 비슷하다는 이유로 식 전체를 그대로 옮기지 않는다.

### 2. for·while의 실행 수
Python range(n)은0..n-1이고 range(a,b)는 b를 포함하지 않는다. C++ for의 초기화는 한 번, 조건은 각 반복 전, 증감은 본문 뒤에 실행된다. break는 가장 안쪽 반복을 끝내고 continue는 해당 반복의 나머지 본문을 건너뛴다. 중첩 루프의 바깥까지 모두 종료한다는 뜻이 아니다.

예제 B:
```python
s = 0
for i in range(1, 6):
    if i % 2 == 0:
        continue
    s += i
print(s)
```

i는1,2,3,4,5다. 짝수2·4를 건너뛰고1+3+5=9를 출력한다. continue가 반복 자체를 끝내는 것은 아니다. i==4에서 break하도록 바꾸면4에서 종료해1+2+3=6이 된다. 두 코드를 섞어 외우지 않는다.

while에서는 진행이 보장되는지 본다. 포인터가 특정 분기에서 증가하지 않으면 무한 루프가 생길 수 있다. `while lo < hi`의 이분 탐색에서 lo=mid로만 바꾸면 lo+1==hi인 상황에서 mid==lo가 되어 진행되지 않을 수 있다. 상태가 줄어드는 양 또는 증가하는 양을 설명해야 한다.

### 3. 입력·출력과 빈 입력
코딩테스트는 프롬프트나 디버그 출력 없이 요구 형식만 출력한다. 입력이 한 줄에만 있다는 보장이 없을 때 whitespace 토큰으로 읽는 방식이 편리하지만 전체 데이터를 메모리에 올리는 비용도 본다. 문자열에 공백이 의미가 있으면 split으로 분리하면 정보가 사라지므로 줄 단위 입력을 사용한다.

```python
import sys
def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    n = data[0]
    values = data[1:]
    if len(values) != n:
        raise ValueError("expected n values")
    print(sum(values))
if __name__ == "__main__":
    main()
```

본 예제는 입력이 “n 다음에 정수 n개”라는 학습 계약이고 잘못된 입력은 예외로 드러낸다. 공식 시험이 올바른 입력을 보장하면 오류 검증 방식은 더 간단할 수 있다. n=0이면 합0을 출력한다. 입력이 아예 비어 있으면 출력 없이 끝낸다. 둘은 다른 입력이다.

C++에서는 `ios::sync_with_stdio(false); cin.tie(nullptr);`를 성능 선택으로 사용할 수 있다. 이때 C stdio와의 섞어 쓰기를 무심코 적용하지 않는다. 정수 합은 범위에 맞는 long long으로 누적하고, 줄바꿈 문자와 형식을 맞춘다. 성능 옵션 자체가 정답을 보장하지는 않는다.

### 4. 연산 우선순위와 위험한 식
우선순위는 식이 묶이는 순서, 평가 순서는 피연산자를 실제로 계산하는 순서다. 둘은 같지 않다. C/C++의 함수 인자 평가나 한 식 안의 여러 증감은 언어 버전과 sequencing 규칙을 읽어야 한다. `i++ + ++i` 같은 식에 임의의 왼쪽 우선 규칙을 붙여 단정하지 않는다. 시험에서도 정의되지 않은 동작인지 먼저 판별해야 할 수 있다.

예제 C: C++17의 안전한 분리 코드 `int x=2; int a=x++; int b=++x;`에서 첫 문장 뒤 a=2,x=3, 다음 뒤 b=4,x=4다. 각 전체 표현식의 종료를 기준으로 바뀐 상태를 적으면 순서를 안전하게 설명할 수 있다. Python에는 x++ 증감 연산자가 없으므로 x+=1 등으로 표현한다.

### 직접 연습과 완료 기준
1. range(2,8,2)는2,4,6이며8은 제외된다.
2. sum=0, i=1부터5까지 i==3에서 break하면 sum=1+2=3이다.
3. Python `"A" or "B"`는 "A"다.
조건이 오른쪽까지 실행되는지, 반복 경계가 포함인지, 출력 시점이 어디인지 표시할 수 있으면 완료한다. 코드는 줄을 읽는 속도보다 상태를 빠뜨리지 않는 정확성이 먼저다.

### 보강 손풀이: 중첩 반복의 continue
다음 코드는 별표가 아니라 정수 합을 계산한다.

```python
s = 0
for i in range(3):
    for j in range(3):
        if i == j:
            continue
        s += i + j
print(s)
```

대각선(0,0),(1,1),(2,2)만 생략한다. 나머지 여섯 쌍의 합은1,2,1,3,2,3으로 총12다. continue는 안쪽 반복만 이어가며 바깥 i를 건너뛰지 않는다. 전체 쌍9개에서 대각선 합0+2+4를 제외하는 검산도 가능하다.

입력 n개를 받는 예제에서는 첫 숫자 n을 데이터 값으로 합하지 않는지 확인한다. 토큰 목록 data의 길이 n+1,값 목록의 길이 n이라는 관계를 쓴다. 공백이 의미인 문자열 입력에서는 split이 원래 정보를 지운다는 점도 점검한다. 출력 마지막 줄바꿈은 요구 형식에 맞추되 디버그 문구를 넣지 않는다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
루프를 추적할 때 continue와 break를 별도로 표시한다. 아래 코드는 Python3이며 답은 7이다.

```python
s = 0
for x in [1, 2, 3, 4]:
    if x == 3:
        continue
    s += x
print(s)
```

continue는 현재 회차의 나머지를 건너뛰고 다음 x로 이동한다. break로 바꾸면 3에서 전체 루프를 끝내어 답은 3이다. Python의 for-else는 한 번도 실행 안 된 루프에도 실행될 수 있고, break 없이 정상 종료한 때 실행된다. '마지막 원소에서 조건을 발견했으므로 else가 실행된다'는 주장은 break가 있으면 틀린다.

입력의 형식도 알고리즘 계약이다. C++의 `while (cin >> x)`는 추출에 성공한 값만 처리한다. 입력이 `2 5 stop 9`라면 2와 5를 처리하고 `stop`에서 실패 상태가 되어 종료하며 9를 처리하지 않는다. 중간에 잘못된 토큰이 들어와도 알아서 건너뛰는 루프가 아니다. 전체 입력 유효성 보장이 없으면 실패를 어떻게 보고할지 별도 설계한다.

n=0 처리에서 최대값을 입력 첫 원소로 초기화하는 구현은 빈 배열 계약을 먼저 정해야 한다. 문제에서 n≥1이면 단순화할 수 있지만 일반 재사용 함수는 예외·없음 반환 등 정책을 명시한다. 입력과 출력 형식까지 포함한 작은 경계 사례를 직접 실행해야 코드가 완결된다.
