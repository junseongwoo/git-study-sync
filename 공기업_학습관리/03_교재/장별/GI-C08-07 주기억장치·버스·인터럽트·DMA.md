# 08-07 주기억장치·버스·인터럽트·DMA

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## CPU만 빨라서는 충분하지 않다
계산할 데이터가 메모리와 장치에서 전달되어야 한다. CPU·메모리·I/O 연결과 데이터 이동 방식을 알면 OS의 인터럽트·프로세스 대기·버퍼링과 장비 개발의 경험이 이어진다.

### 1. 기억장치 계층
레지스터→캐시→메인메모리→보조저장장치로 내려가며 일반적으로 더 큰 용량과 낮은 단위용량 비용,더 긴 접근 지연을 얻는 계층 모델이다. 모든 제품의 가격·속도를 정확한 배수로 예측하는 표는 아니다. 대표적인 DRAM은 데이터 유지를 위한 refresh가 필요하고 SRAM은 다른 셀 구조로 보통 캐시에 사용된다. 둘 모두 일반적인 모델에서 전원이 끊기면 내용 유지를 보장하지 않는 휘발성이다.

ROM이라는 범주와 flash가 동일한 물리적 쓰기 능력을 갖는다고 하지 않는다. 비휘발성 장치도 쓰기 단위·수명·삭제 정책이 있고 SSD는 RAM과 동일한 주소·지연 모델이 아니다. 장치의 분류와 실제 기능을 확인한다.

### 2. 주소선과 데이터선
주소선이 N비트이면 2^N개 주소를 표현한다. 바이트 주소 모델은 최대 2^N바이트 주소 공간이고,한 주소가 word를 가리키는 모델은 주소당 바이트 수를 곱한다. 주소선 수와 데이터 전송 폭은 다른 수치다.

손풀이 예제 A: 주소선20비트,바이트 주소 모델은2^(20)=1MiB다. 데이터 버스32비트가 함께 주어져도 주소 공간이4MiB로 바뀌지 않는다. 반면 주소 하나가32비트word를 지정한다고 명시하면4MiB다.

메모리 모듈 조합은 저장 word 수와 word 폭을 따로 계산한다. 예제 B:1K×8비트 칩으로4K×16비트 메모리를 만들면 word 수4배·폭2배로 총8개 칩이다.1K=1024word라는 문제 정의에서 전체 용량은4096×2바이트=8192바이트다.

### 3. 대역폭과 지연
대역폭은 단위시간 데이터량,지연은 한 요청 완료까지의 시간이다. 데이터 폭64비트,초당 전송1억 번인 단순 모델은8바이트×10^8=8×10^8B/s=800MB/s라는 십진 단위 대역폭이다. 클럭당 전송이2번이라고 주면 그 조건을 곱한다. 주소·제어 overhead,대기,경합이 있으면 실효값은 다르다.

예제 C:100MB를 실효200MB/s로 순차 전송하면0.5초다. 시작 지연10ms가 별도이면0.51초다. MB와 MiB를 섞거나 시작 지연을 매바이트에 더하지 않는다.32비트·100MHz·사이클당2번 전송의 이론 데이터율은4×10^8×2=800MB/s다.

### 4. 폴링과 인터럽트
폴링은 CPU가 장치 상태를 반복 확인하고,인터럽트는 장치나 시스템이 처리가 필요하다는 사건을 알리는 방식이다. 인터럽트가 항상 더 빠른 것은 아니다. 사건이 매우 잦으면 처리 overhead가 크며 batch·polling 전략이 효율적일 수도 있다.

인터럽트에는 문맥 저장,원인 식별,핸들러 처리,복귀 같은 흐름이 있다. 마스크 가능 여부·우선순위·동시 요청 처리는 설계에 따른다. trap·예외·외부 인터럽트의 분류 용어는 자료마다 조금 다를 수 있어 외부 장치 사건과 명령 실행 관련 사건의 원인을 읽는다.

예제 D: 장치 완료를1ms마다 확인하는 polling이면 방금 확인한 직후 완료한 사건을 다음 확인까지 기다릴 수 있다. 이 모델의 알림 지연은 거의0..1ms 범위이고,사건 시점이 균일하다는 이상 가정의 평균은0.5ms다. 실제 스케줄링 지연·확인 비용은 따로 있다.

### 5. DMA
DMA는 전형적인 모델에서 CPU가 매바이트를 직접 복사하지 않고 DMA 엔진 등이 메모리와 장치 사이 데이터를 전송한다. CPU는 버퍼·길이·방향을 설정하고 완료나 오류를 처리할 수 있다. 따라서 DMA를 쓰면 CPU가 아무 일도 하지 않고 캐시·버스 문제도 사라진다는 주장은 틀리다.

예제 E: 이미지 프레임1개8MiB,초당30프레임이면 데이터율240MiB/s다. CPU에 프레임별 전송 설정과 완료 처리가 필요할 수 있지만 매바이트 직접 복사와는 다른 부담이다. 메모리 대역폭·버퍼 용량·일관성·장치 제약이 전체 성능에 영향을 준다.

버퍼2개를 번갈아 받으며 처리하는 double buffering은 입력과 계산의 겹침을 돕지만 생산 속도가 소비 속도보다 계속 빠른 상황을 항상 해결하지 못한다.30fps 입력의 평균 프레임 간격은 약33.333ms다. 처리에 지속적으로40ms가 들면 두 버퍼만으로 무한히 손실 없는 처리를 보장할 수 없다. 입력 속도 조절·추가 처리 능력·드롭 정책 등을 별도로 고려한다.

### 6. 메모리 맵 I/O
장치 레지스터를 CPU 주소 공간의 특정 주소로 접근하는 모델은 memory-mapped I/O다. 분리된 I/O 주소 공간과 특수 명령을 쓰는 설계도 있다. 장치 레지스터 읽기는 일반 RAM 읽기처럼 임의 최적화·재정렬을 허용하지 않을 수 있으므로 플랫폼의 volatile·barrier 등의 계약을 따른다.

### 완료 기준
주소 공간·버스 폭·전송률을 구별하고20비트 주소를 바이트/word 모델별로 계산한다. 폴링·인터럽트·DMA에서 CPU가 무엇을 하는지 적고,영상 데이터율과 처리 시간이 버퍼 부족에 연결되는 이유를 말하면 완료한다.

### 보강 계산: 사건 빈도와 처리 부담
초당10000번 완료 인터럽트가 있고 핸들러당 CPU 시간5마이크로초라는 단순 모델이면 초당0.05초,즉 한 CPU 시간의5%를 쓴다. 같은 의미의 작업을100건씩 묶어 초당100번 알리고 핸들러당 고정5마이크로초만 있다고 가정하면0.0005초다. 그러나 batch 자체의 추가 처리와 사건을 기다리는 지연이 있으므로 실제 전체가 반드시100배 좋아지는 것은 아니다. 고정 비용과 사건당 변동 비용을 구별하는 계산 연습이다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
전송 시간에서 연결 규약/장치 대기와 대역폭의 역할을 분리한다. 64KiB=65536바이트를 유효 전송률 16MiB/s로 보내면 데이터 전송 시간은 65536/16777216=1/256초=3.90625ms다. 설정 비용 0.2ms가 전송 전 한 번만 발생하면 총 4.10625ms다. 대기·오버헤드가 이미 유효 전송률에 포함되었다고 주면 다시 더하지 않는다.

DMA는 CPU가 모든 바이트 복사를 직접 실행하지 않도록 하는 장치 전송 방식이다. CPU는 버퍼/길이/방향 설정과 완료 처리에 관여할 수 있고 버스·메모리 대역폭도 사용된다. DMA 완료 전 버퍼를 재사용하면 장치가 아직 읽거나 쓰는 데이터를 바꿀 수 있다. 캐시 일관성이 하드웨어로 보장되지 않는 모형에서는 CPU 캐시와 장치가 보는 주기억장치의 동기화 정책이 필요하다. DMA가 있다는 사실만으로 캐시 일관성·동시 접근 안전을 보장하지 않는다.

인터럽트 지연은 이벤트 발생부터 처리 시작까지의 시간이므로 한 번의 핸들러 실행 시간이 짧아도 긴 마스킹 구간이 있으면 반응이 늦다. 폴링과 인터럽트의 우열은 이벤트 빈도·CPU 비용·지연 요구에 달린다. 가상주소 2^32바이트 공간을 지원한다는 것이 물리 RAM을 실제로 4GiB 장착했다는 뜻도 아니다.
