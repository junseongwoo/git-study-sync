# 06-02 인증·인가·접근통제: 로그인 뒤에도 권한을 검사하기

[[GI-교재06 정보보안|과목 목차]] · [[GI-문제06 정보보안|문제]] · [[GI-해설06 정보보안|해설]]

### 인증과 인가
인증(AuthN)은 주장한 신원을 확인한다. 인가(AuthZ)는 확인된 주체가 어떤 자원에 어떤 행동을 할 수 있는지 결정한다. 로그인 성공은 모든 신청서에 접근할 권리가 있다는 뜻이 아니다. 서버는 요청마다 적절한 권한과 대상 객체의 관계를 확인해야 한다. 화면에서 버튼을 숨겨도 API 권한 검사가 빠지면 통제가 완성되지 않는다.

인증 요소는 알고 있는 것, 가지고 있는 것, 신체적 특성 등으로 구분한다. 비밀번호와 PIN은 둘 다 지식 요소라서 개수가 두 개라는 이유만으로 서로 다른 요소의 다중요소 인증이 되지는 않는다. 소유 요소의 보안도 피싱·기기 탈취·복구 경로에 영향을 받는다.

### 접근통제 모델
DAC는 자원 소유자 등이 권한을 재량적으로 설정하는 모델이다. MAC는 보안등급·레이블과 중앙 정책에 따른 강제 접근통제를 설명한다. RBAC는 역할에 권한을 부여하고 사용자에게 역할을 할당한다. ABAC는 사용자·자원·행동·환경 속성과 정책을 함께 평가한다. 조직에서 여러 모델을 결합할 수 있다.

최소권한은 업무에 필요한 권한만 부여하는 원칙이다. 직무 분리는 중요한 작업의 승인과 집행을 한 사람이 단독으로 모두 수행하지 못하게 하는 통제다. 최소권한이 권한을 영구히 줄이기만 한다는 뜻은 아니다. 필요한 시간에 제한된 권한을 부여하고 종료 뒤 회수하는 방법도 있다. 기본 거부와 명시적 허용은 실수로 접근을 허용하는 위험을 줄인다.

### 고전적 기밀성·무결성 모델
Bell-LaPadula는 기밀성을 중심으로 설명한다. 기초 규칙은 낮은 등급이 높은 등급을 읽지 못하는 no read up, 높은 등급의 주체가 낮은 등급으로 쓰지 못하는 no write down이다. Biba의 대표적인 엄격 무결성 규칙은 낮은 신뢰도의 데이터를 읽어 오염되지 않도록 하는 no read down, 낮은 무결성 주체가 높은 무결성 대상에 쓰지 못하는 no write up이다.

이 규칙은 해당 모델과 기본 가정 안에서 해석한다. 두 모델의 "높다"는 기밀 등급인지 무결성 신뢰 수준인지 다르다. 모델 이름만 바꾸어 같은 화살표를 적용하지 않는다.

### 단계별 사례: 신청서 조회 API
사용자 17이 신청서 902를 조회한다. 서버는 먼저 세션의 사용자 17을 인증한다. 다음으로 신청서 902의 소유자가 17인지 또는 적절한 심사 역할에 속하는지 확인한다. 신청서 번호가 추측하기 어렵게 생겼어도 권한 검사가 빠지면 객체 단위 권한 취약점이 된다. 입력 값을 난수처럼 바꾸는 것은 보조 방편이고 권한 결정의 대체가 아니다.

역할이 신청자·심사자·관리자라면 단순한 업무 권한은 RBAC로 표현할 수 있다. "심사자이면서 담당 지역이 같고 근무 시간이며 관리 기기에서 접속" 같은 조건은 ABAC 관점이 더 직접적이다. 권한 부여·변경·회수 기록도 확인한다.

### 숫자 예제와 연습
총 사용자 120명 중 12명만 배포 권한이 필요하다. 전원에게 권한을 주었다가 최소권한 원칙으로 12명에만 남기면 배포 권한 보유자는 108명 감소하고 90% 감소한다. 이 수치는 권한 범위 감소를 나타낼 뿐 사고 확률이 곧바로 90% 줄어든다는 뜻은 아니다.

자가 연습: 관리자가 휴직했는데 관리자 권한이 유지된다면 무엇을 확인할까? 현재 업무 필요, 권한 승인·회수 절차, 비상 계정과 일반 계정 분리, 실제 사용 기록을 확인한다.

### 완료 기준
인증·인가를 API 처리 순서로 설명하고, DAC·MAC·RBAC·ABAC를 사례로 구분하며, Bell-LaPadula와 Biba의 읽기·쓰기 방향을 혼동하지 않아야 한다.

### 응용 문제: 역할과 객체 소유권의 결합
신청자 역할이 있다는 이유만으로 모든 신청서 조회를 허용하면 RBAC 설정 자체와 별개로 객체 권한 문제가 생긴다. 먼저 기능 권한을 확인하고, 다음으로 대상 신청서와 요청자의 관계를 확인한다. 심사자라면 담당 범위와 상태 조건도 필요할 수 있다.

Bell-LaPadula에서 비밀 등급 주체가 더 낮은 등급 파일에 비밀 내용을 쓰면 no write down에 위배될 수 있다. Biba에서 낮은 신뢰의 주체가 높은 무결성 자료를 수정하면 no write up에 위배될 수 있다. 같은 높음/낮음 표시라도 보호 목적이 다르므로 모델 이름과 등급 의미를 먼저 고정한다.

### 강화 권한 행렬: 역할·객체·행위의 AND 조건
가상 역할은 조회자·승인자·감사자 중 하나다. 읽기는 (조회자 AND 같은 지역) OR 감사자, 승인은 승인자 AND 같은 지역 AND 요청 작성자가 자신 아님일 때만 허용한다. 다른 경우는 거절한다. 이 규칙은 실제 기관 정책이 아니다.
손풀이: 조회자 민수가 부산 자료를 보되 소속은 경기라면 읽기는 거절이다. 감사자는 지역이 달라도 읽지만 승인 권한은 없다. 부산 승인자 지수가 부산 요청을 처리하더라도 본인이 작성한 요청이면 승인은 거절이다. 로그인 성공은 이 행위 권한을 대신하지 않는다.
서버에서 매 요청의 사용자·대상 객체·행위·현재 권한을 검사한다. 화면에 버튼을 숨겼어도 API를 직접 호출하면 같은 검사가 필요하다. 권한이 철회됐는데 오래된 화면·토큰의 역할만 믿는 반례를 시험한다. 서버의 정책 결정과 거절 결과를 로그에 적절히 남기되 비밀값을 그대로 기록하지 않는다. 최소 권한은 한 번 권한을 작게 준 뒤 끝나는 작업이 아니라 변경·철회·만료도 다루는 원리다.
