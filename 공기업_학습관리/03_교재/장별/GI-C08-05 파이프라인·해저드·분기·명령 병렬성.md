# 08-05 파이프라인·해저드·분기·명령 병렬성

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## 한 명령의 시간과 여러 명령의 완료 간격
파이프라인은 작업을 여러 단계로 나누어 서로 다른 명령이 동시에 다른 단계를 사용하게 한다. 단계가 5개라고 명령 하나가 반드시 1/5시간에 끝나는 것은 아니다. 충분히 많은 명령의 처리량이 늘어나는 효과와 한 명령의 지연을 구별한다.

### 1. 이상적인 k단계 계산
각 단계 시간이 같고 추가 레지스터 비용·stall이 없는 k단계에서 n명령 완료에 n+k-1사이클이 필요하다. 첫 명령은 k사이클 후 완료하고 이후 매 사이클 한 명령이 완료된다. 비파이프라인 대응 모델에서 각 명령을 k단계 직렬로 수행하면 n×k사이클이다.

손풀이 예제 A: k=5,n=8이면 파이프라인 12사이클,비파이프라인 40단계 사이클,이상 향상 40/12 약 3.333배다. 5배라는 극한은 n이 충분히 크고 이상 조건을 만족할 때 접근한다. 첫 명령 완료에 5사이클이 필요하다는 사실은 변하지 않는다.

| 사이클 | 명령1 | 명령2 | 명령3 |
|---|---|---|---|
| 1 | IF | - | - |
| 2 | ID | IF | - |
| 3 | EX | ID | IF |
| 4 | MEM | EX | ID |
| 5 | WB | MEM | EX |
| 6 | 완료 | WB | MEM |
| 7 | 완료 | 완료 | WB |

단계 시간이 2,3,2ns라면 가장 긴 단계 3ns에 맞춘 이상 파이프라인 클럭을 쓴다. 한 명령 지연은 3×3=9ns로 비파이프라인 합 7ns보다 클 수도 있다. 그러나 연속 명령 완료 간격은 3ns로 줄어든다. 실제는 파이프라인 레지스터의 설정·전파 시간 등 추가 비용이 있다.

### 2. 세 가지 해저드
구조 해저드는 동시에 필요한 하드웨어 자원이 겹치는 경우다. 명령 가져오기와 데이터 읽기를 같은 단일 포트 메모리가 동시에 지원하지 못하는 예를 생각한다. 데이터 해저드는 명령 간 데이터 의존 때문에 필요한 값이 준비되지 않은 경우다. 제어 해저드는 분기 결과·대상이 확정되기 전에 어느 경로에서 다음 명령을 가져올지 모르는 경우다.

예제 B: ADD R1,R2,R3 뒤 SUB R4,R1,R5는 첫 명령이 만든 R1을 두 번째가 읽는 RAW(read-after-write) 의존이다. SUB가 이전 R1을 읽으면 잘못된 결과다. 전달(forwarding/bypassing)은 실행 유닛 결과를 필요한 단계로 직접 보낼 수 있다. 필요한 시점보다 값이 늦으면 stall이 필요하므로 전달이 모든 의존을 항상 0stall로 없애지는 않는다.

### 3. load-use의 가정
전형적인 IF-ID-EX-MEM-WB 5단계에서 load 데이터는 MEM 끝에 나오고 다음 명령의 EX에서 필요한 모델을 가정한다. LOAD R1,[x] 바로 뒤 ADD R2,R1,R3이면 전달 경로가 있어도 한 사이클 stall이 필요한 대표 모델이다. 다른 단계 수·메모리 응답 시점에 같은 stall 수를 자동 적용하지 않는다.

예제 C: 기본 CPI1,전체 명령의 10%에 각각 1stall이면 평균 CPI=1+0.1×1=1.1이다. 명령 20개 중 2개가 해당하면 중간 stall은 2사이클이다. 전체 완료 사이클을 묻고 초기 채우기까지 포함하면 5단계에서 20+5-1+2=26사이클이라는 지정 모델을 쓴다. 평균 CPI에 이미 포함한 stall을 중복 가산하지 않는다.

### 4. 분기 예측과 비용
분기 예측은 결과 확정 전에 방향·대상을 예상해 명령을 가져오는 기법이다. 틀리면 잘못 가져온 명령을 취소하고 올바른 경로로 다시 진행해 penalty가 생긴다. 정확도가 높아도 전체 프로그램이 같은 비율로 빨라지는 것은 아니다.

예제 D: 기본 CPI1,분기 명령 비율 20%,분기 중 오예측 10%,오예측 penalty3사이클이면 추가 CPI=0.2×0.1×3=0.06,평균 1.06이다. 오예측 10%가 전체 명령 기준인지 분기 중 기준인지 구별한다. 전체 명령 10%이면 추가 0.1×3=0.3이라는 다른 값이다.

### 5. 여러 명령 발행과 실행 순서
슈퍼스칼라는 여러 명령을 같은 사이클에 발행·실행할 수 있는 설계다. 발행 폭이 4라고 항상 CPI0.25인 것은 아니다. 의존·메모리 대기·자원·분기 제약이 있다. 비순차 실행(out-of-order)은 의존이 허용하는 범위에서 준비된 명령을 먼저 실행해 자원을 활용한다. 명령 의미를 바꾸며 아무렇게나 재배열한다는 뜻은 아니다.

WAR(write-after-read),WAW(write-after-write)는 이름 재사용과 관련한 의존이고 register renaming으로 일부 거짓 의존을 줄일 수 있다. RAW는 실제 데이터 전달이 필요한 의존이므로 이름만 바꾸어 없애지 못한다. 정확한 예외와 관찰 순서의 유지는 별도 구조의 역할이다. 입문에서는 무엇을 기다리는지 설명하는 것이 목표다.

### 완료 기준
5단계·8명령의 12사이클을 그림으로 재현하고 load-use에서 값의 생성·소비 시점을 표시한다. 분기 비중×오예측률×penalty를 각 분모 기준에 맞게 곱한다. 파이프라인이 명령 하나를 무조건 5배 빨리 한다는 오해를 설명으로 바로잡으면 완료한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
이상적 파이프라인의 완료 시간은 (단계 수 k+명령 수 n-1)×사이클 시간이다. 5단계, 명령 8개, 사이클 1ns이면 12ns다. 같은 단계를 순차적으로 각각 1ns 수행하는 비파이프라인 모형은 8×5=40ns라 전체 향상은 40/12=10/3배다. 명령 하나의 단계 통과 지연은 여전히 5ns이고 충분히 긴 연속 처리에서 처리율이 1명령/ns에 가까워진다. 명령 8개만으로 무조건 5배를 주장하지 않는다.

이 모형에 정확히 네 stall 사이클이 추가되면 총 16ns다. 단계 지연이 1,2,1,1,1ns이고 파이프라인 레지스터 비용 0.2ns라면 사이클 시간은 가장 긴 2+0.2=2.2ns다. 단계 지연 합 6ns/5를 사이클 시간으로 쓸 수 없다. 단계 균형과 레지스터 비용도 처리량에 영향을 준다.

분기 빈도 20%, 분기 중 예측 실패 10%, 실패당 추가 3사이클, 기본 CPI=1이고 다른 지연/중첩은 없다고 가정하면 평균 추가 CPI=0.2×0.1×3=0.06, 총 CPI=1.06이다. 실패율이 전체 명령 기준인지 분기 기준인지 먼저 확인한다. 포워딩이 있어도 특정 모형의 load-use 해저드가 항상 사라지는 것은 아니므로 단계에서 데이터가 준비되는 시점을 본다.
