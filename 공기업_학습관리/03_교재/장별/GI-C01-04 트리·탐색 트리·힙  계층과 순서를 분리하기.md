# 01-04 트리·탐색 트리·힙: 계층과 순서를 분리하기

[[GI-교재01 자료구조_알고리즘|과목 목차]] · [[GI-문제01 자료구조_알고리즘|문제]] · [[GI-해설01 자료구조_알고리즘|해설]]

## 용어를 그림 없이 정확히 정의하기
트리는 연결되어 있고 순환이 없는 무방향 그래프로 볼 수 있다. 루트 트리는 루트를 정하고 부모·자식 관계를 부여한 구조다. 노드 수가 n인 비어 있지 않은 트리의 간선 수는 n-1이다. 자식이 없는 노드는 리프다. 이 책은 루트 깊이를 0, 높이를 루트에서 가장 깊은 리프까지의 간선 수로 정의한다. 다른 책의 루트 높이 1 정의와 수치가 한 칸 다를 수 있으므로 문제의 정의를 따른다.

### 1. 이진 트리의 종류
이진 트리는 노드당 자식이 최대 둘이다. 모든 레벨이 꽉 차 있는 포화 이진 트리(perfect binary tree)는 높이 h에서 노드 수 2^(h+1)-1이다. 완전 이진 트리(complete binary tree)는 마지막 레벨을 제외한 레벨이 꽉 차고 마지막 레벨이 왼쪽부터 채워진다. 모든 내부 노드의 자식이 정확히 둘인 정 이진 트리(full/proper binary tree)는 포화와 다르다. 국내 용어 번역이 혼용되므로 성질을 읽고 판단한다.

예제 A: 높이 2의 포화 트리는 레벨별 노드가 1,2,4개로 총7개다. 모든 내부 노드가 두 자식을 갖더라도 한쪽 가지가 더 깊다면 같은 높이의 모든 레벨이 꽉 찬 포화 트리가 아닐 수 있다. “완전”과 “균형”도 같은 뜻이 아니다.

### 2. 순회
전위는 루트→왼쪽→오른쪽, 중위는 왼쪽→루트→오른쪽, 후위는 왼쪽→오른쪽→루트다. 레벨 순회는 큐로 가까운 레벨부터 읽는다. 루트 A, A의 왼쪽 B·오른쪽 C, B의 왼쪽 D·오른쪽 E라는 구조에서 전위 A B D E C, 중위 D B E A C, 후위 D E B C A, 레벨 A B C D E다.

중위 순회가 항상 정렬된 결과를 만든다고 외우면 틀린다. 이진 탐색 트리의 키 순서 성질이 성립할 때 오름차순을 얻는다. 일반 이진 트리에서는 위치 순서만 따른다. 전위와 중위를 주어 트리를 복원할 때 키가 모두 서로 다르다는 등의 조건도 필요하다.

### 3. 이진 탐색 트리(BST)
중복 키를 허용하지 않는 기본 모델에서는 왼쪽 서브트리의 키가 노드 키보다 작고 오른쪽은 크다. 루트만 비교하고 끝나는 조건이 아니라 각 서브트리 전체에 성립해야 한다. 검색·삽입·삭제는 높이 h에 비례해 O(h)이다. 균형을 관리하지 않은 BST에 1,2,3,4를 차례로 넣으면 한쪽으로 길어져 h=n-1, 검색 최악 O(n)이다. AVL·레드블랙 같은 균형 트리는 높이를 O(log n)으로 관리한다.

예제 B: 8,3,10,1,6,14를 순서대로 넣는다. 6 검색은 8에서 왼쪽3, 3에서 오른쪽6으로 간다. 12 검색은 8→10→14→빈 왼쪽으로 가므로 실패한다. 노드 삭제는 리프, 자식 하나, 자식 둘을 나눈다. 자식 둘인 노드는 중위 후속자(오른쪽 서브트리의 최솟값) 또는 선행자로 대체하고 그 원래 위치를 제거할 수 있다.

### 4. 이진 힙
최소 힙은 부모 값이 각 자식 값 이하이며 구조는 완전 이진 트리다. 전체가 정렬되어 있다는 보장이 아니라 루트가 전체 최솟값이라는 보장이다. 0 기반 배열에서 부모는 (i-1)//2, 왼쪽 자식 2i+1, 오른쪽 2i+2다. i=0에는 부모가 없다.

예제 C: 최소 힙 배열 [2,5,3,9,7]에 1을 추가한다. 마지막 인덱스5에 넣고 부모 인덱스2의 3과 교환해 [2,5,1,9,7,3], 다시 부모0의2와 교환해 [1,5,2,9,7,3]이 된다. 삽입은 높이만큼 올라가 O(log n)이다. 최솟값 삭제는 마지막 원소를 루트로 옮기고 더 작은 자식과 내려가며 교환한다.

배열 전체에서 bottom-up으로 heapify하면 O(n)이다. n회 각각 push해서 만드는 O(n log n) 방식과 구별한다. 아래쪽 노드는 내려갈 거리가 짧고 높은 노드는 수가 적어 전체 이동량을 선형으로 합칠 수 있다. 정렬 문제에서 힙을 쓴다고 힙 생성 비용도 무조건 n log n이라고 답하지 않는다.

### 5. BST와 힙의 비교
| 요구 | BST | 최소 힙 |
|---|---|---|
| 임의 키 찾기 | 균형 조건에서 O(log n) | 일반적으로 O(n) |
| 최솟값 찾기 | 왼쪽 끝까지 이동 | 루트 O(1) |
| 작은 값 삭제 | 균형 조건에서 O(log n) | O(log n) |
| 정렬 순회 | 중위 순회로 가능 | 배열 순서는 정렬 아님 |
| 구조 조건 | 키의 좌우 순서 | 완전 트리+부모 자식 우선순위 |

### C#에서 전이할 점
장비의 메뉴 계층·검사 항목 계층은 일반 트리다. 번호 검색용 BST나 작업 우선순위용 힙으로 바로 치환되는 것은 아니다. 같은 트리라는 이름보다 유지해야 할 성질을 말한다. Python heapq는 최소 힙, C++ priority_queue의 기본 비교는 최대값을 우선하므로 최소 힙을 쓰려면 비교 설정을 바꾼다.

### 직접 확인
루트4, 왼쪽2(자식1·3), 오른쪽6(자식5·7)의 중위는 1..7이며 높이는2다. 최소 힙 [1,4,2,8,6]의 배열은 정렬되어 있지 않지만 힙 성질은 성립한다. 세 가지 순회와 부모·자식 인덱스를 암산할 수 있으면 완료한다.

### 보강 손풀이: 순회로 표현식 계산하기
표현식 (2+3)×(7-4)의 이진 트리를 생각한다. 루트는×,왼쪽 서브트리 루트+의 자식2·3,오른쪽 서브트리 루트-의 자식7·4다. 전위는 × + 2 3 - 7 4,후위는2 3 + 7 4 - ×다. 후위는 자식을 먼저 계산해 부모 계산에 쓰는 구조와 맞아 결과15를 얻는다.

일반 트리의 후위가 어떤 상황에 유용한지 설명한다. 디렉터리의 전체 크기를 계산하려면 하위 항목 크기를 모아 부모에 반영할 수 있다. 다만 링크·공유 구조·사이클이 있으면 “항상 순수 트리”라는 가정이 깨지므로 실제 파일시스템과 학습 트리 모델을 구별한다.

BST 삭제 연습에서는 루트8의 두 자식 사례를 그린다. 오른쪽 서브트리의 최솟값10을 대체 키로 쓰면 좌우 키 순서가 유지되고 원래10 위치를 별도로 제거한다. 대체 키만 복사하고 기존 노드를 남기면 중복 키 문제가 생긴다. 단계마다 트리 성질이 유지되는지를 확인한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
최소 힙에서 '루트가 최소'와 '배열이 정렬됨'은 별개다. [1,4,2,7,5,3]은 0 기반 자식 2i+1,2i+2에서 부모≤자식인 최소 힙이다. 배열 세 번째 값 2가 두 번째 값 4보다 작아도 위반이 아니다. 최소값 1을 제거할 때 마지막 3을 루트로 옮기고 자식 4,2 중 작은 2와 교환하면 [2,4,3,7,5]로 복구한다. 둘 중 아무 자식이나 교환하면 다른 자식보다 부모가 클 수 있다.

서브트리 높이로 bottom-up heapify 비용을 더해 보자. 잎 약 n/2개는 내려갈 일이 없고, 높이 1 노드 약 n/4개, 높이 2 노드 약 n/8개다. Σ(h≥0) O(nh/2^(h+1))=O(n)이다. '노드 n개 각각 O(log n)'라는 상한 O(n log n)은 맞지만 가장 타이트한 구축 비용은 아니다. 원소를 하나씩 push하는 별도 구축은 최악 O(n log n)이다.

BST가 같거나 중복된 값을 어떻게 처리하는지는 문제 계약에 달린다. 중복을 노드의 빈도 수로 저장할 수 있고, 한쪽 서브트리에 두는 규칙을 정할 수도 있다. 유일 키의 일반 BST에 1,2,3,4를 순서대로 넣으면 높이 3(간선 수 기준)의 사슬이며 탐색 최악 Θ(n)이다. 균형 보장이 없는 트리를 O(log n)이라고 단정하지 않는다.
