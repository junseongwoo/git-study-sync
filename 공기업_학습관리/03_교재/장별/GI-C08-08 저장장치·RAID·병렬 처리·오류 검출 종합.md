# 08-08 저장장치·RAID·병렬 처리·오류 검출 종합

[[GI-교재08 컴퓨터구조|과목 목차]] · [[GI-문제08 컴퓨터구조|문제]] · [[GI-해설08 컴퓨터구조|해설]]

## 시험용 성질과 운용 의미를 구별한다
보조저장장치는 메모리와 지연·전송 단위·고장 모델이 다르다. RAID의 용량 공식과 고장 허용 수를 배운 뒤 백업을 대신한다는 결론으로 확대하지 않는다. 병렬 처리도 코어 수 하나로 전체 성능을 정하지 않는다.

### 1. 회전 디스크 접근 시간
대표적인 디스크 접근 시간은 탐색 시간+회전 지연+전송 시간이다. 회전 속도 rRPM이면 한 바퀴60/r초,도착 각도가 균일하다는 이상 모델의 평균 회전 지연은 반 바퀴30/r초다. 실제 요청 순서·캐시·스케줄링에 따라 평균이 달라질 수 있다.

손풀이 예제 A:7200RPM은 한 바퀴 약8.333ms,평균 회전 지연4.167ms다. 평균 탐색5ms,전송0.5ms를 더하면9.667ms다. SSD에는 같은 기계적 회전 모델을 적용하지 않는다.0.5ms 전송 시간이 모든 요청 크기에서 고정이라는 일반 주장도 아니다.

### 2. RAID 용량의 가정
동일 용량 디스크 N개,각 용량 S,메타데이터·spare·포맷 손실 제외인 명시 구성으로 계산한다.
- RAID0는 striping으로 데이터를 나누고 중복 정보가 없어 기본 용량 NS다. 디스크1개 고장도 데이터 보호를 보장하지 않는다.
- RAID1은 미러링이며 일반적인 두 디스크 쌍은 사용 용량 S,한 디스크 고장을 견디는 모델이다.
- RAID5는 분산 패리티 하나 분량으로 기본 용량(N-1)S,한 디스크 고장 허용,최소3디스크라는 전형적인 모델이다.
- RAID6은 이중 패리티로(N-2)S,두 디스크 고장 허용이라는 전형적인 모델이다.

실제 구성의 확장·표기 변형,부분 고장,재구축 위험 등은 별도다. 본 장의 공식은 명시한 이상 구성의 기초 용량 계산이다.

예제 B:디스크4개·각2TB이면 RAID0는8TB,RAID5는6TB,RAID6은4TB다. TB 십진 단위를 그대로 사용한다.4디스크를 두 미러 쌍으로 만들어 striping하는 전형적인 RAID10이면4TB다. RAID10의 두 디스크 고장 허용은 어느 쌍에서 고장났는지에 달려 “언제나 두 개”라고 단정하지 않는다.

### 3. 패리티와 백업
XOR 패리티는 A XOR B XOR P=0 같은 관계로 한 조각을 잃었을 때 나머지에서 재구성한다. 예제 C:A=1010,B=1100이면 P=0110이다. A를 잃으면 B XOR P=1010으로 복구한다. 패리티 한 개로 독립적으로 잃어버린 두 조각을 항상 복구할 수 있는 것은 아니다.

RAID는 명시한 하드웨어 고장 모델의 중복성이다. 사용자의 삭제·랜섬웨어·논리적 손상·사업장 전체 손실을 자동 복구하는 버전 백업이 아니다. RAID 성질이 보장하는 범위를 넘어 설명하지 않는다. 백업·보안 운용은 보안 교재와 연결한다.

### 4. Flynn 분류
SISD는 단일 명령 흐름·단일 데이터 흐름,SIMD는 같은 명령을 여러 데이터에 적용,MIMD는 여러 명령 흐름이 여러 데이터를 처리하는 분류다. MISD는 여러 명령 흐름·단일 데이터 흐름이라는 정의이고 일반 PC의 대표 사례를 쉽게 단정하지 않는다.

예제 D:여러 픽셀에 같은 밝기 보정을 하는 벡터 연산은 SIMD 사고와 연결된다. 여러 코어가 서로 다른 독립 작업을 실행하는 것은 MIMD와 연결된다. GPU 실제 실행에는 SIMT 같은 추가 모델이 있으므로 모든 구현이 완전히 같은 SIMD라는 한 문장으로 세부를 없애지 않는다.

### 5. 병렬 처리의 비용과 일관성
작업을 나누고 결과를 합치려면 동기화·통신·메모리 접근 비용이 있다. 같은 cache line에 여러 스레드가 서로 다른 변수를 갱신해도 false sharing으로 성능 비용이 생길 수 있다. 데이터 경쟁과 false sharing은 동일한 오류 개념이 아니다. 전자는 접근의 동기화·언어 규칙,후자는 캐시 라인 공유로 인한 성능 현상일 수 있다.

캐시 일관성(coherence)은 같은 메모리 위치의 여러 캐시 값에 대한 규칙,메모리 일관성 모델(consistency)은 여러 읽기·쓰기의 관찰 순서에 대한 모델로 구별한다. 입문에서는 두 용어를 같은 뜻으로 쓰지 않는 것이 목표이며 모든 ISA의 세부 모델을 암기할 필요는 없다.

### 6. 오류 검출과 교정
단순 짝수 패리티는 전체1의 개수를 짝수로 맞춘다. 단일 비트 변화는 검출할 수 있지만 짝수 개 비트 변화가 언제나 검출되지는 않는다. 오류 검출과 위치 찾기·복구는 별도 기능이다. ECC는 정해진 코드 조건에서 오류 교정을 가능하게 한다. CRC는 네트워크 교재의 검출 개념과 연결되며 암호학적 변조 방지 해시·서명과 혼동하지 않는다.

예제 E:데이터1011에는1이3개여서 짝수 패리티 비트1을 붙이면 전체1이4개다. 데이터 한 비트를 바꾸면 전체1 수의 홀짝이 달라져 검출한다. 두 비트가 바뀌면 홀짝이 유지될 수 있어 단순 패리티로 놓칠 수 있다.

### 7. 종합 문제 푸는 순서
먼저 비트 폭·주소 단위·용량의 의미·이진/십진 단위를 적는다. 다음으로 데이터 경로와 CPU/메모리/I/O의 비용 중 무엇을 묻는지 분류한다. 추가 penalty인지 전체 시간인지,고장 위치를 고정했는지 확인한다. 마지막으로 수식과 단위를 검산한다.

8MiB영상30fps의240MiB/s,4KiB캐시 주소 분할,가중 CPI,암달의 최대 향상,RAID 용량을 가린 채 재계산하면 본 교재의 기본 복습을 마친다. 컴퓨터구조는 두 기관의 공개 명시 핵심 과목을 연결하는 보강 역할이므로 추가 심화에 공부 시간을 무조건 몰아넣지 않는다.

### 보강 계산: 미러 쌍 고장 위치
전형적인4디스크 RAID10에서 미러 쌍이(A,B),(C,D)라고 하자. A와C가 고장 나면 각 쌍에 B,D가 남는 모델이므로 데이터를 유지할 수 있다. A와B가 함께 고장 나면 첫 쌍의 복사본이 없어 해당 구성은 데이터를 보호하지 못한다. 고장 개수2만으로 안전성을 결론 내릴 수 없는 이유다. 반면 동일한 이상 모델의 RAID6은 두 디스크 고장을 허용한다는 서로 다른 중복 코드 조건을 갖는다. 실제 재구축 중의 추가 오류·성능·운용 위험까지 이 기초 문항의 결론으로 단정하지 않는다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
RAID 용량은 디스크 개수·크기·배치 모형을 적고 계산한다. 같은 크기 2TB 디스크 네 개의 RAID5는 한 디스크 상당을 분산 패리티로 사용하여 데이터 용량 (4-1)×2=6TB다. 여기서는 제조사 표기 십진 TB와 동일 크기 모델이며 파일시스템/메타데이터 오버헤드는 제외한다. 두 개씩 mirror하고 두 mirror 쌍을 stripe하는 RAID10은 4TB다. 두 디스크 고장에서도 각 mirror 쌍에서 하나씩이면 살아남을 수 있지만 같은 쌍 두 개가 고장 나면 실패한다. 'RAID10은 항상 두 고장까지 허용'은 틀리다.

패리티는 오류 존재를 일부 검출할 뿐 위치를 자동으로 알아 고치는 체계가 아니다. 짝수 패리티에서 1의 수가 홀수가 되면 홀수 개 bit 반전을 검출하지만 짝수 개 반전은 원래 패리티를 유지해 놓칠 수 있다. 예 데이터 1010과 패리티 0에서 데이터 첫 두 bit를 뒤집어 0110이 되어도 1의 수가 2로 같아 검출하지 못한다. ECC의 검출/교정 한계는 코드의 최소 거리와 모형에 따라 별도로 다룬다.

병렬 작업 분할은 이론적 가속과 실제 오버헤드를 구분한다. 순차 시간 100ms 중 80ms를 네 작업자에 이상적으로 균등 분배해도 20+80/4=40ms로 2.5배다. 통신·동기화 10ms가 추가되면 50ms로 2배다. 작업자 수를 늘려도 순차 부분과 오버헤드 때문에 무제한 선형 향상을 기대하지 않는다.
