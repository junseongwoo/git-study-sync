# 01-05 정렬·탐색: 조건·안정성·경계값을 함께 읽기

[[GI-교재01 자료구조_알고리즘|과목 목차]] · [[GI-문제01 자료구조_알고리즘|문제]] · [[GI-해설01 자료구조_알고리즘|해설]]

## 정렬은 전처리이자 질서 만들기
자료를 오름차순으로 바꾸면 이분 탐색·중복 인접 확인·투 포인터 같은 풀이가 가능해진다. 다만 정렬 과정의 시간과 원본 순서 손실을 계산에 포함한다. 이미 정렬된 입력인지, 원본을 변경해도 되는지, 동일 키의 순서를 지켜야 하는지가 선택의 기준이다.

### 1. 기본 정렬을 손으로 수행
삽입 정렬은 왼쪽의 정렬된 구간에 다음 원소를 끼워 넣는다. [4,2,5,1]에서 2를 삽입하면 [2,4,5,1], 5는 그대로, 1을 삽입하면 [1,2,4,5]이다. 비교·이동 조건에 따라 이미 정렬된 입력은 Θ(n), 최악은 Θ(n^2)이다. 같은 키를 앞질러 옮기지 않는 표준 구현은 안정적이다.

선택 정렬은 남은 구간의 최솟값을 찾아 앞과 교환한다. 표준 구현은 입력 순서와 무관하게 Θ(n^2) 비교를 수행하고 보통 안정적이지 않다. [2a,2b,1]에서 1을 맨 앞의 2a와 교환하면 [1,2b,2a]가 되어 같은 키의 순서가 바뀐다. a,b는 값이 같은 레코드를 구분하는 표지다.

버블 정렬은 이웃을 비교해 큰 값을 뒤로 보낸다. 교환이 없으면 종료하는 최적화를 둔 구현은 최선 Θ(n), 최악 Θ(n^2)이다. 그런 최적화가 없는 구현은 정렬 입력에서도 Θ(n^2)일 수 있다. 시험에서 구현 조건을 생략하고 “언제나 최선 n”이라고 단정하지 않는다.

### 2. 고급 정렬의 비교
| 알고리즘 | 대표 시간 | 추가 공간의 대표 모델 | 안정성의 표준 성질 |
|---|---|---|---|
| 삽입 정렬 | 최악 O(n^2) | O(1) | 안정 가능 |
| 병합 정렬 | O(n log n) | 배열 구현 O(n) | 동률 왼쪽 우선이면 안정 |
| 퀵 정렬 | 평균 O(n log n), 최악 O(n^2) | 재귀 깊이에 따라 다름 | 일반 제자리 구현 불안정 |
| 힙 정렬 | O(n log n) | 배열 구현 O(1) | 일반 구현 불안정 |
| 계수 정렬 | O(n+k) | O(n+k) 등 구현에 따름 | 안정 구현 가능 |

병합 정렬은 나누고 두 정렬 구간을 선형으로 합친다. 퀵 정렬은 피벗을 기준으로 나눈다. 한쪽에 몰리는 분할이 반복되면 n+(n-1)+… 비용이 생긴다. 무작위 피벗 등은 기대 성능을 개선하지만 어떤 조건 없이 “최악 n log n”이 되지는 않는다. 비교 정렬의 일반적인 Ω(n log n) 하한은 임의 키의 순서를 비교로만 결정하는 모델의 하한이다. 정수 범위 정보로 계수 정렬을 하는 경우와 충돌하지 않는다.

예제 A: 정렬된 구간 [1,4,7]과 [2,4,8]의 병합은 1,2,4(왼쪽),4(오른쪽),7,8이다. 동률에서 왼쪽 원소를 먼저 선택하면 기존 순서 보존에 도움이 된다. 안정성은 모든 값이 서로 다른 입력에서는 눈에 드러나지 않으므로 동률 레코드로 검사한다.

### 3. 이분 탐색의 전제
정렬 배열에서 가운데와 비교해 절반을 제외한다. 단순히 “가운데를 본다”가 아니라 답이 있을 수 있는 구간을 보존한다. 경계가 포함인지 제외인지 한 모델로 통일해야 한다.

아래는 [lo,hi) 구간에서 처음으로 a[i]>=target인 위치를 찾는 lower_bound 모델이다. 답이 없으면 n을 반환한다.

```python
def lower_bound(a, target):
    lo, hi = 0, len(a)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

예제 B: a=[1,3,3,7], target=3. 초기 [0,4), mid2의3은 이상이므로 hi2. [0,2), mid1의3으로 hi1. [0,1), mid0의1은 작으므로 lo1. 답1이다. target=8이면 답4다. 반환 위치에 실제 값이 존재하는지 확인하지 않으면 배열 범위를 벗어난다.

`upper_bound`는 처음으로 target보다 큰 위치를 찾는다. [1,3,3,7]에서 3의 upper_bound는3이며 두 경계 차3-1=2가 3의 등장 수다. 존재 확인, 첫 위치, 마지막 위치, 개수는 서로 다른 출력이다.

### 4. 답을 이분 탐색하기
최소 처리 시간처럼 답 x에 대한 판정이 단조라면 정렬 배열 없이도 이분 탐색할 수 있다. 예를 들어 처리 시간 2,3인 두 작업자가 시간 t 동안 floor(t/2)+floor(t/3)개를 처리한다고 하자. 5개 처리 가능 여부는 t가 커질수록 참이 유지된다. t=5에서2+1=3, t=6에서3+2=5이므로 최소 시간은6이다. 판정의 단조성을 설명하지 않고 이분 탐색을 적용하면 근거가 없다.

### C++·Python 주의
C++ `std::sort`는 안정 정렬을 보장하지 않고 `std::stable_sort`는 안정성을 제공한다. Python `sorted`는 새 목록을 만들며 `list.sort`는 원본을 변경하고 None을 반환한다. Python의 정렬은 안정적이다. C++ 이분 탐색 함수들은 보통 반복자를 반환하므로 인덱스로 바꾸려면 시작 반복자와의 차를 계산한다.

### 직접 연습과 완료 기준
[2,2,5,9]에서 2의 lower_bound=0, upper_bound=2이다. target=10의 lower_bound=4이다. 빈 배열도0을 반환한다. 표준 선택 정렬의 안정성 반례를 그릴 수 있고 이분 탐색의 불변 구간을 한 줄로 적으면 완료한다.

### 보강 실습: C++ lower_bound로 중복 개수 찾기
배열은 정렬되어 있고 iterator 차이를 유효한 범위에서 계산한다.

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;
int main() {
    vector<int> a{1, 3, 3, 7};
    auto lo = lower_bound(a.begin(), a.end(), 3);
    auto hi = upper_bound(a.begin(), a.end(), 3);
    cout << (lo - a.begin()) << ' '
         << (hi - a.begin()) << ' '
         << (hi - lo) << '\n';
}
```

출력은1 3 2다. target8의 lower_bound는 end()이므로 결과 위치4는 유효 원소가 아니라 삽입 경계다. `*it`로 값을 읽기 전에 it!=end()인지 확인해야 한다. 존재 확인은 범위 확인과 같은 값 확인을 함께 한다. 이미 정렬되어 있지 않은 입력에 함수만 호출해 정답을 기대하지 않는다.

추가 연습: 사용자 레코드의 점수로 정렬하면서 동률의 입력 순서를 지켜야 한다면 안정 정렬 또는 입력 순서를 포함한 명시적인 비교 키를 선택한다. “이름이 sort이니 안정”이라는 추정은 피한다.

### 강화 응용: 조건을 바꾸어 다시 증명하기
이분 탐색은 값 찾기보다 경계 찾기로 적으면 중복에도 일관된다. 배열 [1,2,2,2,5]에서 x=2의 lower_bound는 첫 a[i]≥2인 인덱스 1, upper_bound는 첫 a[i]>2인 인덱스 4다. 등장 수는 4-1=3이다. x=3이면 두 경계 모두 4이고 등장 수 0이다. x=8이면 두 경계는 n=5이며 a[5]를 읽지 않는다. 반열린 구간 [lo,hi) 불변식에서 hi=n은 답 후보인 경계로 허용되지만 유효 원소 인덱스는 아니다.

안정 정렬은 키가 같은 원소의 상대 순서를 유지한다. (부서,점수) 레코드를 점수 오름차순으로 안정 정렬한 뒤 부서를 오름차순으로 안정 정렬하면 부서가 주키이고 점수가 부키가 된다. 마지막 정렬 키가 주키라는 점을 기억한다. 중간 정렬 중 하나가 불안정하면 같은 부서 안의 점수 순서를 일반적으로 보장할 수 없다.

퀵 정렬의 평균과 최악도 입력·피벗 정책을 구분한다. 이미 정렬된 서로 다른 n개 값에서 첫 원소를 피벗으로 쓰고 나머지를 두 부분으로 분할하면 크기 0,n-1로 나뉠 수 있다. 비교 수는 (n-1)+(n-2)+…+1로 Θ(n^2)이다. 무작위 피벗의 기대 O(n log n)은 특정 한 입력에서 최악 O(n^2)이 사라진다는 뜻이 아니다.
