# 04-08 파일 시스템·저장 I/O·디스크 스케줄링: 영구 저장을 이해하기

[[GI-교재04 운영체제|과목 목차]] · [[GI-문제04 운영체제|문제]] · [[GI-해설04 운영체제|해설]]

## 학습 목표
파일 이름·메타 데이터·실제 데이터의 관계를 설명한다. 저장 완료와 지속성을 구분한다. 디스크 이동 계산은 HDD 모델이며 SSD에 그대로 적용하지 않는다.

## 1. 파일·디렉터리·메타 데이터
파일은 이름으로 접근하는 데이터 객체이며 디렉터리는 이름과 객체를 연결한다. 메타 데이터에는 크기·시간·권한·블록 위치 등이 포함된다. inode는 UNIX 계열의 대표 객체 정보 구조다. 파일 이름이 반드시 inode 자체 안에 저장된다고 생각하지 않는다. 이름 연결은 디렉터리 항목과 관련된다.

파일 열기에서 경로 탐색·권한 검사·열린 파일 상태가 만들어질 수 있다. 파일디 스크립터는 프로세스가 열린 객체를 참조하는 대표 핸들이다. 같은 파일을 여러 번 여는 경우와 하나의 열린 파일 상태를 공유하는 경우의 오프셋 동작은 다를 수 있다. 제품·API의 정의를 확인한다.

## 2. 하드 링크와 심볼릭 링크
하드 링크는 같은 파일 객체를 여러 이름이 참조하는 형태다. 일반적으로 동일 파일 시스템 안에서만 만들 수 있고 디렉터리 링크에 제한이 있다. 심볼릭링크는 경로를 가리키는 별도 객체로 대상 경로가 사라지면 깨진 링크가 될 수 있다. 서로 다른 파일 시스템을 가리킬 수 있다.

### 손풀이 예제 23: 이름 삭제
a와 b가 동일 파일 객체의 하드 링크라고 하자. a를 삭제해도 b가 남아 있어 데이터를 계속 참조한다. a 경로를 가리키는 심볼 릭 링크 s라면 a 삭제 뒤 s가 대상을 찾지 못할 수 있다. 열린 핸들·참조수 등 조건 때문에 마지막 이름 삭제와 실제 저장 공간 반납 시점도 같지 않을 수 있다. 파일 삭제를 단순 바이트 즉시 소거라고 보지 않는다.

## 3. 할당 방식
연속 할당은 연속 블록으로 배치하여 순차·직접 접근이 쉽지만 확장과 외부 단편화를 검토해야 한다. 연결 할당은 블록끼리 연결하여 확장하기 쉽지만 임의 블록 탐색과 포인터 손상 문제가 있다. 인덱스 할당은 블록 위치 배열 등을 이용해 직접 접근을 지원하나 인덱스 공간 비용이 든다. 실제 파일 시스템은 extent·다단계 인덱스 등을 조합할 수 있다.

### 손풀이 예제 24: 간접 포인터 용량
단순 inode에 직접 포인터 12개와 단일 간접 포인터 1개만 있고 블록 4KiB, 포인터 4바이트다. 간접 블록은4096/4=1024개의 데이터 블록 위치를 담는다. 최대 데이터 블록은 12 +1024 =1036개, 파일 데이터 용량 1036×4096 =4,243,456 바이트다. inode·간접 블록 자체 저장 비용은 이 파일 데이터 용량에 포함하지 않는다. 이중·삼중 간접이 있으면 별도로 추가한다.

## 4. 캐시·버퍼·flush·저널링
메모리버퍼에 쓰기 성공했다고 바로 물리 매체에 지속되었다고 보장할 수 없다. flush·fsync 등 API가 보장하는 범위와 파일 시스템·장치의 동작을 확인한다. 실제 유실 범위는 전원 장애·장치캐시·설정과 관련된다. 네트워크 원격 저장에서는 서버 측 보장도 고려한다.

저널링은 메타 데이터 등 변경 기록을 이용해 비정상 종료 후 일관성 복구를 돕는다. 모든 파일 데이터의 이전 내용을 무한히 보관하는 백업이 아니다. 원자적 rename 등을 이용한 파일 교체 패턴도 플랫폼과 동일 파일 시스템 조건 등을 확인한다. 저장 경로에서 예외·부분 쓰기·공간 부족을 처리해야 한다.

## 5. HDD 스케줄링 모델
실린더 0~199, 현재 50, 요청도 착순 82,170,43,140,24,16,190이다. 모든 요청이 처음부터 있고 이동 거리만 계산한다. 탐색 시간·회전·전송 시간은 거리와 분리한다.

### 손풀이 예제 25: FCFS와 SSTF
FCFS 거리는 |82-50|+|170-82|+|43-170|+|140-43|+|24-140|+|16-24|+|190-16|=32 +88 +127 +97 +116 +8 +174 =642이다.
SSTF는 가장 가까운 43->24->16->82->140->170->190순이다. 거리 7 +19 +8 +66 +58 +30 +20 =208이다. 가까운 요청이 지속 도착하면 먼 요청의 기아 가능성을 검토한다. 이 표에서 이동 거리가 짧다는 것이 모든 실제 부하에서 최고 정책이라는 뜻은 아니다.

### 손풀이 예제 26: SCAN과 LOOK
초기 방향은 증가 쪽이다. SCAN은 82,140,170,190 처리 후 끝 199까지 가고 반대 방향으로 43,24,16을 처리한다. 마지막 요청 16에서 측정 종료하면 거리(199-50)+(199-16)=332다. 끝 0까지 계속 가는 시간까지 포함하라는 문제면 답이 다르다.
LOOK은 증가 쪽 최후 요청 190에서 돌아 16까지 처리하여(190-50)+(190-16)=314다. SCAN은 물리 끝,LOOK은 요청 끝이라는 차이다. 방향·종료 조건을 생략하면 여러 답이 생길 수 있다.

## 6. 저장 시간 계산
1MiB를 200MiB/s로 전송하면1/200초 =5ms다. 평균 탐색 8ms·평균 회전 대기 4ms를 별도 더 하는 단순 모델이면 총 17ms다. MB와 MiB를 혼합하거나 밀리 초와 초를 혼합하지 않는다. SSD는 회전·기계적 탐색이 없고 플래시 관리·쓰기 증폭·병렬성 등 다른 특성이 있다.

## 종합 완료 기준
스케줄링 4 차트, 은행가 안전 순서, 주소 변환, 페이지 교체 표, 파일 용량·디스크 거리 중에서 빈 종이에 다시 풀 수 있어야한다. 전공 24 문항을 맞힌 뒤에도 오답 각각의 틀린 가정을 설명한다. 1일 뒤 상태도,3일 뒤 계산,7일 뒤 종합 문제를 회 독한다. 반복 시간은 학습 권장이며 공식 시험 배점과 무관하다.

참고: [OSTEP 파일·디렉터리](https://pages.cs.wisc.edu/~remzi/OSTEP/file-intro.pdf), [파일시스템구현](https://pages.cs.wisc.edu/~remzi/OSTEP/file-implementation.pdf), [저널링](https://pages.cs.wisc.edu/~remzi/OSTEP/file-journaling.pdf), [디스크](https://pages.cs.wisc.edu/~remzi/OSTEP/file-disks.pdf). 파일 용량·디스크표는 가정을 명시한 자체 예제다.

## 강화 손풀이: 파일 링크 수와 열린 참조를 구별한다
POSIX식 파일 모델에서 a,b가 같은 파일의 하드링크이고 링크 수가 2라고 하자. a를 unlink하면 링크 수는 1이 되고 b로 파일 데이터에 접근할 수 있다. b까지 unlink해 링크 수 0이 되어도 어떤 프로세스가 파일을 열고 있는 동안 그 열린 참조로 접근할 수 있으며 저장 자원 회수는 열린 참조까지 사라진 뒤 가능하다. 제품·파일시스템별 API 차이는 확인한다.

심볼릭 링크 s는 경로 문자열을 가리킨다. 대상 경로 a를 지우면 s는 깨질 수 있으며 다른 하드링크 b가 있다고 s가 자동으로 b를 찾아가는 것은 아니다.

**I/O 반례:** write가 사용자 버퍼에서 커널 버퍼로 자료를 넘겼다고,정전 뒤에도 저장 장치에 반드시 남는 것은 아니다. 요구한 지속성 수준에 맞는 동기화 API와 파일·디렉터리 변경 절차,장치 보장을 확인한다. 저널링은 충돌 후 구조 일관성 회복을 도울 수 있으나 모든 과거 사용자 데이터의 백업을 대신하지 않는다.

**계산 모델:** 현재 헤드 50,요청 10·20·70이고 SSTF에서 거리가 같으면 작은 실린더를 택한다. 순서는 70→20→10이고 이동은 20+50+10=80이다. 회전 지연 등은 제외한 실린더 거리 모델이다.
