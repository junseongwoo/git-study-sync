# 1부 - 빈도 배열

## 1. 빈도 배열이란?

어떤 값이 몇 번 나타났는지를 인덱스로 기록하는 배열이다.

```text
입력: 1 3 1 2 3 1

값        0  1  2  3
등장 횟수 0  3  1  2
```

```cpp
vector<int> count(4, 0);

for (int value : numbers) {
    count[value]++;
}
```

`count[3]`은 숫자 `3`이 등장한 횟수다. 값을 곧바로 배열의 주소로 사용한다는 점에서 **직접 주소 방식**의 가장 단순한 형태다.

### 복잡도

입력의 길이가 `N`일 때:

- 빈도 계산: `O(N)`
- 특정 값의 등장 횟수 확인: `O(1)`
- 값 전체 범위 `K`를 순회: `O(K)`
- 공간: `O(K)`

`K`가 매우 크면 메모리가 낭비된다. 이때 해시 테이블이 대안이 된다.

---

## 2. 왜 이중 반복문보다 좋은가?

각 원소마다 전체 배열을 다시 세면 `O(N^2)`이다.

```cpp
for (int x : numbers) {
    int count = 0;

    for (int y : numbers) {
        if (x == y) {
            count++;
        }
    }
}
```

빈도 배열은 한 번 순회하며 센다.

```cpp
vector<int> frequency(101, 0);

for (int number : numbers) {
    frequency[number]++;
}
```

코딩 테스트에서는 먼저 다음 질문을 하자.

> 값의 종류가 제한되어 있다면, 값을 인덱스로 바꿀 수 있는가?

---

## 3. 인덱스로 바꾸는 대표 패턴

### 3.1 숫자 문자 `'0'`~`'9'`

```cpp
int index = ch - '0';
```

```cpp
vector<int> count(10, 0);

for (char ch : text) {
    count[ch - '0']++;
}
```

### 3.2 소문자 `'a'`~`'z'`

```cpp
int index = ch - 'a';
```

```cpp
#include <array>

array<int, 26> count{};

for (char ch : word) {
    count[ch - 'a']++;
}
```

`array<int, 26> count{};`의 `{}`는 모든 값을 `0`으로 초기화한다.

### 3.3 대문자 `'A'`~`'Z'`

```cpp
count[ch - 'A']++;
```

### 3.4 음수가 포함된 작은 범위

값의 범위가 `-50`부터 `50`까지라면 `50`을 더해 인덱스로 바꾼다.

```cpp
vector<int> count(101, 0);

for (int value : numbers) {
    count[value + 50]++;
}
```

`-50 -> 0`, `0 -> 50`, `50 -> 100`이 된다. 이 기법을 **오프셋을 준다**고 표현한다.

---

## 4. `array`와 `vector` 중 무엇을 쓸까?

| 상황 | 추천 |
|---|---|
| 크기가 컴파일 시점에 고정됨 | `array<int, 26>` |
| 크기를 입력받거나 실행 중 결정함 | `vector<int>(size, 0)` |
| 단순한 알파벳/숫자 빈도 | 둘 다 가능 |

입문 단계에서는 `vector<int>`만 사용해도 충분하다. 다만 알파벳 26개처럼 크기가 분명하면 `array`가 의도를 더 잘 드러낸다.

---

## 5. 빈도 배열을 쓰면 안 되는 경우

### 값의 범위가 너무 큰 경우

```text
값: 1, 1,000,000,000
```

이 두 값만 세기 위해 크기 10억짜리 배열을 만드는 것은 낭비다.

### 키가 문자열인 경우

```text
apple, banana, kiwi
```

문자열은 그대로 배열 인덱스로 사용할 수 없다. 문자열을 정수 위치로 바꿔 주는 해시 함수가 필요하다.

### 범위를 모르는 경우

입력값의 최댓값이 명확하지 않으면 배열 크기를 안전하게 정하기 어렵다. 이때도 해시 기반 자료구조가 편리하다.

---

## 6. 빈도 배열 기본 템플릿

### 정수 빈도

```cpp
vector<int> makeFrequency(const vector<int>& numbers, int maximum) {
    vector<int> frequency(maximum + 1, 0);

    for (int number : numbers) {
        frequency[number]++;
    }

    return frequency;
}
```

### 소문자 빈도

```cpp
array<int, 26> countLowercase(const string& word) {
    array<int, 26> frequency{};

    for (char ch : word) {
        frequency[ch - 'a']++;
    }

    return frequency;
}
```

`const vector<int>&`와 `const string&`는 원본을 복사하지 않고 읽기만 하겠다는 뜻이다.

# 2부 - 해시 테이블 원리

## 7. 탐색 문제부터 생각하기

다음 질문은 모두 탐색 문제다.

- 숫자 `42`가 존재하는가?
- 이름 `kim`이 이미 등록되었는가?
- 단어 `apple`이 몇 번 등장했는가?
- 같은 이메일이 두 번 들어왔는가?

배열을 처음부터 끝까지 찾으면 한 번에 `O(N)`이다. 같은 질문을 많이 하면 느려진다. 해시 테이블은 키를 저장 위치로 바꿔 평균적으로 빠르게 찾는다.

---

## 8. 해시 함수

해시 함수는 키를 정수 형태의 해시값으로 바꾼다.

```text
키 -> 해시 함수 -> 해시값 -> 버킷 위치
```

정수 키를 크기 7인 테이블에 넣는 가장 단순한 예:

```cpp
int index = key % 7;
```

```text
2  % 7 = 2
9  % 7 = 2
16 % 7 = 2
```

서로 다른 키가 같은 위치 `2`를 가리킨다. 이것이 **충돌**이다.

### 좋은 해시 함수의 조건

- 같은 키에는 항상 같은 결과를 낸다.
- 가능한 위치에 키를 비교적 고르게 분산한다.
- 계산 비용이 지나치게 크지 않다.

C++ 표준 라이브러리는 `std::hash<T>`를 제공한다.

```cpp
#include <functional>

size_t value = hash<string>{}("apple");
```

중요한 것은 해시값 자체를 외우는 것이 아니라, 해시값을 버킷 위치로 바꾸고 충돌을 처리한다는 흐름이다.

---

## 9. 충돌은 오류가 아니라 반드시 처리할 상황이다

저장할 수 있는 키는 많지만 버킷 수는 유한하다. 따라서 충돌은 피할 수 없다.

충돌 해결의 대표 방법:

1. **체이닝**: 같은 버킷에 여러 값을 연결해 저장한다.
2. **개방 주소법**: 충돌하면 테이블 안의 다른 빈 위치를 찾는다.

---

## 10. 체이닝

각 버킷이 리스트 같은 컨테이너를 가진다.

```text
버킷 0: [ ]
버킷 1: [ ]
버킷 2: [2] -> [9] -> [16]
버킷 3: [ ]
...
```

학습용 정수 집합 구현:

```cpp
#include <algorithm>
#include <functional>
#include <list>
#include <vector>
using namespace std;

class ChainedHashSet {
private:
    vector<list<int>> buckets;

    size_t bucketIndex(int value) const {
        return hash<int>{}(value) % buckets.size();
    }

public:
    explicit ChainedHashSet(size_t bucketCount)
        : buckets(max<size_t>(1, bucketCount)) {
    }

    bool contains(int value) const {
        const list<int>& bucket = buckets[bucketIndex(value)];

        return find(bucket.begin(), bucket.end(), value) != bucket.end();
    }

    void insert(int value) {
        if (!contains(value)) {
            buckets[bucketIndex(value)].push_back(value);
        }
    }

    void erase(int value) {
        buckets[bucketIndex(value)].remove(value);
    }
};
```

실전에서는 직접 구현하기보다 `unordered_set`, `unordered_map`을 사용한다. 오늘은 내부 원리를 이해하기 위한 코드다.

---

## 11. 개방 주소법

각 버킷에 보통 하나의 원소를 두고, 충돌하면 다른 빈 버킷을 찾는다.

### 11.1 선형 탐사

한 칸씩 이동한다.

```text
index, index + 1, index + 2, ...
```

크기 7인 테이블에 `2, 9, 16, 23`을 넣으면:

```text
2  -> 2번
9  -> 2번 충돌 -> 3번
16 -> 2, 3번 충돌 -> 4번
23 -> 2, 3, 4번 충돌 -> 5번
```

연속된 구간에 값이 몰리는 **군집화**가 생길 수 있다.

### 11.2 이차 탐사

이동 폭을 제곱 형태로 늘린다.

```text
index + 1², index + 2², index + 3², ...
```

선형 탐사의 1차 군집화를 완화하지만, 테이블 크기와 탐사 규칙을 잘 정해야 한다.

### 삭제 주의

개방 주소법에서 원소를 그냥 빈칸으로 바꾸면 탐색 경로가 끊길 수 있다. 그래서 `사용한 적 없음`, `사용 중`, `삭제됨` 같은 상태를 구분하는 표식이 필요하다.

---

## 12. 뻐꾸기 해싱

두 개 이상의 해시 함수와 후보 위치를 사용한다. 새 키가 자리를 차지하면 기존 키를 다른 후보 위치로 밀어낸다.

```text
새 키 삽입
  -> 후보 1이 비었으면 저장
  -> 차 있으면 기존 키를 밀어냄
  -> 밀려난 키가 자기 후보 2로 이동
```

탐색할 후보 위치가 적어 조회가 빠르다는 장점이 있다. 그러나 원소들이 서로를 계속 밀어내며 순환할 수 있다. 이때 테이블 크기를 늘리거나 새로운 해시 함수를 사용해 재해싱한다.

코딩 테스트 입문에서는 직접 구현 빈도가 높지 않다. **후보 위치, 밀어내기, 순환, 재해싱**의 흐름만 설명할 수 있으면 충분하다.

---

## 13. 적재율과 재해싱

적재율은 테이블이 얼마나 찼는지를 나타낸다.

```text
적재율 = 저장된 원소 수 / 버킷 수
```

예를 들어 버킷이 10개이고 원소가 7개라면 적재율은 `0.7`이다.

적재율이 커질수록 충돌 가능성이 높아지고 탐색이 느려질 수 있다. 그래서 구현체는 필요할 때:

1. 더 큰 버킷 배열을 만든다.
2. 기존 원소의 버킷 위치를 다시 계산한다.
3. 새 테이블로 옮긴다.

이를 **재해싱**이라고 한다. 버킷 수가 바뀌면 `hashValue % bucketCount`의 결과도 달라지므로 단순 복사가 아니라 위치를 다시 계산해야 한다.

---

## 14. 해시 테이블의 시간 복잡도

| 연산 | 평균 | 최악 |
|---|---:|---:|
| 삽입 | `O(1)` | `O(N)` |
| 탐색 | `O(1)` | `O(N)` |
| 삭제 | `O(1)` | `O(N)` |

최악의 경우는 많은 키가 같은 버킷에 몰리는 상황이다. 따라서 답안에서 단순히 “무조건 `O(1)`”이라고 쓰면 안 된다.

> 정확한 표현: 해시 기반 삽입·탐색·삭제는 **평균적으로 `O(1)`**, 충돌이 심한 최악의 경우 `O(N)`이 될 수 있다.

# 3부 - 블룸 필터

## 15. 블룸 필터란?

어떤 원소가 집합에 들어 있을 가능성을 매우 적은 메모리로 검사하는 확률적 자료구조다.

여러 해시 함수가 가리키는 비트를 `1`로 설정한다.

```text
삽입: key -> h1, h2, h3 -> 해당 비트를 모두 1로 설정
조회: h1, h2, h3의 비트가 모두 1인지 확인
```

조회 결과의 의미가 중요하다.

- 비트 중 하나라도 `0`: **확실히 없음**
- 모든 비트가 `1`: **있을 가능성이 있음**

즉:

- 거짓 음성(false negative)은 없다.
- 거짓 양성(false positive)은 있을 수 있다.

다른 원소들이 우연히 같은 비트들을 켰을 수 있기 때문이다.

### 학습용 개념 코드

```cpp
#include <algorithm>
#include <functional>
#include <string>
#include <vector>
using namespace std;

class SimpleBloomFilter {
private:
    vector<bool> bits;

    size_t first(const string& value) const {
        return hash<string>{}(value) % bits.size();
    }

    size_t second(const string& value) const {
        string salted = "#" + value;
        return hash<string>{}(salted) % bits.size();
    }

public:
    explicit SimpleBloomFilter(size_t size)
        : bits(max<size_t>(1, size), false) {
    }

    void insert(const string& value) {
        bits[first(value)] = true;
        bits[second(value)] = true;
    }

    bool possiblyContains(const string& value) const {
        return bits[first(value)] && bits[second(value)];
    }
};
```

이 코드는 원리를 보기 위한 축소판이다. 실제 시스템에서는 독립성이 좋은 여러 해시 함수, 적절한 비트 배열 크기, 예상 원소 수를 함께 고려한다.

---

## 16. 이메일 중복 검사에 적용하기

이메일이 이미 등록되었는지 검사한다고 하자.

```text
새 이메일
   |
블룸 필터 검사
   |-- 확실히 없음 --> 실제 저장소 조회를 생략하거나 바로 신규 처리
   |
   `-- 있을 가능성 --> 실제 해시 집합/DB에서 정확히 재검사
```

블룸 필터만으로 “중복 확정”을 내리면 안 된다. 거짓 양성이 있기 때문이다. 블룸 필터는 비싼 조회를 줄이는 **앞단 필터**로 사용한다.

## 17. 세 방식 비교

| 방식 | 키 범위 | 결과 | 대표 용도 |
|---|---|---|---|
| 빈도 배열 | 작고 연속적 | 정확함 | 숫자, 알파벳 개수 |
| 해시 테이블 | 크거나 불연속적, 문자열 가능 | 정확함 | 존재 여부, 빈도, 키-값 저장 |
| 블룸 필터 | 매우 큰 집합 | 확률적 | 비싼 실제 조회 전 빠른 필터링 |

선택 순서:

1. 값의 범위가 작고 안전하게 인덱스로 바꿀 수 있는가? -> 빈도 배열
2. 정확한 존재 여부나 빈도가 필요하고 키 범위가 큰가? -> 해시 테이블
3. 메모리가 매우 제한되고 “확실히 없음”을 빠르게 걸러 내면 되는가? -> 블룸 필터 + 실제 저장소

## A. 빈도 배열 기본 문제 F1~F9

### F1. 숫자 문자열의 빈도

숫자로만 이루어진 문자열 `s`가 주어질 때 0부터 9까지 각각 몇 번 등장했는지 반환하라.

```cpp
vector<int> solution(string s) {
    vector<int> answer(10, 0);

    for (char ch : s) {
        answer[ch - '0']++;
    }

    return answer;
}
```

- 시간: `O(N)`
- 공간: `O(1)` - 배열 크기가 항상 10이기 때문

---

### F2. 소문자 빈도

소문자 문자열에서 각 알파벳의 등장 횟수를 반환하라.

```cpp
vector<int> solution(string s) {
    vector<int> answer(26, 0);

    for (char ch : s) {
        answer[ch - 'a']++;
    }

    return answer;
}
```

---

### F3. 없는 숫자의 합

0부터 9 중 주어진 배열에 없는 숫자의 합을 반환하라.

```cpp
int solution(vector<int> numbers) {
    vector<bool> exists(10, false);

    for (int number : numbers) {
        exists[number] = true;
    }

    int answer = 0;

    for (int number = 0; number <= 9; number++) {
        if (!exists[number]) {
            answer += number;
        }
    }

    return answer;
}
```

참고로 0부터 9의 합이 45이므로 `45 - 주어진 숫자의 합`으로도 풀 수 있다. 빈도 배열 학습을 위해 위 풀이를 사용했다.

---

### F4. 한 번만 등장하는 문자

소문자 문자열에서 정확히 한 번 등장하는 문자만 원래 순서대로 이어 붙여 반환하라.

```cpp
string solution(string s) {
    vector<int> frequency(26, 0);

    for (char ch : s) {
        frequency[ch - 'a']++;
    }

    string answer;

    for (char ch : s) {
        if (frequency[ch - 'a'] == 1) {
            answer += ch;
        }
    }

    return answer;
}
```

두 번 순회해도 `O(N) + O(N) = O(N)`이다.

---

### F5. 애너그램 판별

두 소문자 문자열이 같은 문자들을 같은 개수만큼 가지는지 판별하라.

```cpp
bool solution(string a, string b) {
    if (a.size() != b.size()) {
        return false;
    }

    vector<int> frequency(26, 0);

    for (char ch : a) {
        frequency[ch - 'a']++;
    }

    for (char ch : b) {
        frequency[ch - 'a']--;
    }

    for (int count : frequency) {
        if (count != 0) {
            return false;
        }
    }

    return true;
}
```

---

### F6. 최빈값

0 이상 100 이하의 정수 배열에서 가장 많이 등장한 값을 반환하라. 최빈값이 여러 개면 작은 값을 반환한다.

```cpp
int solution(vector<int> numbers) {
    vector<int> frequency(101, 0);

    for (int number : numbers) {
        frequency[number]++;
    }

    int answer = 0;

    for (int value = 1; value <= 100; value++) {
        if (frequency[value] > frequency[answer]) {
            answer = value;
        }
    }

    return answer;
}
```

같은 빈도일 때 작은 값을 유지하려고 `>`만 사용한다.

---

### F7. 대소문자를 무시한 최다 알파벳

영문 문자열에서 대소문자를 무시하고 가장 많이 등장한 알파벳을 대문자로 반환하라. 공동 1등이면 `'?'`를 반환한다.

힌트:

```cpp
char upper = static_cast<char>(toupper(static_cast<unsigned char>(ch)));
frequency[upper - 'A']++;
```

직접 구현할 때는 `#include <cctype>`를 추가한다.

<details>
<summary>정답 확인</summary>

```cpp
#include <cctype>
#include <string>
#include <vector>
using namespace std;

char solution(string s) {
    vector<int> frequency(26, 0);

    for (char ch : s) {
        char upper = static_cast<char>(
            toupper(static_cast<unsigned char>(ch))
        );
        frequency[upper - 'A']++;
    }

    int bestIndex = 0;
    bool tied = false;

    for (int index = 1; index < 26; index++) {
        if (frequency[index] > frequency[bestIndex]) {
            bestIndex = index;
            tied = false;
        } else if (frequency[index] == frequency[bestIndex]) {
            tied = true;
        }
    }

    return tied ? '?' : static_cast<char>('A' + bestIndex);
}
```

</details>

### F8. 목표 문자열 만들기

소문자 문자열 `source`의 문자를 각각 한 번씩만 사용해 `target`을 만들 수 있는지 판별하라.

<details>
<summary>정답 확인</summary>

```cpp
bool solution(string source, string target) {
    vector<int> frequency(26, 0);

    for (char ch : source) {
        frequency[ch - 'a']++;
    }

    for (char ch : target) {
        int index = ch - 'a';
        frequency[index]--;

        if (frequency[index] < 0) {
            return false;
        }
    }

    return true;
}
```

</details>

### B6. STL 해시 컨테이너 미리 보기 - 책 연습문제 16 축약

정수 목록이 주어질 때 다음 두 결과를 구하라.

1. `unordered_set<int>`을 이용해 중복을 제거한 원소 수
2. `unordered_map<int, int>`을 이용한 각 정수의 등장 횟수

```cpp
#include <unordered_map>
#include <unordered_set>
#include <utility>
#include <vector>
using namespace std;

pair<int, unordered_map<int, int>> summarize(const vector<int>& numbers) {
    unordered_set<int> uniqueNumbers;
    unordered_map<int, int> frequency;

    for (int number : numbers) {
        uniqueNumbers.insert(number);
        frequency[number]++;
    }

    return {static_cast<int>(uniqueNumbers.size()), frequency};
}
```

- 집합은 키의 존재 여부와 중복 제거에 적합하다.
- 맵은 키마다 값을 연결하므로 빈도 계산에 적합하다.
- 순회 출력 순서는 정렬되어 있지 않다.

`insert`, `find`, `erase`, 반복문 등 상세 API는 3일차에서 집중 훈련한다.

1. 빈도 배열과 직접 주소 방식의 관계는 무엇인가?
2. `'7' - '0'`의 결과는 무엇인가?
3. 소문자 `z`의 빈도 배열 인덱스는 무엇인가?
4. 값 범위가 `-50`부터 `50`일 때 필요한 배열 크기와 오프셋은?
5. 해시 충돌은 왜 피할 수 없는가?
6. 체이닝과 개방 주소법의 차이는?
7. 선형 탐사의 군집화는 무엇인가?
8. 적재율이 높아지면 어떤 문제가 생길 수 있는가?
9. 재해싱 때 기존 원소의 위치를 다시 계산하는 이유는?
10. 뻐꾸기 해싱에서 순환이 생기면 어떻게 하는가?
11. 해시 탐색의 평균과 최악 시간 복잡도는?
12. 블룸 필터에서 하나의 비트라도 0이면 어떤 결론을 내릴 수 있는가?
13. 모든 비트가 1이어도 존재를 확정할 수 없는 이유는?
14. 문자열 키의 정확한 빈도 계산에는 어떤 자료구조가 적합한가?
15. 값의 범위가 작을 때 해시보다 빈도 배열이 단순한 이유는?

12개 이상 정확히 설명하면 다음 날로 넘어간다.

## 21. 완료 체크리스트

- [ ] 숫자와 알파벳을 빈도 배열의 인덱스로 바꿀 수 있다.
- [ ] 음수의 작은 범위를 오프셋으로 처리할 수 있다.
- [ ] 빈도 배열 문제를 `O(N)`에 해결할 수 있다.
- [ ] 해시 함수와 버킷의 관계를 설명할 수 있다.
- [ ] 충돌이 무엇인지 예로 설명할 수 있다.
- [ ] 체이닝과 선형 탐사의 차이를 말할 수 있다.
- [ ] 적재율과 재해싱을 설명할 수 있다.
- [ ] 평균 `O(1)`, 최악 `O(N)`을 구분할 수 있다.
- [ ] 블룸 필터의 거짓 양성을 설명할 수 있다.
- [ ] F1~F9 중 최소 7문제를 직접 풀었다.
- [ ] B1~B8을 모두 설명하거나 구현했다.
- [ ] A1~A6 중 최소 4문제를 직접 풀었다.
- [ ] 틀린 문제의 반례를 오답 노트에 남겼다.
