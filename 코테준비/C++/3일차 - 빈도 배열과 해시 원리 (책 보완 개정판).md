# 1부 — 빈도 배열과 직접 주소 지정

## 1. 빈도 배열

빈도는 값이 등장한 횟수다.

```text
입력: {1, 3, 1, 2, 3, 1}

0 → 0번
1 → 3번
2 → 1번
3 → 2번
```

값이 `0`부터 `3`까지만 나온다면 값 자체를 배열의 인덱스로 사용한다.

```cpp
vector<int> count(4, 0);

for (int number : numbers) {
    count[number]++;
}
```

이 방식은 입력값을 곧바로 저장 위치로 사용하는 **직접 주소 지정**에 가깝다.

```text
값 0 → count[0]
값 1 → count[1]
값 2 → count[2]
값 3 → count[3]
```

검색·삽입·갱신을 인덱스 한 번으로 처리하므로 `O(1)`이다.

---

## 2. 문자와 인덱스 변환

### 숫자 문자

```cpp
vector<int> count(10, 0);

for (char ch : numberString) {
    count[ch - '0']++;
}
```

### 영문 소문자

```cpp
vector<int> count(26, 0);

for (char ch : word) {
    count[ch - 'a']++;
}
```

### 인덱스를 문자로 복원

```cpp
char ch = static_cast<char>('a' + index);
```

---

## 3. 빈도 배열이 적합한 조건

- 값의 범위가 작다.
- 범위가 문제에서 명확히 주어진다.
- 값이 0 이상의 정수로 쉽게 변환된다.

예시:

- 숫자 `0`~`9`
- 영문 소문자 26개
- 점수 `0`~`100`
- 요일 7개

다음 상황에는 적합하지 않다.

```text
회원 번호: 1, 1,000,000,000
이름: "kim", "lee", "park"
URL: "https://..."
```

1부터 10억까지의 배열을 만들면 대부분의 공간이 낭비된다. 문자열은 애초에 배열 인덱스로 바로 사용할 수 없다.

---

## 4. 선형 탐색과 기록의 차이

매번 전체 배열을 다시 확인하면 `O(N²)`이 될 수 있다.

```cpp
for (int number : numbers) {
    int frequency = 0;

    for (int other : numbers) {
        if (number == other) {
            frequency++;
        }
    }
}
```

빈도를 한 번 기록하면 전체 순회 `O(N)`으로 끝난다.

```cpp
for (int number : numbers) {
    count[number]++;
}
```

> 같은 정보를 반복해서 찾는다면 한 번 계산해 기록할 수 있는지 먼저 생각한다.

# 2부 — 해시 함수와 해시 테이블

## 5. 룩업과 해시

룩업은 키를 이용해 원하는 값이나 존재 여부를 찾는 작업이다.

```text
학번 → 학생 정보
이름 → 등장 횟수
URL → 단축 코드
상품명 → 재고 수량
```

해시 테이블은 키를 해시 함수에 넣어 저장할 버킷 위치를 계산한다.

```text
key → hash(key) → bucket index → 데이터
```

간단한 정수 해시 함수는 나머지 연산으로 만들 수 있다.

```cpp
int index = key % bucketCount;
```

버킷이 7개라면:

```text
2  % 7 → 2번 버킷
10 % 7 → 3번 버킷
25 % 7 → 4번 버킷
```

실제 C++의 해시 함수는 키 자료형에 맞는 더 일반적인 계산을 수행한다.

```cpp
size_t hashValue = hash<string>{}(word);
size_t index = hashValue % bucketCount;
```

---

## 6. 좋은 해시 함수의 조건

- 같은 키에는 항상 같은 해시 값을 만든다.
- 계산이 빠르다.
- 서로 다른 키가 여러 버킷에 비교적 고르게 분포된다.

해시 값은 키 자체가 아니다. 서로 다른 키가 같은 위치로 계산될 수 있다.

```text
2   % 7 → 2
100 % 7 → 2
```

---

## 7. 해시 충돌

서로 다른 키가 같은 버킷을 요구하는 현상을 충돌이라고 한다.

```text
key 2   → bucket 2
key 100 → bucket 2
```

기존 값을 덮어쓰면 한 키를 잃어버린다. 따라서 해시 테이블에는 충돌 처리 방법이 필요하다.

### 충돌은 오류가 아니다

좋은 해시 함수도 충돌을 완전히 없앨 수는 없다. 가능한 키의 수는 매우 많고 버킷 수는 제한되어 있기 때문이다.

---

## 8. 체이닝

체이닝은 버킷마다 여러 값을 저장할 수 있는 리스트를 두는 방식이다.

```text
bucket 0: []
bucket 1: []
bucket 2: [2, 100]
bucket 3: [10]
```

간단한 학습용 구현:

```cpp
#include <algorithm>
#include <functional>
#include <list>
#include <vector>
using namespace std;

class ChainedHashSet {
private:
    vector<list<int>> buckets;

    size_t bucketIndex(int value) const {
        return hash<int>{}(value) % buckets.size();
    }

public:
    explicit ChainedHashSet(size_t bucketCount)
        : buckets(max<size_t>(1, bucketCount)) {
    }

    bool contains(int value) const {
        const list<int>& bucket = buckets[bucketIndex(value)];
        return find(bucket.begin(), bucket.end(), value) != bucket.end();
    }

    void insert(int value) {
        if (!contains(value)) {
            buckets[bucketIndex(value)].push_back(value);
        }
    }

    void erase(int value) {
        buckets[bucketIndex(value)].remove(value);
    }
};
```

실전 문제에서 직접 구현하기보다 `unordered_set`과 `unordered_map`을 사용한다. 이 코드는 내부 동작을 이해하기 위한 학습용이다.

---

## 9. 열린 주소 지정

열린 주소 지정은 모든 데이터를 해시 테이블 배열 안에 저장한다. 충돌하면 다른 빈 칸을 찾는다.

### 선형 탐사

한 칸씩 이동한다.

```text
hash(key)가 사용 중 → +1 위치 확인 → 또 사용 중 → +1
```

단순하지만 값이 한 구간에 뭉치는 군집화가 생길 수 있다.

### 이차 탐사

`1²`, `2²`, `3²`처럼 이동 거리를 늘려 군집화를 줄인다.

### 뻐꾸기 해싱

두 개 이상의 해시 위치 후보를 사용한다. 새 키가 자리를 차지하면 기존 키를 다른 후보 위치로 이동시킨다. 이동이 순환하면 재해싱이 필요하다.

코딩 테스트 초급 단계에서는 직접 구현보다 다음을 이해하면 충분하다.

- 충돌 처리 방식은 하나가 아니다.
- 충돌이 많을수록 검색 비용이 증가할 수 있다.
- STL이 내부 충돌 처리를 담당한다.

---

## 10. 부하율과 재해싱

부하율은 저장된 원소 수를 버킷 수로 나눈 값이다.

```text
load factor = 원소 수 / 버킷 수
```

```text
원소 7개, 버킷 10개 → 부하율 0.7
```

부하율이 너무 높으면 한 버킷에 원소가 몰려 검색이 느려질 수 있다. 해시 컨테이너는 필요할 때 버킷 수를 늘리고 원소를 다시 배치한다. 이 작업이 재해싱이다.

STL에서는 다음 정보를 확인할 수 있다.

```cpp
unordered_set<int> values;

values.bucket_count();
values.load_factor();
values.max_load_factor();
values.reserve(1000);
```

`reserve()`는 많은 원소를 넣을 것을 미리 알 때 재해싱 횟수를 줄이는 데 도움이 될 수 있다.

---

## 11. 평균과 최악 시간복잡도

| 연산 | 평균 | 최악 |
|---|---:|---:|
| 삽입 | `O(1)` | `O(N)` |
| 검색 | `O(1)` | `O(N)` |
| 삭제 | `O(1)` | `O(N)` |

충돌이 적고 키가 고르게 분포한다는 일반적인 상황에서 평균 `O(1)`이다. 모든 키가 한 버킷에 몰리면 그 버킷을 선형으로 찾아야 하므로 최악에는 `O(N)`이다.

# 3부 — 블룸 필터

## 12. 블룸 필터란?

블룸 필터는 적은 메모리로 어떤 값이 들어 있었는지를 빠르게 추정하는 확률적 자료구조다.

실제 값을 저장하지 않고 여러 해시 함수가 가리키는 비트를 1로 만든다.

```text
초기 비트: 0 0 0 0 0 0 0
값 A 삽입: 1 0 1 0 0 1 0
값 B 삽입: 1 1 1 0 1 1 0
```

검색 시 필요한 비트가 하나라도 0이면 해당 값은 **확실히 없다**.

모든 비트가 1이면 다음 두 경우가 가능하다.

- 실제로 들어 있다.
- 다른 값들이 같은 비트를 켜서 들어 있는 것처럼 보인다.

따라서 블룸 필터에는 다음 특징이 있다.

- 거짓 음성: 없음
- 거짓 양성: 있을 수 있음

```text
"절대 없음" → 신뢰 가능
"있을 수 있음" → 추가 확인 필요
```

코딩 테스트 Level 1·2에서 자주 구현하지는 않지만 해시의 확률적 활용을 이해하는 데 도움이 된다.

---

## 13. 학습용 문자열 블룸 필터

```cpp
#include <algorithm>
#include <functional>
#include <string>
#include <vector>
using namespace std;

class SimpleBloomFilter {
private:
    vector<bool> bits;

    size_t first(const string& key) const {
        return hash<string>{}(key) % bits.size();
    }

    size_t second(const string& key) const {
        return hash<string>{}(string("#") + key) % bits.size();
    }

    size_t third(const string& key) const {
        return hash<string>{}(key + string("$")) % bits.size();
    }

public:
    explicit SimpleBloomFilter(size_t bitCount)
        : bits(max<size_t>(1, bitCount), false) {
    }

    void insert(const string& key) {
        bits[first(key)] = true;
        bits[second(key)] = true;
        bits[third(key)] = true;
    }

    bool mightContain(const string& key) const {
        return bits[first(key)] &&
               bits[second(key)] &&
               bits[third(key)];
    }
};
```

실제 서비스에서는 검증된 라이브러리와 해시 함수를 사용한다. 위 코드는 거짓 양성 개념을 확인하는 학습용이다.

<details>
<summary>정답</summary>

```cpp
vector<int> solution(string numberString) {
    vector<int> answer(10, 0);

    for (char ch : numberString) {
        answer[ch - '0']++;
    }

    return answer;
}
```

</details>

## 기본 F2 — 알파벳 빈도

영문 소문자 문자열에서 `a`부터 `z`까지 각 문자의 빈도를 반환한다.

<details>
<summary>정답</summary>

```cpp
vector<int> solution(string word) {
    vector<int> answer(26, 0);

    for (char ch : word) {
        answer[ch - 'a']++;
    }

    return answer;
}
```

</details>

## 기본 F3 — 없는 숫자의 합

`0`부터 `9` 사이의 정수 배열에서 등장하지 않은 숫자의 합을 반환한다. 같은 숫자가 여러 번 들어올 수 있다.

<details>
<summary>정답</summary>

```cpp
int solution(vector<int> numbers) {
    vector<bool> exists(10, false);

    for (int number : numbers) {
        exists[number] = true;
    }

    int answer = 0;

    for (int number = 0; number <= 9; number++) {
        if (!exists[number]) {
            answer += number;
        }
    }

    return answer;
}
```

</details>

## 기본 F4 — 정확히 한 번 등장한 문자

소문자 문자열에서 정확히 한 번 등장한 문자를 알파벳 순서로 이어 붙여 반환한다.

<details>
<summary>정답</summary>

```cpp
string solution(string word) {
    vector<int> count(26, 0);

    for (char ch : word) {
        count[ch - 'a']++;
    }

    string answer = "";

    for (int i = 0; i < 26; i++) {
        if (count[i] == 1) {
            answer += static_cast<char>('a' + i);
        }
    }

    return answer;
}
```

</details>

## 응용 F5 — 애너그램 판별

두 영문 소문자 문자열이 같은 문자를 같은 개수만큼 가지면 `true`를 반환한다.

<details>
<summary>정답</summary>

```cpp
bool solution(string first, string second) {
    if (first.size() != second.size()) {
        return false;
    }

    vector<int> count(26, 0);

    for (char ch : first) count[ch - 'a']++;
    for (char ch : second) count[ch - 'a']--;

    for (int frequency : count) {
        if (frequency != 0) {
            return false;
        }
    }

    return true;
}
```

</details>

## 응용 F6 — 최빈 숫자

`0`부터 `100` 사이의 정수 배열에서 가장 많이 등장한 숫자를 반환한다. 동률이면 더 작은 숫자를 반환한다.

<details>
<summary>정답</summary>

```cpp
int solution(vector<int> numbers) {
    vector<int> count(101, 0);

    for (int number : numbers) {
        count[number]++;
    }

    int answer = 0;

    for (int number = 1; number <= 100; number++) {
        if (count[number] > count[answer]) {
            answer = number;
        }
    }

    return answer;
}
```

</details>

# 책 연습문제 재구성

아래 문제들은 책의 해시 장 연습문제에서 다루는 원리를 유지하되, 코딩 테스트 입문자가 단계적으로 풀 수 있도록 요구사항과 데이터를 재구성했다.

## BOOK-H1 — 나머지 해시 추적

버킷 수가 7이고 해시 함수가 `key % 7`이다. 다음 키를 순서대로 삽입할 때 각 키의 버킷과 충돌 여부를 손으로 기록한다.

```text
키: 2, 25, 10, 100, 55
```

작성 표:

| 키 | 해시 값 | 기존 키와 충돌? |
|---:|---:|---|
| 2 |  |  |
| 25 |  |  |
| 10 |  |  |
| 100 |  |  |
| 55 |  |  |

<details>
<summary>정답</summary>

| 키 | 해시 값 | 기존 키와 충돌? |
|---:|---:|---|
| 2 | 2 | 아니요 |
| 25 | 4 | 아니요 |
| 10 | 3 | 아니요 |
| 100 | 2 | 2와 충돌 |
| 55 | 6 | 아니요 |

</details>

## BOOK-H2 — 충돌을 처리하지 않는 사전의 문제 찾기

다음 구현에서 `insert(2)` 후 `insert(100)`을 수행하면 어떤 문제가 발생하는지 설명한다.

```cpp
vector<int> table(7, -1);

void insert(int value) {
    table[value % 7] = value;
}
```

<details>
<summary>정답</summary>

두 값 모두 인덱스 2를 사용한다. 나중에 삽입한 100이 2를 덮어써서 기존 키 2를 잃어버린다. 키와 해시 값은 같지 않으며 충돌 처리 구조가 필요하다.

</details>

## BOOK-H3 — 체이닝 해시 집합 완성

앞에서 제시한 `ChainedHashSet`에 다음 기능을 추가한다.

- 저장된 서로 다른 값의 개수를 반환하는 `size()`
- 모든 값을 삭제하는 `clear()`
- 현재 부하율을 반환하는 `loadFactor()`

이 문제는 정답을 보지 않고 클래스의 멤버 변수부터 직접 설계한다.

## BOOK-H4 — 선형 탐사 시뮬레이션

크기 7인 테이블에 `2, 9, 16, 23`을 선형 탐사로 삽입한 최종 배열을 작성한다. 해시 함수는 `key % 7`이다.

<details>
<summary>정답</summary>

모든 키의 최초 위치는 2다. 사용 중이면 다음 칸으로 이동한다.

```text
인덱스: 0  1  2  3  4  5  6
값:    -  -  2  9 16 23  -
```

</details>

## BOOK-H5 — 뻐꾸기 해싱 순환 설명

두 해시 테이블과 두 해시 함수가 있을 때, 새 키 삽입으로 기존 키를 계속 밀어내다가 이전 상태로 돌아오면 왜 재해싱이 필요한지 3문장 이내로 설명한다.

## BOOK-H6 — 블룸 필터 판정

블룸 필터의 검색 결과가 다음과 같을 때 확실히 말할 수 있는 내용을 작성한다.

1. 필요한 비트 중 하나가 0이다.
2. 필요한 비트가 모두 1이다.

<details>
<summary>정답</summary>

1. 해당 값은 확실히 없다.
2. 해당 값이 있을 수 있지만 거짓 양성일 수 있으므로 실제 저장소 확인이 필요하다.

</details>

## BOOK-H7 — 이메일 중복 검사 설계

회원가입 요청이 매우 많다. 블룸 필터가 이메일을 “없음”으로 판정한 경우와 “있을 수 있음”으로 판정한 경우 각각 어떤 동작을 수행할지 설계한다.

<details>
<summary>모범 답안</summary>

- “없음”: 실제로 없는 것이 확실하므로 신규 등록 절차를 진행할 수 있다.
- “있을 수 있음”: 거짓 양성일 수 있으므로 데이터베이스에서 실제 중복 여부를 확인한다.

블룸 필터만으로 가입을 거절하면 정상 사용자가 거짓 양성 때문에 거절될 수 있다.

</details>

# 추가 실전 문제 — 정답 없이 풀기

## 추가 1 — 방문한 숫자의 종류 수

값의 범위가 `0`부터 `1,000`일 때 서로 다른 숫자의 개수를 빈도 배열로 구한다.

## 추가 2 — 첫 번째 중복 문자

영문 소문자 문자열을 왼쪽부터 읽어 처음으로 두 번째 등장한 문자를 반환한다. 없으면 `'#'`을 반환한다.

## 추가 3 — 만들 수 있는 문자열

소문자 문자열 `source`의 각 문자를 한 번씩만 사용해 `target`을 만들 수 있는지 판별한다.

## 추가 4 — 부하율 계산

원소 수와 버킷 수가 주어질 때 부하율을 `double`로 반환한다. 버킷 수는 1 이상이다.

## 추가 5 — 충돌 횟수 세기

정수 키 배열과 버킷 수가 주어진다. `key % bucketCount`가 이미 한 번 이상 등장했다면 충돌로 세어 총 충돌 횟수를 반환한다.

## 추가 6 — 빈도 배열인가 해시인가?

다음 입력별로 빈도 배열과 해시 중 하나를 선택하고 이유를 적는다.

- 알파벳 소문자
- 주민등록번호 형태의 긴 문자열
- 시험 점수 0~100
- 웹페이지 URL

# 자료구조 선택 기준

```text
값의 범위가 작고 고정되어 있는가?
        ↓ 예
빈도 배열 또는 직접 주소 지정

        ↓ 아니요
키를 해시해 빠르게 찾을 수 있는가?
        ↓ 예
unordered_set / unordered_map
```

| 필요한 정보 | 적합한 구조 |
|---|---|
| 0~9 숫자의 빈도 | `vector<int>(10)` |
| 알파벳 빈도 | `vector<int>(26)` |
| 문자열 존재 여부 | `unordered_set<string>` |
| 문자열별 횟수 | `unordered_map<string, int>` |
| 메모리를 매우 적게 쓰는 사전 검사 | 블룸 필터 검토 |

# 복습 체크리스트

- [ ] 직접 주소 지정이 가능한 조건을 안다.
- [ ] 문자와 인덱스를 서로 변환할 수 있다.
- [ ] 빈도 배열로 애너그램을 판별할 수 있다.
- [ ] 해시 함수가 키를 버킷 위치로 바꾸는 과정을 설명한다.
- [ ] 서로 다른 키가 같은 해시 값을 가질 수 있음을 안다.
- [ ] 체이닝의 버킷에 여러 값이 저장되는 모습을 설명한다.
- [ ] 선형 탐사의 군집화 문제를 안다.
- [ ] 부하율이 높아지면 충돌 가능성이 커질 수 있음을 안다.
- [ ] `reserve()`가 재해싱 감소에 도움이 될 수 있음을 안다.
- [ ] 블룸 필터의 긍정 결과는 추가 확인이 필요함을 안다.
